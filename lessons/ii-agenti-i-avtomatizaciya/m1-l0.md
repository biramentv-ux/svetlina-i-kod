## Какво е API на модел
Когато пишеш в чат приложение, програмата изпраща текста ти на сървър, а той връща отговор. API (application programming interface) прави същото, но за твоя код: изпращаш HTTP заявка с JSON и получаваш JSON. Предимствата са програмен контрол, автоматизация и възможност да вградиш модела в свое приложение.

Различните услуги имат различни формати, но структурата е почти навсякъде еднаква:

- **Модел** – име на модела, който ще отговаря. Имената и наличността се менят, затова ги вземай от документацията на услугата към деня на ползване.
- **Съобщения (messages)** – списък от обекти с роля (`user`, `assistant`) и съдържание. Някои услуги приемат и роля за системни инструкции, други – отделно поле.
- **Параметри** – ограничение на дължината на отговора, температура и други настройки.
- **Отговор** – текстът на модела, причина за спиране и данни за употребените токени.

Три формата, които ще срещаш най-често: Messages API на Anthropic, API на OpenAI и REST API на Ollama. Много локални сървъри (Ollama, LM Studio, llama.cpp) предлагат и режим, съвместим с формата на OpenAI, затова един и същ код често работи и с облак, и локално – сменяш само адреса и ключа.

## Ключът не е част от кода
API ключът е парола, която позволява харченето на твоя бюджет. Правилата са прости:

1. Никога не го записвай в файл с код, който качваш в git или споделяш.
2. Пази го в променлива на средата. Официалният SDK на Anthropic по подразбиране чете променливата `ANTHROPIC_API_KEY`.
3. Ако ключът е изтекъл (показан в чат, в снимка, в хранилище), считай го за компрометиран: изтрий го в панела на услугата и създай нов.
4. Задай лимит на разходите в панела на услугата, ако той го позволява.

Задаването на променлива за сесията (стойността тук е само пример, вместо нея сложи твоя ключ):

```bash
# Linux и macOS
export ANTHROPIC_API_KEY="твоят-ключ-тук"

# Windows (PowerShell)
$env:ANTHROPIC_API_KEY = "твоят-ключ-тук"
```

За постоянно ползване може да ползваш файл `.env`, който е добавен в `.gitignore`, или мениджър на тайни. Не пиши ключа в чата си, в коментари и в снимки на екрана.

## Първа заявка към Anthropic
Инсталираш официалния пакет с `pip install anthropic`. Минималната заявка към Messages API изглежда така:

```python
import anthropic

client = anthropic.Anthropic()  # ключът се чете от ANTHROPIC_API_KEY

response = client.messages.create(
    model="ИМЕ-НА-МОДЕЛ",  # вземи актуално име от документацията
    max_tokens=300,
    messages=[
        {"role": "user", "content": "Обясни с две изречения какво е API."}
    ],
)

print(response.content[0].text)
print("Спиране:", response.stop_reason)
print("Токени:", response.usage.input_tokens, "вход,",
      response.usage.output_tokens, "изход")
```

Най-важното от кода:

- `max_tokens` е задължително и ограничава дължината на отговора. Ако отговорът бъде отрязан, `stop_reason` ще го покаже.
- `response.content` е списък от блокове. При обикновен текст първият блок съдържа полето `text`.
- `usage` казва колко токена са влезли и излезли – основата на сметката ти.
- Под капака SDK изпраща HTTP заявка към крайната точка `/v1/messages` със заглавия за ключа и за версията на API. Ако предпочиташ да го направиш без SDK, примерите в официалната документация показват точните заглавия.

Системна инструкция в Messages API на Anthropic се подава с отделния параметър `system`, а не като съобщение с роля. Така можеш да зададеш стил и граници: `system="Отговаряй кратко и на български."`.

## Същото без платена услуга: Ollama
Ollama пуска локален сървър на адрес `http://localhost:11434`. Нужно е да имаш инсталирана програмата и свален модел (например с `ollama pull` и името на избран малък модел – какво е налично, виж в каталога на Ollama). Не ти трябват ключ и интернет при самото ползване, а данните не напускат машината ти.

Крайната точка за чат е `POST /api/chat`. Задължителни са полетата `model` и `messages`. Полето `stream` по подразбиране е `true`, а отговорът идва на части; със `"stream": false` получаваш един JSON обект с текста в `message.content`. Ето пример само със стандартната библиотека на Python, без нито една инсталирана зависимост:

```python
import json
import urllib.request

payload = {
    "model": "ИМЕ-НА-ЛОКАЛЕН-МОДЕЛ",  # името от `ollama list`
    "messages": [{"role": "user", "content": "Обясни с две изречения какво е API."}],
    "stream": False,
}
req = urllib.request.Request(
    "http://localhost:11434/api/chat",
    data=json.dumps(payload).encode("utf-8"),
    headers={"Content-Type": "application/json"},
)
with urllib.request.urlopen(req, timeout=120) as resp:
    data = json.load(resp)

print(data["message"]["content"])
print("Токени на изхода:", data.get("eval_count"))
```

Ollama предлага и режим, съвместим с OpenAI, на адрес `http://localhost:11434/v1/`. С официалния пакет `openai` клиентът се насочва към него така: `OpenAI(base_url="http://localhost:11434/v1/", api_key="ollama")`. Ключът е формален – локалният сървър не го проверява, но клиентът изисква непразна стойност. Проверявай подробностите за поддържаните възможности в документацията на Ollama, защото не всички функции са налични в този режим.

## Разговор: историята е твоя
Моделът не помни предишните заявки. Когато искаш разговор, ти сам пазиш списъка със съобщения и го изпращаш целия при всяка нова заявка:

```python
history = []

def ask(client, model, text):
    history.append({"role": "user", "content": text})
    r = client.messages.create(model=model, max_tokens=300, messages=history)
    answer = r.content[0].text
    history.append({"role": "assistant", "content": answer})
    return answer
```

Следствията са важни. Всяка заявка е по-голяма от предишната и струва повече. Контекстният прозорец е ограничен, затова дългите разговори се съкращават или обобщават. И още: цялата история отива при доставчика, така че не включвай лични данни, пароли и поверителни документи, ако нямаш право да ги споделяш с облачна услуга.

## Параметри, които ще ползваш
- **max_tokens** – таван на отговора. Задай го разумно, за да не плащаш за излишен текст.
- **temperature** – по-ниска стойност дава по-предвидими отговори, по-висока – по-разнообразни. За извличане на данни и код започни с ниска. Част от новите модели ограничават или игнорират някои параметри за семплиране, затова провери документацията на избрания модел.
- **system** – постоянни инструкции: роля, формат, език.
- **stream** – при стрийминг отговорът идва на части и потребителят вижда текста веднага. Ползва се в чат интерфейси.

Не променяй по няколко параметъра наведнъж. Така не разбираш кой какво е повлиял.

## Грешки и повторни опити
Заявките могат да се провалят по предвидими причини: грешен или липсващ ключ, превишен лимит на заявките, претоварен сървър, невалидно име на модел, спрян локален сървър. SDK пакетите хвърлят изключения с различни типове – проверявай имената им в документацията на SDK, който ползваш. Принципът е един:

- Грешки на заявката (4xx) обикновено няма смисъл да се повтарят без промяна.
- Временни грешки и лимити се повтарят с нарастваща пауза (exponential backoff) и с горна граница на опитите.
- Винаги задавай таймаут, за да не виси програмата безкрайно.

2. Създай виртуална среда: `python -m venv .venv`, активирай я и инсталирай нужния пакет.
3. Задай ключа като променлива на средата (само за облачния вариант).
4. Запази кода като файл и провери синтаксиса с `python -m py_compile файл.py`.
5. Пусни заявката с кратък въпрос и прочети отговора и броя токени.
6. Промени `max_tokens` на много малка стойност и наблюдавай как се променя `stop_reason`.
7. Добави системна инструкция и сравни резултата.
8. Добави история и задай два свързани въпроса, втория – с местоимение („а той кога е създаден?“).

## Пример от практиката
Да кажем, че искаш да получаваш кратко резюме на български за всяка нова статия, която запазваш. Започваш с най-простото: скрипт, който чете текстов файл, изпраща го със системна инструкция „Обобщи в три изречения на български“ и печата отговора заедно с броя токени.

Първият тест върху дълга статия показва нещо полезно: входните токени са многократно повече от изходните, а българският изисква повече токени от английския за същия смисъл. Решаваш да съкращаваш входа и да ползваш по-малък модел за такава проста задача. А статиите с лични бележки ги пускаш само през локален Ollama, защото не искаш да напускат компютъра ти.

## Чести грешки
- **Ключът в кода** – влиза в git и в чужди ръце. Ползвай променлива на средата.
- **Липсващ или огромен `max_tokens`** – при едни услуги заявката се отхвърля, при други плащаш за ненужно дълги отговори.
- **Запомнено, измислено име на модел** – имената се менят и остаряват. Вземай ги от документацията или от `ollama list`.
- **Очакване, че моделът помни разговора** – без изпратена история всяка заявка започва от нула.
- **Четене на `content[0].text` без проверка** – при други типове блокове полето липсва; в по-сложни приложения обхождай блоковете.
- **Прекалено доверие в отговора** – моделът може да сгреши фактите. Проверявай важното.

## Упражнение
Напиши скрипт с две функции: `ask_cloud(text)` и `ask_local(text)`, които връщат отговора на един и същ въпрос от облачен и от локален модел. Върху общата част от кода сложи общ интерфейс, така че подмяната на модела да е промяна на едно място.

Критерии:
- няма API ключ в нито един файл от проекта;
- и двата файла минават `python -m py_compile`;
- скриптът отпечатва за двата отговора броя токени и причината за спиране или еквивалента в Ollama;
- има таймаут и обработка на грешка при недостъпен сървър, като програмата излиза със смислено съобщение;
- можеш да обясниш на хартия разликата в цената, поверителността и бързината между двата варианта. Ако нямаш ключ за облачна услуга, направи упражнението само с Ollama и сравни два различни локални модела.

## Обобщение
Заявката към API на модел съдържа име на модел, списък със съобщения и параметри, а отговорът – текст, причина за спиране и брой токени. Ключът живее в променлива на средата, а не в кода. Историята на разговора е твое задължение, защото моделът не помни сам. Облачната услуга и локалният Ollama се ползват по сходен начин, затова можеш да започнеш безплатно и да смениш доставчика, когато нуждите го изискат. В следващия урок ще дадеш на модела инструменти.
