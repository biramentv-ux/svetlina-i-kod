> **Цел на урока:** да моделираш данни със `struct` и `enum`, да им добавяш поведение с `impl` и да обработваш всеки възможен случай с `match`, така че компилаторът да ти пази гърба.

## Какво ще научиш
- Как се дефинират структури, кортежни структури и как се създават стойности от тях
- Как методите и свързаните функции се описват в блок `impl`
- Как `enum` носи различни данни във всеки вариант
- Как `match`, `if let` и `let ... else` разглеждат стойностите по образец
- Защо `Option<T>` заменя „null“ и как компилаторът налага изчерпателност

## Структури

Структурата (`struct`) събира именувани полета. Това е основният начин да дадеш име на данни, които вървят заедно:

```rust
#[derive(Debug, Clone)]
struct Settings {
    name: String,
    bpm: u32,
    loop_on: bool,
}
```

Атрибутът `#[derive(Debug, Clone)]` казва на компилатора да генерира сам имплементации: `Debug` позволява печат с `{:?}`, а `Clone` – метод `.clone()`. Създаваш стойност с имената на полетата, а достъпът е през точка. Цялата стойност трябва да е `mut`, за да промениш поле. Не можеш да направиш изменяемо само едно поле. Опитът да присвоиш на поле на неизменяема променлива дава:

```
error[E0594]: cannot assign to `c.name`, as `c` is not declared as mutable
 --> src/main.rs:4:5
  |
4 |     c.name = String::from("b");
  |     ^^^^^^ cannot assign
  |
help: consider changing this to be mutable
  |
3 |     let mut c = Clip { name: String::from("a") };
  |         +++
```

Още три форми, които ще срещаш:

- **Кортежна структура:** `struct Rgb(u8, u8, u8);` – полетата са без имена, достъпът е `c.0`, `c.1`, `c.2`. Подходяща е за малки обвивки, където името на типа вече казва всичко.
- **Съкратен запис:** ако променливата се казва като полето, пишеш `Clip { name, length_ms }`.
- **Копиране от друга стойност:** `Settings { bpm: 140, ..a.clone() }` взема останалите полета от `a`. С `..a` без `.clone()` полетата от тип `String` биха се преместили от `a`.

Тук `a` идва от `Settings::default()`, за която имплементираме трейта `Default`:

```rust
impl Default for Settings {
    fn default() -> Self {
        Settings { name: String::from("без име"), bpm: 120, loop_on: false }
    }
}
```

```
Settings { name: "без име", bpm: 120, loop_on: false }
Settings { name: "без име", bpm: 140, loop_on: false }
```

## Методи с impl

За разлика от езици с класове, в Rust данните и поведението са отделени. Данните са в `struct`, а функциите се закачат към типа в блок `impl`:

```rust
impl Clip {
    fn new(name: &str, length_ms: u64) -> Clip {
        Clip { name: name.to_string(), length_ms, state: State::Stopped }
    }

    fn describe(&self) -> String { /* ... */ }

    fn stop(&mut self) {
        self.state = State::Stopped;
    }
}
```

Първият параметър определя какъв е методът:

| Подпис | Значение | Извикване |
|---|---|---|
| `fn new(...) -> Clip` | свързана функция, без `self` (като статичен метод) | `Clip::new("Тунел", 5000)` |
| `fn describe(&self)` | чете | `clip.describe()` |
| `fn stop(&mut self)` | променя | `clip.stop()` (променливата е `mut`) |
| `fn into_name(self)` | поглъща стойността | `clip.into_name()`; след това `clip` е преместен |

Така правилата от предишния урок се вписват в езика: подписът на метода казва дали чете, променя или консумира. `new` не е ключова дума, а само обичайно име на конструктор. За трейтовете като `Default` ще говорим в третия урок на модула.

## enum: вариант с данни

В повечето езици `enum` е просто списък от имена на числа. В Rust всеки вариант може да носи свои собствени данни, и това е огромна сила. Типът е „сума“: стойността е **или** едното, **или** другото.

```rust
#[derive(Debug, Clone, PartialEq)]
enum State {
    Stopped,
    Playing { position_ms: u64 },
    Paused(u64),
}
```

Тук `Stopped` не носи нищо, `Playing` има именувано поле, а `Paused` – една стойност. В паметта се пази само това, което е нужно за текущия вариант. Невъзможно е да имаш `Stopped` с позиция, която никой не бива да чете. Невалидни състояния просто не могат да се изразят и това е основен подход в Rust: „направи невъзможните състояния непредставими“.

Друг пример: съобщения към програма.

```rust
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
}
```

## match: обработи всеки случай

`match` сравнява стойност с образци и изпълнява първия, който пасне. Ключовото правило е, че **образците трябва да покриват всички възможности**. Ето метод на `Clip`, който описва състоянието:

```rust
fn describe(&self) -> String {
    match &self.state {
        State::Stopped => format!("{}: спрян", self.name),
        State::Playing { position_ms } => format!("{}: свири, {} мс", self.name, position_ms),
        State::Paused(pos) if *pos == 0 => format!("{}: на пауза в началото", self.name),
        State::Paused(pos) => format!("{}: на пауза на {} мс", self.name, pos),
    }
}
```

Образците извличат данните от варианта (`position_ms`, `pos`). Редът `if *pos == 0` е охрана (guard): допълнително условие към образеца. Един цялостен пример: клипът започва спрян, пускаме го, напредваме с 1200 мс, пауза, пак пускане и напредване с 4000 мс при дължина 5000 мс:

```
Тунел: спрян
Тунел: свири, 1200 мс
Тунел: на пауза на 1200 мс
Тунел: спрян
```

Последният ред показва, че `advance` връща клипа в `Stopped`, когато позицията достигне дължината. А ето какво става, ако забравиш вариант:

```
error[E0004]: non-exhaustive patterns: `&State::Paused(_)` not covered
 --> src/main.rs:7:11
  |
7 |     match s {
  |           ^ pattern `&State::Paused(_)` not covered
  |
note: `State` defined here
...
4 |     Paused(u64),
  |     ------ not covered
help: ensure that all possible cases are being handled by adding a match arm with a wildcard pattern or an explicit pattern as shown
```

Това е най-голямата практическа полза. Добавиш ли нов вариант към `enum` след шест месеца, компилаторът сочи **всяко** `match` в проекта, което трябва да се допълни. Заради това избягвай `_ =>` като „хваща всичко“, когато имаш `enum` от твоя код: така се лишаваш от тази защита.

Още форми на образци:

```rust
let kind = match n {
    0 => "нула",
    1..=9 => "цифра",
    10 | 20 | 30 => "кръгло",
    _ => "друго",
};
```

`1..=9` е диапазон, `|` значи „или“, а `_` хваща всичко останало. `match` е **израз** и връща стойност, затова всички рамена трябва да са от един тип.

## if let, let else и Option

Когато те интересува само един вариант, `match` е многословен. Тогава пишеш `if let`:

```rust
fn pause(&mut self) {
    if let State::Playing { position_ms } = self.state {
        self.state = State::Paused(position_ms);
    }
}
```

`let ... else` е удобен за „ранно излизане“:

```rust
let State::Stopped = clip.state.clone() else { panic!("не е спрян") };
```

Блокът `else` трябва да прекъсне изпълнението (`return`, `continue`, `break` или `panic!`).

Най-известният `enum` в стандартната библиотека е:

```rust
enum Option<T> { None, Some(T) }
```

В Rust няма `null`. Стойност, която може да липсва, е `Option<T>`, а не гола `T`. Не можеш да използваш `Option<i32>` като число, без първо да обработиш `None`:

```rust
let items = vec![Some(3), None, Some(7)];
for item in &items {
    match item {
        Some(n) if *n > 5 => println!("голямо {n}"),
        Some(n) => println!("число {n}"),
        None => println!("празно"),
    }
}
```

```
число 3
празно
голямо 7
```

Така класическата грешка с празен указател се превръща в грешка при компилиране. Следващият урок е изцяло за `Option` и `Result`. Накрая един детайл за паметта: `Option<Box<i32>>` заема 8 байта на тази машина, колкото самият указател. Компилаторът ползва нулевия указател като `None`, така че абстракцията не струва нищо.

Често срещана грешка при `match` върху референция към `enum` е опит да извадиш притежавани данни:

```
error[E0507]: cannot move out of `self.cmd` as enum variant `Load` which is behind a shared reference
 --> src/main.rs:5:15
  |
5 |         match self.cmd {
  |               ^^^^^^^^
6 |             Cmd::Load(path) => path,
  |                       ---- data moved here because `path` has type `String`, which does not implement the `Copy` trait
  |
help: consider borrowing here
  |
5 |         match &self.cmd {
  |               +
```

Подсказката е точна: `match &self.cmd` заема вместо да мести. Тогава `path` е `&String`. Ако ти трябва притежавана стойност, добави `.clone()`.

## Стъпка по стъпка

1. Изброй какви състояния има обектът и какви данни трябват във всяко.
2. Ако състоянията се изключват взаимно, направи `enum` с данни във вариантите; ако данните вървят заедно, направи `struct`.
3. Добави `#[derive(Debug)]` и печатай с `{:?}`, за да проверяваш.
4. Напиши `impl` с `new`, методи за четене (`&self`) и методи за промяна (`&mut self`).
5. Обработвай `enum` с `match` без `_ =>`.
6. Пусни `cargo build` и прочети всяка грешка за липсващ вариант като списък със задачи.

## Пример от практиката

Да кажем, че правиш контролер за VJ клипове. Всеки клип има име, дължина и състояние. Първата ти идея е две полета: `playing: bool` и `paused: bool`. Но четирите комбинации не означават четири състояния: „свири“ и „на пауза“ едновременно е безсмислено. Заменяш ги с `enum State` и невалидната комбинация изчезва. После добавяш вариант `Fading(u64)` за плавно изгасяне и компилаторът ти показва точно кои функции не го обработват. Не търсиш ръчно.

## Чести грешки
- **Булеви полета, които се изключват взаимно** – ползвай `enum`.
- **`_ =>` в `match` върху собствен `enum`** – скрива нови варианти. Изброявай ги.
- **`match self.field`, когато вариантът носи `String`** – използвай `match &self.field`.
- **Метод с `&self`, който трябва да променя** – получаваш `E0594` или `E0596`. Смени на `&mut self`.
- **`unwrap()` на `Option` по навик** – при `None` програмата спира. Обработи и двата случая.
- **Огромен `enum` с десетки варианта в един `match`** – раздели логиката на функции.

## Упражнение

Моделирай VJ клип със състояния „спрян“, „свири“ и „на пауза“, както в примера.

1. Дефинирай `enum State` с данни във вариантите и `struct Clip` с име, дължина и състояние.
2. Напиши методи `new`, `play`, `pause`, `stop`, `advance(ms)` и `describe`.
3. Нека `advance` да спира клипа, когато позицията достигне дължината.
4. Напиши `main`, която прави последователност от действия и печата състоянието след всяко.
5. Добави четвърти вариант (например `Fading`) и използвай грешките на компилатора, за да намериш какво да допълниш.

Критерии: няма булеви флагове за състоянието; нито един `match` не ползва `_ =>` върху `State`; `cargo build` е без предупреждения; поне един тест проверява, че `pause` върху спрян клип не променя нищо.

## Бърза справка
- `struct Име { поле: Тип }`, кортежна `struct Име(Тип)`, `..друга` за останалите полета
- `impl Тип { fn new(..) -> Тип; fn m(&self); fn m(&mut self) }`
- `enum` с данни: `Вариант`, `Вариант(Тип)`, `Вариант { поле: Тип }`
- `match` е израз и трябва да е изчерпателен; образци: стойност, `a..=b`, `x | y`, `_`, охрана с `if`
- `if let` за един случай, `let ... else` за ранно излизане
- `Option<T>` вместо null: `Some(x)` и `None`

## Обобщение
Структурите групират полета, а `impl` добавя към тях методи, в които подписът казва дали четеш, променяш или поглъщаш. Енумерациите в Rust носят данни и позволяват да изразиш само валидните състояния. `match` е изчерпателен и компилаторът отказва код, в който липсва случай. Така промяна на модела автоматично сочи всички места, които трябва да се поправят. `Option<T>` прави липсващата стойност част от типа.
