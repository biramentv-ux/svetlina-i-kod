- Как се инсталира Rust с `rustup` и какво получаваш с него

- Как да четеш съобщение за грешка от `rustc`

## Защо Rust

В C и C++ ти управляваш паметта на ръка. Това дава скорост, но една забравена проверка на граница или един използван след освобождаване указател води до срив или до дупка в сигурността. Езици като Python, Java и Go решават проблема със **събирач на боклук** (garbage collector): среда, която по време на работа търси паметта, която никой не ползва. Това е удобно, но струва време, памет и непредвидими паузи.

Rust избира трети път. Правилата за това кой отговаря за всяка стойност в паметта се проверяват **при компилиране**. Ако програмата ги нарушава, тя просто не се компилира. Резултатът е машинен код, близък по скорост до C, без събирач на боклук и без цяла категория грешки с паметта (в безопасния Rust, т.е. извън блоковете `unsafe`, за които ще говорим в последния модул).

Цената е, че компилаторът е строг. В началото ще се караш с него. Този курс е построен така, че да превърнеш строгостта му в навик, който ти помага. Ако идваш от курса „Програмиране от нулата“, разбирането на стека и купчината (heap) оттам ще ти помогне в следващия урок.

## Инсталиране с rustup

Официалният начин е инструментът `rustup` (инсталатор и мениджър на версиите). На официалния сайт на Rust, в страницата за инсталиране, ще намериш точните стъпки за твоята система. Общо взето:

- **Linux, macOS и WSL:** сайтът показва една команда за терминала, която изтегля и стартира `rustup`. Следваш въпросите на екрана и приемаш настройките по подразбиране.
- **Windows:** изтегляш `rustup-init.exe` (има версии за различните процесори) и го пускаш. Rust за Windows използва инструментите за компилиране на Visual Studio, затова инсталаторът може да те подкани да добавиш „C++ build tools“.

След инсталацията отвори **нов** терминал (иначе променливата `PATH` може да не е обновена) и провери:

```
$ rustc --version
rustc 1.97.0 (2d8144b78 2026-07-07)
$ cargo --version
cargo 1.97.0 (c980f4866 2026-06-30)
```

Твоите версии ще са други. Инструментите се слагат в `.cargo/bin` в домашната ти папка, а `rustup update` вдига версията.

С инсталацията получаваш `rustc` (компилаторът, рядко го викаш директно), `cargo` (сглобяване и пакети, с него работиш всеки ден), `rustup` и стандартната библиотека `std`. В целия курс ползваме само нея, без външни пакети.

За редактор вземи VS Code с разширението rust-analyzer или който и да е редактор с поддръжка на езиковия сървър. Показва типовете и грешките докато пишеш.

## Първият проект с Cargo

```
$ cargo new zdravei
    Creating binary (application) `zdravei` package
$ cd zdravei
```

Cargo създава папка със следното съдържание:

- `Cargo.toml` – описание на пакета: име, версия, издание (edition) и списък със зависимости;
- `src/main.rs` – входната точка на програмата;
- `.gitignore`, който изключва папката `target`, където отиват резултатите от компилирането.

Генерираният `Cargo.toml` изглежда така:

```
[package]
name = "zdravei"
version = "0.1.0"
edition = "2024"

[dependencies]
```

„Изданието“ е договор за версията на езика. Секцията `[dependencies]` засега е празна и така ще остане: няма да ползваме външни пакети (crates).

Генерираният `main.rs` печата „Hello, world!“. Пускаш го с:

```
$ cargo run
   Compiling zdravei v0.1.0
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 7.92s
     Running `target/debug/zdravei`
Hello, world!
```

Времето при теб ще е различно.

## Командите на Cargo

| Команда | Какво прави |
|---|---|
| `cargo new име` | създава нов проект |
| `cargo check` | проверява кода без да генерира програма; най-бързата обратна връзка |
| `cargo build` | компилира в режим за разработка (папка `target/debug`) |
| `cargo run` | компилира и пуска |
| `cargo test` | компилира и пуска тестовете |
| `cargo build --release` | компилира с оптимизации (папка `target/release`) |

Режимът `dev` компилира бързо, но програмата е бавна. Режимът `--release` изгражда по-дълго и дава много по-бърза програма, затова скоростта се мери само с него.

## Променливи, mut и типове

Заменяш `src/main.rs` със следното:

```rust
fn greet(name: &str) -> String {
    format!("Здравей, {name}!")
}

fn main() {
    let name = "Мария";
    println!("{}", greet(name));

    let mut counter = 0;
    counter += 1;
    println!("counter = {counter}");

    let price: f64 = 12.5;
    let count: u32 = 4;
    let total = price * count as f64;
    println!("Общо: {total:.2} лв.");

    let x = "5";
    let x: i32 = x.parse().unwrap();
    let x = x * 2;
    println!("x = {x}");

    let point: (i32, i32) = (3, -4);
    let (a, b) = point;
    let levels = [10, 20, 30];
    println!("{a} {b} {} {}", levels[0], levels.len());
    println!("{:?} {:?}", point, levels);
}
```

Изходът е:

```
Здравей, Мария!
counter = 1
Общо: 50.00 лв.
x = 10
3 -4 10 3
(3, -4) [10, 20, 30]
```

Какво се случва тук:

- **`let` създава променлива, а тя по подразбиране е неизменяема.** За да я променяш, пишеш `let mut`. Това е първият пример за философията на Rust: промяната е изричен избор.
- **Типовете се извеждат** (`let name = "Мария"`), но можеш да ги напишеш (`let price: f64`). Функциите винаги пишат типовете на параметрите и на върнатата стойност (`-> String`).
- **Няма автоматично преобразуване между числови типове.** Затова `count as f64`. Компилаторът не гадае дали искаш да губиш точност.
- **Засенчване (shadowing):** `let x` може да се напише отново със същото име. Новата променлива „скрива“ старата и може да има **друг тип**. Това е удобно при преобразуване, например от низ към число. Не е същото като `mut`: тук се създава нова променлива.
- **Последният израз без `;` е върнатата стойност.** В `greet` реда `format!(...)` няма точка и запетая и затова се връща.
- **Форматиране:** `{name}` взима променлива по име, `{:?}` е отпечатване за дебъгване, `{total:.2}` показва две цифри след десетичната запетая.

Основните скаларни типове:

| Вид | Типове | Забележка |
|---|---|---|
| цели със знак | `i8`, `i16`, `i32`, `i64`, `i128`, `isize` | `i32` е по подразбиране |
| цели без знак | `u8`, `u16`, `u32`, `u64`, `u128`, `usize` | `usize` е размерът на указател; ползва се за индекси |
| дробни | `f32`, `f64` | `f64` е по подразбиране |
| логически | `bool` | `true` или `false` |
| символ | `char` | един Unicode символ, 4 байта |
| съставни | кортеж `(i32, i32)`, масив `[i32; 3]` | масивът има фиксирана дължина |

`i32::MAX` е 2147483647, а `u8::MAX` е 255. При препълване в режим `dev` програмата спира с грешка (panic), а в `--release` числото се „завърта“ по правила на допълнителния код, ако не поискаш друго. Не разчитай на нито едното: ползвай `checked_add`, когато препълване е възможно.

## Тестове с Cargo

Добавяш в края на `main.rs`:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn greets_in_bulgarian() {
        assert_eq!(greet("Иван"), "Здравей, Иван!");
    }
}
```

```
$ cargo test
running 1 test
test tests::greets_in_bulgarian ... ok

test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out
```

Ако в теста очакваш „Здравей, Петър!“, получаваш ясно описание какво е различно:

```
---- tests::deliberately_wrong stdout ----
assertion `left == right` failed
  left: "Здравей, Иван!"
 right: "Здравей, Петър!"
test result: FAILED. 1 passed; 1 failed; 0 ignored; 0 measured; 0 filtered out
```

## Компилаторът като учител

Rust има известни с качеството си съобщения за грешки. Ето най-честата грешка на начинаещия:

```rust
fn main() {
    let counter = 0;
    counter = 1;
    println!("{counter}");
}
```

```
error[E0384]: cannot assign twice to immutable variable `counter`
 --> src/main.rs:3:5
  |
2 |     let counter = 0;
  |         ------- first assignment to `counter`
3 |     counter = 1;
  |     ^^^^^^^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut counter = 0;
  |         +++
```

Прочети го по части:

1. **Заглавие:** `error[E0384]` е кодът на грешката, а текстът казва какво не е наред. Кодът можеш да разгледаш с `rustc --explain E0384`, което показва подробно обяснение с примери.
2. **Място:** `src/main.rs:3:5` е файл, ред и колона.
3. **Анотации:** стрелките `^^^` сочат къде е проблемът, а `---` показва свързаното място (първото присвояване).
4. **Подсказка (`help`):** често е готово решение, тук добавяне на `mut`.

Втората класическа грешка е умножение на `f64` с `u32`: получаваш `E0277 cannot multiply f64 by u32`. Лекарството е `price * count as f64`. Съобщението продължава с дълъг списък от типове, които _могат_ да се умножават, затова започвай винаги от първите редове.

## Стъпка по стъпка
1. Инсталирай Rust и провери `rustc --version` и `cargo --version` в нов терминал.
2. Изпълни `cargo new zdravei` и разгледай `Cargo.toml` и `src/main.rs`.
3. Изпълни `cargo run`, после `cargo check` и `cargo build --release`. Забележи, че са различни папки в `target`.
4. Замени програмата с поздрав на български, ползвай `let` и `let mut`.
5. Добави тест с `#[test]` и пусни `cargo test`.
6. Нарочно направи грешка (присвояване на неизменяема променлива) и прочети съобщението.

## Пример от практиката

Да кажем, че правиш малка помощна програма за VJ сет: от темпото в удари в минута (BPM) тя смята колко милисекунди трае един такт. Започваш с `let bpm: f64 = 128.0;`, после `let beat_ms = 60_000.0 / bpm;` и `let bar_ms = beat_ms * 4.0;`. Цифрите с подчертавка (`60_000.0`) са четими и са валиден запис. Ако опиташ да умножиш `bpm` от тип `u32` с дробно число, ще получиш точно грешката `E0277` отгоре. Така виждаш защо Rust иска явни преобразувания: тихото закръгляне би разсинхронизирало визуализациите.

## Чести грешки
- **Забравено `mut`** – получаваш `E0384`. Добави `mut` само ако наистина променяш стойността.
- **Точка и запетая след последния израз** – функцията, която трябва да върне стойност, връща `()` и компилаторът се оплаква за несъвпадащи типове. Махни `;` в края.
- **Смесване на числови типове** – `f64 * u32` и подобни. Преобразувай с `as` или промени типа на променливата.
- **Тестване на скорост с `cargo run`** – `dev` режимът е в пъти по-бавен. Ползвай `cargo run --release`.
- **Игнориране на предупреждения** – `warning` не спира компилирането, но обикновено сочи реален проблем. Целта е `cargo build` без предупреждения.

## Упражнение

Създай проект `pozdrav`. Програмата трябва да:

1. има функция `greet(name: &str) -> String`, която връща „Здравей, <име>!“ на български;
2. печата поздрав за три различни имена;
3. има променлива `let mut` за брояч на поздравите и печата колко са били;
4. пресмята дължината на такт при 140 BPM в милисекунди и я печата с една цифра след запетаята;
5. има поне два теста с `#[test]`.

Критерии: `cargo build` не дава предупреждения; `cargo test` минава; можеш да обясниш защо `bpm` е `f64`; нарочно си предизвикал грешката `E0384` и можеш да прочетеш всяка част от съобщението ѝ.

## Бърза справка
- `cargo new`, `check`, `build`, `run`, `test`, `build --release`
- `let` е неизменяема, `let mut` е изменяема; `let x = ...` отново засенчва
- Числови типове се преобразуват с `as`; по подразбиране `i32` и `f64`
- Последният израз без `;` е върнатата стойност
- `{}` и `{:?}` печатат; `{име}` и `{:.2}` са форматиране
- `rustc --explain КОД` обяснява грешка

## Обобщение
Rust проверява правилата за паметта при компилиране, затова няма нужда от събирач на боклук и няма много от класическите грешки на C. Cargo е центърът на работата: създава проекти, компилира, пуска и тества. Променливите са неизменяеми по подразбиране, а типовете се преобразуват изрично. Съобщенията на компилатора сочат точното място, обясняват причината и често предлагат поправка, затова ги чети внимателно. В следващия урок започва най-важната идея на езика: собствеността.
