> **Цел на урока:** да разбереш трите правила на собствеността и на заемането, да виждаш кога стойност се премества и кога се копира, и да четеш и поправяш най-честите откази на borrow checker-а.

## Какво ще научиш
- Кои са трите правила на собствеността и защо те заместват събирача на боклук
- Разликата между преместване (move), копиране (Copy) и клониране (clone)
- Как работят `&T` и `&mut T` и правилото „много читатели или един писател“
- Как животът на стойностите (lifetimes) предпазва от висящи референции
- Как да четеш и поправяш пет типични грешки на компилатора

## Трите правила

В Rust паметта се управлява без събирач на боклук и без ръчно `free`. Мястото на двете заема система от правила, която компилаторът проверява:

1. Всяка стойност има **собственик** (променлива).
2. В даден момент собственикът е **само един**.
3. Когато собственикът излезе от обхват (scope), стойността се **освобождава** автоматично.

Третото правило е познато от C++ като RAII. Компилаторът вмъква извикването на освобождаването точно в края на блока. Не можеш да го забравиш или да го направиш два пъти. Можеш да го видиш, ако дадеш на структура собствена функция `drop`:

```rust
struct Clip { name: String }

impl Drop for Clip {
    fn drop(&mut self) {
        println!("освобождавам {}", self.name);
    }
}

fn main() {
    let _outer = Clip { name: String::from("външен") };
    {
        let _inner = Clip { name: String::from("вътрешен") };
        println!("край на вътрешния блок");
    }
    let moved = Clip { name: String::from("преместен") };
    drop(moved);
    println!("край на main");
}
```

```
край на вътрешния блок
освобождавам вътрешен
освобождавам преместен
край на main
освобождавам външен
```

Вътрешният се освобождава в края на своя блок, `moved` – при изричното `drop(moved)`, а външният – последен, в края на `main`. Освобождаването е по обратен ред на създаването.

## Преместване, копиране и клониране

Числата са прости стойности, които живеят изцяло на стека. Присвояването ги копира:

```rust
let a = 5;
let b = a;
println!("a={a} b={b}"); // a=5 b=5
```

`String` е различен. Тя държи указател към текст в купчината (heap), дължина и капацитет. Ако `let s3 = s1` копираше само тези три полета, два собственика щяха да сочат към една памет и щяха да я освободят два пъти. Затова Rust **премества** собствеността: след `let s3 = s1;` променливата `s1` вече не може да се ползва.

```rust
let s1 = String::from("здравей");
let s2 = s1.clone();   // истинско копие на данните
println!("{s1} {s2}"); // здравей здравей
let s3 = s1;           // преместване; от тук нататък s1 е недостъпна
println!("{s3}");
```

Същото важи при подаване на стойност на функция. Ето първата класическа грешка:

```rust
fn consume(s: String) -> usize {
    s.len()
}

fn main() {
    let title = String::from("Алфа");
    let n = consume(title);
    println!("{n}");
    println!("{title}");
}
```

```
error[E0382]: borrow of moved value: `title`
 --> src/main.rs:9:16
  |
6 |     let title = String::from("Алфа");
  |         ----- move occurs because `title` has type `String`, which does not implement the `Copy` trait
7 |     let n = consume(title);
  |                     ----- value moved here
8 |     println!("{n}");
9 |     println!("{title}");
  |                ^^^^^ value borrowed here after move
  |
note: consider changing this parameter type in function `consume` to borrow instead if owning the value isn't necessary
help: consider cloning the value if the performance cost is acceptable
```

Компилаторът ти показва три неща: къде е създадена стойността, къде е преместена и къде е използвана след това. Дава и две лекарства: да **заемеш** вместо да преместиш (по-добро) или да **клонираш** (струва копие на данните).

| Понятие | Какво се случва | Пример за типове |
|---|---|---|
| Copy | битово копие; оригиналът остава валиден | `i32`, `f64`, `bool`, `char`, кортежи от такива |
| Move | собствеността минава към новия; старият е невалиден | `String`, `Vec<T>`, `Box<T>` |
| Clone | изрично, обикновено скъпо копие с `.clone()` | почти всички стандартни типове |

Типът е `Copy`, само ако е евтино да се копира и няма какво да се освобождава. Няма `Copy` тип, който притежава памет в купчината.

## Заемане: &T и &mut T

Преместването при всяко извикване би било неудобно. Затова има **заемане** (borrowing): подаваш референция, а собственикът остава същият.

```rust
fn length(s: &String) -> usize { s.len() }
fn shout(s: &mut String) { s.push_str("!"); }

fn main() {
    let mut title = String::from("Тунел");
    println!("дължина в байтове: {}", length(&title)); // 10
    shout(&mut title);
    println!("{title}"); // Тунел!
}
```

Стойността 10 не е грешка: „Тунел“ са пет кирилски букви по два байта. За това ще говорим в модул 3.

Правилото, което покрива почти всичко, е:

> В даден момент имаш **или** произволно много неизменяеми референции (`&T`), **или** точно една изменяема (`&mut T`), но никога и двете заедно.

Това е същото като при заключване за четене и писане, само че проверено при компилиране и без цена по време на работа. Забранява гонитбите за данни (data races) и класически грешки като инвалидиране на итератор по време на промяна.

Втората класическа грешка: държиш референция към елемент и променяш вектора.

```rust
let mut clips = vec![String::from("a"), String::from("b")];
let first = &clips[0];
clips.push(String::from("c"));
println!("{first}");
```

```
error[E0502]: cannot borrow `clips` as mutable because it is also borrowed as immutable
 --> src/main.rs:4:5
  |
3 |     let first = &clips[0];
  |                  ----- immutable borrow occurs here
4 |     clips.push(String::from("c"));
  |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ mutable borrow occurs here
5 |     println!("{first}");
  |                ----- immutable borrow later used here
```

Това не е формалност: `push` може да премести целия вектор на ново място в паметта и тогава `first` би сочила към освободена памет. Rust не те оставя да стигнеш дотам. Решението е да ползваш `first` преди `push` или да вземеш копие на стойността (`clips[0].clone()`).

Забележи, че грешката сочи и мястото на **по-късното използване**. Заемането живее само дотам, докъдето референцията се ползва за последно (нарича се „non-lexical lifetimes“). Затова този код минава:

```rust
let r1 = &title;
let r2 = &title;
println!("{r1} {r2}");
let w = &mut title; // r1 и r2 вече не се ползват
w.push('?');
```

Другите две грешки на правилото:

```
error[E0499]: cannot borrow `s` as mutable more than once at a time
 --> src/main.rs:4:13
  |
3 |     let a = &mut s;
  |             ------ first mutable borrow occurs here
4 |     let b = &mut s;
  |             ^^^^^^ second mutable borrow occurs here
5 |     a.push('1');
  |     - first borrow later used here
```

```
error[E0596]: cannot borrow `*v` as mutable, as it is behind a `&` reference
 --> src/main.rs:2:5
  |
2 |     v.push(1);
  |     ^ `v` is a `&` reference, so it cannot be borrowed as mutable
help: consider changing this to be a mutable reference
  |
1 | fn add_one(v: &mut Vec<i32>) {
  |                +++
```

Първата е два `&mut s` едновременно, а втората – опит да промениш през неизменяема референция. И двете имат ясно решение: един писател наведнъж и `&mut` в подписа на функцията.

## Животът на стойностите

Референцията не трябва да надживява това, към което сочи. Компилаторът следи това с **животи** (lifetimes). В повечето случаи не ги пишеш, защото се извеждат сами. Ето двата случая, в които ще ги видиш.

Първо, референция към вътрешна променлива, която вече е изчезнала:

```rust
let r;
{
    let x = String::from("кратък живот");
    r = &x;
}
println!("{r}");
```

```
error[E0597]: `x` does not live long enough
 --> src/main.rs:5:13
  |
4 |         let x = String::from("кратък живот");
  |             - binding `x` declared here
5 |         r = &x;
  |             ^^ borrowed value does not live long enough
6 |     }
  |     - `x` dropped here while still borrowed
7 |     println!("{r}");
  |                - borrow later used here
```

Това е „висящ указател“ (dangling pointer), познат от C. В Rust е грешка при компилиране, а не срив на произволно място по време на работа.

Второ, функция, която връща референция, но няма откъде да я вземе:

```rust
fn longest() -> &String {
    let s = String::from("hello");
    &s
}
```

```
error[E0106]: missing lifetime specifier
 --> src/main.rs:1:17
  |
1 | fn longest() -> &String {
  |                 ^ expected named lifetime parameter
  |
  = help: this function's return type contains a borrowed value, but there is no value for it to be borrowed from
help: instead, you are more likely to want to return an owned value
```

Правилното решение тук е да върнеш самата стойност (`-> String`). Когато реално връщаш част от входа, казваш на компилатора коя:

```rust
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}
```

`'a` значи: „върнатата референция живее най-много колкото двата аргумента“. Не променя колко живеят стойностите, а само описва връзката между тях. Типът `&str` е референция към част от низ (slice) и приема и `&String`, и литерал. Предпочитай `&str` пред `&String` и `&[T]` пред `&Vec<T>` в параметрите.

## Стъпка по стъпка

Така подхождаш към всяка грешка за собственост:

1. Прочети първата грешка и намери трите места: създаване, преместване или заемане, и по-късно използване.
2. Попитай: функцията трябва ли да **притежава** стойността? Ако не, смени параметъра на `&T` или `&mut T`.
3. Ако наистина ти трябват две независими копия, използвай `.clone()`.
4. Ако промяната и четенето си пречат, пренареди кода така, че да използваш референцията преди промяната.
5. Ако връщаш референция, провери откъде идва. Ако е от локална променлива, върни стойността.
6. Пусни `cargo build` отново. Поправяй по една грешка.

## Пример от практиката

Да кажем, че пишеш програма, която пази списък с имена на клипове за лайв сет. Функция `rename_all(clips: Vec<String>)` взема вектора по стойност и след извикването в `main` не можеш да го ползваш, защото е преместен. Подписът `rename_all(clips: &mut Vec<String>)` решава задачата и ясно казва на читателя: „тази функция ще промени списъка“. А `count_long(clips: &[String]) -> usize` обещава само да чете. По подписа знаеш какво прави функцията, още преди да прочетеш тялото ѝ.

## Чести грешки
- **`.clone()` навсякъде, за да замълчи компилаторът** – работи, но крие проблема и харчи памет. Първо опитай със заемане.
- **Държане на референция към елемент, докато колекцията се променя** – `E0502`. Вземи копие или използвай референцията по-рано.
- **Връщане на референция към локална променлива** – `E0106` или `E0597`. Върни притежавана стойност.

## Упражнение

Създай проект и напиши пет малки програми. Всяка трябва да е **нарочно счупена** и да дава различна грешка: `E0382` (използване след преместване), `E0502` (четене и писане едновременно), `E0499` (две `&mut`), `E0596` (промяна през `&`) и `E0597` или `E0106` (висяща референция). За всяка от тях:

1. запиши кода и първите редове от съобщението;
2. обясни с две изречения какво правило е нарушено;
3. поправи я по два различни начина, където е възможно (например заемане и `.clone()`);
4. провери с `cargo build`, че няма грешки и предупреждения.

Критерии: поправките не използват `.clone()` там, където заемането е достатъчно; можеш да кажеш за всяка функция дали притежава, чете или променя аргумента си; обясненията ти не повтарят текста на компилатора, а го преразказват със свои думи.

## Бърза справка
- Един собственик; освобождаване в края на обхвата
- `Copy` за прости типове, `move` за притежаващи, `.clone()` за изрично копие
- `&T`: много; `&mut T`: един; никога заедно
- Заемането трае до последното използване
- Не връщай референция към локална стойност
- Параметри: `&str` и `&[T]` вместо `&String` и `&Vec<T>`

## Обобщение
Собствеността е идеята, която прави Rust различен: всяка стойност има един собственик и се освобождава, когато той излезе от обхват. Подаването на стойност я премества, освен ако типът е `Copy`. За временен достъп заемаш с `&T` или `&mut T`, при правилото „много читатели или един писател“. Животът на референциите гарантира, че никога не сочат към освободена памет. Когато компилаторът откаже, ти показва къде е създадена, преместена и използвана стойността. Това е почти цялата информация за поправката.
