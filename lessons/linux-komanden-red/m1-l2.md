> **Цел на урока:** да напишеш надежден Bash скрипт с аргументи, проверки и обработка на грешки, който архивира папка с дата в името.

## Какво ще научиш
- Как да започнеш скрипт с shebang, да го направиш изпълним и да му подадеш аргументи
- Как се ползват променливи, кавички и защо кавичките са най-честият източник на грешки
- Как да пишеш `if`, `for` и функции и да върнеш код за изход
- Какво правят `set -euo pipefail` и `trap` и защо ги слагаш в началото на всеки сериозен скрипт
- Как да тестваш и дебъгваш скрипта си с `bash -n` и `bash -x`

## Скриптът е записана поредица от команди

Всичко, което пишеш в терминала, може да се запише във файл и да се изпълнява наново. Но скриптът е нещо повече от „запис“: той има променливи, условия и цикли, така че се държи различно според входа. Ето най-малкия полезен пример:

```
#!/usr/bin/env bash
ime="${1:-свят}"
echo "Здравей, $ime!"
echo "Скриптът е $0, аргументи: $#, всички: $*"
```

Първият ред, **shebang** (`#!`), казва на системата с какъв интерпретатор да изпълни файла. Вариантът `#!/usr/bin/env bash` намира `bash` в пътя на потребителя и работи и на дистрибутиви, където той не е в `/bin`. След това правиш файла изпълним (както в първия урок) и го пускаш:

```
$ chmod +x zdravej.sh
$ ./zdravej.sh
Здравей, свят!
Скриптът е ./zdravej.sh, аргументи: 0, всички:
$ ./zdravej.sh Ана Борис
Здравей, Ана!
Скриптът е ./zdravej.sh, аргументи: 2, всички: Ана Борис
```

Специалните променливи са: `$0` – името на скрипта, `$1`, `$2`, … – аргументите, `$#` – броят им, `$*` и `$@` – всички, `$?` – кодът за изход на последната команда. Изразът `${1:-свят}` значи „стойността на `$1`, а ако е празна – `свят`“.

## Променливи и кавички

Присвояването е без интервали около `=`: `име="Ана"`. Стойността се чете с `$име` или `${име}`. Резултат от команда се вмъква с `$(команда)`, а аритметика – с `$((2 + 3))`.

Кавичките решават какво се разширява:

| Запис | Поведение |
|---|---|
| `"$x"` | стойността се вмъква като **един** аргумент, интервалите се пазят |
| `'$x'` | буквален текст, нищо не се разширява |
| `$x` (без кавички) | стойността се разцепва на думи и може да се разшири до файлове |

Разликата е видна веднага:

```
$ x="a  b"; echo $x; echo "$x"; echo '$x'
a b
a  b
$x
```

Още по-опасно е с имена на файлове с интервал. Цикъл върху `$(ls)` разбива име като `fa il.txt` на две части, а цикъл с шаблон не:

```
$ for f in $(ls); do echo "[$f]"; done
[fa]
[il.txt]
[zdravej.sh]
$ for f in *; do echo "<$f>"; done
<fa il.txt>
<zdravej.sh>
```

Затова правилото е: **винаги слагай променливите в двойни кавички** (`"$f"`), а за файлове ползвай `for f in *`, не `$(ls)`.

## Условия, цикли и функции

Условията ползват `[[ ... ]]` (в Bash) и кодове за изход: 0 е успех, всяко друго число е грешка. Ето скрипт, който проверява папка:

```
#!/usr/bin/env bash
if [[ ! -d "$1" ]]; then
  echo "Няма такава папка: $1" >&2
  exit 1
elif [[ -z "$(ls -A "$1")" ]]; then
  echo "Папката е празна"
else
  echo "Във $1 има $(ls -A "$1" | wc -l) обекта"
fi
```

```
$ ./proveri.sh /nema; echo "rc=$?"
Няма такава папка: /nema
rc=1
$ ./proveri.sh prazna
Папката е празна
$ ./proveri.sh .
Във . има 4 обекта
```

Полезни тестове: `-d` (папка), `-f` (файл), `-e` (съществува), `-z` (празен низ), `-n` (непразен), `-eq`/`-lt`/`-gt` за числа и `==` за низове. Съобщенията за грешка пращай към stderr с `>&2`, а с `exit` завършваш с код.

Цикълът `for` обхожда списък, а `while read` чете ред по ред:

```
$ for ext in txt sh; do echo "$ext: $(find . -maxdepth 1 -name "*.$ext" | wc -l)"; done
txt: 1
sh: 2
```

Функцията събира повтарящ се код. Променливите вътре е добре да са `local`, а аргументите ѝ се казват `$1`, `$2` – като при скрипта:

```
$ f() { local n=$1; echo "Двойно: $((n*2))"; return 0; }; f 21
Двойно: 42
```

## Режимът „строг“: set -euo pipefail

Без допълнителни настройки Bash е щедър: ако една команда се провали, скриптът продължава. Това води до катастрофи, като `cd` не успява и после `rm -rf *` се изпълнява в грешната папка. Три настройки променят това:

- `set -e` – спира скрипта при първата неуспешна команда
- `set -u` – грешка при обръщение към несъществуваща променлива (вместо празен низ)
- `set -o pipefail` – конвейерът е неуспешен, ако **някоя** негова част е неуспешна, а не само последната

Реални изходи:

```
$ bash -c 'false; echo "продължава"'
продължава
$ bash -c 'set -e; false; echo "няма да се види"'; echo "rc=$?"
rc=1
$ bash -c 'set -u; echo "$neexistvasht"'
bash: line 1: neexistvasht: unbound variable
$ bash -c 'false | true; echo "rc без pipefail=$?"'
rc без pipefail=0
$ bash -c 'set -o pipefail; false | true; echo "rc с pipefail=$?"'
rc с pipefail=1
```

Не е магия, а компромис: `set -e` има странни изключения (например в условия `if` и в `||`), така че не заменя изричните проверки. Добавяй и двете.

За изчистване при завършване ползвай `trap 'команда' EXIT`. Тя се изпълнява при нормален изход и при грешка (но не при `SIGKILL`). Така временните файлове не остават.

## Стъпка по стъпка: архив с дата в името

Събираме всичко в един скрипт, който архивира папка в `.tar.gz` с дата и час в името.

```
#!/usr/bin/env bash
set -euo pipefail

usage() { echo "Употреба: $0 ПАПКА [ДЕСТИНАЦИЯ]" >&2; exit 2; }
[[ $# -ge 1 ]] || usage
src="${1%/}"
dest="${2:-.}"
[[ -d "$src" ]] || { echo "Грешка: '$src' не е папка" >&2; exit 1; }
mkdir -p "$dest"
stamp="$(date +%Y-%m-%d_%H%M%S)"
out="$dest/$(basename "$src")_$stamp.tar.gz"
tmp="$(mktemp "$dest/.arhiv.XXXXXX")"
trap 'rm -f "$tmp"' EXIT
tar -czf "$tmp" -C "$(dirname "$src")" "$(basename "$src")"
mv "$tmp" "$out"
echo "Готово: $out ($(du -h "$out" | cut -f1))"
```

Какво прави всяка част:

1. `set -euo pipefail` включва строгия режим.
2. `usage` извежда помощ и излиза с код 2, ако няма аргумент.
3. `${1%/}` маха последна наклонена черта; `${2:-.}` дава подразбираща се цел – текущата папка.
4. Проверката `-d` спира скрипта с ясно съобщение, ако източникът не е папка.
5. `date +%Y-%m-%d_%H%M%S` прави име, което се подрежда по азбучен ред и по време.
6. Архивът първо се пише във временен файл и чак после се премества на мястото си. Така недовършен архив никога не изглежда като готов (преместването в същата папка е атомарно).
7. `trap` трие временния файл, ако нещо се провали по средата.

Пускам го върху малко дърво (в името на единия файл има интервал, за да се провери коректната работа с кавички):

```
$ ./arhiv.sh; echo "rc=$?"
Употреба: ./arhiv.sh ПАПКА [ДЕСТИНАЦИЯ]
rc=2
$ ./arhiv.sh nema; echo "rc=$?"
Грешка: 'nema' не е папка
rc=1
$ ./arhiv.sh proekt backups; echo "rc=$?"
Готово: backups/proekt_2026-11-22_130422.tar.gz (4.0K)
rc=0
$ tar -tzf backups/*.tar.gz
proekt/
proekt/data/
proekt/data/b c.txt
proekt/data/a.txt
```

Архивът запазва относителните пътища и не съдържа абсолютния път на изходната папка.

## Тестване и дебъгване

Две команди вършат голямата част от работата:

```
$ bash -n arhiv.sh && echo "синтаксис OK"
синтаксис OK
$ bash -x ./arhiv.sh proekt backups 2>&1 | head -5
+ set -euo pipefail
+ [[ 2 -ge 1 ]]
+ src=proekt
+ dest=backups
+ [[ -d proekt ]]
```

`bash -n` проверява синтаксиса без да изпълнява, а `bash -x` печата всяка команда със стойностите на променливите. За по-прецизни проверки има инструментът `shellcheck`: намира липсващи кавички и други капани. Не е инсталиран по подразбиране и не съм го пускал тук; на Ubuntu/Debian е в пакет `shellcheck` (`sudo apt install shellcheck`), на Fedora – `ShellCheck` (`sudo dnf install ShellCheck`).

## Различия и пренос

- **`sh` не е `bash`.** На Ubuntu и Debian `/bin/sh` е `dash`: прост и бърз, но без `[[`, масиви и др. Скрипт с `#!/bin/sh`, който ползва `[[`, дава грешка:

```
$ ./t.sh
./t.sh: 2: [[: not found
```

  Ако ползваш Bash възможности, пиши `#!/usr/bin/env bash`.
- **macOS** носи стар Bash 3.2 (и `zsh` по подразбиране), затова по-нови функции може да липсват.
- **WSL:** редовете в скриптовете трябва да са с Linux край (`LF`). Файл, записан от Windows редактор с `CRLF`, дава грешки от типа `bad interpreter`. Настрой редактора на LF.
- **Fedora и Ubuntu:** Bash е еднакъв по поведение; различават се само пътищата за пакети и някои допълнителни помощни програми.

## Пример от практиката

Да кажем, че преди всяка работа с проект за генеративни визуализации искаш бърз архив на папката. Слагаш `arhiv.sh` в `~/bin`, добавяш папката към `PATH` и пишеш `arhiv.sh ~/proekti/vizualizacia ~/backups`. Ако искаш това да става автоматично всяка нощ, можеш да го пуснеш с `cron` или таймер на systemd, но първо го изпробвай ръчно: автоматизираш само проверено. Същият модел „проверка на входа, действие, ясно съобщение“ се прилага за конвертиране на файлове, смяна на имена и подготовка на среда.

## Чести грешки

- **Липсващи кавички** – `rm $f` с интервал в името трие грешни файлове. Пиши `rm -- "$f"`.
- **Интервали около `=`** – `x = 5` пуска команда `x`. Пиши `x=5`.
- **Без `set -euo pipefail`** – скриптът продължава след грешка и причинява вреда. Започвай сериозните скриптове с него.
- **`cd` без проверка** – `cd "$dir" || exit 1`, иначе следващите команди работят в грешната папка.
- **Парсване на `ls`** – ползвай шаблони `*` или `find`.
- **Скрипт без `x` или с CRLF** – `Permission denied` или `bad interpreter`.

## Упражнение

Напиши `arhiv.sh` по описанието. После го разшири: нов втори параметър е броят архиви, които да се запазят (например 3), а по-старите се изтриват. Подсказка: подреждането по име в `backups` е хронологично; ползвай `ls -1`, `head` и внимавай да триеш само файлове, чиито имена започват с очаквания префикс.

Критерии:
- без аргументи скриптът пише помощ и излиза с код 2
- при несъществуваща папка излиза с код 1 и ясно съобщение
- името на архива съдържа дата и час, а архивът не съдържа абсолютни пътища
- работи с имена на папки с интервал
- `bash -n` не дава грешки и не изтрива нищо извън избрания префикс

## Бърза справка

| Конструкция | Значение |
|---|---|
| `#!/usr/bin/env bash` | shebang |
| `"$1"`, `$#`, `"$@"`, `$?` | аргумент, брой, всички, код на изход |
| `${x:-стойност}` | подразбираща се стойност |
| `$(команда)`, `$((a+b))` | резултат от команда, аритметика |
| `[[ -d "$p" ]]`, `[[ -z "$s" ]]` | е папка, е празен |
| `for f in *; do ...; done` | цикъл по файлове |
| `set -euo pipefail` | строг режим |
| `trap 'rm -f "$t"' EXIT` | изчистване при изход |
| `bash -n` / `bash -x` | проверка / проследяване |

Ако в курса `programirane-ot-nulata` вече пишеш на Python, запомни кога Bash е достатъчен (свързване на команди, файлове) и кога вече си струва да минеш на Python (сложна логика, структури от данни).

## Обобщение

Bash скриптът е изпълним файл със shebang, променливи, условия, цикли и функции. Кавичките около `"$променливите"` предпазват от разбиване на имена с интервали, а `set -euo pipefail` и `trap` правят скрипта безопасен при грешка. Кодовете за изход и съобщенията към stderr го правят удобен за свързване с други инструменти. Проверявай с `bash -n`, следи с `bash -x` и тествай първо върху безвредни данни.
