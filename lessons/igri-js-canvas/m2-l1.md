> **Цел на урока:** да направиш играта да се усеща добре, да е честна към играча и да става по-трудна постепенно, и да проверяваш това с числа и с живи хора, а не по усещане.

## Какво ще научиш
- Как малки ефекти (частици, треперене, звук) показват на играча, че действието му е сработило
- Какво значи честна игра и защо загубата трябва да е обяснима
- Как да изчислиш и настроиш крива на трудността, вместо да налучкваш числата
- Как да организираш тест с други хора и какво да записваш

## Усещането е обратна връзка
Две игри могат да имат еднакви правила и да се усещат напълно различно. Разликата е в **обратната връзка (feedback)**: колко ясно играта казва „хвана звезда“, „удари те камък“, „мина ниво“. Когато няма отговор, играчът не е сигурен дали е направил нещо, и губи интерес.

Основното правило: **всяко важно събитие получава поне два различни отговора** – например образ и звук. Ефектите са кратки (под секунда) и не пречат на следващото действие.

| Събитие | Образ | Звук |
|---|---|---|
| Хваната звезда | 12 жълти частици | висок тон, 0,08 s |
| Удар с камък | треперене, червен блясък, 16 частици | нисък тон, 0,2 s |
| Ново ниво | надпис „Ниво N“ | (добави сам) |

Ето ефектите в „Звездопад“. Частиците са прости обекти с живот, треперенето и блясъкът намаляват сами във времето, а звукът е кратък осцилатор от Web Audio:

```js
let parts = [], shake = 0, flash = 0, audio = null;

function beep(freq, dur = 0.08) {
  if (!audio) return;
  const o = audio.createOscillator(), g = audio.createGain();
  o.frequency.value = freq; g.gain.value = 0.08;
  g.gain.exponentialRampToValueAtTime(0.001, audio.currentTime + dur);
  o.connect(g); g.connect(audio.destination);
  o.start(); o.stop(audio.currentTime + dur);
}
function burst(x, y, color, n) {
  for (let i = 0; i < n; i++) {
    const a = Math.random() * Math.PI * 2, v = 60 + Math.random() * 140;
    parts.push({ x, y, vx: Math.cos(a) * v, vy: Math.sin(a) * v, life: 0.5, color });
  }
}
function updateFx(dt) {
  for (const p of parts) { p.x += p.vx * dt; p.y += p.vy * dt; p.life -= dt; }
  parts = parts.filter(p => p.life > 0);
  shake = Math.max(0, shake - 40 * dt);
  flash = Math.max(0, flash - 3 * dt);
}
```

При хващане викаш `burst(d.x, d.y, "#ffd23f", 12); beep(660);`, а при удар – `shake = 12; flash = 1; burst(d.x, d.y, "#ff7a8f", 16); beep(140, 0.2);`. В `drawWorld` пред рисуването слагаш `ctx.save()` и `ctx.translate()` със случайно отместване до `shake`, а накрая – `ctx.restore()` и полупрозрачен червен правоъгълник с прозрачност `flash * 0.5`. Звукът може да започне едва след действие на играча, затова `AudioContext` се създава в първия `keydown`.

Автоматичен тест с Playwright вмъква звезда и камък върху героя и чете състоянието (реален изход):

```

звезда   -> точки: 1 | частици: 12
след 0,7 s -> частици: 0
камък    -> животи: 2 | треперене: 10.7 | флаш: 0.9 | частици: 16
пиксел вляво (5,60): [ 122, 45, 62, 255 ]
след 1,5 s -> треперене: 0 | флаш: 0 | частици: 0
конзола: празна
```

Пикселът на тъмния фон (13, 18, 48) се е зачервил в момента на удара, а след секунда и половина всичко е спряло само. Ако ефектите не затихват, имаш грешка в таймерите.

## Честна игра
Играта е **честна**, когато играчът може да обясни загубата си с „това беше моя грешка“, а не с „не видях“ или „не беше възможно“. Няколко практични правила:
- Опасното и полезното се различават по цвят **и** по форма: светеща жълта звезда срещу матово сиво кръгче. Не разчитай само на цвета – част от хората не различават някои цветове.
- Сблъсъкът става, когато фигурите наистина се докосват. По-малка зона за удар от видимата е по-прощаваща; по-голяма води до „как ме удари, нали го заобиколих?“.
- Нищо не се появява върху героя без предупреждение.
- Рекордът и точките се виждат постоянно.

## Крива на трудността
Трудността е как расте предизвикателството с времето. Линейният растеж е лесен за писане, но обикновено е скучен или нечестен. Добрата крива има рамка: бавно начало за научаване, нарастване, и граница, над която играта не става невъзможна.

Вместо да налучкваш числа, измери нещо. В „Звездопад“ най-важният въпрос е: **колко от съседните двойки звезди е невъзможно да хванеш и двете?** Звездите падат на `every` секунди една след друга, героят се движи със скорост 240, а хоризонталното разстояние между две звезди е случайно. Ако е по-голямо от `240 * every`, втората не може да се достигне. Скриптът смята това на формула и го проверява със симулация (опростен модел: без камъните и без трета звезда). Генераторът е с фиксирано начало, така че изходът е един и същ при всяко пускане.

```js
const SPEED = 240, L = 440;                 // скорост на героя и ширина на зоната на падане
function rng(seed) {                        // детерминиран генератор: същите числа при всяко пускане
  return () => {
    seed |= 0; seed = seed + 0x6D2B79F5 | 0;
    let t = Math.imul(seed ^ seed >>> 15, 1 | seed);
    t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;
    return ((t ^ t >>> 14) >>> 0) / 4294967296;
  };
}
const rand = rng(42);

// Дял на двойките звезди, при които не можеш да хванеш и двете.
const theory = every => (1 - Math.min(1, SPEED * every / L)) ** 2;
function measured(every, n = 200000) {
  let bad = 0;
  for (let i = 0; i < n; i++) {
    if (Math.abs(rand() * L - rand() * L) > SPEED * every) bad++;
  }
  return bad / n;
}

console.log("every  теория  симулация");
for (const e of [0.9, 0.7, 0.5, 0.35]) {
  console.log(e.toFixed(2).padStart(5), (theory(e) * 100).toFixed(1).padStart(6) + "%",
              (measured(e) * 100).toFixed(1).padStart(8) + "%");
}

// Крива по формула: интервалът намалява с 10% на стъпка, но не под 0,35 s.
const params = n => ({ every: Math.max(0.35, 1.1 * 0.9 ** n), speed: Math.min(260, 80 + n * 12) });
console.log("\nстъпка  every  speed  невъзможни");
for (let n = 0; n <= 10; n += 2) {
  const q = params(n);
  console.log(String(n).padStart(5), q.every.toFixed(2).padStart(6), String(q.speed).padStart(6),
              (theory(q.every) * 100).toFixed(0).padStart(8) + "%");
}
```

Формулата и симулацията съвпадат, така че сметката е вярна. Какво показва тя: при `every = 0,5` повече от половината двойки вече не могат да се хванат и двете, а в `LEVELS` от предишния урок трето ниво е точно такова. Скоростта на падане не влияе на този показател, а само на времето за реакция. Затова `every` решава колко място има за избор, а `speed` – колко време за решение. Формулата с `Math.max` и `Math.min` държи и двете числа в граници, които си избрал съзнателно.

Числата не казват дали играта е забавна. Те само не позволяват да рисуваш крива „на сляпо“ и показват къде е стената.

## Тест с хора
Ти знаеш играта прекалено добре, за да я оцениш. Дай я на двама души, които не са я виждали:
1. Не обяснявай нищо. Кажи само „пробвай“.
2. Мълчи и гледай екрана и ръцете, а не лицето.
3. Записвай **факти**: къде спират, кой клавиш търсят, какво казват на глас, колко секунди оцеляват.
4. В края попитай: „Какво според теб правиха камъните?“ и „Какво би променил?“.

Таблица за записките (редовете са примерни):

| Момент | Какво направи играчът | Какво означава |
|---|---|---|
| 0:05 | натисна мишката вместо Enter | менюто не показва клавиша достатъчно ясно |
| 0:40 | загуби първия живот и спря | не разбра, че сивото е опасно |

Не защитавай играта и не обяснявай „така е замислено“. Ако двама души се объркват на едно и също място, проблемът е в играта.

## Стъпка по стъпка
1. Добави `beep`, `burst`, `shake` и `flash` и закачи ефектите към хващането и удара.
2. Остави само ефекти, които се виждат и чуват под секунда.
3. Пусни скрипта за баланс и избери желана стойност на „невъзможни“ за всяко ниво.
4. Запиши в `LEVELS` стойностите на `every` и `speed`.
5. Дай играта на двама души и попълни таблицата.
6. Поправи най-честото объркване и тествай отново.

## Пример от практиката
Да кажем, че двама приятели играят твоята версия. И двамата загубват първия си живот още на седмата секунда и не реагират, като че ли нищо не се е случило. Записваш: „Камъкът ме удари, но не разбрах какво стана.“ Решението е в ефектите, а не в числата: добавяш треперене, червен блясък и нисък звук. На следващия тест и двамата казват „ааа, камъните са лошите“ още на първия удар.

## Чести грешки
- **Много ефекти наведнъж** – екранът става шарен и играчът не вижда играта. Един силен ефект е по-добър от пет слаби.
- **Дълги ефекти, които блокират управлението** – треперенето е украса, а не причина героят да не реагира.
- **Скок на трудността между нивата** – ако `every` падне от 0,9 на 0,3, играчът го усеща като нечестно.
- **Тест само със себе си** – всичко ти е ясно, защото си го писал.
- **Промяна на няколко неща наведнъж след теста** – не знаеш коя промяна е помогнала.

## Бърза справка
| Въпрос | Отговор |
|---|---|
| Колко дълъг е ефектът? | под секунда |
| Колко отговора на събитие? | поне два (образ и звук) |
| Кога започва звукът? | след първо действие на играча |
| Как се ограничава трудността? | `Math.max` за долна и `Math.min` за горна граница |
| Колко души за тест? | двама-трима, които не са виждали играта |

## Упражнение
Дай играта на двама души и запиши какво са объркали.
1. Попълни таблица като горната за двамата играчи.
2. Намери най-честото объркване и го поправи с ефект, надпис или промяна на цвета.
3. Пусни скрипта за баланс със собствена формула за `every` и избери стойности, при които „невъзможни“ расте от около 15% до около 50%.

Проверка: двамата са разбрали без обяснение как се печелят точки и какво е опасно? Ефектите затихват ли сами? Растежът на трудността е равномерен, без скокове?

## Обобщение
Усещането идва от бърза обратна връзка: всяко събитие получава образ и звук, които затихват сами. Честната игра позволява да обясниш загубата, а кривата на трудността се настройва с измерване и граници. Накрая един тест с двама непознати показва повече от час твое гледане.

## Бележки за видеото
- Улавяне на звезда с частици и удар с камък с треперене и червен блясък
- Терминал с резултата от скрипта за баланс
- Таблица с наблюденията от теста с двама души
