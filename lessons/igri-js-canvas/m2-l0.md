> **Цел на урока:** да превърнеш играта от един безкраен екран в цялостна игра с меню, нива, пауза, край и запазен рекорд, като управляваш всичко с една ясна машина на състоянията.

## Какво ще научиш
- Защо няколко флага („играе ли се“, „на пауза ли е“) се объркват и с какво ги заменя една променлива
- Как да опишеш всяко състояние с обект, който има свои `update`, `draw` и обработка на клавиши
- Как да държиш нивата като данни, а не като копиран код
- Как да запазиш рекорд в `localStorage` така, че играта да не се счупи, ако запазването е недостъпно
- Как да тестваш всички преходи автоматично

## Проблемът с флаговете
Първият прототип обикновено има `playing`. После трябва пауза и се появява `paused`, после меню – `inMenu`, после край – `gameOver`. Скоро кодът е пълен с условия от вида `if (playing && !paused && !gameOver)` и рано или късно някоя комбинация се оказва възможна, макар да е безсмислена: играта е на пауза и в менюто едновременно.

Решението е една променлива, която казва в кое **състояние (state)** си. В един момент играта е точно в едно състояние. Невъзможните комбинации просто не могат да се запишат.

Тази схема се нарича **машина на състоянията (state machine)**. Състоянието е възел, а преходът е стрелка между два възела, предизвикана от събитие: натиснат клавиш, изтекъл таймер, изгубен последен живот.

| Състояние | Какво показва | Преходи |
|---|---|---|
| `menu` | заглавие и рекорд | Enter води към `intro` |
| `intro` | „Ниво N“ за 1,2 секунди | таймерът води към `play` |
| `play` | самата игра | P или Escape към `pause`; цел изпълнена към `intro` (следващо ниво) или `over` (победа); без животи към `over` |
| `pause` | замръзнала сцена и надпис | P или Escape обратно към `play` |
| `over` | резултат и рекорд | Enter към `menu` |

Нарисувай таблицата на лист, преди да пишеш код. Ако не можеш да кажеш как се излиза от дадено състояние, в играта има капан.

## Всяко състояние е обект
В кода състоянията са обекти с еднакви методи. Главният цикъл не знае нищо за играта: на всеки кадър вика `update(dt)` и `draw()` на текущото състояние, а `keydown` предава клавиша на неговото `key(code)`.

```js
const states = {
  menu: { key(c) { /* ... */ }, update() {}, draw() { /* ... */ } },
  play: { key(c) { /* ... */ }, update(dt) { /* ... */ }, draw: drawWorld },
};
function go(next) {
  state = next;
  if (states[next].enter) states[next].enter();
}
```

Методът `enter` е по желание и се изпълнява **веднъж** при влизане. Там е подготовката: нулиране на героя, таймер, сравнение на рекорда. Така `update` не проверява „първи кадър ли е“.

Паузата няма `enter`, защото не нулира нищо: връщането към `play` продължава от същото място. Затова `pause.draw` вика `drawWorld()` и отгоре слага полупрозрачен слой.

## Нивата са данни
Ниво 2 не е нов код, а друг набор от числа. Масив от обекти описва всичко, което се променя: име, цел, интервал на появяване и скорост.

```js
const LEVELS = [
  { name: "Ниво 1", goal: 5, every: 0.9, speed: 90 },
  { name: "Ниво 2", goal: 8, every: 0.7, speed: 130 },
];
```

За ново ниво добавяш ред, а не функция. Така балансът се настройва на едно място.

## Рекорд, който оцелява
Рекордът се пази в `localStorage` – хранилище на ключ и текст, което остава в браузъра между отваряния. Две правила:

1. Стойностите са текст. Записваш `String(v)`, четеш `Number(...)`.
2. Достъпът може да хвърли грешка (например при блокирани данни на сайта), затова всяко четене и писане е в `try/catch`. Играта без рекорд е по-добра от счупена игра.

Рекордът се обновява в `enter` на `over`, а не на всеки кадър.

## Стъпка по стъпка
1. Начертай таблицата с преходите.
2. Създай `states` и `state`; `go()` е единственият начин за смяна.
3. Цикълът вика `states[state].update(dt)` и `draw()`.
4. Добавяй състоянията едно по едно: `menu`, `intro`, `play`, `pause`, `over`.
5. Премести числата на нивата в `LEVELS`.
6. Добави `loadBest` и `saveBest` с `try/catch`.
7. Обиколи всички стрелки от таблицата.

Ето цялата игра „Звездопад“ в един файл – ловиш звезди с хоризонтална лента, а сивите камъни отнемат животи:

```html
<!doctype html>
<html lang="bg">
<meta charset="utf-8">
<title>Звездопад</title>
<canvas id="c" width="480" height="320"></canvas>
<script>
const cv = document.getElementById("c");
const ctx = cv.getContext("2d");
const W = cv.width, H = cv.height;
const keys = {};

const LEVELS = [
  { name: "Ниво 1", goal: 5, every: 0.9, speed: 90 },
  { name: "Ниво 2", goal: 8, every: 0.7, speed: 130 },
  { name: "Ниво 3", goal: 12, every: 0.5, speed: 170 },
];

let state = "menu", levelIx = 0, score = 0, caught = 0, lives = 3;
let won = false, newRecord = false, best = loadBest();
let hero, drops = [], spawnT = 0, timer = 0;

function loadBest() {
  try { return Number(localStorage.getItem("zvezdopad.best")) || 0; }
  catch (e) { return 0; }
}
function saveBest(v) {
  try { localStorage.setItem("zvezdopad.best", String(v)); }
  catch (e) { /* режим без запис – играта продължава */ }
}

function go(next) {
  state = next;
  if (states[next].enter) states[next].enter();
}
function newGame() { levelIx = 0; score = 0; lives = 3; go("intro"); }
function startLevel() {
  hero = { x: W / 2 - 25, y: H - 30, w: 50, h: 14 };
  drops = []; caught = 0; spawnT = 0.3;
}

function clear() { ctx.fillStyle = "#0d1230"; ctx.fillRect(0, 0, W, H); }
function text(s, x, y, size, color = "#fff") {
  ctx.fillStyle = color; ctx.font = size + "px sans-serif";
  ctx.textAlign = "center"; ctx.fillText(s, x, y);
}
function drawWorld() {
  clear();
  for (const d of drops) {
    ctx.fillStyle = d.star ? "#ffd23f" : "#8a8f9c";
    ctx.beginPath(); ctx.arc(d.x, d.y, d.r, 0, Math.PI * 2); ctx.fill();
  }
  ctx.fillStyle = "#5fd6c8"; ctx.fillRect(hero.x, hero.y, hero.w, hero.h);
  text("Точки: " + score, 60, 22, 16);
  text("Животи: " + lives, W - 60, 22, 16);
  text(LEVELS[levelIx].name + "  " + caught + "/" + LEVELS[levelIx].goal, W / 2, 22, 16);
}

const states = {
  menu: {
    key(c) { if (c === "Enter") newGame(); },
    update() {},
    draw() {
      clear();
      text("ЗВЕЗДОПАД", W / 2, 120, 40, "#ffd23f");
      text("Enter – старт", W / 2, 170, 20);
      text("Рекорд: " + best, W / 2, 210, 16);
    },
  },
  intro: {
    enter() { startLevel(); timer = 1.2; },
    update(dt) { timer -= dt; if (timer <= 0) go("play"); },
    draw() { clear(); text(LEVELS[levelIx].name, W / 2, H / 2, 36); },
  },
  play: {
    key(c) { if (c === "KeyP" || c === "Escape") go("pause"); },
    update(dt) {
      const L = LEVELS[levelIx];
      const dir = (keys.ArrowRight ? 1 : 0) - (keys.ArrowLeft ? 1 : 0);
      hero.x = Math.max(0, Math.min(W - hero.w, hero.x + dir * 240 * dt));
      spawnT -= dt;
      if (spawnT <= 0) {
        spawnT += L.every;
        drops.push({ x: 20 + Math.random() * (W - 40), y: -10, r: 9, star: Math.random() > 0.25 });
      }
      for (const d of drops) {
        d.y += L.speed * dt;
        const hit = d.y + d.r >= hero.y && d.y - d.r <= hero.y + hero.h &&
                    d.x >= hero.x - d.r && d.x <= hero.x + hero.w + d.r;
        if (hit) { d.dead = true; if (d.star) { score++; caught++; } else lives--; }
        else if (d.y > H + 10) d.dead = true;
      }
      drops = drops.filter(d => !d.dead);
      if (lives <= 0) { won = false; go("over"); }
      else if (caught >= L.goal) {
        if (levelIx + 1 < LEVELS.length) { levelIx++; go("intro"); }
        else { won = true; go("over"); }
      }
    },
    draw: drawWorld,
  },
  pause: {
    key(c) { if (c === "KeyP" || c === "Escape") go("play"); },
    update() {},
    draw() { drawWorld(); ctx.fillStyle = "#000a"; ctx.fillRect(0, 0, W, H); text("Пауза", W / 2, H / 2, 36); },
  },
  over: {
    enter() {
      newRecord = score > best;
      if (newRecord) { best = score; saveBest(best); }
    },
    key(c) { if (c === "Enter") go("menu"); },
    update() {},
    draw() {
      clear();
      text(won ? "Победа!" : "Край на играта", W / 2, 110, 36, won ? "#5fd6c8" : "#ff7a8f");
      text("Точки: " + score, W / 2, 160, 22);
      text(newRecord ? "Нов рекорд!" : "Рекорд: " + best, W / 2, 195, 18);
      text("Enter – към менюто", W / 2, 250, 16);
    },
  },
};

addEventListener("keydown", e => {
  keys[e.code] = true;
  if (states[state].key && !e.repeat) states[state].key(e.code);
  if (["Space", "ArrowLeft", "ArrowRight"].includes(e.code)) e.preventDefault();
});
addEventListener("keyup", e => { keys[e.code] = false; });

let last = 0;
function frame(t) {
  const dt = Math.min((t - last) / 1000, 0.05);
  last = t;
  states[state].update(dt);
  states[state].draw();
  requestAnimationFrame(frame);
}
requestAnimationFrame(t => { last = t; frame(t); });
</script>
</html>
```

## Тест на преходите
Скрипт с Playwright (Chromium) натиска клавиши и чете `state`, а прост бот следва най-ниската звезда. Ето реалния изход от пускането на горния файл:

```
старт: menu | рекорд: 0
след Enter: intro
след 1,4 s: play
след P: pause
след P отново: play
състояния: play:ниво1 > intro:ниво2 > play:ниво2 > intro:ниво3 > play:ниво3 > over:ниво3
победа: true | живота: 1 | точки: 25 | рекорд: 25 | localStorage: 25
след презареждане – състояние: menu | рекорд: 25
конзола: празна
```

Редът „състояния“ започва с `play`, защото ботът е включен, след като менюто и първото въведение са минали. Рекордът оцелява след презареждане, а конзолата е чиста. На снимката от паузата се виждат тъмен слой, надпис „Пауза“ и лентата на героя.

## Пример от практиката
Да кажем, че правиш игра за цялото семейство и искаш да добавиш екран „Как се играе“ преди първото ниво. С флагове ще търсиш из кода всички места, където менюто и играта се редуват. С машина на състоянията добавяш обект `help` с `key` и `draw` и сменяш един преход: `menu` към `help`, а `help` към `intro`.

## Чести грешки
- **Смяна на състоянието с директно `state = "play"`** – пропуска `enter` и ти се налага да помниш подготовката навсякъде. Винаги `go("play")`.
- **Нулиране на играта в `play.update`** – при всяка пауза играта започва отначало. Подготовката е в `enter` на състоянието, което предхожда играта.
- **Рекорд без `try/catch`** – една блокирана настройка на браузъра и играта се срива на екрана за край.
- **Забравен `!e.repeat`** – ако държиш клавиша P, паузата мига нагоре-надолу. Събитието `keydown` се повтаря при задържане и трябва да се филтрира.
- **Числа на нивата, разпръснати из кода** – при настройка на баланса променяш пет места и забравяш шестото.

## Бърза справка
| Задача | Код |
|---|---|
| Смяна на състояние | `go("pause")` |
| Еднократна подготовка | `enter()` в обекта на състоянието |
| Време в състояние | `timer -= dt` в `update`, преход при `timer <= 0` |
| Четене на рекорд | `Number(localStorage.getItem(ключ)) \|\| 0` |
| Запис на рекорд | `localStorage.setItem(ключ, String(v))` в `try/catch` |
| Игнориране на повторения | `if (!e.repeat) ...` |

## Упражнение
Добави към „Звездопад“ меню, пауза и екран за край, ако още ги нямаш, и после направи още три неща:
1. Състояние `help` с кратки правила, до което се стига с клавиша H от менюто.
2. Четвърто ниво в `LEVELS`, без да променяш нито един ред логика.
3. Нулиране на рекорда с клавиша R в менюто.

Проверка: можеш ли да обиколиш всяка стрелка от таблицата? Остава ли рекордът след затваряне и отваряне на страницата? Чиста ли е конзолата? Натисни P в менюто – не трябва да се случва нищо.

## Обобщение
Една променлива за състоянието е по-надеждна от куп флагове: невъзможните комбинации не могат да съществуват. Всяко състояние е обект с `update`, `draw` и `key`, а `enter` върши еднократната подготовка. Нивата са данни, рекордът се пази в `localStorage` с `try/catch`, а преходите се проверяват автоматично със скрипт.

## Бележки за видеото
- Таблица с петте състояния и стрелките между тях
- Менюто на играта, натискане на Enter и надпис „Ниво 1“
- Пауза с P и връщане, като замръзналата сцена остава на екрана
- Екран „Край“ с „Нов рекорд“ и презареждане на страницата с запазен рекорд
- Терминал със състоянията, които скриптът е записал
