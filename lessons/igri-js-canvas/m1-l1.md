- Как се реагира на сблъсък: поправка на позицията по оси и флаг „стои на земята“

## Позиция, скорост, ускорение

Три величини описват движението на всеки обект:

- **позиция** – къде е обектът (`y`);
- **скорост** (velocity) – колко пиксела за секунда променя позицията (`vy`);
- **ускорение** (acceleration) – колко пиксела за секунда на секунда променя скоростта.

**Гравитацията** е просто постоянно ускорение надолу. Понеже `y` расте надолу, то е положително число. Във всяка стъпка правиш две неща в този ред:

```js
vy += GRAVITY * dt;   // първо скоростта
y  += vy * dt;        // после позицията, със новата скорост
```

Подредбата „първо скорост, после позиция“ се нарича **полунеявна схема на Ойлер** (semi-implicit Euler) и в игрите се предпочита, защото е проста и достатъчно стабилна. Обратната подредба също работи, но леко се държи различно. Важното е да я ползваш постоянно и с фиксирана стъпка от предишния урок: така резултатите са еднакви на всеки компютър.

Скокът е само задаване на скорост. Когато играчът натисне „скок“ и героят стои на земята, поставяш `vy = -JUMP_SPEED` (минус, защото нагоре е към по-малко `y`). Гравитацията сама го забавя, обръща и връща надолу. Не движиш героя нагоре с код – само му даваш начална скорост.

Приблизителната височина на скока е `JUMP_SPEED² / (2 * GRAVITY)`. При скорост 620 и гравитация 1800 теорията дава 106,8 пиксела. Чрез тази формула настройваш усещането: искаш скок от 100 пиксела? Избери скорост и гравитация така, че формулата да го даде.

## Сблъсъци на правоъгълници

Повечето игри използват правоъгълни кутии (**AABB** – axis-aligned bounding box, правоъгълник, подравнен с осите). Два правоъгълника се пресичат, ако се припокриват и по двете оси:

```js
const overlap = (a, b) =>
  a.x < b.x + b.w && a.x + a.w > b.x &&
  a.y < b.y + b.h && a.y + a.h > b.y;
```

Две кръгли фигури се пресичат, когато разстоянието между центровете е по-малко от сбора на радиусите. За да избегнеш корен квадратен, сравнявай квадратите:

```js
const circlesHit = (a, b) => (a.x - b.x) ** 2 + (a.y - b.y) ** 2 < (a.r + b.r) ** 2;
```

За кръг и правоъгълник намираш най-близката до центъра на кръга точка от правоъгълника с „захващане“ на координатите, после мериш разстоянието до нея:

```js
function circleHitsRect(c, r) {
  const nx = Math.max(r.x, Math.min(c.x, r.x + r.w));
  const ny = Math.max(r.y, Math.min(c.y, r.y + r.h));
  return (c.x - nx) ** 2 + (c.y - ny) ** 2 < c.r * c.r;
}
```

Тестове в Node.js с `node:assert` минаха без грешка и изведоха `всички проверки минаха`. Те покриват и граничните случаи: два квадрата, които само се допират (`x` на единия е равно на `x + w` на другия), не се броят за сблъсък, а кръг със радиус 6 до ъгъла на квадрат 10 × 10 на разстояние `(5, 5)` от ъгъла (около 7,07) не го докосва.

## Реакция при сблъсък

Откриването е половината работа. Другата половина е **поправката**: да върнеш героя извън стената. Най-устойчивият подход за платформи е да движиш и поправяш **по една ос наведнъж**:

1. Премести героя по `x`. Ако се пресича с твърд обект, върни го до ръба му според посоката.
2. Премести героя по `y`. Ако се пресича: при падане (`vy > 0`) го постави върху обекта и вдигни флага `onGround`; при движение нагоре (`vy < 0`) го постави под обекта. И в двата случая занули `vy`.

Така знаеш с коя страна се е ударил и не се получават странни „залепвания“ по ъглите. Флагът `onGround` се нулира в началото на всяка вертикална стъпка и се вдига само ако героят е спрял върху нещо; от него зависи дали скокът е позволен.

## Стъпка по стъпка

Ще направиш платформа с герой, две висящи платформи и монета.

1. Платно 640 × 360, фиксирана стъпка 1/60 от предишния урок.
2. Константи: `GRAVITY = 1800`, `JUMP_SPEED = 620`, `RUN_SPEED = 220`.
3. Герой `{ x, y, w: 28, h: 40, vx, vy, onGround }` и масив `platforms` с правоъгълници.
4. В `update(dt)`: задай `vx` от клавишите, при `Space` и `onGround` дай скок, добави гравитацията.
5. Премести по `x` и поправи, после по `y` и поправи.
6. Провери монетата с `circleHitsRect`.
7. В `render()` нарисувай платформите, монетата и героя. Героят е тюркоазен на земята и лилав във въздуха – така веднага виждаш флага `onGround`.

Основата на `update`:

```js
function update(dt) {
  player.vx = ((keys.has("ArrowRight") ? 1 : 0) - (keys.has("ArrowLeft") ? 1 : 0)) * RUN_SPEED;
  if (keys.has("Space") && player.onGround) player.vy = -JUMP_SPEED;
  player.vy += GRAVITY * dt;

  player.x += player.vx * dt;
  for (const p of platforms) {
    if (!overlap(player, p)) continue;
    player.x = player.vx > 0 ? p.x - player.w : p.x + p.w;
  }

  player.y += player.vy * dt;
  player.onGround = false;
  for (const p of platforms) {
    if (!overlap(player, p)) continue;
    if (player.vy > 0) { player.y = p.y - player.h; player.onGround = true; }
    else               { player.y = p.y + p.h; }
    player.vy = 0;
  }
  player.x = Math.max(0, Math.min(canvas.width - player.w, player.x));

  if (!coin.taken && circleHitsRect(coin, player)) { coin.taken = true; score++; }
}
```

Платформите са `{ x: 0, y: 320, w: 640, h: 40 }` (под), `{ x: 200, y: 240, w: 120, h: 16 }` и `{ x: 380, y: 170, w: 120, h: 16 }`. Монетата е на `(440, 140)` с радиус 10.

## Какво показаха тестовете

Заредих играта в Chromium без грешки в конзолата и управлявах героя с клавиатурата чрез Playwright. Резултатите:

| Проверка | Очаквано | Получено |
|---|---|---|
| Падане от `y = 100` върху пода | `y = 320 − 40 = 280`, `onGround` | `y = 280`, `vy = 0`, `onGround = true` |
| Върху първата платформа | `y = 240 − 40 = 200` | `y = 200` |
| Върху втората платформа | `y = 170 − 40 = 130` | `y = 130` |
| Монета при докосване | `score` 0 → 1 | `score = 1` |
| Ляв край на платното | `x = 0` | `x = 0` |

Измерих и скока. Героят стартира от `y = 280`, най-високата точка беше `y = 178,3`, т.е. скок от 101,7 пиксела, докато формулата дава 106,8. Разликата е около 5% и е нормална: формулата е за непрекъснато време, а ние работим със стъпки. Особено влияе фактът, че гравитацията се прибавя още в кадъра на скока, преди първото преместване. Ако искаш точно 107 пиксела, просто увеличи `JUMP_SPEED` леко и измери пак.

На снимката от теста се виждат пода и двете платформи, героят в тюркоазено до лявата стена и надпис „Монети: 1“.

## Тунелиране: когато обектът минава през стената

Проверките за сблъсък се правят само в позициите след всяка стъпка. Ако един обект се движи по-бързо от дебелината на стената, за една стъпка „прескача“ напълно и никога не се пресича. Това се нарича **тунелиране** (tunneling).

Пример: топка 10 × 10 пада със скорост 1500 px/s. На 60 стъпки в секунда това са 25 пиксела на стъпка, докато подът е дебел само 10. Ето резултата от Node.js симулация (подът е на `y = 200`):

```
начало -12, 1 стъпка на кадър :  1488 (подът е на 200, топката е минала през него)
начало -12, 4 стъпки на кадър :  190
от 25 различни начални позиции минават през пода: 1 стъпка -> 6 , 4 стъпки -> 0
```

Забележи колко коварно е: от 25 начални позиции само 6 минават през пода, така че грешката се появява понякога и трудно се възпроизвежда. Защити:

- **подстъпки** – раздели кадъра на няколко по-малки стъпки (както в симулацията: при 4 подстъпки преместването е 6,25 пиксела, по-малко от дебелината);
- **по-дебели стени** – стената да е по-дебела от най-дългото преместване;
- **ограничение на скоростта** – задай максимална скорост на падане (terminal velocity), например 900 px/s.

За игри като тази най-лесно е ограничението на скоростта.

## Пример от практиката

Да кажем, че героят ти събира монети и скача по платформи, но играчът се оплаква, че понякога пада през пода при скок от голяма височина. Причината е тунелиране при висока скорост на падане. Слагаш `player.vy = Math.min(player.vy, 900)` след добавянето на гравитацията и оплакването изчезва; ако платформите са по-дебели от 15 пиксела, при 60 стъпки в секунда няма да има прескачане.

## Чести грешки
- **Движение по двете оси наведнъж и после поправка** – не знаеш от коя страна е ударът и героят „залепва“ по ъглите. Поправяй по оси.
- **Скок без `onGround`** – играчът скача във въздуха безкрайно. Скачай само ако `onGround`.
- **Не се нулира `vy` при приземяване** – гравитацията се натрупва и след малко героят „пробива“ пода.
- **Сравнение `<=` вместо `<`** – обекти, които само се допират, се броят за сблъсък. Проверката за допир се прави с `<` и `>` както по-горе.
- **Корен квадратен за разстояние** – бавно и ненужно. Сравнявай квадрати.
- **Висока скорост и тънка стена** – тунелиране. Ограничи скоростта или раздели стъпките.
- **Гравитация, която зависи от кадрите** – ползвай фиксирана стъпка.

## Упражнение

Направи платформа с героя от урока и добави:
- три платформи на различна височина;
- „койот време“: за 0,1 секунда след като героят падне от ръба, все още може да скочи (запомни времето от последния контакт със земята);
- кръгло препятствие (кръг), което при досег връща героя в началото.

Критерии:
- героят стъпва на всяка платформа и не пада през нея;
- скокът е възможен само от земя или в рамките на 0,1 секунди след ръба;
- скоростта на падане е ограничена;
- можеш да изчислиш височината на скока по формулата и да я сравниш с измерената;
- конзолата е без грешки.

## Бърза справка

| Понятие | Формула или код |
|---|---|
| Гравитация | `vy += GRAVITY * dt` |
| Преместване | `y += vy * dt` |
| Скок | `vy = -JUMP_SPEED`, само ако `onGround` |
| Височина на скока (приблизително) | `JUMP_SPEED² / (2 * GRAVITY)` |
| Правоъгълник – правоъгълник | припокриване по `x` и по `y` |
| Кръг – кръг | `dx² + dy² < (r1 + r2)²` |
| Кръг – правоъгълник | най-близка точка със захващане |
| Ред на поправка | първо `x`, после `y` |
| Тунелиране | подстъпки, дебели стени, максимална скорост |

## Обобщение
Скоростта променя позицията, а гравитацията е ускорение, което променя скоростта; всяка стъпка първо обновява скоростта, после позицията. Сблъсъците при правоъгълници са проста проверка по две оси, а за кръгове сравняваш квадрати на разстояния. Реакцията се прави по една ос, с флаг `onGround` за скока. Тестът показа очакваните позиции върху пода и платформите, а скокът е с около 5% по-нисък от формулата заради дискретното време. Бързите обекти могат да тунелират през тънки стени, затова ограничавай скоростта.
