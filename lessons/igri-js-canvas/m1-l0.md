> **Цел на урока:** да управляваш герой с клавиатура, мишка и докосване – да пазиш състоянието на входа в структура, която цикълът чете на всеки кадър, и да превръщаш координатите на екрана в координати на платното.

## Какво ще научиш
- Защо играта пази „кой клавиш е натиснат сега“, вместо да реагира на всяко събитие
- Каква е разликата между `event.code` и `event.key` и защо за управление ползваме `code`
- Как да превърнеш позицията на мишката в координати на платното, дори когато платното е мащабирано
- Как Pointer Events обединяват мишка, докосване и писалка
- Как да избегнеш типичните грешки: залепнали клавиши, превъртане на страницата и по-бърз ход по диагонал

## Състояние вместо събития

Браузърът съобщава за входа чрез **събития**: `keydown` при натискане и `keyup` при пускане. Играта, обаче, не работи на събития, а на кадри. На всеки кадър `update` трябва да попита: „в момента натиснат ли е клавишът надясно?“.

Затова се строи малко **състояние на входа**: събитията само го променят, а цикълът го чете.

```js
const keys = new Set();
addEventListener("keydown", (e) => keys.add(e.code));
addEventListener("keyup", (e) => keys.delete(e.code));
addEventListener("blur", () => keys.clear());
```

`Set` е подходящ, защото добавянето на вече присъстващ елемент не прави нищо. Това решава един неочакван проблем: когато държиш клавиш, операционната система започва да праща повтарящи се `keydown` събития (автоповторение). Ако движеше героя вътре в събитието, той щеше да тръгне, да спре за миг и после да продължи. Със състояние движението тръгва веднага и е равномерно, защото зависи от кадрите, не от темпото на повторението.

Редът `blur` е за случая, когато играчът държи клавиш и сменя прозореца. Тогава `keyup` никога не пристига на страницата и героят би продължил да върви вечно. При загуба на фокус изчистваме всичко.

### code или key

Събитието носи две полезни свойства:

| Свойство | Какво описва | Пример |
|---|---|---|
| `event.code` | физическото място на клавиша на клавиатурата | `KeyW`, `Space`, `ArrowLeft` |
| `event.key` | знакът, който клавишът дава в текущата подредба | `w`, `ц`, `Enter` |

За управление ползвай `code`. Клавишът, който на английска подредба е W, на българска фонетична или БДС подредба дава друга буква, но има същия `code`. Затова схемата „WASD“ работи за всички по едно и също място на клавиатурата. С `key` би трябвало да изброяваш буквите на всяка подредба.

Проверих този принцип със синтетично събитие, в което `key` е кирилична буква, а `code` е `KeyW` (`key: "ц"`, `code: "KeyW"`). Реална клавиатура с българска подредба в тази среда нямах, така че това е симулация и не е вързана към конкретна подредба:

```
keys след key:'ц' code:'KeyW' -> ["KeyW"]
```

Играта записва `KeyW`, независимо от буквата. `key` ползвай, когато искаш наистина знака – например при въвеждане на име за таблицата с рекорди.

### Спиране на превъртането

Стрелките и интервалът превъртат страницата. За игра това е нежелано, затова в `keydown` викаш `e.preventDefault()` само за клавишите, които играта ползва. Не го викай за всички – би блокирал клавиши като F5 или Ctrl+T.

## Мишка, докосване и писалка

Преди години трябваше да пишеш три групи събития (`mouse…`, `touch…`, `pen…`). Днес **Pointer Events** покриват всички с еднакви имена: `pointerdown`, `pointermove`, `pointerup`. Свойството `pointerType` казва какво е устройството: `"mouse"`, `"touch"` или `"pen"`.

За докосване добави в CSS на платното `touch-action: none`. Така браузърът няма да започне превъртане или мащабиране, когато играчът плъзга пръст по играта.

### Координати върху платното

`event.clientX` и `event.clientY` са позиции спрямо прозореца на браузъра, а не спрямо платното. Трябва да извадиш мястото на платното и да коригираш мащаба, ако CSS размерът е различен от размера на рисунката:

```js
function toCanvas(e) {
  const r = canvas.getBoundingClientRect();
  return {
    x: (e.clientX - r.left) * (canvas.width / r.width),
    y: (e.clientY - r.top) * (canvas.height / r.height),
  };
}
```

`getBoundingClientRect()` връща кутията на платното на екрана. Отношението `canvas.width / r.width` превръща CSS пиксели в пиксели на рисунката. Без него мишката „бяга“, когато платното е разтегнато.

## Стъпка по стъпка

Ще направиш страница с герой, който се движи със стрелки или WASD, и мерник, който следва показалеца.

1. Платно с атрибути 480 × 270, а в CSS ширина 960 пиксела и `touch-action: none`. Така проверяваш и мащабирането.
2. Състояние на входа: `keys` и обработчиците за `keydown`, `keyup`, `blur`.
3. Обект `pointer` с `x`, `y`, `down` и `type` и обработчици за `pointerdown`, `pointermove`, `pointerup`.
4. В `update(dt)` събери посоката от клавишите, нормализирай я и премести героя.
5. Ограничи героя в рамките на платното.
6. В `render()` нарисувай героя и мерника.

Цялата логика за движение и рисуване:

```js
const hero = { x: 60, y: 120, w: 30, h: 30, speed: 180 };

function update(dt) {
  let dx = 0, dy = 0;
  if (keys.has("ArrowLeft")  || keys.has("KeyA")) dx -= 1;
  if (keys.has("ArrowRight") || keys.has("KeyD")) dx += 1;
  if (keys.has("ArrowUp")    || keys.has("KeyW")) dy -= 1;
  if (keys.has("ArrowDown")  || keys.has("KeyS")) dy += 1;
  const len = Math.hypot(dx, dy) || 1;
  hero.x += (dx / len) * hero.speed * dt;
  hero.y += (dy / len) * hero.speed * dt;
  hero.x = Math.max(0, Math.min(canvas.width - hero.w, hero.x));
  hero.y = Math.max(0, Math.min(canvas.height - hero.h, hero.y));
}
```

Делението на `len` е важно. Без него, при натиснати „надясно“ и „надолу“, векторът е `(1, 1)` с дължина около 1,41 и героят би вървял по диагонал с 41% по-голяма скорост. `Math.hypot(dx, dy)` смята дължината, а `|| 1` предпазва от делене на нула, когато няма натиснат клавиш.

Указателите са толкова:

```js
const pointer = { x: 240, y: 135, down: false, type: "" };
canvas.addEventListener("pointerdown", (e) => {
  canvas.setPointerCapture(e.pointerId);
  Object.assign(pointer, toCanvas(e), { down: true, type: e.pointerType });
});
canvas.addEventListener("pointermove", (e) => Object.assign(pointer, toCanvas(e), { type: e.pointerType }));
canvas.addEventListener("pointerup", () => { pointer.down = false; });
```

`setPointerCapture` кара платното да получава движенията, дори когато пръстът или мишката излязат извън него по време на натискане. Така хващането не се къса в края на екрана.

## Какво показаха тестовете

Заредих страницата в Chromium без грешки в конзолата и симулирах вход с Playwright. Героят стартира на `x = 60, y = 120`, скорост 180 пиксела в секунда:

| Действие | Резултат |
|---|---|
| държа `ArrowRight` 0,5 секунди | `x = 153` (60 плюс 93; паузата в теста не е точно 0,5 секунди) |
| пускам клавиша | позицията спира и не се променя 300 милисекунди по-късно |
| `ArrowDown` и `ArrowRight` заедно 0,5 секунди | `x = 216,6`, `y = 183,6` |
| събитие `blur` при натиснат клавиш | `keys` става празно |
| мишка в центъра на платното (платно 960 пиксела на екрана) | `x = 240, y = 135`, `down = true`, `type = "mouse"` |
| докосване на същото място при `hasTouch` | `x = 120, y = 67,5`, `type = "touch"` |

Диагоналът е проверка на нормализацията. За 0,5 секунди при скорост 180 всеки от двете канала се изминава по `180 * 0,5 / 1,414 ≈ 63,6` пиксела. От старта (153, 120) имаме `216,6` и `183,6`, а това са точно 63,6 по оста. Без нормализация щяха да са 90.

Мишката в центъра на екрана (480 CSS пиксела вдясно и 270 надолу от ъгъла на платното) се преведе в `(240, 135)` – центъра на рисунката 480 × 270. Докосването беше направено на 240 CSS пиксела, затова се преведе на 120, а не на 240: платното е разтегнато двойно и функцията `toCanvas` го отчита.

## Пример от практиката

Да кажем, че правиш игра, в която хвърляш топки с мишката: държиш бутона, мерникът свети в оранжево, пускаш и топката тръгва към мерника. Същата игра трябва да работи на телефон. Понеже ползваш Pointer Events и `pointer.down`, нямаш отделен код за пръст. Единствената добавка е `touch-action: none`, за да не се превърта страницата, докато играчът цели.

## Чести грешки
- **Движение директно в `keydown`** – автоповторението прави старта накъсан. Променяй състояние, а движението го прави цикълът.
- **Липсва `blur`** – клавиш, пуснат извън прозореца, остава „натиснат“.
- **`event.key` за управление** – схемата се чупи при друга подредба. Ползвай `event.code`.
- **`preventDefault()` за всички клавиши** – блокираш и обикновени клавишни комбинации на браузъра.
- **`clientX` без корекция** – мерникът е на грешното място. Извади `getBoundingClientRect()` и мащабирай.
- **Диагонал без нормализация** – героят по диагонал е по-бърз.
- **Страница в `iframe` без фокус** – клавишите отиват другаде. Кликни върху играта или извикай `focus()`.
- **Само клавиатурно управление** – на телефон няма стрелки. Предвиди докосване или бутони на екрана.

## Упражнение

Направи малка арена. Героят се движи със стрелки или WASD. При клик или докосване върху платното на това място се появява кръг, който после изчезва след секунда.

Критерии:
- клавишите се пазят в `Set` и се четат в `update`;
- движението по диагонал е със същата скорост като по права линия;
- героят не излиза извън платното;
- кликът работи правилно, дори когато платното е увеличено със CSS;
- играта работи и с докосване на екран с докосване (или в емулация на браузъра);
- след `blur` героят спира.

## Бърза справка

| Нужда | Решение |
|---|---|
| Кой клавиш е натиснат | `Set` с `event.code` |
| Загубен фокус | `blur` и `keys.clear()` |
| Без превъртане | `preventDefault()` само за игровите клавиши |
| Физическо място на клавиш | `event.code` |
| Знак от подредбата | `event.key` |
| Мишка, пръст, писалка | `pointerdown`, `pointermove`, `pointerup` |
| Вид устройство | `event.pointerType` |
| Координати върху платното | `getBoundingClientRect()` и мащаб |
| Без превъртане при докосване | CSS `touch-action: none` |
| Равна скорост по диагонал | деление на `Math.hypot(dx, dy)` |

## Обобщение
Играта не реагира на всяко събитие, а пази състояние на входа, което цикълът чете на кадър. Ползвай `event.code` за управление и `event.key` само когато ти трябва знакът. Pointer Events обединяват мишка, докосване и писалка, а `getBoundingClientRect` с мащаб превръща екранните координати в координати на платното. Нормализирай диагонала, изчиствай входа при загуба на фокус и спирай превъртането само там, където е нужно.

## Бележки за видеото
- `keydown` добавя `event.code` в `Set`, `keyup` го маха.
- Цикълът чете множеството и движи квадрата надясно при натиснат `ArrowRight`.
- Добавено е движение наляво с `KeyA`; натискат се `ArrowRight` и после `KeyA` и квадратът се връща.
- Надписът обяснява защо `event.code` работи и на кирилична подредба.
