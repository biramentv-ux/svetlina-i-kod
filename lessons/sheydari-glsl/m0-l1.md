## Харнесът: страницата, която ще ползваш през целия курс
За да пишеш шейдъри, ти трябват три неща: платно, малка програма на JavaScript, която го рисува, и самият шейдър. Не се нуждаеш от рамка или сървър. Запази следния файл като `index.html` и го отвори с двойно щракване в Chrome или Firefox.

```html
<!doctype html>
<html lang="bg">
<head>
<meta charset="utf-8">
<title>Шейдър</title>
<style>
  html, body { margin: 0; height: 100%; background: #000; }
  canvas { width: 100vw; height: 100vh; display: block; }
</style>
</head>
<body>
<canvas id="c"></canvas>

<script id="frag" type="x-shader/x-fragment">
precision mediump float;
uniform vec2 u_resolution;
uniform float u_time;

void main() {
  vec2 uv = gl_FragCoord.xy / u_resolution;
  gl_FragColor = vec4(uv, 0.5, 1.0);
}
</script>

<script>
const canvas = document.getElementById("c");
const gl = canvas.getContext("webgl");
const vsSrc = "attribute vec2 p; void main(){ gl_Position = vec4(p, 0.0, 1.0); }";
const fsSrc = document.getElementById("frag").textContent;

let failed = false;

function compile(type, src) {
  const s = gl.createShader(type);
  gl.shaderSource(s, src);
  gl.compileShader(s);
  if (!gl.getShaderParameter(s, gl.COMPILE_STATUS)) {
    console.error(gl.getShaderInfoLog(s));
    failed = true;
  }
  return s;
}

const prog = gl.createProgram();
gl.attachShader(prog, compile(gl.VERTEX_SHADER, vsSrc));
gl.attachShader(prog, compile(gl.FRAGMENT_SHADER, fsSrc));
gl.linkProgram(prog);
if (failed) throw new Error("Шейдърът не се компилира – виж първата грешка по-горе.");
gl.useProgram(prog);

const buf = gl.createBuffer();
gl.bindBuffer(gl.ARRAY_BUFFER, buf);
gl.bufferData(gl.ARRAY_BUFFER, new Float32Array([-1,-1, 1,-1, -1,1, 1,1]), gl.STATIC_DRAW);
const loc = gl.getAttribLocation(prog, "p");
gl.enableVertexAttribArray(loc);
gl.vertexAttribPointer(loc, 2, gl.FLOAT, false, 0, 0);

const uRes = gl.getUniformLocation(prog, "u_resolution");
const uTime = gl.getUniformLocation(prog, "u_time");
const fixed = new URLSearchParams(location.search).get("t");

function frame(now) {
  const w = canvas.clientWidth, h = canvas.clientHeight;
  if (canvas.width !== w || canvas.height !== h) { canvas.width = w; canvas.height = h; }
  gl.viewport(0, 0, w, h);
  gl.uniform2f(uRes, w, h);
  gl.uniform1f(uTime, fixed !== null ? parseFloat(fixed) : now / 1000);
  gl.drawArrays(gl.TRIANGLE_STRIP, 0, 4);
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
</script>
</body>
</html>
```

Тази страница е същата в целия курс. Във всеки следващ урок ще ти давам само съдържанието на блока `<script id="frag" ...>`. Ти го заместваш в `index.html`, записваш и натискаш F5. Три практични детайла:

- **Замразен кадър.** Добави `?t=3` към адреса (например `index.html?t=3`) и шейдърът ще получи `u_time = 3.0` вместо реалното време. Така можеш да сравняваш кадри и да фиксираш момент, който ти харесва.
- **Грешки.** Отвори конзолата с F12. Ако шейдърът не се компилира, там ще видиш ред и описание, например `ERROR: 0:9: ...`. Числото след `0:` е номерът на реда в шейдъра, като броенето започва от първия ред вътре в блока.
- **Само един файл.** Страницата няма външни файлове и библиотеки и работи офлайн.

Ако нещо не рисува, първо погледни конзолата. Ако WebGL липсва, провери дали хардуерното ускорение е включено в настройките на браузъра.

## Координатите на пиксела
`gl_FragCoord` е вграден вектор с позицията на текущия пиксел. Началото (0, 0) е в **долния ляв** ъгъл, а `y` расте нагоре, обратно на повечето екранни координати. Стойностите са в пиксели, затова на платно 320 x 180 те стигат до около 320 и 180. Това е неудобно, защото шейдърът работи различно при различен размер.

Нормализирането решава проблема: делиш на резолюцията и получаваш числа от 0 до 1.

```glsl
precision mediump float;
uniform vec2 u_resolution;
uniform float u_time;

void main() {
  vec2 uv = gl_FragCoord.xy / u_resolution;
  vec3 c = vec3(uv.x, uv.y, 0.0);
  c.b = 1.0 - uv.x;          // отделна компонента
  vec2 flip = uv.yx;         // размяна на компоненти
  c.rg = mix(c.rg, flip, 0.5);
  gl_FragColor = vec4(c, 1.0);
}
```

`gl_FragCoord.xy` взема първите две компоненти на четирикомпонентния вектор. `c.b` е втори начин да кажеш `c.z`. `uv.yx` разменя компонентите. Този запис се нарича swizzle. Резултат при кадър 320 x 180: долният ляв ъгъл е син (11, 11, 247), центърът е сив (127, 127, 127), а горният десен ъгъл е жълт (244, 244, 8). Малките отклонения от чистите стойности идват от смесването с `flip`.

Таблицата показва какво носи всяка форма:

| Запис | Значение | Пример |
|---|---|---|
| `vec2`, `vec3`, `vec4` | вектори от 2, 3 и 4 дробни числа | `vec3(1.0, 0.0, 0.0)` |
| `.x .y .z .w` | компоненти като координати | `uv.x` |
| `.r .g .b .a` | същите компоненти като цвят | `c.g` |
| `.xy`, `.rgb` | няколко компоненти наведнъж | `p.xy` |
| `vec3(uv, 0.5)` | сглобяване от части | `vec4(c, 1.0)` |
| `mix(a, b, t)` | `a * (1.0 - t) + b * t` | смесване на цветове |

## Центрирани координати и пропорции
При `uv` началото е в ъгъла, а оста `x` е по-широка от `y`, защото екранът е в пропорция 16:9. Ако нарисуваш „кръг“ като `length(uv - 0.5) < 0.3`, ще получиш елипса. Причината е проста: единица по `x` е 320 пиксела, а единица по `y` е 180. Върху кадър 320 x 180 хоризонталният радиус е 0,3 x 320 = 96 пиксела, а вертикалният – 0,3 x 180 = 54 пиксела.

Стандартното решение е да центрираш координатите и да делиш на височината:

```glsl
precision mediump float;
uniform vec2 u_resolution;
uniform float u_time;

void main() {
  vec2 p = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;
  float d = length(p);
  float ring = step(0.30, d) - step(0.32, d);
  gl_FragColor = vec4(vec3(ring), 1.0);
}
```

Тук `p` има начало в центъра. `x` минава приблизително от -0,89 до 0,89 при пропорция 16:9, а `y` – от -0,5 до 0,5. `length(p)` е разстоянието до центъра, а разликата на два `step` оставя тънък пръстен между радиус 0,30 и 0,32. Резултатът е бял кръгов контур, който остава кръгъл при всякакъв размер на прозореца. Върху 320 x 180 пиксел (160, 35) е бял (255, 255, 255), а пиксел (160, 90) в центъра е черен. Радиусът 0,30 на височина 180 пиксела е 54 пиксела от центъра, а центърът е на y = 90, така че ръбът на пръстена е около y = 36.

## Време и анимация
`u_time` расте непрекъснато. Самото число не прави нищо интересно, но когато го вкараш в `sin`, получаваш колебание между -1 и 1. За цветове искаш стойност между 0 и 1, затова винаги се прави преобразуването `0.5 + 0.5 * sin(...)`.

```glsl
precision mediump float;
uniform vec2 u_resolution;
uniform float u_time;

void main() {
  vec2 uv = gl_FragCoord.xy / u_resolution;
  vec3 a = vec3(0.10, 0.05, 0.40);   // тъмно лилаво
  vec3 b = vec3(1.00, 0.45, 0.10);   // оранжево
  float t = 0.5 + 0.5 * sin(u_time * 0.5 + uv.x * 3.0);
  gl_FragColor = vec4(mix(a, b, t), 1.0);
}
```

Времето е умножено по 0.5 и така движението е по-бавно, а към него е добавено `uv.x * 3.0`, за да се получи вълна по ширина. Така цветът в различните колони не е еднакъв и вълната пътува. Измерени стойности на средния ред пиксели: при `u_time = 0` лявата ивица е (152, 69, 60), центърът е ярко оранжев (255, 115, 26) и дясната е (166, 75, 55). При `u_time = 3` ярко оранжевото вече е в лявата ивица (255, 115, 26), а дясната е почти лилава (31, 15, 100). Вълната се е изместила наляво. При `u_time = 6` лилавото е в центъра (28, 14, 101).

Правилото за скорост е просто: `u_time * k` дава k радиана в секунда. Периодът на синуса е около 6,28, така че пълен цикъл отнема 6,28 / k секунди.

## Пример от практиката
Да кажем, че подготвяш фон за лайв сет, който трябва да „диша“ бавно между две цветови схеми и да не прилича на видеоклип на цикъл. Започваш с градиента по-горе. Сменяш `a` и `b` с цветовете на проекта, увеличаваш периода до около 20 секунди и добавяш втората вълна с `uv.y`. След десетина минути имаш фон, който не се повтаря видимо и тежи няколко реда текст.

## Чести грешки
- **Нормализираш с ширината вместо с височината.** Тогава `y` се свива и формите се разтягат. За центрирани координати дели на `u_resolution.y`.
- **Забравяш, че `y` е нагоре.** Ако нещо излиза обърнато спрямо очакването ти, помни: в `gl_FragCoord` началото е долу вляво.
- **Забравяш десетичната точка.** `float t = 1;` не се компилира; пиши `1.0`.
- **Смесваш вектори с различна размерност.** `vec3 c = uv;` е грешка. Конзолата казва `'=' : dimension mismatch`. Ползвай `vec3(uv, 0.0)`.
- **Питаш за несъществуваща компонента.** `c.xyzw` върху `vec3` дава `'xyzw' : vector field selection out of range`.
- **Не ограничаваш стойностите.** Над 1.0 цветът просто се изрязва до бяло. Ако една от компонентите е по-голяма от 1.0, ще виждаш равни петна. Ползвай `clamp` или умножение с по-малко число.

## Упражнение
Направи градиент, който бавно сменя цветовете си с времето. Подходът е по твой избор, но ето един работещ скелет, който ползва косинусна палитра:

```glsl
precision mediump float;
uniform vec2 u_resolution;
uniform float u_time;

vec3 palette(float t) {
  return 0.5 + 0.5 * cos(6.28318 * (t + vec3(0.0, 0.33, 0.67)));
}

void main() {
  vec2 uv = gl_FragCoord.xy / u_resolution;
  float t = uv.x * 0.5 + uv.y * 0.25 + u_time * 0.05;
  gl_FragColor = vec4(palette(t), 1.0);
}
```

Скелетът е проверен: средният ред пиксели при `u_time = 0` е (208, 2, 175) отляво, (37, 92, 250) в центъра и (29, 246, 104) отдясно. При `u_time = 20` изходът е същият, защото `u_time * 0.05` достига точно 1.0, а палитрата се повтаря на всяка единица. Цикълът е 20 секунди.

Критерии за самопроверка:
- Цветовете се променят видимо, но плавно, без скокове.
- Цялата картина няма яркост над 1.0 и под 0.0 (няма бели петна и черни дупки).
- Можеш да удвоиш скоростта, като промениш само едно число.
- Можеш да обясниш защо `palette` приема едно число и връща `vec3`.

## Бърза справка
- `gl_FragCoord.xy / u_resolution` дава `uv` от 0 до 1, началото е долу вляво.
- `(gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y` дава центрирани координати без деформация.
- `mix(a, b, t)` е линейно смесване. `0.5 + 0.5 * sin(x)` връща число от 0 до 1.
- Swizzle: `.xy`, `.rgb`, `.yx`, `vec3(uv, 0.0)`.
- Дробните числа винаги имат точка. Типовете трябва да съвпадат.
- `step(a, x)` е 0.0, когато `x < a`, иначе 1.0. Редът на аргументите е важен: при `step(uv.x, 0.5)` лявата половина става синя, а дясната червена.

## Обобщение
Харнесът ти дава постоянна работна среда: платно, WebGL и шейдър в един файл. С `gl_FragCoord` и нормализиране превръщаш пикселите в числа от 0 до 1 или в центрирани координати, а векторите `vec2`, `vec3`, `vec4` и `mix` ти позволяват да смесваш цветове. `u_time` и `sin` внасят движение. Грешките при компилация са четими: номер на ред и кратко описание. Следващият модул започва с функцията на разстоянието, с която ще рисуваш форми.
