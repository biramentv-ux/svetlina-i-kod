## Защо шейдърът няма random()
В обикновена програма извикваш `random()` и получаваш ново число. В шейдъра това е невъзможно по две причини. Първо, всеки пиксел се изчислява независимо и няма общо състояние за „следващо число“. Второ, пикселът трябва да получава **едно и също** число във всеки кадър, освен ако не го движиш нарочно, иначе картината трепти.

Решението е **хеш функция**: детерминирана функция, която приема число или вектор и връща число, което изглежда случайно. Същият вход винаги дава същия изход, а съседни входове дават несвързани изходи. Ето хеш на два аргумента, който не ползва `sin` и затова е по-устойчив на разлики в точността между видеокартите:

```c
float hash(vec2 p) {
  vec3 p3 = fract(vec3(p.xyx) * 0.1031);
  p3 += dot(p3, p3.yzx + 33.33);
  return fract((p3.x + p3.y) * p3.z);
}
```

Тя приема `vec2` (например номер на клетка) и връща число от 0.0 до 1.0. Бял шум получаваш, като разделиш екрана на клетки и дадеш на всяка собствена сивота.

```glsl
precision mediump float;
uniform vec2 u_resolution;
uniform float u_time;

float hash(vec2 p) {
  vec3 p3 = fract(vec3(p.xyx) * 0.1031);
  p3 += dot(p3, p3.yzx + 33.33);
  return fract((p3.x + p3.y) * p3.z);
}

void main() {
  vec2 uv = gl_FragCoord.xy / u_resolution;
  vec2 cell = floor(uv * vec2(32.0, 18.0));
  float n = hash(cell);
  gl_FragColor = vec4(vec3(n), 1.0);
}
```

При кадър 320 x 180 клетките са 10 пиксела (320 / 32 и 180 / 18). Пиксел (109, 100) и пиксел (110, 100) са в различни клетки и получават (180, 180, 180) и (145, 145, 145), докато (100, 100) и (101, 100) са в една клетка и са еднакви. Същият пиксел при `u_time = 1` и `u_time = 5` дава една и съща стойност: хешът не зависи от времето. Средната сивота на кадъра е 131 (от 255), стандартното отклонение е 73, а средната разлика между съседни пиксели по хоризонтала е 7,8. 

## Value noise: плавен шум от случайни стойности
Белият шум е твърде рязък за дим или облаци. Идеята на value noise е да хешираш само ъглите на мрежата, а между тях да интерполираш. За точка `p` намираш клетката (`floor`), позицията в нея (`fract`) и стойностите в четирите ъгъла. После смесваш първо по `x`, после по `y`.

Линейното `mix` оставя видими ръбове по границите на клетките, затова позицията се преобразува с кривата `f * f * (3.0 - 2.0 * f)`: това е същата плавна крива като при `smoothstep`, която има нулев наклон в двата края.

```c
float vnoise(vec2 p) {
  vec2 i = floor(p);
  vec2 f = fract(p);
  vec2 u = f * f * (3.0 - 2.0 * f);          // плавна крива вместо права линия
  float a = hash(i);
  float b = hash(i + vec2(1.0, 0.0));
  float c = hash(i + vec2(0.0, 1.0));
  float d = hash(i + vec2(1.0, 1.0));
  return mix(mix(a, b, u.x), mix(c, d, u.x), u.y);
}
```

В `main` ползваш `float n = vnoise(uv * vec2(8.0, 4.5));` и показваш `vec3(n)`. Функцията се поставя под `hash`.

Резултатът е меко, петнисто поле. Средната разлика между съседни пиксели пада от 7,8 на 1,7. Тук `uv * vec2(8.0, 4.5)` определя честотата: колкото по-голямо е числото, толкова по-ситни са петната. Стойностите 8 и 4,5 пазят клетките квадратни при пропорция 16:9.

## Gradient noise: шум от посоки
Петната на value noise следват мрежата и изглеждат квадратни. Gradient noise (на него се основава класическият шум на Перлин) хешира не стойности, а **посоки**. Във всеки ъгъл на клетката има случаен вектор, а стойността в точката е скаларно произведение (`dot`) между този вектор и вектора от ъгъла до точката.

```c
vec2 grad(vec2 i) {
  float a = hash(i) * 6.28318;
  return vec2(cos(a), sin(a));
}

float gnoise(vec2 p) {
  vec2 i = floor(p);
  vec2 f = fract(p);
  vec2 u = f * f * (3.0 - 2.0 * f);
  float a = dot(grad(i), f);
  float b = dot(grad(i + vec2(1.0, 0.0)), f - vec2(1.0, 0.0));
  float c = dot(grad(i + vec2(0.0, 1.0)), f - vec2(0.0, 1.0));
  float d = dot(grad(i + vec2(1.0, 1.0)), f - vec2(1.0, 1.0));
  return mix(mix(a, b, u.x), mix(c, d, u.x), u.y);   // около от -0.7 до 0.7
}
```

Извикването е `float n = 0.5 + 0.5 * gnoise(uv * vec2(8.0, 4.5));`.

В кадър 320 x 180 стойностите са между 56 и 190 (от 255), със средно 127: шумът е центриран около нулата, а след `0.5 + 0.5 * шум` – около средно сиво. Средната разлика между съседни пиксели е 1,5, а квадратността не се забелязва.

| | Бял шум | Value noise | Gradient noise |
|---|---|---|---|
| Какво хешираш | стойност за клетка | стойност във всеки ъгъл | посока във всеки ъгъл |
| Външен вид | зърно | меки петна, малко „квадратни“ | по-естествени вълни |
| Обхват | 0 до 1 | 0 до 1 | приблизително от -0,7 до 0,7 |
| Употреба | зърно | прости облаци | дим, мрамор |

## fbm: наслагване на октави
Един слой шум има една мащабна структура. В природата има структура във всички мащаби: големи облаци, в тях по-малки валма. **fbm** (fractional Brownian motion) имитира това, като събира няколко слоя шум, наречени октави. Всяка следваща октава е по-ситна и по-слаба.

Два параметъра управляват процеса: **лакунарност** (lacunarity) – с колко се умножава честотата на всяка октава (обикновено 2.0), и **усилване** (gain) – с колко се умножава амплитудата (обикновено 0.5).

```c
float fbm(vec2 p) {
  float sum = 0.0;
  float amp = 0.5;
  for (int i = 0; i < 5; i++) {
    sum += amp * gnoise(p);
    p *= 2.0;        // всяка октава е два пъти по-ситна
    amp *= 0.5;      // и два пъти по-слаба
  }
  return sum;
}
```

Извикването е `float n = 0.5 + 0.9 * fbm(uv * vec2(4.0, 2.25));`, а функцията се поставя под `gnoise`.

В цикъла `p *= 2.0` удвоява честотата, а `amp *= 0.5` намалява наполовина силата. Сборът на амплитудите е 0,5 + 0,25 + 0,125 + 0,0625 + 0,03125, около 0,97, така че fbm остава в сходен обхват с един слой. Формулата `0.5 + 0.9 * fbm` повишава контраста; изходът обхваща стойности от 64 до 200 (от 255), със средно 132, а разликата между съседни пиксели е 1,4. Картината има едри облачни маси и ситна текстура вътре в тях.

В GLSL ES 1.0 (WebGL 1) границата на цикъла трябва да е константа. Ако я замениш с променлива, например `n` от `int(u_time)`, получаваш грешката `Loop index cannot be compared with non-constant expression`. За променлив брой октави пиши константен максимум и излез с `if (i >= n) break;`.

Повече октави дават повече ситни детайли, но струват повече на графичния процесор.

## Движение и изкривяване на пространството
Шумът е функция на позицията, затова го движиш, като променяш позицията, подадена в него. Ако извадиш `u_time * 0.12` от `y`, шарката се издига.

Силен ефект дава **изкривяване на пространството** (domain warping): използваш fbm, за да отместиш координатите, подавани на друг fbm. Така шарките се завихрят като дим. Точно това прави шейдърът по-долу.

## Стъпка по стъпка
1. Пусни белия шум и промени броя на клетките. Провери, че не трепти.
2. Замени с value noise, после с gradient noise и сравни петната.
4. Пусни fbm с 2, 5 и 8 октави.
5. Добави движение с `- u_time * 0.12` в y.
6. Добави изкривяване и настрой множителя пред `w`.

## Пример от практиката
Да кажем, че имаш тъмен фон за електронен сет и искаш мъгла, която тече бавно и не се повтаря. Видеоклипът се вижда като цикъл след минута-две. Шейдър с fbm не се повтаря, защото `u_time` расте. Цветът следва палитрата на проекта, а скоростта по-късно може да се свърже с баса.

## Чести грешки
- **Хеш със `sin` и големи числа на слаби видеокарти.** Класическата формула `fract(sin(dot(p, ...)) * 43758.5453)` дава различни резултати при ниска точност (`mediump`) на някои мобилни устройства. Хешът без `sin` по-горе е по-безопасен.
- **Октави без отместване.** Ако не отместваш `p` между октавите, следите от мрежата се подравняват. Решението е `p = p * 2.0 + vec2(1.7, 9.2)`.
- **Твърде много октави.** Всяка е още един пълен шум и осем октави върху целия екран могат да свалят кадрите на слаб хардуер.
- **Прекалено бързо време.** С голям множител пред `u_time` шарката „кипи“, а не тече. Започни между 0,03 и 0,2.
- **Забравен диапазон.** Gradient noise е около нулата и като цвят дава черни зони. Ползвай `0.5 + 0.5 * шум`.

## Упражнение
Направи бавно движещ се дим с fbm. Ето работещ вариант:

```glsl
precision mediump float;
uniform vec2 u_resolution;
uniform float u_time;

float hash(vec2 p) {
  vec3 p3 = fract(vec3(p.xyx) * 0.1031);
  p3 += dot(p3, p3.yzx + 33.33);
  return fract((p3.x + p3.y) * p3.z);
}

vec2 grad(vec2 i) {
  float a = hash(i) * 6.28318;
  return vec2(cos(a), sin(a));
}

float gnoise(vec2 p) {
  vec2 i = floor(p);
  vec2 f = fract(p);
  vec2 u = f * f * (3.0 - 2.0 * f);
  float a = dot(grad(i), f);
  float b = dot(grad(i + vec2(1.0, 0.0)), f - vec2(1.0, 0.0));
  float c = dot(grad(i + vec2(0.0, 1.0)), f - vec2(0.0, 1.0));
  float d = dot(grad(i + vec2(1.0, 1.0)), f - vec2(1.0, 1.0));
  return mix(mix(a, b, u.x), mix(c, d, u.x), u.y);   // около от -0.7 до 0.7
}

float fbm(vec2 p) {
  float sum = 0.0;
  float amp = 0.5;
  for (int i = 0; i < 5; i++) {
    sum += amp * gnoise(p);
    p = p * 2.0 + vec2(1.7, 9.2);   // отместване, за да не се подравняват октавите
    amp *= 0.5;
  }
  return sum;
}

void main() {
  vec2 p = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;
  vec2 q = p * 1.6 + vec2(0.0, -u_time * 0.12);            // димът се издига
  vec2 w = vec2(fbm(q + vec2(0.0, 0.0)), fbm(q + vec2(5.2, 1.3)));
  float n = fbm(q + 0.7 * w + vec2(0.0, u_time * 0.04));   // изкривяване на пространството
  float smoke = smoothstep(-0.30, 0.35, n);
  vec3 dark = vec3(0.02, 0.03, 0.06);
  vec3 light = vec3(0.75, 0.80, 0.90);
  gl_FragColor = vec4(mix(dark, light, smoke), 1.0);
}
```

В кадър 320 x 180 при `u_time = 1` яркостите са от 8 до 203 (от 255), със средно 91,5: тъмен фон със светли струи дим. При `u_time = 6` струите са на други места, защото `q` се измества по `y`.

Критерии за самопроверка:
- Димът тече плавно и не трепти, виждат се едри маси и ситни завъртулки.
- Можеш да промениш скоростта, мащаба и силата на изкривяването с по едно число.
- При силно изкривяване (множител около 1.5 пред `w`) шарката се усуква като мрамор. Можеш да обясниш защо.

## Бърза справка
- Хеш: `hash(vec2)` дава 0 до 1, без време.
- Value noise: хеш на ъглите, интерполация с `f * f * (3.0 - 2.0 * f)`.
- Gradient noise: хеш като посока, `dot` с вектора до точката.
- fbm: цикъл с `p *= 2.0` и `amp *= 0.5`, константна граница на цикъла.
- Движение: промени позицията, не резултата. Изкривяване: fbm в координатите на друг fbm.

## Обобщение
Шейдърът няма генератор на случайни числа, затова ползваш хеш функция, която превръща координати в псевдослучайно число. Value и gradient noise правят от него плавно поле, а fbm събира няколко октави с нарастваща честота и намаляваща амплитуда в естествена структура. Движението и изкривяването на координатите дават дим и мъгла. Следващият урок е за повторение и симетрия.
