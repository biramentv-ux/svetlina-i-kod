> **Цел на урока:** да изградиш система с обратна връзка (ping-pong буфери), в която всеки кадър се ражда от предишния, и да добавиш постобработка: сияние, хроматична аберация и зърно.

## Какво ще научиш
- Защо шейдър не може да чете и пише в една и съща текстура и как два буфера решават проблема
- Как да рисуваш в текстура чрез framebuffer и да я покажеш на екрана
- Как затихване, мащаб и завъртане на предишния кадър дават следи, ехо и тунели
- Защо 8-битовите буфери оставят „призраци“ и как да ги избегнеш
- Как да подредиш постобработка: блум, хроматична аберация, зърно и виньетка

## Какво е обратна връзка
Досега всеки кадър се изчисляваше от нулата: `u_time` и координатите определяха всичко. При обратната връзка (feedback) шейдърът получава като вход предишния кадър. Ако го нарисуваш малко по-тъмен, малко приближен и малко завъртян, а отгоре добавиш нова форма, получаваш следи, които се разтварят и летят навън. Така работят ефектите „ехо“, „тунел“ и „дим от светлина“, познати от VJ програмите.

Има един технически капан. Графичният процесор не позволява да четеш и пишеш в една и съща текстура в един и същ проход, защото пикселите се обработват паралелно и не е ясно коя стойност е „старата“. Решението се казва **ping-pong**: държиш две текстури, A и B. В кадър 1 четеш от A и пишеш в B. В кадър 2 четеш от B и пишеш в A. След всеки кадър ролите се разменят.

За да рисуваш в текстура вместо на екрана, ползваш обект **framebuffer** (FBO): закачаш текстурата към него, привързваш го и всичко, което рисуваш, отива в текстурата. Привързването на `null` връща рисуването към екрана.

## Двата шейдъра
Първият шейдър прави самата обратна връзка. Той чете предишния кадър от `u_prev`, трансформира го и добавя нова форма: светла точка, която обикаля по крива на Лисажу.

```glsl
precision mediump float;
uniform sampler2D u_prev;
uniform vec2 u_resolution;
uniform float u_time;
uniform float u_emit;    // 1.0 = рисуваме нова форма, 0.0 = само затихване
uniform float u_decay;   // 0.97 = всеки кадър остава 97% от яркостта
uniform float u_sub;     // малко изваждане, за да стигне яркостта до нула

void main() {
  vec2 uv = gl_FragCoord.xy / u_resolution;

  // предишният кадър, леко завъртян и приближен
  vec2 p = uv - 0.5;
  float a = 0.004;
  p = mat2(cos(a), -sin(a), sin(a), cos(a)) * p * 0.992;
  vec3 prev = texture2D(u_prev, p + 0.5).rgb;
  prev = prev * u_decay - u_sub;

  // новата форма: светла точка по крива на Лисажу
  vec2 q = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;
  vec2 c = 0.28 * vec2(cos(u_time * 1.3), sin(u_time * 1.7));
  float dotMask = smoothstep(0.05, 0.03, length(q - c)) * u_emit;
  vec3 col = 0.5 + 0.5 * cos(6.2831 * (u_time * 0.1 + vec3(0.0, 0.33, 0.67)));

  gl_FragColor = vec4(max(prev, col * dotMask), 1.0);
}
```

Обърни внимание на `p * 0.992`: вземаме проби от точка, по-близо до центъра, затова старата картина изглежда приближена и следите летят навън. Умножението по `u_decay` я затъмнява, а `max(prev, нова форма)` слага новата форма отгоре, без да я „залива“ със стари стойности.

Вторият шейдър е постобработка. Той чете готовата текстура и добавя ефекти само за показване; те не влизат обратно във веригата. Ако ги върнеш в буфера, ефектите се натрупват и картината се разпада.

```glsl
precision mediump float;
uniform sampler2D u_tex;
uniform vec2 u_resolution;
uniform float u_time;

float hash(vec2 p) {
  return fract(sin(dot(p, vec2(12.9898, 78.233))) * 43758.5453);
}

void main() {
  vec2 uv = gl_FragCoord.xy / u_resolution;
  vec2 dir = uv - 0.5;

  // хроматична аберация: R, G и B се четат от малко различни места
  vec3 c;
  c.r = texture2D(u_tex, uv + dir * 0.02).r;
  c.g = texture2D(u_tex, uv).g;
  c.b = texture2D(u_tex, uv - dir * 0.02).b;

  // евтин блум: осем съседни проби, добавени като сияние
  vec3 glow = vec3(0.0);
  for (int i = 0; i < 8; i++) {
    float t = 6.2831 * float(i) / 8.0;
    glow += texture2D(u_tex, uv + 0.012 * vec2(cos(t), sin(t))).rgb;
  }
  c += glow / 8.0 * 0.6;

  // зърно и виньетка
  c += (hash(gl_FragCoord.xy + fract(u_time) * 100.0) - 0.5) * 0.05;
  c *= 1.0 - 0.8 * dot(dir, dir);

  gl_FragColor = vec4(c, 1.0);
}
```

Ефектите в него:

| Ефект | Как работи | Типична стойност |
|---|---|---|
| Хроматична аберация | R, G и B се четат от леко различни координати по посока от центъра | отместване 0,01–0,03 |
| Блум (bloom, сияние) | осем съседни проби се усредняват и добавят към цвета | сила 0,3–0,8 |
| Зърно (grain) | случаен шум, различен във всеки кадър | амплитуда 0,03–0,08 |
| Виньетка | краищата се затъмняват по разстоянието до центъра | 0,5–1,0 |

Истинският блум в игри и редактори работи с няколко размазани и намалени копия на картината; осем проби са евтина имитация, достатъчна за сцена.

## Харнесът за ping-pong
Ето цялата JavaScript част. Функцията `makeTarget` създава текстура с framebuffer, а `createFeedback` връща функция `step`, която изпълнява два прохода и разменя буферите.

```js
// Ping-pong: две текстури, които се разменят всеки кадър
function makeTarget(gl, w, h) {
  const tex = gl.createTexture();
  gl.bindTexture(gl.TEXTURE_2D, tex);
  gl.texImage2D(gl.TEXTURE_2D, 0, gl.RGBA, w, h, 0, gl.RGBA, gl.UNSIGNED_BYTE, null);
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.LINEAR);
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAG_FILTER, gl.LINEAR);
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_S, gl.CLAMP_TO_EDGE);
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_T, gl.CLAMP_TO_EDGE);
  const fbo = gl.createFramebuffer();
  gl.bindFramebuffer(gl.FRAMEBUFFER, fbo);
  gl.framebufferTexture2D(gl.FRAMEBUFFER, gl.COLOR_ATTACHMENT0, gl.TEXTURE_2D, tex, 0);
  gl.bindFramebuffer(gl.FRAMEBUFFER, null);
  return { tex, fbo };
}

function createFeedback(gl, feedbackProg, postProg, w, h) {
  let read = makeTarget(gl, w, h);
  let write = makeTarget(gl, w, h);
  const set1 = (p, n, v) => gl.uniform1f(gl.getUniformLocation(p, n), v);
  const set2 = (p, n, x, y) => gl.uniform2f(gl.getUniformLocation(p, n), x, y);

  function step(time, params, canvasW, canvasH) {
    // проход 1: рисуваме в "write", като четем от "read"
    gl.bindFramebuffer(gl.FRAMEBUFFER, write.fbo);
    gl.viewport(0, 0, w, h);
    gl.useProgram(feedbackProg);
    gl.activeTexture(gl.TEXTURE0);
    gl.bindTexture(gl.TEXTURE_2D, read.tex);
    gl.uniform1i(gl.getUniformLocation(feedbackProg, 'u_prev'), 0);
    set2(feedbackProg, 'u_resolution', w, h);
    set1(feedbackProg, 'u_time', time);
    set1(feedbackProg, 'u_emit', params.emit);
    set1(feedbackProg, 'u_decay', params.decay);
    set1(feedbackProg, 'u_sub', params.sub);
    gl.drawArrays(gl.TRIANGLES, 0, 3);

    // проход 2: резултатът върви през постобработка към екрана
    gl.bindFramebuffer(gl.FRAMEBUFFER, null);
    gl.viewport(0, 0, canvasW, canvasH);
    gl.useProgram(postProg);
    gl.bindTexture(gl.TEXTURE_2D, write.tex);
    gl.uniform1i(gl.getUniformLocation(postProg, 'u_tex'), 0);
    set2(postProg, 'u_resolution', canvasW, canvasH);
    set1(postProg, 'u_time', time);
    gl.drawArrays(gl.TRIANGLES, 0, 3);

    [read, write] = [write, read];       // разменяме ролите
  }
  step.latest = () => read;              // последният завършен кадър
  return step;
}
```

Използването е кратко. Двете програми (`feedbackProg` и `postProg`) се компилират както досега, със същия триъгълник, който покрива екрана:

```js
const step = createFeedback(gl, feedbackProg, postProg, 512, 288);

function frame(t) {
  step(t / 1000, { emit: 1, decay: 0.97, sub: 0.008 }, canvas.width, canvas.height);
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

Буферът е 512 × 288, независимо от размера на платното. Това е полезен трик: обратната връзка върху по-малък буфер е по-бърза и малко размитата картина дори изглежда добре, защото следите са меки по природа.

## Реален тест: призраците
Системата е изпробвана в Chromium със софтуерен рендер: 120 кадъра точката се рисува, след това рисуването спира и се гледа как угасва буферът. Измерена е най-високата стойност на канал в текстурата (0–255):

| Кадър | Само `decay 0.97` | `decay 0.97` и `sub 0.008` |
|---|---|---|
| 119 (последен с форма) | 214 | 214 |
| 150 | 83 | 42 |
| 250 | 14 | 0 |
| 399 | 3 | 0 |

Без изваждане в буфера остава слаб призрак (стойност 3 след почти 300 кадъра без нова форма). Причината е закръглянето: буферът е 8-битов, а умножение по 0,97 на малка стойност, закръглена обратно, често дава същото число. С малко изваждане (`0.008` е приблизително 2/255) всичко стига до чиста нула. Затова формулата `prev * decay - sub` е стандартна за feedback шейдъри.

В последния кадър на тест с работеща точка на екрана се вижда светещо кълбо в лилаво със син ръб, зад което се точи размита опашка, подобна на комета. Синият и червеникавият ръб са от хроматичната аберация, а по-широкото сияние е от блума.

## Стъпка по стъпка
1. Направи две текстури и два framebuffer-а с `makeTarget` и провери, че `gl.getError()` връща 0.
2. Пусни само първия проход и рисувай в екрана, за да видиш следите. После премини към втория проход.
3. Започни с `decay = 0.9` (кратки следи) и го вдигай към 0,98. Стойност 1,0 или по-висока води до бяло петно.
4. Добави малко завъртане (`a = 0.004`) и мащаб (`0.992`). Опитай и обратен знак: следите ще се стягат към центъра.
5. Добави постобработката една по една и сравнявай с изключен ефект.
6. Свържи `u_bass` от предния урок с `emit` или с мащаба: на всеки удар картината леко „скача“.

## Пример от практиката
Да кажем, че имаш прост шейдър с въртящ се пръстен и искаш той да оставя светещ дим. Вместо да усложняваш математиката, го слагаш като „нова форма“ във feedback шейдъра, а предишния кадър връщаш с `decay 0.95`, лек мащаб и завъртане. Резултатът е пръстен, който оставя спирала след себе си. Благодарение на `sub` при смяна на сцената картината се изчиства сама и не се налага нулиране на буфера.

## Чести грешки
- **Четене и писане в една текстура** – получаваш грешка или неопределен резултат. Винаги използвай два буфера и ги размествай.
- **Забравена размяна на буферите** – картината замръзва или мига между два кадъра.
- **`decay` над 1** – яркостта расте, докато екранът побелее. Започвай ниско.
- **Липса на изваждане при 8-битов буфер** – остават призраци, които не изчезват.
- **Постобработка, върната в буфера** – ефектите се натрупват. Нея показвай само на екрана.
- **Float текстури без разширения** – в WebGL 1 те изискват разширения и не работят навсякъде. Започни с 8 бита и ги заменяй само ако видиш лентови преходи.
- **Неправилен `viewport` при смяна на проход** – буферът е 512 × 288, платното е друго; задавай размера на всеки проход.

## Упражнение
Добави следи към движеща се форма от предишните уроци.
- Формата се рисува във feedback шейдъра, а не само в крайния.
- Следите имат поне два параметъра: затихване и завъртане (или мащаб).
- След няколко секунди без нова форма буферът е напълно черен (провери с `readPixels` върху буфера, не върху екрана, където зърното добавя шум).
- Постобработката е подредена: хроматична аберация, блум и зърно, поне два от тях.
- По желание: свържи един параметър с `u_bass`.

Критерии: компилира се без грешки; няма светло петно при дълго пускане; няма видими призраци; кодът има ясно разделени проходи.

## Бърза справка
| Понятие | Значение |
|---|---|
| Framebuffer (FBO) | обект, който пренасочва рисуването към текстура |
| Ping-pong | два буфера, които разменят ролите четене и писане |
| `decay` | множител на предишния кадър (0,9–0,98) |
| `sub` | малко изваждане, което чисти призраците |
| Мащаб под 1 в проби | следите летят навън |
| Постобработка | показва се само на екрана, не се връща в буфера |

## Обобщение
Обратната връзка добавя памет: всеки кадър е трансформиран предишен кадър плюс нещо ново. Ping-pong буферите заобикалят забраната да се чете и пише в една текстура. Затихването, мащабът и завъртането определят характера на следите, а `prev * decay - sub` ги чисти докрай. Постобработката идва последна и само за екрана. Следващият урок показва как да изнесеш такива шейдъри в VJ софтуера.

- Включвай и изключвай хроматичната аберация, блума и зърното едно по едно.
