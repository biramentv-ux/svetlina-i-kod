## Какво ще научиш

## Заданието
Създай шейдър за твоя сет. Ти избираш стила: геометричен, органичен, абстрактен, минималистичен. Задължително е да има:
1. **Генеративна картина** от поне три различни техники от курса (например SDF форма, fbm шум, повторение или калейдоскоп, палитра).
2. **Реакция на звук** през поне две от трите нива (`u_bass`, `u_mid`, `u_high`), като всяко управлява различно нещо.
3. **Обратна връзка или постобработка** (следи, блум, хроматична аберация, зърно или комбинация).
4. **Три до пет параметъра**, достъпни за управление на живо: например скорост, цвят, интензитет на звука, брой сектори.
5. **Измерена производителност** при резолюцията, на която ще свириш.
6. **Представяне:** шейдърът, кратко видео и описание на параметрите.

Не се изисква нито сложна математика, нито най-новите техники. Оценява се ясна идея, чиста работа и ефект на сцена.

## Основа, от която да тръгнеш
Ако ти трябва начало, ето стартов шейдър. Той е изпробван в Chromium със софтуерен рендер и се компилира без грешки: калейдоскоп с шест сектора, чиято текстура е fbm шум, пръстен, който следва баса, и искри за високите честоти.

```glsl
precision mediump float;
uniform vec2 u_resolution;
uniform float u_time;
uniform float u_bass;
uniform float u_mid;
uniform float u_high;

#define PI 3.14159265

float hash(vec2 p) {
  return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}

float noise(vec2 p) {
  vec2 i = floor(p), f = fract(p);
  f = f * f * (3.0 - 2.0 * f);
  return mix(mix(hash(i), hash(i + vec2(1.0, 0.0)), f.x),
             mix(hash(i + vec2(0.0, 1.0)), hash(i + vec2(1.0, 1.0)), f.x), f.y);
}

float fbm(vec2 p) {
  float v = 0.0, a = 0.5;
  for (int i = 0; i < 4; i++) {
    v += a * noise(p);
    p *= 2.0;
    a *= 0.5;
  }
  return v;
}

// палитра: цветът е функция на едно число
vec3 palette(float t) {
  return 0.5 + 0.5 * cos(6.2831 * (t + vec3(0.0, 0.33, 0.67)));
}

// калейдоскоп: огледални сектори в полярни координати
vec2 kaleido(vec2 p, float n) {
  float a = atan(p.y, p.x);
  float r = length(p);
  float seg = 2.0 * PI / n;
  a = abs(mod(a, seg) - 0.5 * seg);
  return r * vec2(cos(a), sin(a));
}

void main() {
  vec2 uv = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;

  // 1. геометрия: сектори, които се въртят бавно
  float s = sin(u_time * 0.1), c = cos(u_time * 0.1);
  vec2 p = mat2(c, -s, s, c) * uv;
  p = kaleido(p, 6.0);

  // 2. текстура: fbm, чието изкривяване зависи от средните честоти
  float n = fbm(p * 3.0 + u_time * 0.2 + u_mid * 2.0);

  // 3. форма: пръстен, чийто радиус следва баса
  float radius = 0.25 + 0.12 * u_bass;
  float ring = 0.01 / (abs(length(uv) - radius + 0.1 * (n - 0.5)) + 0.01);

  // 4. цвят
  vec3 col = palette(n + u_time * 0.05) * (0.15 + ring * (0.5 + u_bass));
  col += u_high * step(0.97, hash(floor(gl_FragCoord.xy / 3.0) + floor(u_time * 10.0)));

  gl_FragColor = vec4(col, 1.0);
}
```

При ниско ниво на баса (`u_bass = 0.1`) се вижда шестоъгълен пръстен със син и зелен цвят, изкривен от шума; средната яркост на кадъра е около 25 от 255. При `u_bass = 0.9`, `u_mid = 0.5` и `u_high = 0.5` пръстенът е по-ярък, а около него се появяват светли точки (искри); средната яркост е около 39. Обърни внимание на структурата: геометрия, текстура, форма, цвят. Тя е направена така, за да можеш да сменяш една част, без да чупиш другите.

Бележка: пръстенът следва `length(uv)`, а не калейдоскопните координати `p`. Това е нарочно, защото така формата остава кръгла, а шумът я изкривява. Промени това и виж какво се случва; такива експерименти са добра основа за собствен стил.

## Тест с фалшиви стойности
Преди да търсиш музика, направи режим, в който нивата са зададени от адресния ред, например `?bass=0.8&mid=0.3&high=0.1`. Така можеш да сравниш кадри и да ги проверяваш автоматично.

```js
const q = new URLSearchParams(location.search);
const fake = q.has('bass')
  ? { bass: +q.get('bass'), mid: +(q.get('mid') || 0), high: +(q.get('high') || 0) }
  : null;
// във всеки кадър:  const lv = fake || read();
```

За да сравниш кадрите с числа, измерваш средната яркост на изрисувания кадър със `readPixels` (платното трябва да е създадено с `preserveDrawingBuffer: true`):

```js
function meanBrightness(gl, w, h) {
  const px = new Uint8Array(w * h * 4);
  gl.readPixels(0, 0, w, h, gl.RGBA, gl.UNSIGNED_BYTE, px);
  let s = 0;
  for (let i = 0; i < px.length; i += 4) s += px[i] + px[i + 1] + px[i + 2];
  return s / (w * h * 3);
}
```

Разумна самопроверка: при `bass = 0` и `bass = 1` средните яркости трябва да се различават осезаемо (в стартовия шейдър около 25 срещу около 39 при допълнителни нива на `u_mid` и `u_high`). Ако числата са еднакви, `u_bass` не влияе на картината и нещо е свързано погрешно.

## Чести грешки
- **Твърде много ефекти наведнъж** – картината става каша. По-добре три добре настроени ефекта, отколкото осем случайни.
- **Всичко реагира на баса** – няма разнообразие. Раздели ролите между трите нива.
- **Трептене и резки смени** – няма изглаждане, а при по-силен светлинен блясък може да е неприятно за част от публиката. Избягвай честа и рязка смяна на ярък кадър; ограничи честотата на светкавиците.
- **Тест само с една песен** – настрой с поне две различни по динамика песни.
- **Забравена тишина** – шейдърът трябва да изглежда добре и когато няма звук, и когато анализаторът е блокиран.
- **Измерване само на малък прозорец** – измервай на резолюцията на сцената.
- **Параметри без граници** – плъзгач, който чупи картината, на сцена е опасен.
