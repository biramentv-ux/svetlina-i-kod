> **Цел на урока:** да превърнеш звука от песен или микрофон в три плавни числа (бас, средни и високи честоти) и да ги подадеш на шейдър така, че картината да пулсира в ритъма, без да трепти.

## Какво ще научиш
- Как Web Audio API и FFT анализът превръщат звука в честотен спектър
- Как да изчислиш нива за бас, средни и високи честоти и да ги нормализираш до 0…1
- Защо суровите стойности трептят и как асиметрично изглаждане (бърза атака, бавно затихване) решава проблема
- Как да подадеш нивата на фрагментния шейдър като `uniform` стойности
- Как да тестваш аудио-визуалния шейдър и без музикален файл

## От звука до числата
Звукът е вълна, която се променя хиляди пъти в секунда. Шейдърът не може да използва такава вълна директно, защото му трябват няколко прости числа на кадър. Мостът е бързото преобразуване на Фурие (FFT, Fast Fourier Transform): то разделя звука на честоти и казва колко енергия има във всяка от тях.

В браузъра това върши `AnalyserNode` от Web Audio API. Свързваш го към източник на звук и на всеки кадър викаш `getByteFrequencyData(масив)`. Масивът се пълни с числа от 0 до 255, по едно за всяка честотна „кошница“ (bin). Първата кошница е най-ниските честоти, последната е най-високите.

Колко широка е една кошница? Формулата е проста: `binHz = sampleRate / fftSize`. При честота на дискретизация 44100 Hz и `fftSize = 1024` всяка кошница е около 43 Hz, а кошниците са `fftSize / 2 = 512`. Затова басът (20–150 Hz) е само четири-пет кошници, а високите са стотици.

Три групи са достатъчни за повечето VJ шейдъри:

| Група | Диапазон (ориентир) | Какво чуваш | Подходящо за |
|---|---|---|---|
| Бас (`u_bass`) | 20–150 Hz | кик и бас линия | размер, пулс, удар |
| Средни (`u_mid`) | 150–2000 Hz | вокали, синтове, малък барабан | въртене, изкривяване, цвят |
| Високи (`u_high`) | 2000–12000 Hz | хай-хет, шум, въздух | искри, зърно, ръбове |

Границите са договорка, не закон. Ако музиката ти има много нисък бас, измести границата на 100 Hz; ако хай-хетът е слаб, спусни високите от 1500 Hz.

## Анализаторът: целият код
Ето функция, която прави всичко описано. Тя е изпробвана в Chromium с `OscillatorNode` вместо музикален файл.

```js
// Анализатор: превръща звука в три числа 0..1 (bass, mid, high)
function createAudioAnalyser(audioCtx, sourceNode) {
  const analyser = audioCtx.createAnalyser();
  analyser.fftSize = 1024;               // 512 честотни кошници
  analyser.smoothingTimeConstant = 0.6;  // вградено изглаждане между кадрите
  sourceNode.connect(analyser);

  const data = new Uint8Array(analyser.frequencyBinCount);
  const binHz = audioCtx.sampleRate / analyser.fftSize;

  function band(fromHz, toHz) {
    const a = Math.max(0, Math.floor(fromHz / binHz));
    const b = Math.min(data.length - 1, Math.ceil(toHz / binHz));
    let sum = 0;
    for (let i = a; i <= b; i++) sum += data[i];
    return sum / ((b - a + 1) * 255);    // средно, нормализирано 0..1
  }

  const smooth = { bass: 0, mid: 0, high: 0 };
  function follow(prev, target) {        // бърза атака, бавно затихване
    const k = target > prev ? 0.6 : 0.08;
    return prev + (target - prev) * k;
  }

  return function read() {
    analyser.getByteFrequencyData(data);
    smooth.bass = follow(smooth.bass, band(20, 150));
    smooth.mid  = follow(smooth.mid,  band(150, 2000));
    smooth.high = follow(smooth.high, band(2000, 12000));
    return smooth;
  };
}
```

Три неща заслужават внимание.

**Нормализирането.** Функцията `band` събира стойностите на кошниците и ги дели на броя им и на 255. Така резултатът е между 0 и 1 независимо от размера на FFT.

**Вграденото изглаждане.** `smoothingTimeConstant` (0…1) усреднява спектъра с предишния кадър. При 0 няма изглаждане, при 0,8 реакцията е бавна и „мазна“. Около 0,5–0,7 е добро начало.

**Собственото изглаждане.** Функцията `follow` е второто ниво: ако новата стойност е по-висока, следваме я бързо (коефициент 0,6), ако е по-ниска, затихваме бавно (0,08). Така ударът се вижда веднага, а картината не пада рязко между два удара. Това е „атака и затихване“ (attack and release), същото като в звуковите компресори.

## Реалният тест: какво показа изпробването
При изпробване в Chromium с чисти тонове от `OscillatorNode` (честота на дискретизация 44100 Hz) нивата след 30 кадъра са:

| Тон | bass | mid | high |
|---|---|---|---|
| 80 Hz | 0,977 | 0,072 | 0 |
| 800 Hz | 0 | 0,215 | 0 |
| 6000 Hz | 0 | 0 | 0,040 |

Виждаш две важни неща. Първо, всеки тон попада в правилната група. Второ, чистият тон на 6000 Hz дава само 0,04 във високите, защото усредняваме по стотици кошници, а тонът заема една-две. Истинската музика запълва повече кошници, но високите почти винаги са по-слаби от баса. Затова им добавяш усилване: `Math.min(1, band(2000, 12000) * 4)`. Нива, които никога не стигат 1, са най-честата причина шейдърът да изглежда „вял“.

## Шейдърът, който реагира
Шейдърът получава три `uniform` числа и ги ползва за различни неща: басът променя радиуса и цвета на пръстен, средните го чупят на въртящи се зъби, високите добавят искри.

```glsl
precision mediump float;
uniform vec2 u_resolution;
uniform float u_time;
uniform float u_bass;
uniform float u_mid;
uniform float u_high;

float hash(vec2 p) {
  return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}

void main() {
  vec2 uv = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;
  float r = length(uv);
  float a = atan(uv.y, uv.x);

  // радиусът на пръстена расте с баса
  float radius = 0.16 + 0.16 * u_bass;
  float d = abs(r - radius);
  float ring = smoothstep(0.012, 0.0, d);
  float glow = 0.012 / (d + 0.012) * (0.25 + 0.75 * u_bass);

  // средните честоти въртят и чупят пръстена на зъби
  float teeth = 0.5 + 0.5 * sin(a * 12.0 + u_time * 1.5);
  glow *= mix(1.0, teeth, u_mid);

  // високите добавят искри около пръстена
  vec2 cell = floor(uv * 60.0);
  float spark = step(0.985 - 0.1 * u_high, hash(cell + floor(u_time * 8.0)));
  spark *= smoothstep(0.35, 0.0, abs(r - radius - 0.1)) * u_high;

  vec3 cold = vec3(0.1, 0.3, 0.9);
  vec3 hot  = vec3(1.0, 0.25, 0.5);
  vec3 col = mix(cold, hot, u_bass) * (ring + glow);
  col += vec3(1.0) * spark;
  col += 0.03 * vec3(0.2, 0.1, 0.4) * (1.0 - r);

  gl_FragColor = vec4(col, 1.0);
}
```

Шейдърът е изпробван в Chromium със софтуерен рендер и се компилира без грешки. При `u_bass = 0` се вижда малък тъмносин пръстен върху почти черен фон със средна яркост около 3 от 255. При `u_bass = 1`, `u_mid = 0.8` и `u_high = 0.9` пръстенът е по-голям, розов и зъбчат, а около него са пръснати светли искри; средната яркост е около 21 от 255.

## Свързване: `uniform` стойности и източници на звук
Във всеки кадър четеш нивата и ги подаваш на шейдъра със същия механизъм като `u_time`. Закачането към източник е отделна стъпка. Програмата и буферът са същите като в предишните уроци; ето само новото:

```js
let read = () => ({ bass: 0, mid: 0, high: 0 });   // докато няма звук

function frame(t) {
  const lv = read();
  gl.uniform1f(gl.getUniformLocation(prog, 'u_time'), t / 1000);
  gl.uniform1f(gl.getUniformLocation(prog, 'u_bass'), lv.bass);
  gl.uniform1f(gl.getUniformLocation(prog, 'u_mid'),  lv.mid);
  gl.uniform1f(gl.getUniformLocation(prog, 'u_high'), lv.high);
  gl.drawArrays(gl.TRIANGLES, 0, 3);
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);

document.getElementById('go').onclick = async () => {
  const ctx = new AudioContext();
  await ctx.resume();                        // нужен е жест на потребителя
  const src = ctx.createMediaElementSource(document.getElementById('song'));
  src.connect(ctx.destination);              // за да се чува
  read = createAudioAnalyser(ctx, src);
  document.getElementById('song').play();
};
```

Източниците са три:
- **Файл през `<audio>`:** `createMediaElementSource`. Ако файлът е от друг адрес, сървърът трябва да разрешава CORS, иначе браузърът връща тишина. Най-лесно е файлът да е на същия адрес като страницата.
- **Микрофон или линеен вход:** `navigator.mediaDevices.getUserMedia({ audio: true })` и после `ctx.createMediaStreamSource(stream)`. Изисква се защитен контекст (https или localhost) и разрешение от потребителя. Изключи ехо-потискането (`echoCancellation: false` в ограниченията на аудиото), иначе браузърът ще „чисти“ музиката ти.
- **Генератор за тест:** `ctx.createOscillator()`. Свързваш го през `GainNode` със стойност 0 към изхода, за да не чуваш тон, и анализаторът пак го вижда.

Браузърите не пускат звук без жест на потребителя, затова `AudioContext` се създава или възобновява вътре в обработчик на клик. Това е една от най-честите причини „не работи“.

Целият описан файл е изпробван като една страница: при тишина средната яркост на кадъра е 3,22 от 255, а при тон 80 Hz през осцилатор става 15,47. Картината наистина следва звука.

## Пример от практиката
Да кажем, че миксираш мек хаус сет и искаш логото ти да „диша“ с кика. С `u_bass` без изглаждане то трепти, защото кикът е кратък, а между два удара има шум. С `follow` (0,6 нагоре, 0,08 надолу) логото се разширява веднага при удара и бавно се връща, преди да дойде следващият. След това на `u_high` слагаш усилване 4 и хай-хетът започва да оставя дребни искри около формата. Цялата настройка е три числа, а ефектът изглежда като ръчно анимиран.

## Чести грешки
- **Нищо не се чува или не реагира след зареждане на страницата** – `AudioContext` е блокиран до първи клик. Създай или възобнови контекста в обработчик на събитие.
- **Тишина при файл от друг сървър** – липсва CORS. Сложи файла на същия адрес или разреши CORS на сървъра.
- **Суровите стойности на анализатора движат формата директно** – картината трепти. Винаги изглаждай.
- **Нивата никога не стигат до 1** – диапазонът е твърде широк или звукът е тих. Добави усилване и ограничи с `Math.min(1, …)`.
- **Фиксиран `fftSize` за всички случаи** – по-големият размер дава по-точен бас, но по-бавна реакция. 1024 е добър компромис за визуали.
- **Микрофон с включено ехо-потискане** – браузърът отрязва музиката като „шум“.

- Цветът или въртенето се управляват от `u_mid`.
- Поне един ефект използва `u_high`.
- Картината не трепти: при равномерен кик движението е плавно.

Критерии: компилира се без грешки; със стойности 0 и 1 на ръка се виждат ясно различни кадри; няма резки скокове между кадрите; кодът за звука е отделен от шейдъра.

## Бърза справка
| Задача | Код |
|---|---|
| Анализатор | `ctx.createAnalyser()` |
| Брой кошници | `analyser.frequencyBinCount` (равен на `fftSize / 2`) |
| Ширина на кошница | `ctx.sampleRate / analyser.fftSize` |
| Спектър в масив | `analyser.getByteFrequencyData(data)` (0…255) |
| Бас / средни / високи | около 20–150 / 150–2000 / 2000–12000 Hz |
| Бърза атака, бавно затихване | `prev + (t - prev) * (t > prev ? 0.6 : 0.08)` |
| Тест без файл | `ctx.createOscillator()` през `GainNode` със стойност 0 |

## Обобщение
FFT разделя звука на честоти, а `AnalyserNode` ти дава спектъра на всеки кадър. Усредняваш три диапазона до числа между 0 и 1, изглаждаш ги с бърза атака и бавно затихване и ги подаваш като `uniform` стойности. Звукът е само вход: колкото по-ясно е шейдърът ти разделен на геометрия, текстура и цвят, толкова по-лесно решаваш кое ниво какво управлява. Ако си преминал курса „Програмиране от нулата“, този цикъл „чети, изглади, подай“ ти е познат от всяка интерактивна програма. В следващия урок добавяш памет към картината чрез обратна връзка.
