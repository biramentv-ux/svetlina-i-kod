> **Цел на урока:** Пишеш CSS правила със селектори, разбираш защо печели едно, а не друго правило, и оразмеряваш елементите правилно чрез кутиения модел.

## Какво ще научиш
- как е устроено едно CSS правило и къде се записват стиловете;
- какви селектори има и как се комбинират;
- как каскадата избира кое правило да се приложи (специфичност, ред, `!important`);
- как работи кутиеният модел (content, padding, border, margin) и защо почти всеки сайт започва с `box-sizing: border-box`;
- кои свойства се наследяват и кога да ползваш `rem`, `em` и проценти.

## Правило и къде се пише
CSS е списък от правила. Всяко правило има **селектор** (кои елементи) и **декларации** (какво да им се случи):

```css
p {
  color: gray;
  font-size: 1.125rem;
}
```

`p` е селекторът, `color` и `font-size` са **свойства**, а `gray` и `1.125rem` са техните **стойности**. Всяка декларация завършва с точка и запетая.

Стиловете могат да се запишат на три места:

1. **Във външен файл**, който се свързва с `<link rel="stylesheet" href="stil.css">` в `<head>`. Това е основният начин: един файл за много страници, браузърът го запазва и не го тегли отново.
2. **В елемент `<style>`** в `<head>`. Удобно е за малки демонстрации и за примерите във видеата.
3. **Вграден стил (inline)** в атрибута `style="color: red"`. Той има висок приоритет и трудно се презаписва, затова го избягвай.

В този урок примерите са във външен файл `stil.css`.

## Селектори
Селекторът казва кои елементи да се стилизират. Най-често ползваните:

| Селектор | Пример | Избира |
|---|---|---|
| по елемент | `p` | всички абзаци |
| по клас | `.karta` | елементите с `class="karta"` |
| по `id` | `#glavna` | единствения елемент с `id="glavna"` |
| няколко | `h1, h2` | и двата вида |
| низходящ | `article p` | абзаци на всяко ниво във `article` |
| пряк наследник | `article > p` | само преките деца |
| следващ съсед | `p + p` | абзац, който е веднага след друг абзац |
| състояние | `a:hover` | връзка под мишката |
| фокус с клавиатура | `a:focus-visible` | елемент, фокусиран с клавиатурата |
| позиция | `li:nth-child(2)` | втория `li` сред съседите си |

Класът се записва в HTML като `class="karta"` и може да се повтаря. Елемент може да има няколко класа, разделени с интервал. Идентификаторът `id` е уникален за страницата и в CSS се избягва като средство за оформяне: прекалено силен е и трудно се презаписва. Ползвай класове.

Имената избирай по смисъл (`karta`, `belejka`), а не по външен вид (`cherven-tekst`): утре цветът ще се смени, а смисълът – не.

## Каскадата: кой печели
CSS означава *Cascading* Style Sheets. Когато две правила се опитват да зададат едно и също свойство на един елемент, браузърът решава по ред:

1. **Важност:** декларацията с `!important` печели (освен ако и двете са такива). Не я ползвай, освен ако няма друг начин.
2. **Специфичност:** по-конкретният селектор печели. Груба скала: вграден стил > `id` > клас, атрибут и състояние > елемент.
3. **Ред:** при еднаква специфичност печели правилото, което е написано по-късно.

Нека проверим. Ето страница с правила (съкратено):

```css
p { color: gray; }
.nota { color: green; }
#glavna { color: blue; }
p.nota { color: orange; }
.red { color: crimson; }
.red { color: teal; }
.vazhno { color: purple !important; }
article p { font-size: 20px; }
article > p + p { color: brown; }
```

HTML-ът има абзаци с различни комбинации от клас, `id` и вграден стил. Ето изчисления цвят на всеки (резултат от Chromium през `getComputedStyle`):

| Абзац | Какво се прилага | Резултат |
|---|---|---|
| само елемент | `p` | `rgb(128, 128, 128)` – сиво |
| елемент + клас `nota` | `p.nota` е по-специфично от `.nota` и `p` | `rgb(255, 165, 0)` – оранжево |
| `id="glavna"` + клас | `#glavna` | `rgb(0, 0, 255)` – синьо |
| вграден стил `color: red` | `style` | `rgb(255, 0, 0)` – червено |
| два еднакви селектора | вторият по ред | `rgb(0, 128, 128)` – teal |
| `!important` срещу вграден | `!important` | `rgb(128, 0, 128)` – виолетово |

В `article` вторият и третият абзац получават цвят по `article > p + p`, а размер 20px по `article p`: двете правила не си пречат, защото задават различни свойства. Реалният изход (цвят и размер) е `rgb(165, 42, 42) 20px` за втория и третия абзац и `rgb(128, 128, 128) 20px` за първия.

Практични правила: пиши селектори с **ниска специфичност** (един клас), задавай по-общите правила най-горе и по-частните след тях, и не използвай `id` и `!important`. Когато стил не се прилага, отвори инструментите за разработчици: в панела със стиловете зачертаните декларации са загубилите, а в „Computed“ виждаш крайния резултат.

## Наследяване
Част от свойствата се **наследяват** от родителя към децата: `color`, `font-family`, `font-size`, `line-height`. Затова е достатъчно да зададеш шрифта на `body`. Други не се наследяват: `border`, `margin`, `padding`, `background`. Иначе всяка дума във всеки абзац щеше да получи собствена рамка.

Доказателство: родителски `div` с `color: teal; border: 3px solid red; font-family: serif` и вътре `<span>`. Изчислените стойности на `span` са:

```
color: rgb(0, 128, 128)   font: serif   border-top-width: 0px
```

Цветът и шрифтът са наследени, рамката – не.

## Кутиеният модел
Всеки елемент в страницата е правоъгълна кутия с четири слоя отвътре навън:

1. **content** – самото съдържание, с `width` и `height`;
2. **padding** – вътрешно разстояние между съдържанието и рамката (фонът му се вижда);
3. **border** – рамка;
4. **margin** – външно разстояние до съседите (винаги прозрачно).

Ето най-честият източник на объркване. Елемент със `width: 200px; padding: 20px; border: 5px solid` по подразбиране (`box-sizing: content-box`) е **по-широк** от 200 пиксела, защото `width` описва само съдържанието. Измерено в Chromium:

```
content-box:  width: 200px,  реална ширина (offsetWidth): 250
border-box:   width: 200px,  реална ширина (offsetWidth): 200
```

250 е 200 + 2 × 20 (padding) + 2 × 5 (border). При `box-sizing: border-box` ширината включва padding и рамка, така че 200 значи 200. Затова повечето сайтове започват с:

```css
*, *::before, *::after { box-sizing: border-box; }
```

Две правила за `margin`:

- **Сгъване на вертикалните отстояния (margin collapsing):** когато горният елемент има долен margin 20px, а долният – горен 30px, разстоянието между тях е не 50, а 30 – по-голямото. Измерено: `30`. Хоризонталните margin не се сгъват.
- `margin: 0 auto` с зададена ширина центрира блоковия елемент хоризонтално.

Съкратеният запис: `margin: 10px 20px` значи 10 горе и долу, 20 вляво и вдясно; четири стойности вървят по часовниковата стрелка – горе, дясно, долу, ляво.

## Единици
| Единица | Значение | Измерено |
|---|---|---|
| `px` | пиксел на екрана | |
| `rem` | размерът на шрифта на корена (по подразбиране обикновено 16px) | `1.5rem` → `24px` |
| `em` | размерът на шрифта на самия елемент (за `font-size` – на родителя) | `2em` → `32px` при родител 16px |
| `%` | част от размера на родителя | `50%` от 400px → `200px` |
| `vw` / `vh` | процент от ширината / височината на прозореца | |

Предпочитай `rem` за шрифтове и разстояния: ако потребителят увеличи шрифта в браузъра си, страницата се мащабира заедно с него. За рамки от един-два пиксела `px` е нормален избор.

## Стъпка по стъпка
1. Вземи страницата си от предишния урок. Създай `stil.css` до нея и го свържи в `<head>`.
2. Започни с `box-sizing: border-box` за всичко и с `margin: 0` за `body`.
3. Задай на `body` шрифт, `line-height: 1.6`, цвят на текста и фон.
4. Сложи на съдържанието `main` с `max-width: 40rem` и `margin: 0 auto`, за да е в средата и четливо.
5. Създай клас `.karta` с `padding`, рамка, `border-radius` и долен `margin`. Сложи го на разделите.
6. Направи връзките видими: цвят и подчертаване. Добави `a:hover` и `a:focus-visible` (с видим контур).
7. Отвори инструментите за разработчици, избери абзац и провери в „Computed“ и в схемата на кутията откъде идват размерите.
8. Умишлено напиши две конфликтни правила за един елемент и обясни кое печели и защо.

## Пример от практиката
Да кажем, че оформяш страницата на фотографа Ива. Ето част от `stil.css`:

```css
*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; font-family: system-ui, sans-serif; line-height: 1.6;
       color: #1f2933; background: #f5f1e8; }
.stranica { max-width: 40rem; margin: 0 auto; padding: 1rem; }
.karta { padding: 1.25rem; margin-bottom: 1rem; background: #fff;
         border: 1px solid #d9d2c3; border-radius: 0.5rem; }
.glava a:hover { text-decoration: none; }
.glava a:focus-visible { outline: 3px solid #fff; outline-offset: 3px; }
```

Проверката във Chromium на прозорец 900 пиксела дава:

```
body фон: rgb(245, 241, 232) | шрифт: 16px | line-height: 25.6px
main ширина: 640px | margin-left: 130px
карта padding/рамка/радиус: 20px 1px 8px
връзка преди hover: underline
връзка при hover: none
фокус след Tab: Снимки | outline: solid 3px
грешки: 0
```

Читаемо е: `40rem` са 640 пиксела, останалите 260 се разпределят по 130 от двете страни (`margin: 0 auto`), `1.25rem` е 20 пиксела, а `1.6 × 16` е 25,6. Бутонът Tab премества фокуса върху първата връзка и тя получава контура. Така управлението само с клавиатура остава видимо.

## Чести грешки
- **Стилове с `!important` навсякъде** – скоро и те ще започнат да се бият помежду си. Намали специфичността на селекторите.
- **Забравен `box-sizing`** – елементите „излизат“ извън родителя си, защото padding и рамката се добавят отвън.
- **Селектори с `id` и дълги вериги** – `#glava nav ul li a` е трудно да се презапише. Ползвай клас.
- **Име на клас по външен вид** – `.cherveno` ще стане синьо след година.
- **Фиксирана височина на текстови блок** – текстът прелива, когато потребителят увеличи шрифта. Остави височината автоматична.
- **Липсваща точка и запетая или скоба** – браузърът мълчаливо пропуска правилото или следващото след него. Ако нещо не се прилага, потърси в панела със стиловете зачертана или липсваща декларация.
- **Премахване на контура при фокус** (`outline: none`) без замяна – потребителите с клавиатура губят къде се намират.

## Упражнение
Оформи страницата си с външен CSS файл.

Критерии за самопроверка:
- файлът е свързан с `link` и страницата няма грешки в конзолата;
- `box-sizing: border-box` важи за всички елементи;
- използвани са поне пет различни селектора, от които поне два класа, един комбиниран (`article p`) и едно състояние (`:hover` или `:focus-visible`);
- няма `id` селектори и `!important`;
- шрифтът е зададен само на `body`, а размерите са в `rem`;
- можеш да покажеш конфликт между две правила и да обясниш кое печели и защо (специфичност или ред);
- със Tab връзките получават видим контур.

## Бърза справка
- Правило: `селектор { свойство: стойност; }`.
- Селектори: `p`, `.клас`, `#id`, `a, b`, `a b`, `a > b`, `a + b`, `:hover`, `:focus-visible`, `:nth-child()`.
- Каскада: `!important` > специфичност (inline > id > клас > елемент) > по-късно правило.
- Наследяват се `color`, `font-*`, `line-height`; не се наследяват `margin`, `padding`, `border`, `background`.
- Кутия: content + padding + border + margin; `box-sizing: border-box`.
- Вертикалните margin се сгъват: остава по-големият.
- `rem` – от корена, `em` – от родителя, `%` – от родителя, `px` – фиксиран.

## Обобщение
CSS правилото съчетава селектор и декларации и се пише най-добре във външен файл. Когато правила си противоречат, решава каскадата: важност, после специфичност, после ред, затова пиши прости селектори с клас. Някои свойства се наследяват, други не. Всеки елемент е кутия, а `box-sizing: border-box` прави `width` да означава това, което очакваш. В следващия урок ще подреждаш кутиите една спрямо друга с Flexbox и Grid.

## Бележки за видеото
Видеото е с редактор вляво и браузър вдясно, като CSS се пише в елемент `<style>` в края на същия файл. Показва пет стъпки: страница без стил; селектори по елемент за `body` и `h1`; селектор по клас `.karta`; кутиен модел (padding, border, margin); и конфликт на две правила за абзац, който се решава от по-специфичния клас. След всяка стъпка страницата вдясно се променя.
