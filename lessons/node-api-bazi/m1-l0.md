> **Цел на урока:** да разбереш как работи HTTP и да напишеш сървър само с `node:http`, който маршрутизира заявки на ръка и отговаря с текст и JSON.

## Какво ще научиш
- Как изглеждат HTTP заявката и отговорът и какво значат метод, адрес, заглавия и статус
- Как се създава сървър с `createServer` и се слуша на порт
- Как се разчита адресът и се маршрутизира на ръка
- Как се чете тялото на заявка и как се връща JSON
- Как се тества с `curl`, как се спира сървърът и какво става при грешка в обработчика

## HTTP накратко

HTTP е договор между клиент (браузър, приложение, `curl`) и сървър. Клиентът праща **заявка**, сървърът връща **отговор**. И двете са текст, подреден по правила. Заявката изглежда така:

```text
POST /api/echo HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json

{"tekst":"здравей"}
```

Първият ред съдържа **метод** (`POST`), **път** (`/api/echo`) и версия. После идват **заглавия** (headers) – двойки „име: стойност“, и след празен ред – по избор **тяло** (body). Отговорът има подобна форма: **статус** (число и текст), заглавия и тяло:

```text
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8

{"poluchih":{"tekst":"здравей"}}
```

Основните методи и значението им:

| Метод | Обичайно значение |
|---|---|
| `GET` | прочети ресурс; не променя нищо |
| `POST` | създай нещо или изпрати данни |
| `PUT` / `PATCH` | замени / промени ресурс |
| `DELETE` | изтрий ресурс |

Статус кодовете са групирани по първата цифра: `2xx` – успех, `3xx` – пренасочване, `4xx` – грешка на клиента (лоша заявка, липсващ ресурс), `5xx` – грешка на сървъра. Най-често ще ползваш `200 OK`, `400 Bad Request`, `404 Not Found`, `405 Method Not Allowed` и `500 Internal Server Error`.

Сървърът слуша на **адрес и порт**. Адресът `127.0.0.1` (още `localhost`) означава „този компютър“ и до него няма достъп отвън. Портът е число, чрез което различаваме програмите на един компютър. За разработка се ползват номера като 3000 или 8080.

## Първият сървър

Модулът `node:http` е вграден. Функцията `createServer` приема обработчик, който се вика при **всяка** заявка и получава два обекта: `req` (заявката) и `res` (отговорът). Целият сървър, който ще изграждаме в този урок, е един файл `server.js`:

```js
import { createServer } from "node:http";

const PORT = Number(process.env.PORT ?? 3000);

function json(res, status, data) {
  res.writeHead(status, { "Content-Type": "application/json; charset=utf-8" });
  res.end(JSON.stringify(data));
}

async function chetiTialo(req) {
  const chastichki = [];
  for await (const chast of req) chastichki.push(chast);
  return Buffer.concat(chastichki).toString("utf8");
}

const server = createServer(async (req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`);
  console.log(`${req.method} ${url.pathname}`);

  if (url.pathname === "/") {
    res.writeHead(200, { "Content-Type": "text/plain; charset=utf-8" });
    res.end("Здравей от Node.js!\n");
    return;
  }

  if (url.pathname === "/api/vreme" && req.method === "GET") {
    const grad = url.searchParams.get("grad") ?? "София";
    return json(res, 200, { grad, gradusi: 18, jasno: true });
  }

  if (url.pathname === "/api/echo") {
    if (req.method !== "POST") {
      res.setHeader("Allow", "POST");
      return json(res, 405, { greshka: "Позволен е само POST" });
    }
    try {
      const danni = JSON.parse(await chetiTialo(req));
      return json(res, 200, { poluchih: danni });
    } catch {
      return json(res, 400, { greshka: "Невалиден JSON" });
    }
  }

  json(res, 404, { greshka: "Не е намерено" });
});

server.on("error", (e) => {
  console.error("Грешка в сървъра:", e.code);
  process.exitCode = 1;
});

server.listen(PORT, "127.0.0.1", () => console.log(`Слушам на http://127.0.0.1:${PORT}`));

process.on("SIGINT", () => {
  console.log("\nСпирам...");
  server.close(() => console.log("Затворен."));
});
```

Да го разгледаме на части.

**Портът** идва от променливата на средата `PORT` с резервна стойност 3000 – познатият от предишния урок шаблон. **`server.listen(PORT, "127.0.0.1", ...)`** казва на Node да слуша само на локалния адрес. Така сървърът ти не е достъпен от мрежата, докато го разработваш – това е добра предпазна настройка по подразбиране.

**Адресът.** `req.url` съдържа само пътя и заявката за търсене, например `/api/vreme?grad=Варна`. Класът `URL` го разделя: `url.pathname` е пътят, а `url.searchParams.get("grad")` – параметърът. Вторият аргумент на `new URL` е базовият адрес; нужен е, защото `req.url` е относителен.

**Отговорът.** `res.writeHead(статус, заглавия)` задава статуса и заглавията, `res.end(тяло)` праща тялото и приключва отговора. Заглавието `Content-Type` казва на клиента как да чете тялото. Добавяй `charset=utf-8`, за да е ясно, че кирилицата е в UTF-8. Вграденото `JSON.stringify` превръща обект в JSON текст.

**Маршрутизирането** е верига от `if`: проверяваме път и метод и връщаме отговор. Всеки клон завършва с `return`, за да не се продължи към следващата проверка. Накрая стои общият отговор `404`.

**Тялото на заявката** е поток, който се чете на части. Функцията `chetiTialo` събира частите (`for await`), слепва ги и ги превръща в текст. После `JSON.parse` го разчита; ако е счупен, хващаме грешката и връщаме `400`.

## Проверка с curl

Пусни сървъра в един терминал и пробвай от втори. Сървърът пише:

```text
Слушам на http://127.0.0.1:3000
```

Ключът `-i` на `curl` показва заглавията на отговора:

```bash
curl -i http://127.0.0.1:3000/
```

```text
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
Connection: keep-alive
Transfer-Encoding: chunked

Здравей от Node.js!
```

Node добавя и заглавия, които не си задавал (`Date`, `Keep-Alive`; тук са пропуснати). Сега JSON маршрутът:

```bash
curl -s http://127.0.0.1:3000/api/vreme
```

```text
{"grad":"София","gradusi":18,"jasno":true}
```

Ключът `-s` скрива лентата за напредък. Параметър със кирилица трябва да е кодиран в адреса. Ако го напишеш директно, Node ще отхвърли заявката още преди твоят код да я види (получаваш `HTTP/1.1 400 Bad Request`). Оставяш `curl` да го кодира с `-G` и `--data-urlencode`:

```bash
curl -s -G http://127.0.0.1:3000/api/vreme --data-urlencode "grad=Пловдив"
```

```text
{"grad":"Пловдив","gradusi":18,"jasno":true}
```

Липсващ маршрут и POST с тяло:

```bash
curl -si http://127.0.0.1:3000/nema | head -1
curl -s -X POST -H "Content-Type: application/json" -d '{"tekst":"здравей"}' http://127.0.0.1:3000/api/echo
```

```text
HTTP/1.1 404 Not Found
{"poluchih":{"tekst":"здравей"}}
```

А невалиден JSON и грешен метод:

```text
$ curl -i -X POST -d '{тест' http://127.0.0.1:3000/api/echo
HTTP/1.1 400 Bad Request
Content-Type: application/json; charset=utf-8
Transfer-Encoding: chunked

{"greshka":"Невалиден JSON"}

$ curl -i http://127.0.0.1:3000/api/echo
HTTP/1.1 405 Method Not Allowed
Allow: POST
```

Най-често ползваните ключове на `curl`:

| Ключ | Значение |
|---|---|
| `-i` | покажи заглавията на отговора |
| `-I` | само заглавията (праща `HEAD`) |
| `-s` | тих режим |
| `-X МЕТОД` | задай метода |
| `-H "Име: стойност"` | добави заглавие |
| `-d 'данни'` | тяло на заявката (методът става `POST`) |
| `-G --data-urlencode` | кодирай параметри в адреса |

Конзолата на сървъра показва дневник на заявките:

```text
GET /
GET /api/vreme
GET /api/vreme
POST /api/echo
GET /nema
POST /api/echo
```

## Спиране и грешки

С `Ctrl+C` процесът получава сигнала `SIGINT`. Обработчикът му вика `server.close()`, който спира приемането на нови връзки и приключва нормално, вместо да се прекъсне рязко:

```text
Спирам...
Затворен.
```

Ако портът е зает, например защото вече имаш пуснат екземпляр, `listen` излъчва събитие `error`. Нашият обработчик печата кода и задава изходен код 1:

```text
Грешка в сървъра: EADDRINUSE
```

Най-опасното е необработена грешка в обработчика. Ако тя се хвърли (`throw`), целият процес пада, не само заявката. При обработчик, който хвърля грешка за адрес `/boom`, клиентът получава `curl: (52) Empty reply from server`, следващите заявки са отказани (`curl: (7)`, връзката е отказана), а процесът е спрян. Затова парчетата код, които могат да се счупят, са в `try`/`catch`. Централизираната обработка на грешки е тема на третия урок от модула.

## Стъпка по стъпка

1. Създай `server.js` със съдържанието от урока и го пусни с `node server.js`.
2. От втори терминал изпрати заявките с `curl` една по една и сравни резултата с урока.
3. Отвори `http://127.0.0.1:3000/api/vreme` в браузъра и погледни как е показан JSON.
4. Пусни втори екземпляр на същия порт и прочети грешката.
5. Спри сървъра с `Ctrl+C` и провери, че виждаш „Затворен.“.
6. Добави нов маршрут `/api/chas`, който връща текущото време като JSON.

## Пример от практиката

Да кажем, че правиш табло за училищен клуб по астрономия, което показва кога е залезът. Страницата ще пита сървъра за данни и ти още нямаш база. Започваш със сървър, който връща JSON със заключени стойности за три града. Страницата се разработва срещу него, а когато данните станат истински, сменяш само вътрешността на маршрута. Формата на отговора (`{ grad, ... }`) остава същият. Така клиентът и сървърът се разработват независимо.

## Чести грешки

- **Липсва `res.end()`** – клиентът чака вечно. Всеки клон трябва да завърши отговора.
- **Два отговора за една заявка** – забравено `return` и код, който пише отново, хвърля `ERR_HTTP_HEADERS_SENT` и също събаря процеса.
- **Липсва `Content-Type`** – клиентът не знае дали получава текст, или JSON.
- **Кирилица в адреса без кодиране** – сървърът връща `400`, а кодът ти не се изпълнява. Кодирай параметрите.
- **Слушане на всички адреса без нужда** – по време на разработка ползвай `127.0.0.1`.
- **Хвърлена грешка в обработчика** – убива сървъра; хващай грешките.
- **Четене на тялото без проверка на размера** – безкрайно голяма заявка запълва паметта. В истински сървър ограничаваш размера (ще го направим в следващия урок).

## Упражнение

Разшири `server.js` така, че:
1. `GET /api/chas` да връща `{ "chas": "<ISO време>" }`;
2. `GET /api/pozdrav?ime=Мария` да връща `{ "tekst": "Здравей, Мария!" }`, а без параметър – `{ "tekst": "Здравей, непознати!" }`;
3. `POST /api/sbor` с тяло `{"a":2,"b":3}` да връща `{ "sbor": 5 }`, а при липсващи или нечислови полета – статус `400` със съобщение;
4. всички останали адреси да връщат `404` с JSON.

Провери се сам: всеки маршрут е изпробван с `curl -i`, статусите са точни, кирилицата се чете правилно, сървърът се спира без грешка и след края на упражнението няма останали процеси.

## Бърза справка

| Задача | Код |
|---|---|
| Създай сървър | `createServer((req, res) => { ... })` |
| Слушай | `server.listen(порт, "127.0.0.1", () => ...)` |
| Метод и адрес | `req.method`, `new URL(req.url, base)` |
| Параметър на адреса | `url.searchParams.get("име")` |
| Заглавия на заявката | `req.headers` (имената са с малки букви) |
| Статус и заглавия | `res.writeHead(200, { "Content-Type": "..." })` |
| Изпрати отговор | `res.end(текст)` |
| Прочети тялото | `for await (const част of req)` |
| Спри сървъра | `server.close()` |

## Обобщение

HTTP е заявка и отговор с метод, път, заглавия, тяло и статус. С `node:http` създаваш сървър с една функция, която получава `req` и `res`. Маршрутизираш по метод и път, четеш параметрите с `URL`, четеш тялото от потока и връщаш JSON със `Content-Type` и подходящ статус. С `curl` проверяваш всеки маршрут, а грешките в обработчика трябва да се хващат, иначе сървърът пада. В следващия урок превръщаме тази идея в подреден REST API.
