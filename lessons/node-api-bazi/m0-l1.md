> **Цел на урока:** да четеш и пишеш файлове, да работиш с пътища и да управляваш програмата си отвън чрез аргументи, променливи на средата, вход и изходен код.

## Какво ще научиш
- Как се четат, пишат, изброяват и изтриват файлове с `node:fs/promises`
- Как се сглобяват пътища с `node:path`, без да зависиш от операционната система
- Как програмата получава аргументи и настройки чрез `process.argv` и `process.env`
- Какво е изходен код и защо отчита успех или грешка
- Как да прочетеш стандартния вход и коя вградена помощна функция да ползваш за аргументи

## Файлове с node:fs

Модулът `node:fs` има три „стила“ на едни и същи операции: със функции за обратно извикване (callbacks), синхронни (с окончание `Sync`) и с обещания (promises) в `node:fs/promises`. В съвременния код ползваш третия, защото върви с `async`/`await`, който познаваш от курса „JavaScript за уеб“. Синхронните блокират програмата и са приемливи само в кратки скриптове.

Най-често ползваните функции:

| Функция | Какво прави |
|---|---|
| `readFile(път, "utf8")` | чете целия файл като текст |
| `writeFile(път, данни)` | създава или презаписва файл |
| `appendFile(път, данни)` | добавя в края |
| `mkdir(път, { recursive: true })` | създава папка (и родителите ѝ) |
| `readdir(път, { withFileTypes: true })` | изброява съдържанието на папка |
| `stat(път)` | размер, дата на промяна, вид |
| `rm(път, { recursive: true })` | изтрива файл или цяла папка |

Без втория параметър `"utf8"` `readFile` връща суров буфер от байтове, а не текст. Кирилицата е в UTF-8, затова винаги задавай кодировката, когато четеш текст.

Следният скрипт създава папка, записва три файла, изброява ги и накрая я изтрива:

```js
import { mkdir, writeFile, appendFile, readFile, readdir, stat, rm } from "node:fs/promises";
import { join, extname, parse } from "node:path";

const papka = join(import.meta.dirname, "danni");
await mkdir(papka, { recursive: true });

await writeFile(join(papka, "zadachi.json"), JSON.stringify([{ id: 1, tekst: "Купи хляб" }], null, 2));
await writeFile(join(papka, "dnevnik.log"), "старт\n");
await appendFile(join(papka, "dnevnik.log"), "втори ред\n");
await writeFile(join(papka, "belezhka.txt"), "кратка бележка\n");

const zapisi = await readdir(papka, { withFileTypes: true });
for (const z of zapisi.sort((a, b) => a.name.localeCompare(b.name))) {
  const info = await stat(join(papka, z.name));
  console.log(z.isDirectory() ? "папка" : "файл ", z.name.padEnd(14), String(info.size).padStart(4), "байта", extname(z.name));
}

const dannite = JSON.parse(await readFile(join(papka, "zadachi.json"), "utf8"));
console.log("прочетено:", dannite);
console.log(parse("/proekt/danni/dnevnik.log"));
await rm(papka, { recursive: true });
console.log("изтрита ли е папката?", await stat(papka).then(() => "не", (e) => "да (" + e.code + ")"));
```

```text
файл  belezhka.txt     28 байта .txt
файл  dnevnik.log      29 байта .log
файл  zadachi.json     57 байта .json
прочетено: [ { id: 1, tekst: 'Купи хляб' } ]
{
  root: '/',
  dir: '/proekt/danni',
  base: 'dnevnik.log',
  ext: '.log',
  name: 'dnevnik'
}
изтрита ли е папката? да (ENOENT)
```

Обърни внимание на две неща. Първо, размерите са в **байтове**, а не в знаци: „кратка бележка“ са 14 знака плюс нов ред, но файлът е 28 байта, защото всяка кирилска буква заема два байта в UTF-8. Второ, `JSON.stringify(данни, null, 2)` записва четим JSON с отстъп; `JSON.parse` го връща обратно в обект. Това е най-простият начин да пазиш данни във файл и ще го ползваме в следващите уроци.

За големи файлове `readFile` е лоша идея, защото зарежда всичко в паметта. Тогава четеш на части. Ето ред по ред през `node:readline`:

```js
import { createReadStream } from "node:fs";
import { createInterface } from "node:readline";

const rl = createInterface({ input: createReadStream("tekst.txt", "utf8"), crlfDelay: Infinity });
let n = 0;
for await (const red of rl) {
  n++;
  console.log(`${n}: ${red}`);
}
```

```text
1: Ранна пролет в Родопите.
2: Снегът се топи, а потоците
3: шумят по-силно всяка сутрин.
```

## Пътища с node:path

Пътищата се различават между системите: Linux и macOS ползват `/`, Windows – `\`. Никога не ги слепвай с `+`. Ползвай `node:path`:

```text
join("a","b","../c","f.txt")        ->  a/c/f.txt
resolve("/proekt","danni","x.txt")  ->  /proekt/danni/x.txt
extname("arhiv.tar.gz")             ->  .gz
basename("/a/b/c.txt", ".txt")      ->  c
relative("/a/b/c", "/a/d")          ->  ../../d
```

Разликата между двете основни функции: `join` просто слепва части с правилния разделител и нормализира `..`, а `resolve` връща **абсолютен** път и, ако липсва начало, започва от текущата работна папка. Изходът по-горе е от Linux; на Windows разделителят щеше да е `\`.

Най-честият проблем е относителният път. `readFile("tekst.txt")` търси файла в **работната папка на процеса** (`process.cwd()`), а тя е там, откъдето си пуснал `node`, а не там, където е скриптът. Когато файлът е до скрипта, строй пътя от `import.meta.dirname`: `join(import.meta.dirname, "tekst.txt")`.

## Процесът: аргументи, среда, изход

Глобалният обект `process` описва програмата, която се изпълнява.

**Аргументи.** `process.argv` е масив: първите два елемента са пътят до `node` и до скрипта, а аргументите на потребителя започват от индекс 2. Затова пишеш `process.argv.slice(2)`:

```text
$ node proc.js a "b c" --fl=1
argv има 5 елемента
аргументи: [ 'a', 'b c', '--fl=1' ]
```

Кавичките в обвивката (shell) обединяват `b c` в един аргумент. Всички аргументи са текст; ако очакваш число, преобразувай го сам.

**Променливи на средата.** `process.env` съдържа настройките, наследени от обвивката, а стойностите също са винаги низове:

```js
const port = Number(process.env.PORT ?? 3000);
```

```text
$ PORT=8080 node proc.js
PORT: 8080 | тип: string
порт като число: 8080
```

Без зададена променлива получаваш `undefined`, затова слагаш резервна стойност с `??`. Това е стандартният начин сървърът да получи порта, паролата на базата и други настройки извън кода (в урок 3 на модул 2 ще го направим системно).

**Аргументи с имена.** Ръчното разчитане на `--име=стойност` бързо става досадно. Вграденият `parseArgs` от `node:util` го решава:

```js
import { parseArgs } from "node:util";
const { values, positionals } = parseArgs({
  options: { glagol: { type: "string", short: "g", default: "Здравей" }, glasno: { type: "boolean", short: "v" } },
  allowPositionals: true,
});
console.log(values, positionals);
```

```text
$ node args.js -g Хей Мария --glasno
[Object: null prototype] { glagol: 'Хей', glasno: true } [ 'Мария' ]
$ node args.js
[Object: null prototype] { glagol: 'Здравей' } []
```

Неизвестна опция води до `TypeError [ERR_PARSE_ARGS_UNKNOWN_OPTION]`, което е желано поведение: програмата не приема мълчаливо грешни аргументи.

**Стандартен вход.** Програмите в командния ред се свързват с тръба (`|`). `process.stdin` е поток, който четеш с `for await`:

```js
let text = "";
process.stdin.setEncoding("utf8");
for await (const chunk of process.stdin) text += chunk;
const dumi = text.split(/\s+/).filter(Boolean);
console.log("думи от stdin:", dumi.length);
```

```text
$ printf 'едно две три\nчетири\n' | node stdin.js
думи от stdin: 4
```

Освен `console.log` (стандартен изход) има `console.error`, който пише в стандартния изход за грешки (stderr). Двата потока могат да се пренасочват поотделно: `node скрипт.js > резултат.txt` записва само нормалния изход, а грешките остават на екрана.

## Изходен код

Всяка програма завършва с число. **0 означава успех**, всяко друго – грешка. Обвивката го пази в `$?`, а скриптове и системи за автоматично изграждане решават какво да правят по него. В Node има два начина да го зададеш:
- `process.exit(код)` спира веднага, дори да има недовършена работа.
- `process.exitCode = код` само запомня кода; програмата завършва нормално, когато свърши заявената работа. Това е по-безопасният избор.

С `process.on("exit", ...)` можеш да видиш крайния код. Скриптът `izhod.js` задава `process.exitCode = 3`:

```text
$ node izhod.js
работя
излизане с код 3
shell видя: 3
```

Необработеното изключение (`throw` без `try`) и необработеното отхвърлено обещание също завършват с код 1, като първото печата стека на грешката. Така Node сигнализира, че нещо не е наред.

## Стъпка по стъпка: броячът на думи

Да сглобим всичко в малка полезна програма. Файлът `tekst.txt` е от три реда. Програмата `broi.js` получава път, брои редове, думи и знаци и връща правилен изходен код:

```js
import { readFile } from "node:fs/promises";
import { basename } from "node:path";

const putyat = process.argv[2];

if (!putyat) {
  console.error("Употреба: node broi.js <файл>");
  process.exit(2);
}

try {
  const text = await readFile(putyat, "utf8");
  const redove = text.split("\n").filter((r) => r.trim() !== "").length;
  const dumi = text.split(/\s+/).filter(Boolean);
  console.log(`Файл: ${basename(putyat)}`);
  console.log(`Редове: ${redove}`);
  console.log(`Думи: ${dumi.length}`);
  console.log(`Знаци: ${[...text].length}`);
} catch (greshka) {
  if (greshka.code === "ENOENT") {
    console.error(`Няма такъв файл: ${putyat}`);
    process.exitCode = 1;
  } else {
    throw greshka;
  }
}
```

Три пускания и техните резултати:

```text
$ node broi.js tekst.txt
Файл: tekst.txt
Редове: 3
Думи: 13
Знаци: 81
(код 0)

$ node broi.js nema.txt
Няма такъв файл: nema.txt
(код 1)

$ node broi.js
Употреба: node broi.js <файл>
(код 2)
```

Какво прави програмата добра:
1. Проверява входа и казва как се ползва, ако липсва аргумент.
2. Хваща **само** грешката, която очаква (`ENOENT` – файлът не съществува), и обработва другите като необработени. Ако му подадеш папка, получаваш `EISDIR: illegal operation on a directory` и код 1. Не прикривай грешки, които не разбираш.
3. Пише грешките в `stderr`, а резултата в `stdout`, и връща различни кодове за различни случаи.
4. Брои знаците с `[...text]` (по кодови точки), а думите – чрез разделяне по интервали.

## Малки вградени помощници

`node:crypto` дава `randomUUID()` (уникален идентификатор от 36 знака) и хешове: `createHash("sha256").update("здравей").digest("hex")` започва с `774fd5baab12de30`, същото като `sha256sum` в Linux. За пароли ще ползваме друга функция (в модул 3). `node:os` дава `EOL` (края на реда за системата) и информация за паметта и процесора.

## Пример от практиката

Да кажем, че всяка седмица получаваш папка с текстови съобщения за читалищен сайт. Пишеш скрипт `obobshti.js`, който получава папката от `process.argv[2]`, чете всички `.txt` файлове с `readdir` и `readFile`, брои думите във всеки и записва `obobshtenie.json`. Пътищата се строят с `join`, а ако папката липсва, скриптът пише в `stderr` и завършва с код 1. Така можеш да го слагаш в автоматична задача, която знае дали е минал успешно.

## Чести грешки

- **Относителен път без да знаеш работната папка** – скриптът работи при теб, но не и от друго място. Строй пътя от `import.meta.dirname`.
- **Четене без `"utf8"`** – получаваш буфер вместо текст.
- **`process.env.PORT` ползван като число** – винаги е низ; преобразувай с `Number()`.
- **`process.exit()` вътре в асинхронна работа** – може да прекъсне запис. Предпочети `process.exitCode`.
- **Празен `catch`** – прикрива истински проблеми. Хващай конкретния `code` и пропускай останалите.
- **Слепване на пътища с `+`** – чупи се между системите; ползвай `join`.

## Упражнение

Направи скрипт `statistika.js`, който:
1. приема път до текстов файл и по избор опцията `--top=N` (ползвай `parseArgs`);
2. брои редове, думи и знаци;
3. изброява N най-честите думи (с малки букви, без препинателни знаци) заедно с броя им;
4. при липсващ файл печата съобщение в `stderr` и връща код 1, а при липсващ аргумент – код 2;
5. записва резултата и в `statistika.json` до скрипта (с `import.meta.dirname`).

Провери се сам: пускаш го с реален файл, с липсващ файл и без аргументи; кодовете са 0, 1 и 2; JSON файлът се чете обратно с `JSON.parse`; скриптът работи, когато се пусне от друга папка.

## Бърза справка

| Задача | Код |
|---|---|
| Прочети текст | `await readFile(път, "utf8")` |
| Запиши / добави | `writeFile(път, текст)` / `appendFile(път, текст)` |
| Създай папка | `mkdir(път, { recursive: true })` |
| Съдържание на папка | `readdir(път, { withFileTypes: true })` |
| Размер и вид | `stat(път)` |
| Изтрий | `rm(път, { recursive: true })` |
| Сглоби път | `join(...)`, абсолютен: `resolve(...)` |
| До скрипта | `import.meta.dirname` |
| Аргументи | `process.argv.slice(2)` или `parseArgs` |
| Настройка | `Number(process.env.PORT ?? 3000)` |
| Код при успех / грешка | `0` / `process.exitCode = 1` |
| Грешка към stderr | `console.error(...)` |

## Обобщение

Файловете се обработват най-удобно с `node:fs/promises` и `async`/`await`, а пътищата – с `node:path` и `import.meta.dirname`. Програмата получава аргументи от `process.argv`, настройки от `process.env` и данни от стандартния вход, а резултата връща чрез изход и изходен код. Хващай само грешките, които очакваш, като `ENOENT`, и използвай кодове, по които други програми да решават какво да правят. С тези основи можеш да преминеш към мрежата: в следващия модул започваме с HTTP сървър.
