## Какво е Node.js

Node.js е среда, която изпълнява JavaScript извън браузъра. Ползва същия двигател като Chrome (V8), но вместо достъп до страницата (`document`, `window`) дава достъп до компютъра: файлове, мрежа, процеси. С Node пишеш сървъри, инструменти за командния ред и скриптове за автоматизация.

Езикът е същият, който познаваш от курса „JavaScript за уеб“: променливи, функции, обекти, `async`/`await`. Различава се околната среда:

| Какво | В браузъра | В Node.js |
|---|---|---|
| Глобален обект | `window` (и `globalThis`) | `globalThis` |
| Страницата | `document`, DOM | няма |
| Модули | `<script type="module">` | CommonJS и ES модули |

Файловете и мрежата са достъпни чрез `node:fs` и `node:http`. Някои неща са общи: `fetch`, `URL`, `structuredClone` и `setTimeout` работят и в двете среди.

Курсът изисква Node.js 22 или по-нов. Версията се проверява така:

```bash
node -v
npm -v
```

```text
v22.23.4
10.9.9
```

Номерата при теб може да са различни; важно е първото число да е поне 22. `npm` е мениджърът на пакети и идва с Node.

Малък код можеш да пуснеш и направо от командния ред: `node -p "process.version"` печата версията. Обектът `process` е специфичен за Node и ще го разгледаме в следващия урок.

## Два формата модули

Модулът е файл, който изнася част от кода си и ползва кода на други файлове. В Node съжителстват два формата.

**CommonJS** е по-старият. Изнасяш с `module.exports`, внасяш с `require()`. Файл `math.js`:

```js
function sum(a, b) { return a + b; }
const PI2 = Math.PI * 2;
module.exports = { sum, PI2 };
```

Файл `main.js` в същата папка:

```js
const { sum, PI2 } = require("./math");
const path = require("node:path");
console.log("sum:", sum(2, 3));
console.log("PI2:", PI2.toFixed(4));
console.log("файл:", path.basename(__filename));
console.log("папка свършва на:", path.basename(__dirname));
```

```text
sum: 5
PI2: 6.2832
файл: main.js
папка свършва на: cjs
```

В CommonJS са налични `__filename` и `__dirname` – пътят до текущия файл и до неговата папка. Забележи и `node:path`: префиксът `node:` показва, че модулът е вграден в Node, а не пакет от `node_modules`. Винаги го пиши, така няма объркване.

**ES модулите** са стандартният формат на езика и работят същото в браузъра. Изнасяш с `export`, внасяш с `import`. Файл `math.mjs`:

```js
export function sum(a, b) { return a + b; }
export const PI2 = Math.PI * 2;
export default function greet(name) { return `Здравей, ${name}!`; }
```

Файл `main.mjs`:

```js
import greet, { sum, PI2 } from "./math.mjs";
import { basename } from "node:path";
console.log(greet("свят"));
console.log("sum:", sum(2, 3), "PI2:", PI2.toFixed(4));
console.log("файл:", basename(import.meta.filename));
console.log("папка:", basename(import.meta.dirname));
console.log(typeof __dirname);
```

```text
Здравей, свят!
sum: 5 PI2: 6.2832
файл: main.mjs
папка: esm
undefined
```

В ES модулите няма `__dirname`. Вместо това ползваш `import.meta.dirname` и `import.meta.filename`. В ES модули при относителен внос пишеш и разширението на файла (`./math.mjs`), а в CommonJS то може да се пропусне.

### Как Node избира формат

Node решава по следните правила:
- Файл с разширение `.mjs` е ES модул, а `.cjs` е CommonJS.
- За `.js` решава най-близкият `package.json`: при `"type": "module"` е ES модул, при `"type": "commonjs"` или липса на полето – CommonJS.

В тази версия Node разпознава ES синтаксис и в `.js` файл без `type`: кодът по-горе, записан като `t.js` без `package.json`, се изпълни без оплакване. Не разчитай на това, а задавай `type` изрично.

Смесването има граници. Ако в `.cjs` файл напишеш `import`, ще видиш:

```text
SyntaxError: Cannot use import statement outside a module
```

В ES модул няма глобален `require`, но ES модул може да внася CommonJS с `import`. А CommonJS файл може да зареди ES модул с `require()`. В тази версия на Node това работи:

```js
const m = require("./math.mjs");
console.log(Object.keys(m), m.sum(1, 2));
```

```text
[ 'PI2', '__esModule', 'default', 'sum' ] 3
```

В по-старите версии на Node това не се поддържаше, така че ако поддържаш чужд проект, провери коя версия ползва. Курсът ползва ES модули, защото са едни и същи в браузъра и на сървъра.

## package.json и npm

Всеки проект на Node има в корена си файл `package.json`. Той описва проекта: име, версия, формат на модулите, скриптове и зависимости. Командата `npm init -y` създава такъв с примерни стойности. Ние ще го напишем сами, защото е по-кратко и по-ясно:

```json
{
  "name": "pozdrav",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "main": "src/index.js",
  "scripts": {
    "start": "node src/index.js",
    "dev": "node --watch src/index.js"
  }
}
```

Полетата, които ще срещаш най-често:

| Поле | Значение |
|---|---|
| `name`, `version` | идентичност на проекта; името е с малки букви, без интервали |
| `private` | `true` пази от случайно публикуване в публичния регистър на npm |
| `type` | формат на `.js` файловете: `module` или `commonjs` |
| `scripts` | именувани команди за `npm run` |
| `dependencies` | пакетите, от които проектът има нужда |

JSON не допуска коментари и висящи запетаи. Ако `package.json` е счупен, `npm` ще съобщи грешка още при първата команда.

### Скриптове

Скриптът е име на команда. Файлът `src/pozdrav.js`:

```js
export function pozdrav(ime) {
  return `Здравей, ${ime}!`;
}
```

Файлът `src/index.js`:

```js
import { pozdrav } from "./pozdrav.js";

const ime = process.argv[2] ?? "свят";
console.log(pozdrav(ime));
```

Стартираш го през скрипта:

```bash
npm start
```

```text
> pozdrav@1.0.0 start
> node src/index.js

Здравей, свят!
```

`start` е специален: `npm start` работи без `run`. За всички останали имена пишеш `npm run <име>`. Аргументи към програмата се подават след `--`:

```bash
npm start -- Мария
```

```text
> pozdrav@1.0.0 start
> node src/index.js Мария

Здравей, Мария!
```

С `-s` (тих режим) получаваш само изхода на програмата: `npm run -s start -- Иван` печата `Здравей, Иван!`. Списъкът със скриптове се вижда с `npm run` без име, а за несъществуващ скрипт получаваш `npm error Missing script: "nema"`.

### Зависимости

Пакетите се инсталират с `npm install <име>`. Регистърът на npm е публичен и съдържа огромно количество пакети, но този курс ще работи изцяло с вградените модули. Затова, за да видиш механизма без интернет, ще инсталираме малък локален пакет. Папка `uslugi` със свой `package.json` и файл `index.js`:

```js
export const dvoino = (n) => n * 2;
```

От папката на проекта:

```bash
npm install ../uslugi
```

```text
added 1 package, and audited 3 packages in 264ms

found 0 vulnerabilities
```

Времето при теб ще е различно. Какво се случи:
- В `package.json` се появи секция `"dependencies": { "uslugi": "file:../uslugi" }`.
- Появи се папка `node_modules`, в която `uslugi` е препратка (символна връзка) към оригинала.
- Появи се `package-lock.json` – точен списък на инсталираното, така че всички на екипа да получат едни и същи версии.

Сега пакетът се внася по име, а не по път:

```js
import { dvoino } from "uslugi";
console.log(dvoino(21));
```

```text
42
```

За истински пакет от регистъра командата е същата, а в `dependencies` се записва диапазон на версията. Практическите правила:
- `node_modules` е голяма и се възстановява с `npm install`, затова не я качваш в хранилището за код (git). Добави я в `.gitignore`.
- `package-lock.json` се качва.

Всеки външен пакет е чужд код, който пускаш на компютъра си, затова курсът се опира на вградените модули. Алтернативи на `npm` с общ `package.json` са `pnpm` и `yarn`.

## Удобства при разработка

Две опции на самия Node правят работата приятна, без нищо да инсталираш.

**`--watch`** рестартира програмата при всяка промяна на файл. Скриптът `dev` по-горе го ползва. Ето истинска сесия с файл `watch.js`, към който се добавя ред, докато програмата работи:

```text
версия: 1
Completed running 'src/watch.js'. Waiting for file changes before restarting...
Restarting 'src/watch.js'
версия: 1
променено
Completed running 'src/watch.js'. Waiting for file changes before restarting...
```

Процесът не излиза, а чака; спираш го с `Ctrl+C`.

**`--env-file`** зарежда променливи на средата от файл. Ако `.env` съдържа реда `VERSIA=1`, а програмата чете `process.env.VERSIA`:

```bash
node --env-file=.env src/watch.js
node src/watch.js
```

```text
версия: 1
променено
версия: няма
променено
```

Първото пускане е с файла и вижда `1`, второто е без него и получава резервната стойност `няма`. Така настройките стоят извън кода. Във `.env` често има тайни, затова файлът също влиза в `.gitignore`.

## Пример от практиката

Да кажем, че правиш малко приложение за читалище, което печата разписание на събития. Първо е един файл, но след седмица има три задачи: форматиране на дати, зареждане на събития и печат. Разделяш ги на `src/dati.js`, `src/subitiya.js` и `src/index.js`. Добавяш `start` и `dev`. Колега, който клонира проекта, пуска само `npm install` и `npm start`.

## Чести грешки

- **Липсва `"type": "module"`, а се пише `import`** – в `.cjs` файл или в по-стара среда получаваш `Cannot use import statement outside a module`. Задавай `type` винаги.
- **Забравен `.js` при относителен внос** – в ES модулите пиши `./pozdrav.js`, а не `./pozdrav`.
- **Грешно име при внос** – `import { nema } from "./pozdrav.js"` дава `SyntaxError: The requested module './pozdrav.js' does not provide an export named 'nema'`.
- **Качване на `node_modules`** – ненужно голяма папка; ползвай `.gitignore`.
- **Аргументи без `--`** – за скриптове подавай аргументите след `--`, както в `npm start -- Мария`, за да стигнат до твоята програма.

## Упражнение

Направи проект `pozdrav2` със следното:
1. `package.json` с `"type": "module"` и скриптове `start` и `dev`.
2. Файл `src/index.js`, който чете два аргумента: име и град, и печата `Здравей, <име> от <град>!`. Ако градът липсва, печата `Здравей, <име>!`.
3. Втори модул `src/format.js`, който изнася функцията, използвана от `index.js`.
4. Файл `.env` с променлива `TITLA=г-н` (или друга по избор), която скриптът добавя пред името, когато е зададена. Добави скрипт `start:env`, който пуска програмата с `--env-file=.env`.

Провери се сам: `npm start -- Мария София` печата правилния ред; `npm run dev` рестартира при промяна; `npm start` без `.env` печата името без титла (ако `--env-file` сочи към несъществуващ файл, Node спира с `not found`); в проекта няма `require`.

| Задача | Команда или код |

## Обобщение

Node.js изпълнява JavaScript извън браузъра и добавя достъп до файлове, мрежа и процеси. Кодът се дели на модули: CommonJS (`require`, `module.exports`) и ES модули (`import`, `export`), а полето `type` в `package.json` решава как се чете `.js` файл. `package.json` описва проекта, скриптовете и зависимостите, а `package-lock.json` фиксира версиите. С `--watch` и `--env-file` получаваш удобна разработка без допълнителни пакети. В следващия урок ще работим с файлове и процеси.
