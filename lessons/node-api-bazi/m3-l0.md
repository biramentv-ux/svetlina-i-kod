> **Цел на проекта:** да построиш цялостно API за лични бележки само с вградените модули на Node.js: с база SQLite, регистрация и вход, валидиране, защита и автоматични тестове.

## Какво ще научиш
- как да проектираш ресурсите и маршрутите на API-то
- как да реализираш сървър с `node:http`, база с `node:sqlite` и вход с `node:crypto`
- как да валидираш входа и да затвориш слабостите от предишните уроци
- как да напишеш тестове с `node:test` и кратък отчет
- как да предадеш код, тестове и инструкция за пускане

## Задание
Правиш „Бележник“: API, в което всеки потребител си води свои бележки. Потребителят се регистрира, влиза, създава, чете, променя и трие бележки и вижда само своите. Няма уеб страница; ползваш `curl` и тестове. Ако по-късно искаш интерфейс, свържи API-то с курса „JavaScript за уеб“.

Ограничения:
- само вградени модули: `node:http`, `node:sqlite`, `node:crypto`, `node:test`, `node:assert`, `node:fs`;
- Node.js 22 или по-нов;
- без външни пакети и без `npm install`;
- данните на примера са измислени; реални пароли и домейни не се ползват.

## Ресурси и маршрути
Проектирай преди да пишеш. Минималният набор:

| Метод и адрес | Какво прави | Успех | Типични грешки |
|---|---|---|---|
| `POST /register` | Създава потребител | 201 | 400, 409 |
| `POST /login` | Влиза и задава бисквитка | 200 | 401, 429 |
| `POST /logout` | Изтрива сесията | 200 | |
| `GET /me` | Кой съм аз | 200 | 401 |
| `GET /notes` | Моите бележки, по избор `?q=` за търсене | 200 | 401 |
| `POST /notes` | Нова бележка | 201 | 400, 401, 415 |
| `GET /notes/:id` | Една моя бележка | 200 | 401, 404 |
| `PUT /notes/:id` | Променя заглавие и текст | 200 | 400, 401, 404 |
| `DELETE /notes/:id` | Трие бележка | 204 | 401, 404 |

Бележката има `id`, `title` (1–100 знака), `body` (до 2000 знака), `created_at` и `updated_at`. Чужда бележка се третира като несъществуваща: отговорът е 404, за да не се издава, че такава има.

## Структура на проекта
Раздели кода така, че тестовете да стартират приложението без да заемат фиксиран порт:

```
belezhnik/
  package.json
  server.mjs        # само стартира сървъра
  app.mjs           # createApp(dbFile) връща http сървър
  auth.mjs          # hashPassword, verifyPassword, сесии
  notes.mjs         # заявки и логика за бележките
  validate.mjs      # проверка на входа
  app.test.mjs      # тестове за бележките
  auth.test.mjs     # тестове за вход
  README.txt        # инструкция за пускане и кратък отчет
```

Файлът `server.mjs` е кратък, а портът и файлът на базата идват от средата:

```js
import { createApp } from "./app.mjs";

const port = Number(process.env.PORT ?? 3000);
createApp(process.env.DB_FILE ?? "belezhki.db").listen(port, "127.0.0.1", () => console.log(`Слушам на порт ${port}`));
```

В `package.json` добави `"type": "module"` и два скрипта:

```json
{
  "name": "belezhki-api",
  "private": true,
  "type": "module",
  "scripts": {
    "start": "node server.mjs",
    "test": "node --test --test-reporter=spec"
  }
}
```

## Стъпка по стъпка
1. **Проектиране (за около 20 минути).** Нарисувай таблиците `users`, `sessions` и `notes`. Реши кои колони са `NOT NULL`, `UNIQUE` и кои имат `REFERENCES`. Запиши маршрутите и статусите в README.
2. **Данни.** Създай схемата в `createApp`. Всички заявки са подготвени веднъж и приемат параметри. Бележките се филтрират по `user_id` в самата заявка, а не след като са прочетени.
3. **Вход.** Регистрация с проверка на име и парола, хеш със `scrypt` и сол, сесия със случаен токен, пазен като хеш, бисквитка с `HttpOnly`, `SameSite=Lax` и `Max-Age`, ограничение на неуспешните опити. Използвай идеите от урока за пароли и сесии.
4. **Валидиране и защита.** Всичко във `validate.mjs`: тип, дължина, формат, лимит на тялото (413), `Content-Type` (415). Добави заглавията `X-Content-Type-Options: nosniff`, `Referrer-Policy` и `Content-Security-Policy`. Ако позволяваш CORS, ползвай списък от един произход. Грешките минават през единна обработка, която връща общо 500 без подробности.
5. **Тестове.** Виж следващия раздел.
6. **Отчет и предаване.** Допълни README.

## Тестове с node:test
Тестът стартира приложението на свободен порт (`0`), с база в паметта, праща заявки с вградения `fetch` и затваря сървъра. Ето работещ пример за бележки:

```js
import { test, before, after, describe } from "node:test";
import assert from "node:assert/strict";
import { createApp } from "./app.mjs";

let server, base;

before(async () => {
  server = createApp(":memory:");
  await new Promise((resolve) => server.listen(0, "127.0.0.1", resolve));
  base = `http://127.0.0.1:${server.address().port}`;
});

after(() => new Promise((resolve) => server.close(resolve)));

const postJson = (path, body) =>
  fetch(base + path, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(body) });

describe("бележки", () => {
  test("празен списък в началото", async () => {
    const res = await fetch(base + "/notes");
    assert.equal(res.status, 200);
    assert.deepEqual(await res.json(), []);
  });

  test("създаване връща 201 и записа", async () => {
    const res = await postJson("/notes", { title: "Първа", body: "Здравей" });
    assert.equal(res.status, 201);
    const note = await res.json();
    assert.equal(note.title, "Първа");
    assert.equal(typeof note.id, "number");
  });

  test("липсващо заглавие връща 400", async () => {
    const res = await postJson("/notes", { body: "без заглавие" });
    assert.equal(res.status, 400);
  });

  test("непозната бележка връща 404", async () => {
    const res = await fetch(base + "/notes/9999");
    assert.equal(res.status, 404);
  });
});
```

Примерът е за първоначален вариант на API без вход. Твоите тестове трябва да вземат бисквитка след `POST /login` и да я пращат нататък. Вземи я така: `res.headers.getSetCookie()[0].split(";")[0]` дава `sid=...`, което подаваш в заглавие `Cookie`. Изход с `npm test` за примера (с четири теста):

```
▶ бележки
  ✔ празен списък в началото (19.321792ms)
  ✔ създаване връща 201 и записа (9.467269ms)
  ✔ липсващо заглавие връща 400 (3.690976ms)
  ✔ непозната бележка връща 404 (1.362422ms)
✔ бележки (39.265154ms)
ℹ tests 4
ℹ pass 4
ℹ fail 0
```

Времената при теб ще са различни. Когато тестът очаква 200, а сървърът връща 404, той се проваля със съобщение `404 !== 200` (получено, очаквано), а отчетът показва `fail 1`. Само един тест можеш да пуснеш с `--test-name-pattern="създаване"`. Предупреждението за експериментален `node:sqlite` излиза и в тестовете; това е нормално.

Минимален набор тестове (поне 12):
- регистрация: успех (201), заето име (409), къса парола (400);
- вход: успех със бисквитка, грешна парола (401), шестият грешен опит (429);
- достъп до `/notes` без сесия (401) и след `logout` (401);
- създаване, четене, промяна и изтриване на бележка;
- потребител А не вижда и не променя бележка на потребител Б (404);
- празно заглавие, твърде дълго заглавие и счупен JSON (400);
- търсене с апостроф `?q=Д'Артанян` не дава грешка 500;
- паролата не се вижда в никой отговор.

Не забравяй, че редовете от `get()` и `all()` нямат прототип: при `assert.deepEqual` разгъни ги с `{ ...row }`. За да тестваш ограничението на опитите, направи прага конфигурируем през `createApp`.

## Критерии за оценка
Работата се оценява със 100 точки. Успешна е от 60 точки и без нито един от блокиращите проблеми по-долу.

| Критерий | Точки | Какво се проверява |
|---|---|---|
| Ресурси и маршрути | 20 | Всички маршрути от таблицата, верни методи, статус кодове и JSON |
| База и заявки | 15 | Схема с ограничения, подготвени заявки, данните оцеляват след рестарт |
| Вход и пароли | 20 | `scrypt` със сол, сесия с хеширан токен, правилна бисквитка, ограничение на опитите |
| Валидиране и защита | 15 | Валидиране с лимити, 413 и 415, заглавия, без изтичане на грешки |
| Тестове | 20 | Поне 12 теста, минават с `npm test`, покриват и грешните случаи |
| Структура и документация | 10 | Разделен код, README с инструкция, ясни имена |

Блокиращи проблеми, при които работата се връща за поправка:
- парола в явен вид в базата или в журнала;
- SQL заявка с входни данни, залепени в текста;
- потребител чете или променя чужда бележка;
- външен пакет или код, който не се стартира със зададената инструкция.

## Пример от практиката
Да кажем, че твоят тест „потребител А не вижда бележка на Б“ мине от първия път. Преди да се зарадваш, счупи го умишлено: махни `user_id` от заявката за четене и пусни тестовете пак. Ако те остават зелени, тестът не проверява нищо. Добрият тест пада, когато кодът е грешен.

## Чести грешки
- **Фиксиран порт в тестовете.** Ползвай порт `0`, иначе тестовете се бият със стар процес.
- **Тестове, които зависят от реалния файл на базата.** Ползвай `:memory:`.
- **Филтриране по потребител в кода, а не в заявката.** Лесно се забравя в някой маршрут.
- **Само „щастливи“ тестове.** Проверявай и 400, 401, 404, 409, 429.
- **Забравен сървър след тестовете.** Затваряй го в `after` и провери с `pgrep`, че няма останал процес.
- **Пускане на заявка преди края на `before`.** Изчакай `listen` с `Promise`.
- **README без точни команди.** Който го чете, трябва да пусне проекта за две минути.
