> **Цел на урока:** да пренапишеш структура и функции от C като клас на C++ и да разбереш какво добавят референциите, пространствата от имена и `std::string`.

## Какво ще научиш
- Как данните и функциите, които работят с тях, се събират в един клас с публична и частна част.
- Защо референцията е по-удобна и по-безопасна от указателя в повечето случаи.
- Как `namespace` разделя имена, които иначе биха се сблъскали.
- Как се ползват `std::string`, `std::cout` и `std::vector` вместо `char*`, `printf` и ръчни масиви.
- Как да четеш типичните съобщения за грешка на компилатора.

## Какво се променя, когато минаваш от C към C++

В C програмата е набор от функции и структури, които живеят отделно. Ти сам помниш, че `vec2_add` работи с `Vec2`, и сам внимаваш никой да не пипа полетата отвън. В C++ тези две неща се слепват в **клас (class)**: данните стоят заедно с функциите, които ги обработват, а компилаторът пази границите.

C++ не е „C с класове“. Почти всичко от C продължава да работи, но съвременният C++ го заменя със стандартни средства.

Всички примери са компилирани с `g++ -std=c++20 -Wall -Wextra`. Ако ползваш Clang (`clang++`), командата е същата. Предупрежденията са включени винаги: те хващат много грешки още преди пускане. Курсът се надгражда върху основите на C от „Програмиране от нулата“, модул 3.

### Началната точка: структура в C стил

Ето малка програма за двумерен вектор, написана така, както би я написал C програмист (само че върху C++ компилатор):

```cpp
#include <cstdio>
#include <cmath>

struct Vec2 { double x, y; };

Vec2 vec2_add(Vec2 a, Vec2 b) { return {a.x + b.x, a.y + b.y}; }
double vec2_len(Vec2 v) { return std::sqrt(v.x * v.x + v.y * v.y); }

int main() {
    Vec2 a{3, 4}, b{1, 2};
    Vec2 c = vec2_add(a, b);
    std::printf("c = (%.1f, %.1f), length %.3f\n", c.x, c.y, vec2_len(c));
}
```

Изход:

```
c = (4.0, 6.0), length 7.211
```

Работи, но има слабости. Всеки може да запише `c.x = -1`, без да мине през каквато и да е проверка. Функциите са разпилени и имената им носят префикс `vec2_`, за да не се бъркат с чужди. А `printf` не проверява типовете: ако напишеш `%d` за `double`, получаваш боклук, а не грешка.

## Клас: данни и методи заедно

Същото като клас:

```cpp
#include <iostream>
#include <cmath>

class Vec2 {
public:
    Vec2(double x, double y) : x_(x), y_(y) {}
    double x() const { return x_; }
    double y() const { return y_; }
    double length() const { return std::sqrt(x_ * x_ + y_ * y_); }
    Vec2 operator+(const Vec2& o) const { return Vec2(x_ + o.x_, y_ + o.y_); }
private:
    double x_, y_;
};

int main() {
    Vec2 a(3, 4), b(1, 2);
    Vec2 c = a + b;
    std::cout << "c = (" << c.x() << ", " << c.y() << "), length " << c.length() << '\n';
}
```

Изход:

```
c = (4, 6), length 7.2111
```

Какво се случва тук:

- **`public` и `private`.** Всичко след `public:` е достъпно отвън, всичко след `private:` е само за методите на класа. Полетата са частни, а отвън се четат през `x()` и `y()`. Договорът е ясен: никой не може да остави вектора в неконсистентно състояние.
- **Конструктор.** `Vec2(double x, double y)` се вика при създаването на обекта. Частта `: x_(x), y_(y)` е **списък за инициализация (member initializer list)** и задава стойностите на полетата, преди да започне тялото. Това е предпочитаният начин. Следващият урок се занимава изцяло с конструкторите.
- **`const` след метода.** `double length() const` обещава, че методът не променя обекта. Така можеш да го викаш и върху константни обекти.
- **`operator+`.** Можеш да дадеш на типа си оператори, така че `a + b` да работи. Това е синтактична захар над обикновен метод, но кодът се чете като математика.

Разликата между `struct` и `class` в C++ е само една: в `struct` членовете са по подразбиране публични, в `class` – частни. Затова за прости пакети от данни без правила се ползва `struct`, а за типове с инварианти (правила, които винаги трябва да са верни) – `class`.

### Какво казва компилаторът, ако нарушиш границата

Ако опиташ да прочетеш частно поле отвън:

```cpp
Vec2 a(3, 4);
std::cout << a.x_ << '\n';
```

G++ 13 отговаря:

```
error: 'double Vec2::x_' is private within this context
note: declared private here
```

Грешката е при компилиране, не при изпълнение: колкото повече правила проверява компилаторът, толкова по-малко проверяваш ти.

## Референции: псевдоним вместо указател

**Референцията (reference)** е второ име за вече съществуваща променлива. Записва се с `&` в типа. Сравни два начина да размениш две числа:

```cpp
void swap_ptr(int* a, int* b) { int t = *a; *a = *b; *b = t; }
void swap_ref(int& a, int& b) { int t = a; a = b; b = t; }

void inc_copy(int v) { v++; }
void inc_ref(int& v) { v++; }
```

При извикването `swap_ptr(&x, &y)` трябва да подадеш адреси, а вътре да разкрасяваш всичко със `*`. При `swap_ref(x, y)` пишеш като при обикновена функция. Пълната програма даде:

```
ptr: 2 1
ref: 1 2
copy: 10
ref:  11
bytes: 16
n = 42
```

`inc_copy` не променя `n`, защото работи върху копие. `inc_ref` го променя. Последните два реда са за `int& r = n; r = 42;` – `r` е просто друго име за `n`.

Разлики спрямо указателя:

| Свойство | Указател `T*` | Референция `T&` |
|---|---|---|
| Може да е „празен“ | да (`nullptr`) | не |
| Може да сочи другаде по-късно | да | не, свързва се веднъж |
| Нужен ли е `*` за достъп | да | не |
| Нужен ли е `&` при извикване | да | не |

Правилото за практиката: ако аргументът задължително съществува, ползвай референция. Указател ползвай само когато „няма обект“ е нормален отговор.

### const& – не копирай излишно

Голям обект не искаш да копираш при всяко извикване, но и не искаш функцията да го променя. Решението е **константна референция**:

```cpp
std::size_t count_letters(const std::string& s) { return s.size(); }
```

Нищо не се копира и функцията не може да промени `s`. Важно: `s.size()` връща **байтове**, не букви. За низа „Светлина“ резултатът е 16, защото всяка кирилска буква в UTF-8 заема два байта. Помни това, когато броиш символи на български.

Компилаторът пази и тук:

```cpp
void inc_ref(int& v) { v++; }
int main() {
    inc_ref(5);
    const int c = 3;
    int& r = c;
}
```

```
error: cannot bind non-const lvalue reference of type 'int&' to an rvalue of type 'int'
error: binding reference of type 'int&' to 'const int' discards qualifiers
```

Първата грешка казва: не можеш да промениш литерал `5`. Втората: не можеш да получиш променяема референция към константа. Ако видиш „discards qualifiers“, почти винаги ти липсва `const` някъде.

## Пространства от имена и стандартни типове

В голям проект две библиотеки могат да имат тип `Color`. В C решението са префикси. В C++ има **пространства от имена (namespace)**:

```cpp
#include <iostream>
#include <string>
#include <vector>

namespace gfx {
    struct Color { int r, g, b; };
    std::string to_hex(const Color& c) {
        const char* d = "0123456789abcdef";
        std::string s = "#";
        for (int v : {c.r, c.g, c.b}) { s += d[v / 16]; s += d[v % 16]; }
        return s;
    }
}
namespace audio {
    struct Color { int hue; };   // същото име, друг свят
}

int main() {
    gfx::Color c{255, 128, 0};
    audio::Color a{7};
    std::string name = "праг";
    name += " " + gfx::to_hex(c);
    std::cout << name << ", hue " << a.hue << ", size " << name.size() << '\n';
    std::vector<std::string> words{"един", "два", "три"};
    for (const auto& w : words) std::cout << w << ' ';
    std::cout << '\n';
    std::cerr << "това отива в stderr\n";
}
```

Изход:

```
праг #ff8000, hue 7, size 16
един два три 
това отива в stderr
```

Какво виждаш:

- `gfx::Color` и `audio::Color` са два различни типа. Двоеточията `::` са оператор за достъп до пространство от имена.
- Цялата стандартна библиотека живее в `std`. Затова пишем `std::string`, `std::cout`, `std::vector`.
- **`std::string`** е низ, който сам управлява паметта си. Слепваш с `+` и `+=`, питаш за дължина с `.size()`, не мислиш за терминиращ нула и за препълване на буфера.
- **`std::cout`** изписва през `<<`, а `std::cerr` е стандартният поток за грешки. Типовете се проверяват при компилиране.
- **`std::vector`** е динамичен масив, който сам расте (подробно в модул 1).
- **`for (const auto& w : words)`** е цикъл по диапазон. `auto` оставя компилатора да изведе типа, а `const&` избягва копирането.

Избягвай `using namespace std;` в заглавни файлове (`.h`/`.hpp`): наливаш всичките имена на стандартната библиотека във всеки файл, който ги включва, и рано или късно се сблъскваш с чуждо име. В малки `.cpp` файлове е приемливо, но като навик е по-добре да пишеш `std::`.

## Стъпка по стъпка: от C към C++

1. Вземи C структура и функциите ѝ, например `Particle` и `particle_update`.
2. Смени `struct` с `class`, а полетата направи `private` с суфикс `_`.
3. Замени функциите `particle_xxx(Particle* p, ...)` с методи. Параметърът-указател изчезва, защото обектът е `this`.
4. Постави `const` на всеки метод, който само чете.
5. Замени аргументите-указатели с `T&` или `const T&`, а `char*`/`printf` със `std::string`/`std::cout`.
6. Огради всичко в собствено `namespace` и компилирай с `-Wall -Wextra`.

## Пример от практиката

Да кажем, че пишеш малка програма за VJ визуал, която пази позиция и скорост на светеща точка. В C имаш `struct Dot` и пет функции с префикс `dot_`. Грешките откриваш чак на екрана.

В C++ правиш `class Dot` с частни `pos_` и `vel_` и метод `bounce()`, който сам решава кога да обърне скоростта. Отвън никой не може да остави точката извън платното, защото единственият път към полетата минава през методи, които проверяват. Грешките, които преди видеше на сцената, сега се хващат на компилатора или в първия тест.

## Чести грешки

- **Забравен `const` на метода.** Тогава не можеш да го викаш върху `const T&` и получаваш съобщението „discards qualifiers“. Слагай `const` по подразбиране и го махай само при нужда.
- **Голям обект по стойност.** `void draw(std::string s)` копира низа всеки път. Ползвай `const std::string&`.
- **Референция към локална променлива, върната от функция.** `int& f() { int x = 1; return x; }` връща псевдоним на нещо, което вече не съществува. Компилаторът обикновено предупреждава; не игнорирай предупреждението.
- **Смесване на `size()` с брой букви.** При UTF-8 `size()` брои байтове. За „Светлина“ е 16, не 8.

## Упражнение

Вземи тази C структура и пренапиши цялата програма в C++:

```c
struct Counter { int value; int step; };
void counter_init(struct Counter* c, int step);
void counter_tick(struct Counter* c);
int counter_get(const struct Counter* c);
```

Критерии за проверка:
- Имаш `class Counter` с частни полета `value_` и `step_` и конструктор със списък за инициализация.
- `tick()` променя обекта, `get()` е маркиран с `const`.
- Класът е в собствено пространство от имена (например `util`).
- Има функция `void print(const util::Counter&)`, която пише с `std::cout`, без да копира обекта.
- Програмата се компилира с `g++ -std=c++20 -Wall -Wextra` без предупреждения.

## Бърза справка

| Искаш | Пишеш |
|---|---|
| Частни данни, публичен интерфейс | `class X { public: ... private: ... };` |
| Метод, който не променя обекта | `int get() const;` |
| Втори псевдоним на променлива | `int& r = n;` |
| Подаване без копиране и без промяна | `const T&` |
| Име в пространство | `gfx::Color` |
| Низ, вектор, изход | `std::string`, `std::vector<T>`, `std::cout` |

## Обобщение

Класът събира данни и методи и позволява на компилатора да пази границите чрез `public` и `private`. Референцията е псевдоним, който не може да е празен, а `const T&` е стандартният начин за подаване на големи обекти без копиране. Пространствата от имена заместват префиксите от C, а `std::string`, `std::vector` и `std::cout` заместват ръчните буфери и `printf`. Следващият урок показва как класът поема отговорност за ресурсите си.
