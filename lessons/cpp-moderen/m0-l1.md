> **Цел на урока:** да напишеш клас-обвивка, който взема ресурс в конструктора и го освобождава в деструктора, и да знаеш кога да дефинираш копирането и преместването сам.

## Какво ще научиш
- Кога точно се викат конструкторът и деструкторът и в какъв ред.
- Какво е RAII и защо освобождаването става дори при изключение.
- Правилото на трите, петте и нулата.
- Защо копирането по подразбиране на клас с указател води до двойно освобождаване.
- Как да обвиеш `FILE*` в клас, който никога не изтича.

## Живот на обекта

Обектът в C++ има ясно начало и край. Началото е конструкторът, краят е **деструкторът (destructor)** – метод с име `~Име()`, който компилаторът вика автоматично, когато обектът излезе от обхват. Не го викаш ръчно.

Ето клас, който само показва кога се случва това:

```cpp
class Tracer {
public:
    explicit Tracer(std::string name) : name_(std::move(name)) {
        std::cout << "  + " << name_ << '\n';
    }
    ~Tracer() { std::cout << "  - " << name_ << '\n'; }
private:
    std::string name_;
};

void work(bool fail) {
    Tracer a("a");
    Tracer b("b");
    if (fail) throw std::runtime_error("neshto se schupi");
    std::cout << "  kraj na work\n";
}
```

В `main` викаме `work(false)`, а после `work(true)` в `try`/`catch`. Изход:

```
bez greshka:
  + a
  + b
  kraj na work
  - b
  - a
s greshka:
  + a
  + b
  - b
  - a
  hvanato: neshto se schupi
```

Забележи две неща. Първо, локалните обекти се унищожават в **обратен ред** на създаването: `b`, после `a`. Второ, при изключение деструкторите пак се извикват, преди изключението да стигне до `catch`. Това се нарича **разгъване на стека (stack unwinding)** и е основата на целия урок.

Ключовата дума `explicit` пред конструктор с един аргумент забранява неявно преобразуване (`Tracer t = "x";`). Слагай я по подразбиране на такива конструктори.

## RAII: ресурсът живее колкото обекта

**RAII** (Resource Acquisition Is Initialization) е идея, а не библиотека: ресурсът се взема в конструктора и се връща в деструктора. Ресурс е всичко, което трябва да се върне: памет, файл, ключалка, сокет, текстура в GPU.

В C пишеш `fopen` ... `fclose` и трябва да помниш `fclose` на всеки път за излизане: при ранен `return`, при грешка, при `goto cleanup`. В C++ това е задача на компилатора. Обвивка за файл:

```cpp
class File {
public:
    File(const std::string& path, const char* mode) : f_(std::fopen(path.c_str(), mode)) {
        if (!f_) throw std::runtime_error("ne moga da otvorya " + path);
    }
    ~File() { if (f_) { std::fclose(f_); std::puts("  (fclose)"); } }

    File(const File&) = delete;
    File& operator=(const File&) = delete;

    File(File&& o) noexcept : f_(std::exchange(o.f_, nullptr)) {}
    File& operator=(File&& o) noexcept {
        if (this != &o) {
            if (f_) std::fclose(f_);
            f_ = std::exchange(o.f_, nullptr);
        }
        return *this;
    }

    void write_line(const std::string& s) { std::fputs((s + "\n").c_str(), f_); }
private:
    std::FILE* f_;
};
```

Ако конструкторът не успее да отвори файла, хвърля изключение – така няма обект в „половин“ състояние. Използване:

```cpp
void log_and_fail(const std::string& path) {
    File f(path, "w");
    f.write_line("start");
    throw std::runtime_error("greshka po sredata");
}
```

В `main` извикваме `log_and_fail`, после опитваме да отворим несъществуваща папка, накрая местим един `File` в друг и пишем в него. Изход:

```
  (fclose)
hvanato: greshka po sredata
hvanato: ne moga da otvorya /nqma/takava/papka/x.txt
  (fclose)
```

Първият `(fclose)` се вика при разгъването на стека, преди да се изпише „хванато“. Файлът се затваря въпреки изключението, без нито един `try`/`finally` в `log_and_fail`. За втория опит няма `(fclose)`: конструкторът е хвърлил изключение, обектът никога не е бил създаден, така че деструкторът му не се вика. Последният `(fclose)` е краят на `main`: затваря се само `b`, защото `a` е празен след преместването. Файлът `out.txt` съдържа „start“ и „kraj“.

## Правилото на трите, петте и нулата

Какво става, ако класът държи сурова памет и оставиш копирането по подразбиране? Компилаторът генерира копиращ конструктор, който просто копира полетата. Указателят се копира, паметта – не.

```cpp
class Buffer {
public:
    explicit Buffer(std::size_t n) : n_(n), p_(new char[n]) { std::memset(p_, 0, n); }
    ~Buffer() { delete[] p_; }
private:
    std::size_t n_;
    char* p_;
};

int main() {
    Buffer a(16);
    Buffer b = a;      // копира указателя, не паметта
}
```

Компилира се без предупреждение. При изпълнение с `-fsanitize=address` (в GCC и Clang) получаваш:

```
ERROR: AddressSanitizer: attempting double-free on 0x502000000010 in thread T0:
    #1 0x... in Buffer::~Buffer() bad.cpp:7
    #2 0x... in main bad.cpp:17
```

И `a`, и `b` сочат към една и съща памет и двата деструктора я освобождават. Това е **двойно освобождаване (double free)**. Инструментите за откриване на такива грешки са същите като в C: AddressSanitizer и Valgrind.

От този проблем идват правилата:

| Правило | Какво казва |
|---|---|
| **Три** | Ако дефинираш деструктор, копиращ конструктор или копиращо присвояване, най-вероятно трябват и трите. |
| **Пет** | От C++11 към тях се добавят преместващ конструктор и преместващо присвояване. |
| **Нула** | По възможност не дефинирай нито едно: ползвай членове, които сами се грижат за себе си. |

Поправеният `Buffer` по правилото на петте:

```cpp
class Buffer {
public:
    explicit Buffer(std::size_t n) : n_(n), p_(new char[n]()) {}
    ~Buffer() { delete[] p_; }
    Buffer(const Buffer& o) : n_(o.n_), p_(new char[o.n_]) { std::copy(o.p_, o.p_ + n_, p_); }
    Buffer& operator=(const Buffer& o) {
        if (this != &o) { Buffer tmp(o); swap(tmp); }
        return *this;
    }
    Buffer(Buffer&& o) noexcept : n_(std::exchange(o.n_, 0)), p_(std::exchange(o.p_, nullptr)) {}
    Buffer& operator=(Buffer&& o) noexcept { swap(o); return *this; }
    void swap(Buffer& o) noexcept { std::swap(n_, o.n_); std::swap(p_, o.p_); }
    std::size_t size() const { return n_; }
private:
    std::size_t n_;
    char* p_;
};
```

С `Buffer a(16); Buffer b = a; Buffer c = std::move(a);` програмата изписва размерите `16 16 0` и минава чисто през AddressSanitizer. Копието има собствена памет, а `a` след преместването е празен, но валиден. Присвояването през копие и `swap` (идиомата copy-and-swap) е безопасно дори при изключение. Преместванията се маркират с `noexcept`, защото контейнерите като `vector` ги ползват само ако са сигурни, че не хвърлят. Подробно за преместването – в модул 1.

Всичко това е много код за една `char*`. Затова най-добрата версия е правилото на нулата:

```cpp
struct Track {
    std::string name;
    std::vector<float> samples;
};   // нито ctor, нито dtor, нито копиране
```

`std::string` и `std::vector` вече знаят да се копират и преместват. Компилаторът генерира правилното за `Track`. С `Track a{"kick", std::vector<float>(1000, 0.5f)}; Track b = a; Track c = std::move(a);` получаваме размери `1000 1000 0`: `b` е дълбоко копие, `c` е изтеглило данните от `a`. Пиши собствен деструктор само в класове, чиято единствена работа е да обвиват един ресурс, като `File` по-горе.

## Стъпка по стъпка: обвивка за ресурс

1. Определи ресурса и как се връща (`fclose`, `delete[]`, `unlock`).
2. Вземи го в конструктора. Ако не успее, хвърли изключение.
3. Върни го в деструктора и **никога не хвърляй** от него.
4. Реши за копирането: забрани го (`= delete`) или го реализирай като дълбоко копие.
5. Ако има смисъл, дай преместване, което оставя изходния обект празен.
6. Тествай с AddressSanitizer или Valgrind.

## Пример от практиката

Да кажем, че пишеш инструмент, който зарежда кадри за VJ клип от диск. Всяка функция отваря файл, чете заглавие и при невалиден формат излиза рано. В C ръчният `fclose` е на пет места и на шестото е забравен: след час работа стигаш до лимита на отворените файлове. С класа `File` излизането е по един ред и затварянето е гарантирано при всички пътища, включително при изключение от вложена функция.

## Чести грешки

- **Копиране на обвивка по подразбиране.** Води до двойно освобождаване. Забрани копирането с `= delete` или го дефинирай.
- **Хвърляне на изключение от деструктор.** Ако това стане по време на разгъване, програмата завършва с `std::terminate`.
- **Забравено `noexcept` на преместването.** Контейнерите тогава копират вместо да местят.
- **Използване на обект след `std::move`.** Позволено е само присвояване и деструктор. Не разчитай на съдържанието.
- **`new` и `delete` в обикновен код.** Ако сам пишеш `delete`, почти винаги има по-добро решение: контейнер или умен указател (следващите модули).

## Упражнение

Направи клас `ScopedFile`, който обвива `FILE*`.

Критерии:
- Конструкторът приема път и режим и хвърля `std::runtime_error`, ако `fopen` върне `nullptr`.
- Деструкторът затваря файла точно веднъж.
- Копирането е забранено, а преместването е реализирано и маркирано `noexcept`.
- Методът `write_line` пише ред. Добави и `const` метод, който връща дали файлът е отворен.
- Добави временен изход в деструктора и провери, че при `throw` вътре в блока се изписва веднъж.
- Пусни програмата през Valgrind (`valgrind --leak-check=full ./prog`) и виж „All heap blocks were freed“.

## Бърза справка

| Ситуация | Какво правиш |
|---|---|
| Обект с един ресурс | RAII клас: ctor взема, dtor връща |
| Копирането е опасно | `T(const T&) = delete;` |
| Може да се прехвърля собственост | преместващ ctor с `noexcept` |
| Класът само съдържа други RAII типове | правило на нулата |
| Откриване на двойно освобождаване | `-fsanitize=address`, Valgrind |

## Обобщение

Деструкторът се вика автоматично при излизане от обхват, в обратен ред, и също при разгъване на стека след изключение. RAII ползва това: ресурсът се взема в конструктора и се връща в деструктора, така че няма път, по който да се забрави. Ако класът обвива суров ресурс, трябва ясно да решиш какво значи копиране и преместване (правилото на петте), а най-добрият клас е онзи, който не се нуждае от нито едно от тях (правилото на нулата).
