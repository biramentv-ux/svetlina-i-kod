## Какво ще научиш
- Как един шаблон замества десетки копирани функции за различни типове.
- Как се четат съобщенията за грешка от шаблони.
- Как `concept` казва на компилатора какво изискваш от типа.
- Как работи улавянето в ламбдите: по стойност, по референция и с инициализация.
- Кога да ползваш `std::function` и кога шаблонен параметър.

## Шаблони: код, написан веднъж за много типове

В C за „по-голямото от две числа“ пишеш `max_int`, `max_double`, `max_float`, или се оправяш с макроси. В C++ описваш функцията веднъж, а компилаторът пише версиите, които наистина ползваш. Това е **шаблон (template)**.

```cpp
template <typename T>
T my_max(T a, T b) { return a < b ? b : a; }

template <typename T>
class Stack {
public:
    void push(T v) { data_.push_back(std::move(v)); }
    T pop() { T v = std::move(data_.back()); data_.pop_back(); return v; }
    bool empty() const { return data_.empty(); }
    std::size_t size() const { return data_.size(); }
private:
    std::vector<T> data_;
};
```

Употреба и изход:

```cpp
std::cout << my_max(3, 7) << ' ' << my_max(2.5, 1.5) << ' ' << my_max<std::string>("ab", "ac") << '\n';
Stack<std::string> s;
s.push("a"); s.push("b");
std::cout << s.pop() << s.pop() << ' ' << s.empty() << '\n';
```

```
7 2.5 ac
ba 1
```

- Компилаторът **извежда (deduces)** `T` от аргументите: `my_max(3, 7)` е `my_max<int>`. Можеш и да го посочиш: `my_max<std::string>`.
- Шаблонът на клас се ползва със скоби от типове: `Stack<std::string>`, `Stack<int>`. Всеки различен тип е отделен клас, създаден при компилиране. Нищо не се решава по време на изпълнение, затова няма загуба на скорост.
- Шаблонният код обикновено стои изцяло в заглавни файлове (`.h`/`.hpp`), защото компилаторът трябва да види тялото при създаването.

### Грешките от шаблони

Шаблонът има скрит договор: типът трябва да поддържа операциите, които кодът ползва. Тук `a < b`. Ако нарушиш договора:

```cpp
my_max(1, 2.5);
my_max(P{1}, P{2});   // struct P { int x; };
```

GCC 13 казва:

```
error: no matching function for call to 'my_max(int, double)'
note:   deduced conflicting types for parameter 'T' ('int' and 'double')
error: no match for 'operator<' (operand types are 'P' and 'P')
```

Първата грешка е ясна: `T` не може да е едновременно `int` и `double`. Решение: `my_max<double>(1, 2.5)`. Втората се вижда чак в **тялото** на шаблона, а в по-сложен код това означава десетки реда „необходимо от“. Именно за това са концепциите.

## Концепции (concepts) в C++20

**Концепцията** е име за множество изисквания към тип. Слагаш я там, където иначе би стояло `typename`, и компилаторът проверява договора още при извикването.

```cpp
#include <concepts>

template <typename T>
concept Number = std::integral<T> || std::floating_point<T>;

template <Number T>
constexpr T clamp_to(T v, T lo, T hi) {
    return v < lo ? lo : (v > hi ? hi : v);
}

static_assert(clamp_to(15, 0, 10) == 10);
static_assert(clamp_to(-3, 0, 10) == 0);
```

Извикани с `clamp_to(15, 0, 10)`, `clamp_to(0.5, 0.0, 1.0)`, `clamp_to(-1.5f, 0.0f, 1.0f)` и `clamp_to(7u, 1u, 5u)`, получаваме:

```
10 0.5 0 5
```

- `std::integral` и `std::floating_point` са готови концепции от `<concepts>`. Ние ги комбинираме с `||` в собствена, `Number`.
- `constexpr` позволява функцията да се изпълни при компилиране, а `static_assert` проверява резултата още там: ако е грешен, програмата не се компилира.
- Забележи `-1.5f` с граници `0.0f` и `1.0f`: резултатът е 0, защото е под долната граница.

Ако извикаш `clamp_to` със `std::string`, съобщението е кратко и казва точно проблема:

```
error: no matching function for call to 'clamp_to(std::string, std::string, std::string)'
note: candidate: 'template<class T>  requires  Number<T> T clamp_to(T, T, T)'
note: constraints not satisfied
note: no operand of the disjunction is satisfied
```

Прочита се така: „Number<T> не е изпълнено“. Не трябва да разчиташ нищо от тялото на функцията. Има и кратък запис без отделен `template`: `Number auto clamp_to(Number auto v, ...)`, но по-ясна за начало е формата с `template <Number T>`. Ако трябва да изискваш конкретна операция, ползвай `requires`: `requires(T a, T b) { a < b; }`.

## Ламбди и улавяне на променливи

**Ламбдата (lambda)** е безименна функция, която пишеш точно там, където я ползваш. Форма: `[улавяне](параметри) { тяло }`. Улавянето определя какво от околния обхват е достъпно вътре.

```cpp
std::vector<std::string> names{"kick", "snare", "hat", "clap"};
std::sort(names.begin(), names.end(),
          [](const std::string& a, const std::string& b) { return a.size() < b.size(); });

std::size_t threshold = 4;
auto longer = [threshold](const std::string& s) { return s.size() > threshold; };
std::cout << std::count_if(names.begin(), names.end(), longer) << " dalgi\n";
threshold = 100;   // копието в ламбдата не се променя
std::cout << std::count_if(names.begin(), names.end(), longer) << " dalgi sled promyana\n";
```

```
hat kick clap snare 
1 dalgi
1 dalgi sled promyana
```

`[threshold]` улавя **по стойност**: ламбдата си прави копие в момента на създаването. Затова промяната на `threshold` отвън не се вижда (резултатът остава 1, а не 0). При `[&threshold]` би се видяла, защото ламбдата държи референция.

| Улавяне | Значение |
|---|---|
| `[]` | нищо |
| `[x]` | `x` по стойност (копие) |
| `[&x]` | `x` по референция |
| `[=]` / `[&]` | всичко ползвано по стойност / по референция |
| `[n = 0]` | нова променлива, инициализирана при създаването (C++14) |

Още три техники:

```cpp
int calls = 0;
auto count_ref = [&calls](int) { ++calls; };
for (int i = 0; i < 5; ++i) count_ref(i);          // calls = 5

auto counter = [n = 0]() mutable { return ++n; };
counter(); counter();                               // третото извикване връща 3

auto add = [](auto a, auto b) { return a + b; };    // обобщена ламбда
```

- **`mutable`**: по подразбиране копие, уловено по стойност, е константно. С `mutable` ламбдата може да променя собственото си състояние. Тук `counter` връща 3 на третото извикване.
- **Обобщена ламбда (generic lambda)**: `auto` в параметрите прави шаблон. `add(1, 2)` дава 3, `add(1.5, 2.0)` дава 3.5, `add(std::string("a"), std::string("b"))` дава `ab`.
- **Улавяне с инициализация** (`n = 0`) може да премести ресурс в ламбдата: `[p = std::move(ptr)]`.

### Опасност: висящо улавяне

Ламбда, която излиза от функцията, не бива да държи референция към локална променлива:

```cpp
std::function<int()> make() {
    int local = 42;
    return [&local] { return local; };   // &local умира с функцията
}
```

Извикването `make()()` е недефинирано поведение: при нашето пускане изписа `21861`, но това не е гаранция за нищо, друг път може да се счупи или да „работи“. Излизащите ламбди улавят **по стойност**.

### std::function или шаблон?

`std::function<R(Args...)>` е тип, който пази всякакъв извикваем обект със същата сигнатура: ламбда, функция, метод. Удобен е за член на клас или за списък от обработчици, но има цена (допълнително извикване, често заделяне на памет). Когато само подаваш функция на друга и не я пазиш, шаблонен параметър е по-ефективен:

```cpp
template <typename F>
void repeat(int n, F f) { for (int i = 0; i < n; ++i) f(i); }
```

Измерването в нашата среда: `count_if` над 5 милиона числа с директна ламбда отне около 11 ms, а през `std::function` около 12 ms. Разликата тук е малка, защото операцията е проста; при по-кратка работа на извикване или по-голям брой извиквания разликата расте. Числата са ориентировъчни и зависят от машината.

## Пример от практиката

Да кажем, че в симулация на частици искаш да ограничаваш стойности: яркост между 0 и 1, позиция в рамките на екрана, брой частици между 0 и максимум. Една функция `clamp_to` с концепция `Number` покрива `float`, `double` и `int`, а при случайно извикване със `std::string` не се компилира. С ламбда избираш частиците за изтриване: `std::erase_if(p, [](const Particle& x) { return x.life <= 0; })`.

## Чести грешки

- **Шаблонът е в `.cpp` файл.** Компилаторът не вижда тялото при ползването и линкерът не намира функцията. Слагай шаблоните в заглавни файлове.
- **Смесени типове при извеждане.** `my_max(1, 2.5)` не се компилира; посочи `T` или направи типовете еднакви.
- **Улавяне на `[&]` в ламбда, която живее по-дълго.** Висящи референции, виж по-горе.
- **Очакване, че `[x]` следи промените.** Улавянето по стойност прави копие в момента на създаването.
- **Ненужно `std::function`.** Ползвай `auto` за локална ламбда и шаблонен параметър за подавана.

## Бърза справка

| Искаш | Пишеш |
|---|---|
| Функция за много типове | `template <typename T> T f(T x)` |
| Само числа | `template <Number T>` с `concept` |
| Проверка при компилиране | `static_assert(условие)` |
| Безименна функция | `[улавяне](параметри) { ... }` |
| Състояние в ламбда | `[n = 0]() mutable { return ++n; }` |
| Пазене на извикваем обект | `std::function<int(int)>` |
| Подаване на извикваем обект | шаблонен параметър `F` |

## Обобщение

Шаблонът описва код веднъж и компилаторът го създава за всеки ползван тип. Концепциите правят договора с типа явен и дават кратки, ясни грешки. Ламбдите носят логика на мястото на ползване, а видът на улавянето (по стойност, по референция, с инициализация) определя какво живее вътре. Пази се от референции към променливи, които ще изчезнат, и ползвай `std::function` само когато наистина трябва да запазиш функция.
