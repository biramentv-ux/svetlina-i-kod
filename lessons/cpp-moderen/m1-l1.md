> **Цел на урока:** да различаваш копиране от преместване и да изразяваш собственост върху паметта с `unique_ptr`, `shared_ptr` и `weak_ptr`.

## Какво ще научиш
- Какво са lvalue и rvalue и какво прави `std::move` всъщност.
- Как да видиш кога се копира и кога се мести.
- Кога да ползваш `unique_ptr`, кога `shared_ptr` и защо `weak_ptr` разкъсва цикли.
- Защо `new` и `delete` почти не се пишат в съвременен C++.
- Как да измериш разликата между копиране и преместване на голям `vector`.

## lvalue, rvalue и std::move

Всеки израз в C++ е или **lvalue** (има име и адрес, може да се използва пак: `a`), или **rvalue** (временна стойност, която скоро изчезва: `make()`, `5`, `a + b`). Това разграничение има практическа цел. Ако обектът така или иначе ще изчезне, не е нужно да копираш съдържанието му: можеш да му **вземеш** ресурсите. Това е преместването.

Класът, който може да се премества, има **преместващ конструктор** `T(T&&)`. Двойният амперсанд значи „референция към rvalue“. Да го проследим с клас, който пише какво му се случва:

```cpp
struct Noisy {
    std::string name;
    explicit Noisy(std::string n) : name(std::move(n)) { std::cout << "  ctor " << name << '\n'; }
    Noisy(const Noisy& o) : name(o.name) { std::cout << "  COPY " << name << '\n'; }
    Noisy(Noisy&& o) noexcept : name(std::move(o.name)) { std::cout << "  move -> " << name << '\n'; }
    ~Noisy() { std::cout << "  dtor [" << name << "]\n"; }
};

Noisy make() { return Noisy("from-make"); }
void sink(Noisy n) { std::cout << "  sink got " << n.name << '\n'; }
```

Основната програма прави пет неща: копира (`Noisy b = a`), мести (`Noisy c = std::move(a)`), връща от функция, подава с `std::move` на функция по стойност и слага временен обект във `vector`. Изход:

```
1) kopie:
  ctor a
  COPY a
2) premestvane:
  move -> a
   a.name sled move: ''
3) return ot funkciya:
  ctor from-make
4) sink(std::move(b)):
  move -> a
  sink got a
  dtor [a]
5) vector:
  ctor p
  move -> p
  dtor []
```

Чети го внимателно:

- **Ред 1:** `b = a` е копие, защото `a` е lvalue и може да се ползва по-късно.
- **Ред 2:** `std::move(a)` **не мести нищо**. Той само „преобразува“ израза в rvalue (`static_cast<T&&>`), за да избере компилаторът преместващия конструктор. Самото преместване прави конструкторът. След него `a.name` е празен низ: обектът е във валидно, но неопределено състояние.
- **Ред 3:** при `return Noisy(...)` няма нито копиране, нито преместване. Компилаторът конструира обекта директно на мястото на получателя (**елизия на копирането, copy elision**; от C++17 е гарантирана за временни обекти).
- **Ред 4:** параметърът на `sink` се строи с преместване от `b`.
- **Ред 5:** `push_back(Noisy("p"))` премества временния обект във вектора, а временният остава празен и се разрушава (`dtor []`).

### Правила, които да запомниш

- Не пиши `return std::move(x);` за локална променлива. Това **пречи** на елизията. GCC предупреждава: `moving a local object in a return statement prevents copy elision [-Wpessimizing-move]`. Просто пиши `return x;`.
- След `std::move(x)` използвай `x` само за присвояване на нова стойност или унищожаване.
- Ако класът ти следва правилото на нулата (предишния урок), преместването ти идва безплатно.

## Умни указатели: кой притежава паметта

**Умният указател (smart pointer)** е RAII обвивка около `new`. Всички са в `<memory>`.

| Тип | Собственост | Копира ли се | Цена |
|---|---|---|---|
| `std::unique_ptr<T>` | един собственик | не, само се мести | колкото сурово указател |
| `std::shared_ptr<T>` | много собственици, брояч | да | брояч (атомарен), допълнителен блок |
| `std::weak_ptr<T>` | наблюдава, не притежава | да | не пази обекта жив |

Малка програма с текстури показва различията:

```cpp
auto t = std::make_unique<Texture>(1);
use(*t);
take(std::move(t));                // собствеността се предава
std::cout << (t ? "ima" : "nyama") << " obekt\n";

auto s1 = std::make_shared<Texture>(2);
{
    auto s2 = s1;
    std::cout << "use_count = " << s1.use_count() << '\n';
}
std::cout << "use_count = " << s1.use_count() << '\n';
```

```
  texture 1 created
  use 1
  take 1
  texture 1 freed
nyama obekt
  texture 2 created
use_count = 2
use_count = 1
```

- `std::make_unique<T>(args...)` и `std::make_shared<T>(args...)` са предпочитаният начин за създаване. Не пишеш `new`, а изключенията не могат да оставят изтекъл обект.
- `take(std::move(t))` предава собствеността. Текстурата е освободена в края на `take`, а `t` остава празен.
- Броячът `use_count` се увеличава при копиране и намалява, когато копието излезе от обхват. Обектът се унищожава, когато стигне до нула.
- Функциите, които само **ползват** обекта, не приемат умен указател: приемат `const Texture&` (или `Texture*`, ако може да е празно), точно както `use`.

`unique_ptr` е по подразбиране. Той е толкова лек, колкото сурова указател, и се слага във `vector<std::unique_ptr<T>>`. Видя, че при унищожаване на вектора освобождаването става автоматично в реда на елементите.

`unique_ptr` приема и собствена функция за освобождаване. Така обвиваш и ресурс на C без да пишеш клас:

```cpp
std::unique_ptr<std::FILE, int(*)(std::FILE*)> f(std::fopen("p.txt", "w"), &std::fclose);
std::fputs("hello\n", f.get());
```

`f.get()` дава суровия указател за C функциите. Файлът се затваря сам при излизане.

### Кога да не ползваш shared_ptr

`shared_ptr` изглежда лесен („не мисля за собствеността“), но е най-често злоупотребяваният тип. Причини да го избягваш:

- Всяко копие променя брояч (обикновено атомарен): това е скъпо в горещи цикли и при много нишки.
- Скрива истинската собственост: никой не знае кога обектът наистина умира.
- **Циклите го превръщат в изтичане на памет.** Нека два възела се сочат взаимно със `shared_ptr`:

```cpp
struct Node { std::shared_ptr<Node> next; };
auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;
b->next = a;   // цикъл
```

Нито един от двата брояча не стига до нула. Пуснато с AddressSanitizer (който включва LeakSanitizer), завършва с `ERROR: LeakSanitizer: detected memory leaks` и посочва заделените блокове. Решението е едната посока да е `std::weak_ptr`:

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;
};
// ...
std::cout << a.use_count() << ' ' << b.use_count() << '\n';   // 1 2
if (auto p = b->prev.lock()) std::cout << "prev zhiv\n";
```

Изход: `1 2` и `prev zhiv`. Броячът на `a` е 1, защото `weak_ptr` не брои. За да ползваш обекта, викаш `lock()`: връща `shared_ptr`, който е празен, ако обектът вече е унищожен.

Правило: започвай с `unique_ptr`; `shared_ptr` ползвай само при истинска споделена собственост (например кеш на текстури, ползван от няколко независими системи); `weak_ptr` – за връзки назад и наблюдатели.

## Стъпка по стъпка: премахване на ръчната памет

1. Намери всеки `new` и всеки `delete` в кода.
2. Ако обектът е локален по смисъл, направи го обикновена променлива.
3. Ако трябва да е в купчината, ползвай `std::make_unique`.
4. Функциите, които само четат, да приемат `const T&`.
5. Ако наистина имаш много собственици, смени с `std::make_shared` и провери за цикли.
6. Пусни с `-fsanitize=address` и с Valgrind и потвърди, че няма изтичане.

## Пример от практиката

Да кажем, че пишеш кеш на текстури за VJ програма. Всяка сцена иска текстурата „fire.png“. С `std::shared_ptr<Texture>` кешът връща същия обект на всички сцени, а когато последната сцена приключи и кешът го пусне, текстурата се освобождава. Ако кешът пази `weak_ptr`, той не държи текстурата жива сам и можеш да я презаредиш при нужда. И в двата случая не пишеш нито един `delete`.

## Чести грешки

- **`std::move` върху `const` обект.** Резултатът е `const T&&` и пак се копира. Преместване не става.
- **`return std::move(local)`.** Пречи на елизията, видя предупреждението на GCC.
- **Два `shared_ptr` от един и същ суров указател.** Всеки има свой брояч и обектът се освобождава два пъти. Създавай `shared_ptr` само чрез `make_shared` или чрез копие на съществуващ.
- **Цикли от `shared_ptr`.** Изтичане, което няма да видиш без инструмент.
- **Предаване на `shared_ptr` по стойност навсякъде.** Приемай `const T&`, освен ако функцията наистина ще запази собствеността.

## Бърза справка

| Ситуация | Инструмент |
|---|---|
| Един собственик | `std::unique_ptr` + `make_unique` |
| Много собственици | `std::shared_ptr` + `make_shared` |
| Връзка назад, кеш наблюдател | `std::weak_ptr` и `lock()` |
| Функция само ползва обекта | `const T&` |
| Предаване на собственост | `f(std::move(p))` |
| Обвивка на C ресурс | `unique_ptr` със собствен deleter |

## Обобщение

Преместването прехвърля ресурсите на временен или вече ненужен обект вместо да ги копира, а `std::move` само го разрешава. Умните указатели правят собствеността ясна: `unique_ptr` за един собственик, `shared_ptr` за много, `weak_ptr` за наблюдение и разкъсване на цикли. Ръчни `new` и `delete` в обикновен код не ти трябват. Същата идея за собствеността е в центъра на Rust (курсът „Rust от нулата“).
