> **Цел на урока:** да разбереш производната като наклон, градиента като вектор от частни производни и да проверяваш всяка производна числено.

## Какво ще научиш
- Какво е производна и как се чете като наклон
- Как се пресмята производна числено с малка стъпка
- Какво са частни производни и градиент
- Защо градиентът сочи към най-бързия растеж и как да го използваш за намаляване на функция
- Как да направиш числена проверка на градиент, която ще ползваш през целия курс

## Производната като наклон
Обучението на невронна мрежа е търсене на числа (тегла), при които грешката е малка. За да знаеш в коя посока да променяш теглото, ти трябва отговор на въпроса: „Ако увелича това число съвсем малко, грешката нараства или намалява и колко бързо?“ Този отговор е **производната**.

Представи си функцията `f(x) = x**2`. Графиката ѝ е парабола. В точката x = 1 тя се изкачва: ако преместиш x малко надясно, f расте. В точката x = -3 слиза: ако преместиш x надясно, f намалява. В точка x = 0 е на дъното и е плоска.

Производната в точка е **наклонът на допирателната** към графиката: колко единици расте f при единица промяна на x, когато стъпката е безкрайно малка. За `x**2` производната е `2*x` (това правило ще го приемем, без доказателство). Така:

- при x = 1 наклонът е 2 (расте),
- при x = -3 наклонът е -6 (намалява, и то стръмно),
- при x = 0 наклонът е 0 (дъно).

Знакът казва посоката, а големината казва стръмнината. Това е всичко, което ще ни трябва.

## Числена проверка с малка стъпка
Наклонът може да се приближи без никаква теория: вземаш две близки точки и делиш разликата на стойностите на разликата на аргументите. Най-точният начин е **централната разлика**:

```
f'(x) ~ (f(x + h) - f(x - h)) / (2 * h)
```

където `h` е много малка стъпка, например `1e-5`. Ето я в код, сравнена с правилото `2*x`:

```python
import numpy as np
f = lambda x: x**2
def num_deriv(f, x, h=1e-5):
    return (f(x + h) - f(x - h)) / (2 * h)
for x in [-3.0, 0.0, 1.0, 2.5, 10.0]:
    print(x, 2 * x, round(num_deriv(f, x), 6))
```

```
-3.0 -6.0 -6.0
0.0 0.0 0.0
1.0 2.0 2.0
2.5 5.0 5.0
10.0 20.0 20.0
```

Втората колона е формулата, третата е числената оценка. Съвпадат. Тази идея е толкова полезна, че ще я ползваш като **контрол**: когато изведеш производна на ръка, винаги я сверявай с числената.

Колко малка трябва да е `h`? Не колкото може по-малка. Сравни грешките на двата варианта (напред: `(f(x+h) - f(x)) / h`, и централна разлика) за функцията синус в x = 1, където истинската производна е косинус:

```python
x0 = 1.0
for h in [1e-1, 1e-3, 1e-5, 1e-8, 1e-12]:
    fw = (np.sin(x0 + h) - np.sin(x0)) / h
    ce = (np.sin(x0 + h) - np.sin(x0 - h)) / (2 * h)
    print(f"h={h:.0e}  напред={abs(fw - np.cos(x0)):.1e}  централно={abs(ce - np.cos(x0)):.1e}")
```

```
h=1e-01  напред=4.3e-02  централно=9.0e-04
h=1e-03  напред=4.2e-04  централно=9.0e-08
h=1e-05  напред=4.2e-06  централно=1.1e-11
h=1e-08  напред=3.0e-09  централно=2.6e-09
h=1e-12  напред=4.3e-05  централно=1.2e-05
```

Две неща личат ясно. Първо, централната разлика е много по-точна при същото `h`. Второ, при твърде малко `h` грешката започва да **расте**: компютърът пази числата с краен брой цифри и когато извадиш две почти равни числа, губиш значещите цифри. Затова за числена проверка се избира `h` около `1e-5` до `1e-6`.

## Частни производни и градиент
Невронната мрежа няма една променлива, а милиони тегла. Функцията има много входове, а резултатът ѝ (грешката) е едно число. Тогава питаме за всеки вход поотделно: „Ако променя само този, как реагира резултатът?“ Отговорът е **частната производна** по него: другите променливи се държат като константи.

Нека `f(x, y) = x**2 + 3*y**2 + x*y`. Частната производна по x третира y като константа и дава `2*x + y`. Частната по y дава `6*y + x`. Редим двете числа в един вектор и получаваме **градиента**:

```
градиент(f) = [ 2*x + y,  6*y + x ]
```

В точката (1, 2) градиентът е [4, 13]. Ето го в код заедно с общата функция за числен градиент, която обхожда вход по вход:

```python
def f(p):
    x, y = p
    return x**2 + 3*y**2 + x*y
def grad_analytic(p):
    x, y = p
    return np.array([2*x + y, 6*y + x])
def num_grad(f, p, h=1e-6):
    g = np.zeros_like(p)
    for i in range(len(p)):
        d = np.zeros_like(p)
        d[i] = h
        g[i] = (f(p + d) - f(p - d)) / (2 * h)
    return g
p = np.array([1.0, 2.0])
print(grad_analytic(p), num_grad(f, p).round(6))
```

```
[ 4. 13.] [ 4. 13.]
```

Функцията `num_grad` работи за всяка `f`, която приема масив и връща число. Ще я използваш пак и пак.

## Накъде сочи градиентът
Основното свойство на градиента е, че сочи в посоката на **най-бързо нарастване** на функцията. Обратният вектор, `-градиент`, сочи към най-бързо намаляване. Проверка с малка стъпка 0,01 от същата точка:

```python
g = grad_analytic(p)
print(round(f(p), 4), round(f(p - 0.01 * g), 4), round(f(p + 0.01 * g), 4))
```

```
15.0 13.2075 16.9075
```

От 15,0 надолу срещу градиента получаваме 13,2075, а по градиента – 16,9075. Това е цялата идея на градиентното спускане, което ще направиш в следващия урок: да вървиш срещу градиента, докато загубата спре да намалява.

Дължината на градиента (`np.linalg.norm(g)`, тук около 13,6) показва колко е стръмно. Близо до дъното тя е почти нула, затова стъпките там стават малки.

## Справочна таблица

| Понятие | Значение | Как се проверява |
|---|---|---|
| Производна | Наклон на функция на една променлива | `(f(x+h) - f(x-h)) / (2*h)` |
| Частна производна | Наклон по една променлива, другите са константи | Променяш само един вход |
| Градиент | Вектор от всички частни производни | `num_grad(f, p)` |
| `-градиент` | Посока на най-бързо намаляване | `f(p - малка_стъпка * g)` е по-малко |
| Дължина на градиента | Колко стръмно е мястото | `np.linalg.norm(g)` |

## Стъпка по стъпка
Как да проверяваш производна, която си изкарал на ръка:

1. Запиши функцията като Python функция, която приема масив.
2. Запиши ръчно изведения градиент като втора функция.
3. Изчисли `num_grad` в същата точка с `h` около `1e-6`.
4. Сравни двата вектора с `np.allclose(a, b, atol=1e-6)` или виж най-голямата разлика.
5. Повтори в няколко случайни точки от `default_rng(0)`, не само в една.
6. Ако има разминаване, провери най-напред знаците и липсващите множители.

Така за всяка нова формула ще имаш доказателство, а не просто чувство, че е вярна.

## Пример от практиката
Да кажем, че имаш модел с едно тегло `w`, който предсказва `w * x`, и грешка за един пример `(w * 3 - 6) ** 2`. Търсиш такова `w`, че предсказанието да е 6. При `w = 0` грешката е 36. Числената производна по `w` е около -36, значи грешката намалява, когато `w` расте. Правилото (производна на `(w*3 - 6)**2` е `2*(w*3 - 6)*3`) дава същото число. Така знаеш в коя посока да поправиш `w` и колко голяма да е промяната, без да гадаеш.

## Чести грешки
- **Твърде малко `h`** – при `1e-12` грешката е по-голяма, отколкото при `1e-5`. Не търси „най-малкото“ `h`.
- **Бъркане на производна и стойност** – производната в точка е число за наклона, а не стойността на функцията.
- **Забравяне на знака** – за намаляване на функцията се върви срещу градиента. Знакът плюс увеличава грешката.
- **Проверка в една точка** – формула с грешка може да съвпадне в точка като (0, 0). Тествай в няколко случайни точки.
- **Промяна на входния масив на място** – в `num_grad` правим копие чрез `p + d`. Ако промениш `p` директно и не го върнеш, всички следващи оценки са грешни.

4. Допълнително: за `f(x, y) = x*y + y**2` изведи градиента на ръка (`[y, x + 2*y]`) и го провери с `num_grad` в пет случайни точки.

Критерии: всички разлики са по-малки от `1e-8`; можеш да кажеш на глас какво означава положителна, отрицателна и нулева производна.

## Бърза справка
- Централна разлика: `(f(x + h) - f(x - h)) / (2 * h)`, `h` около `1e-5`.
- Градиент: вектор от частни производни; сочи към растежа.
- Намаляване: `p - стъпка * g` с малка стъпка.
- Проверка: `np.allclose(ръчен, числен, atol=1e-6)` в няколко точки.
- Производната на `x**2` е `2*x`; на `sin` е `cos`.

## Обобщение
Производната е наклонът на функцията, а градиентът събира наклоните по всички входове в един вектор, който сочи към най-бързото нарастване. Числената оценка с централна разлика ти дава безплатна проверка на всяка формула, стига `h` да не е нито твърде голямо, нито твърде малко. В следващия урок ще направиш стъпки срещу градиента и ще обучиш първия си модел. Пътеката `programirane-ot-nulata` е добра опора, ако ти трябва опресняване на функциите и циклите в Python.
