> **Цел на урока:** да събереш fork, exec, dup2 и pipe в един работещ мини shell, който изпълнява команди, пренасочва вход и изход и свързва команди в конвейер.

## Какво ще научиш
- Как се разделя редът на лексеми и се подрежда в команди
- Как `dup2` реализира пренасочванията `<`, `>` и `>>`
- Как `pipe` и `fork` строят конвейер от произволна дължина
- Защо `cd` и `exit` трябва да са вградени команди
- Защо неполученият край на канал спира програмата завинаги

## Как работи един shell

Обвивката върти един и същ цикъл: изписва покана, чете ред, разбира го, изпълнява го, събира кода на изход и започва наново. Всичко нужно вече го знаеш от предишните два урока: `fork`, `execvp`, `waitpid` и файловите дескриптори. Остава да ги свържем.

| Стъпка | Какво прави | Функция в кода |
|---|---|---|
| Лексикален анализ | реже реда на думи и оператори | `tokenize` |
| Разбор | групира думите в команди | `parse` |
| Подготовка на дете | пренасочва дескрипторите | `child` |
| Изпълнение | създава процеси и ги чака | `run` |
| Вградени команди | `cd`, `exit` | `main` |

Програмата е около 145 реда. Ще я разгледаме по части; сглобена в един файл `msh.c`, тя се компилира без предупреждения с `gcc -Wall -Wextra`.

## Заглавни файлове и структурата за команда

Една команда е масив от аргументи плюс по-избрани файлове за вход и изход:

```c
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/wait.h>
#include <unistd.h>

#define MAXARGS 64
#define MAXCMDS 16

typedef struct {
    char *argv[MAXARGS];
    char *in, *out;     /* имена за < и > / >> */
    int append;
} Cmd;
```

## Стъпка 1: от ред до команди

Лексерът реже по интервали, но разпознава `|`, `<`, `>`, `>>` като отделни лексеми дори без интервали около тях, и пази целите низове в двойни или единични кавички. Той **променя реда на място**: на мястото на всеки разделител записва `\0`, така лексемите са указатели в същия буфер.

```c
/* Разделя реда на лексеми по интервали; поддържа "..." и '...' */
static int tokenize(char *line, char **tok, int max) {
    int n = 0;
    char *p = line;
    while (*p) {
        while (*p == ' ' || *p == '\t' || *p == '\n') p++;
        if (!*p) break;
        if (n >= max - 1) return -1;
        if (*p == '|' || *p == '<') { tok[n++] = (*p == '|') ? "|" : "<"; *p++ = 0; continue; }
        if (*p == '>') {
            if (p[1] == '>') { tok[n++] = ">>"; *p = 0; p += 2; }
            else { tok[n++] = ">"; *p++ = 0; }
            continue;
        }
        if (*p == '"' || *p == '\'') {
            char q = *p++;
            tok[n++] = p;
            while (*p && *p != q) p++;
            if (!*p) return -2;           /* незатворена кавичка */
            *p++ = 0;
        } else {
            tok[n++] = p;
            while (*p && !strchr(" \t\n|<>", *p)) p++;
            if (*p == ' ' || *p == '\t' || *p == '\n') *p++ = 0;
        }
    }
    tok[n] = NULL;
    return n;
}
```

Разборът обхожда лексемите. Операторът `|` затваря текущата команда и започва нова, а `<`, `>` и `>>` взимат следващата лексема за име на файл. Празна команда около `|` е синтактична грешка:

```c
/* Подрежда лексемите в команди; връща броя или -1 при синтактична грешка */
static int parse(char **tok, int n, Cmd *cmds) {
    int c = 0, a = 0;
    memset(&cmds[0], 0, sizeof(Cmd));
    for (int i = 0; i < n; i++) {
        char *t = tok[i];
        if (strcmp(t, "|") == 0) {
            if (a == 0 || c + 1 >= MAXCMDS) return -1;
            cmds[c].argv[a] = NULL;
            c++; a = 0;
            memset(&cmds[c], 0, sizeof(Cmd));
        } else if (!strcmp(t, "<") || !strcmp(t, ">") || !strcmp(t, ">>")) {
            if (i + 1 >= n) return -1;
            char *f = tok[++i];
            if (t[0] == '<') cmds[c].in = f;
            else { cmds[c].out = f; cmds[c].append = (t[1] == '>'); }
        } else {
            if (a >= MAXARGS - 1) return -1;
            cmds[c].argv[a++] = t;
        }
    }
    if (a == 0) return n == 0 ? 0 : -1;
    cmds[c].argv[a] = NULL;
    return c + 1;
}
```

## Стъпка 2: пренасочване с dup2

`dup2(стар, нов)` прави дескриптора `нов` да сочи към същото като `стар` (затваря `нов`, ако е бил отворен). За `echo тест > f.txt` детето отваря `f.txt`, пренасочва го върху дескриптор 1 с `dup2` и затваря излишния оригинал. После `execvp` стартира `echo`, който пише на дескриптор 1, без да подозира, че това е файл. Пренасочванията се правят **в детето**, между `fork` и `exec`, затова не променят самия shell.

```c
static void child(Cmd *cmd, int in_fd, int out_fd, int *pipes, int npipes) {
    if (in_fd != 0)  { dup2(in_fd, 0);  }
    if (out_fd != 1) { dup2(out_fd, 1); }
    for (int i = 0; i < npipes * 2; i++) close(pipes[i]);   /* всички краища на канали */
    if (cmd->in) {
        int fd = open(cmd->in, O_RDONLY);
        if (fd < 0) { fprintf(stderr, "msh: %s: %s\n", cmd->in, strerror(errno)); _exit(1); }
        dup2(fd, 0); close(fd);
    }
    if (cmd->out) {
        int flags = O_WRONLY | O_CREAT | (cmd->append ? O_APPEND : O_TRUNC);
        int fd = open(cmd->out, flags, 0644);
        if (fd < 0) { fprintf(stderr, "msh: %s: %s\n", cmd->out, strerror(errno)); _exit(1); }
        dup2(fd, 1); close(fd);
    }
    execvp(cmd->argv[0], cmd->argv);
    fprintf(stderr, "msh: %s: %s\n", cmd->argv[0], strerror(errno));
    _exit(errno == ENOENT ? 127 : 126);
}
```

Кодът за изход при неуспех на `exec` следва обичая: 127 за липсваща команда, 126 за команда без право за изпълнение.

## Стъпка 3: конвейерът

`pipe(fd)` създава канал с два края: `fd[0]` за четене и `fd[1]` за запис. За конвейер от `n` команди са нужни `n-1` канала. Команда `i` чете от канала преди нея и пише в канала след нея. Първата чете от стандартния вход, последната пише на стандартния изход.

За `ls -l | wc -l` процесите са два: `ls` с дескриптор 1, пренасочен към писащия край, и `wc` с дескриптор 0, пренасочен към четящия край. След `dup2` всеки процес трябва да затвори **всички** краища на каналите, а родителят също ги затваря, след като е създал децата:

```c
static int run(Cmd *cmds, int n) {
    int pipes[2 * MAXCMDS];
    pid_t pids[MAXCMDS];
    for (int i = 0; i < n - 1; i++)
        if (pipe(pipes + 2 * i) < 0) { perror("pipe"); return 1; }
    fflush(NULL);
    for (int i = 0; i < n; i++) {
        pids[i] = fork();
        if (pids[i] < 0) { perror("fork"); break; }
        if (pids[i] == 0) {
            int in_fd  = (i == 0)     ? 0 : pipes[2 * (i - 1)];
            int out_fd = (i == n - 1) ? 1 : pipes[2 * i + 1];
            child(&cmds[i], in_fd, out_fd, pipes, n - 1);
        }
    }
    for (int i = 0; i < 2 * (n - 1); i++) close(pipes[i]);  /* родителят не ползва каналите */
    int last = 0;
    for (int i = 0; i < n; i++) {
        int st;
        if (pids[i] < 0) continue;
        while (waitpid(pids[i], &st, 0) < 0 && errno == EINTR) { }
        if (i == n - 1)
            last = WIFEXITED(st) ? WEXITSTATUS(st) : 128 + WTERMSIG(st);
    }
    return last;
}
```

Родителят чака всички деца, а кодът на изход на конвейера е на **последната** команда, както в повечето обвивки (ако е убита от сигнал, ползваме `128 + сигнала`).

## Стъпка 4: cd и exit са вградени

Ако `cd` се изпълни в дете, то ще смени папката си и ще излезе – родителят остава на мястото си. Затова `cd` и `exit` се обработват от самия shell, преди да стигнем до `fork`:

```c
int main(void) {
    char line[1024];
    int status = 0;
    int tty = isatty(0);
    for (;;) {
        if (tty) { printf("msh> "); fflush(stdout); }
        if (!fgets(line, sizeof line, stdin)) break;
        char *tok[MAXARGS * 2];
        Cmd cmds[MAXCMDS];
        int nt = tokenize(line, tok, MAXARGS * 2);
        if (nt < 0) { fprintf(stderr, "msh: синтактична грешка\n"); status = 2; continue; }
        if (nt == 0) continue;
        int nc = parse(tok, nt, cmds);
        if (nc < 0) { fprintf(stderr, "msh: синтактична грешка\n"); status = 2; continue; }
        if (nc == 1 && strcmp(cmds[0].argv[0], "exit") == 0) break;
        if (nc == 1 && strcmp(cmds[0].argv[0], "cd") == 0) {
            const char *dir = cmds[0].argv[1] ? cmds[0].argv[1] : getenv("HOME");
            if (!dir || chdir(dir) < 0) { fprintf(stderr, "msh: cd: %s\n", strerror(errno)); status = 1; }
            else status = 0;
            continue;
        }
        status = run(cmds, nc);
    }
    return status;
}
```

## Проба

С празна папка и три файла `a`, `b`, `c` подаваме на `msh` следното:

```text
ls -l | wc -l
echo тест > f.txt
cat f.txt
echo втори ред >> f.txt
wc -l < f.txt
cat f.txt | sort -r | head -n 1
ls | sort -r | head -n 2
echo "две  думи в кавички"
```

Изходът е:

```text
4
тест
2
тест
f.txt
c
две  думи в кавички
```

Четири реда в първия резултат са „total“ и трите файла. Кодовете на изход (получени чрез `echo ... | ./msh; echo $?`):

| Команда | Код |
|---|---|
| `sh -c 'exit 5'` | 5 |
| `nonexist` (`msh: nonexist: No such file or directory`) | 127 |
| `true \| false` | 1 |
| `false \| true` | 0 |

Синтактичните грешки (`ls |`, `> f`, `echo a >`) дават `msh: синтактична грешка`. Програмата изпълни и `cat big.txt | cat | wc -c` върху файл от 3 000 000 байта с правилен резултат `3000000`.

## Какво става, ако не затвориш краищата

Махнем ли реда, в който родителят затваря каналите, `ls | wc -l` **увисва**. Същото прави `yes | head -n 2`: отпечатва `y y`, но `timeout` го спира след 3 секунди с код 124. Причината е, че `wc` чака край на входа, а той настъпва само когато **всички** писащи краища на канала са затворени. Родителят държи един отворен, затова четецът вечно чака. Обратно, ако читателят излезе, а някой друг държи четящия край, писачът не получава `SIGPIPE` и не спира.

Правило: всеки процес затваря краищата, които не ползва, възможно най-рано.

## Пример от практиката

Да кажем, че искаш `msh` да подава дневника на сървъра през `grep ГРЕШКА | sort | uniq -c`. Три команди значат два канала и четири затворени дескриптора във всяко дете. Ако дневникът е голям, виждаш важното свойство на канала: той има ограничен буфер, затова `grep` спира, когато `sort` още не чете. Процесите работят едновременно, а не един след друг – затова родителят трябва да чака всички и да не чете канала сам.

## Чести грешки

- **Незатворен край на канал** – конвейерът увисва или не получава край на данните.
- **`cd` в дете** – няма ефект върху shell-а.
- **Липсващ `_exit` след неуспешен `exec`** – детето продължава да изпълнява кода на shell-а.
- **Чакане само на последната команда** – останалите стават зомбита, докато shell-ът работи.
- **Промяна на дескрипторите в родителя** – по-късните команди наследяват чуждото пренасочване; прави го в детето.
- **Пропуснат `fflush(NULL)` преди `fork`** – буферираният текст излиза два пъти.
- **Неограничено копиране в буфери** – проверявай лимитите на аргументите и командите.

## Упражнение

Реализирай `msh` така, че да изпълнява `ls -l | wc -l` и `echo тест > f.txt` (задачата на урока).

1. Напиши разделянето на ред, разбора и `child`/`run` стъпка по стъпка и тествай всяка отделно.
2. Добави вградената команда `pwd` и променлива за последния код: `echo $?` да печата кода на последната команда.
3. Добави пренасочване на грешките с `2>` (разпознай лексемата и пренасочи дескриптор 2).
4. Провери програмата с `valgrind` и с `strace -f`.

Критерии:
- `ls -l | wc -l`, `echo тест > f.txt`, `cat < f.txt` и тройният конвейер работят;
- кодовете на изход съвпадат с таблицата;
- `valgrind` не показва изтичане и невалидни достъпи;

## Бърза справка

| Нужда | Решение |
|---|---|
| Пренасочи изход във файл | `open` + `dup2(fd, 1)` + `close(fd)` в детето |
| Добавяне в края | `O_WRONLY \| O_CREAT \| O_APPEND` |
| Конвейер от n команди | `n-1` канала, `dup2` към краищата, затвори всички |
| Вградена команда | изпълнява се в shell-а, без `fork` |
| Код на конвейер | кодът на последната команда |
| Команда не е намерена | код 127 |

## Обобщение

Мини shell е цикъл върху три идеи: `fork`+`exec` стартират програми, `dup2` пренасочва техните дескриптори, а `pipe` свързва изхода на една с входа на друга. Редът има значение: пренасочванията се правят в детето, между `fork` и `exec`, а всички ненужни краища на каналите се затварят навсякъде. `cd` и `exit` са вградени, защото засягат самия shell. Този модел стои под обвивката, с която работиш всеки ден.
