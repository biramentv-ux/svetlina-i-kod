## Какво ще построим

В урока за файлове четеше CSV, а в предишния написа тестове за функция. Сега свързваме всичко в **инструмент за командния ред (command-line tool, CLI)** – програма, която се пуска с аргументи от терминала, както `git` или `ls`. Ще я наречем `csvsum`: тя взема CSV файл, групира редовете по една колона и показва брой и сума по друга колона.

Пример: имаме `expenses.csv` с разходи:

```
дата,категория,сума
2026-03-01,храна,12.50
2026-03-02,транспорт,8
2026-03-03,храна,"7,30"
2026-03-04,кафе,3.20
2026-03-05,храна,20
```

Искаме да напишем `python3 csvsum.py expenses.csv --by категория --value сума` и да получим обобщение. Забележи, че една сума е с десетична запетая – така пишат много български таблици.

Ключовото решение е да **разделим логиката от входа/изхода**. Функциите `read_rows`, `summarize`, `render_table` и `render_json` работят със стойности и могат да се тестват лесно. Функцията `main` само чете аргументите и ги свързва. Така не тестваш „терминала“, а обикновени функции.

## Стъпка 1: логиката

Започваме с четенето и обобщаването:

```python
"""csvsum – обобщава CSV файл по колона."""
import argparse
import csv
import json
import sys


class CsvSumError(Exception):
    """Грешка с вход, която показваме на потребителя без трасировка."""


def read_rows(path):
    try:
        with open(path, encoding="utf-8-sig", newline="") as f:
            return list(csv.DictReader(f))
    except FileNotFoundError:
        raise CsvSumError(f"няма такъв файл: {path}") from None


def summarize(rows, group_col, value_col):
    """Връща {група: {"count": брой, "sum": сума}}."""
    result = {}
    for number, row in enumerate(rows, start=2):  # ред 1 е заглавният
        for col in (group_col, value_col):
            if col not in row:
                raise CsvSumError(f"няма колона {col!r}; налични: {', '.join(row)}")
        try:
            value = float(row[value_col].replace(",", "."))
        except ValueError:
            raise CsvSumError(
                f"ред {number}: {row[value_col]!r} не е число"
            ) from None
        group = result.setdefault(row[group_col], {"count": 0, "sum": 0.0})
        group["count"] += 1
        group["sum"] += value
    for group in result.values():
        group["sum"] = round(group["sum"], 2)
    return result
```

Какво е важно тук:
- `encoding="utf-8-sig"` чете UTF-8 и тихо маха маркера BOM, който Excel често слага в началото на файла. Без него първата колона би се казвала `﻿категория`. `newline=""` е препоръката на модула `csv`.
- `csv.DictReader` дава всеки ред като речник, ключът е името на колоната.
- Собствената грешка `CsvSumError` е същият модел като в урока за грешки: очакваните проблеми имат собствен тип.
- `from None` скрива вътрешната трасировка, понеже потребителят иска съобщение, не история.
- Номерът на реда започва от 2, защото ред 1 е заглавният, а потребителят гледа файла си в редактор.
- `.replace(",", ".")` приема и `7,30`.

## Стъпка 2: показване на резултата

```python
def render_table(summary):
    if not summary:
        return "(няма данни)"
    width = max(len(name) for name in summary)
    lines = [f"{'група':<{width}}  {'брой':>5}  {'сума':>10}"]
    for name, g in sorted(summary.items(), key=lambda p: -p[1]["sum"]):
        lines.append(f"{name:<{width}}  {g['count']:>5}  {g['sum']:>10.2f}")
    return "\n".join(lines)


def render_json(summary):
    return json.dumps(summary, ensure_ascii=False, indent=2)
```

Форматът `{name:<{width}}` подравнява текста вляво според най-дългото име, а `ensure_ascii=False` пази кирилицата четима в JSON. Таблицата е сортирана по сума.

## Стъпка 3: `argparse` и входната точка

**`argparse`** е модулът от стандартната библиотека, който чете аргументите от командния ред. Ти описваш какво приема програмата, а той прави останалото: проверява, показва помощ и казва ясно какво не е наред.

```python
def build_parser():
    p = argparse.ArgumentParser(
        prog="csvsum",
        description="Обобщава CSV файл: брой и сума по колона.",
    )
    p.add_argument("file", help="път до CSV файла (UTF-8)")
    p.add_argument("--by", required=True, help="колоната, по която се групира")
    p.add_argument("--value", required=True, help="колоната с числата")
    p.add_argument("--format", choices=["table", "json"], default="table",
                   help="вид на изхода (по подразбиране: table)")
    return p


def main(argv=None):
    args = build_parser().parse_args(argv)
    try:
        summary = summarize(read_rows(args.file), args.by, args.value)
    except CsvSumError as e:
        print(f"csvsum: грешка: {e}", file=sys.stderr)
        return 1
    render = render_json if args.format == "json" else render_table
    print(render(summary))
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

Три решения заслужават обяснение:

- **`main(argv=None)`** приема списък с аргументи. Когато е `None`, `argparse` взема реалните от терминала. При тест подаваме собствен списък и не се нуждаем от терминал.
- **Позиционен аргумент (`file`) и опции (`--by`).** Позиционният се пише по ред, опцията се именува. Опциите с `required=True` са задължителни.
- **`choices`** ограничава формата до две стойности и `argparse` отхвърля всичко друго.

Помощта се получава безплатно:

```
$ python3 csvsum.py --help
usage: csvsum [-h] --by BY --value VALUE [--format {table,json}] file

Обобщава CSV файл: брой и сума по колона.

positional arguments:
  file                  път до CSV файла (UTF-8)

options:
  -h, --help            show this help message and exit
  --by BY               колоната, по която се групира
  --value VALUE         колоната с числата
  --format {table,json}
                        вид на изхода (по подразбиране: table)
```

Думите „usage“, „positional arguments“ и „options“ идват от самия `argparse` и са на английски. Текстовете, които ти пишеш в `help`, са на български. Точното заглавие на секцията („options“ или „optional arguments“) зависи от версията на Python.

## Стъпка 4: пускане и изходни кодове

```
$ python3 csvsum.py expenses.csv --by категория --value сума
група       брой        сума
храна          3       39.80
транспорт      1        8.00
кафе           1        3.20
```

С `--format json`:

```
$ python3 csvsum.py expenses.csv --by категория --value сума --format json
{
  "храна": {
    "count": 3,
    "sum": 39.8
  },
  "транспорт": {
    "count": 1,
    "sum": 8.0
  },
  "кафе": {
    "count": 1,
    "sum": 3.2
  }
}
```

Сега грешките. Помисли как би искал инструментът да се държи при лоша употреба. Вместо трасировка, потребителят получава едно ясно съобщение:

```
$ python3 csvsum.py nope.csv --by а --value б
csvsum: грешка: няма такъв файл: nope.csv

$ python3 csvsum.py expenses.csv --by град --value сума
csvsum: грешка: няма колона 'град'; налични: дата, категория, сума

$ python3 csvsum.py bad.csv --by категория --value сума
csvsum: грешка: ред 3: 'abc' не е число
```

И трите завършват с код за изход `1`. А когато липсва задължителна опция, сам `argparse` отказва:

```
$ python3 csvsum.py expenses.csv --by категория
usage: csvsum [-h] --by BY --value VALUE [--format {table,json}] file
csvsum: error: the following arguments are required: --value
```

Този път кодът за изход е `2` – това е конвенцията на `argparse` за грешна употреба. Кодът за изход е числото, което програмата връща на обкръжението. `0` значи успех, всичко различно значи неуспех. Така други програми и скриптове могат да разберат дали си успял, без да четат текста. В Bash последният код се вижда с `echo $?`.

Грешките отиват в **`stderr`** (стандартния поток за грешки), а резултатът – в **`stdout`**. Така ако някой пренасочи изхода във файл с `> result.txt`, съобщенията за грешка няма да се смесят с данните.

## Стъпка 5: тестове

Сега връзката с предишния урок. Създаваме `tests/test_csvsum.py`. Първата част тества чистата логика:

```python
import json
import pytest
import csvsum
from csvsum import CsvSumError, summarize, render_table

ROWS = [
    {"категория": "храна", "сума": "12.50"},
    {"категория": "кафе", "сума": "3,20"},
    {"категория": "храна", "сума": "7.30"},
]

def test_summarize_groups_and_sums():
    result = summarize(ROWS, "категория", "сума")
    assert result == {
        "храна": {"count": 2, "sum": 19.8},
        "кафе": {"count": 1, "sum": 3.2},
    }

def test_empty_input_gives_empty_summary():
    assert summarize([], "g", "v") == {}

def test_missing_column_names_available_ones():
    with pytest.raises(CsvSumError, match="няма колона 'град'"):
        summarize(ROWS, "град", "сума")

def test_bad_number_reports_row_number():
    rows = [{"g": "a", "v": "1"}, {"g": "a", "v": "abc"}]
    with pytest.raises(CsvSumError, match="ред 3"):
        summarize(rows, "g", "v")
```

Втората част тества командния ред през `main`. Ползваме `capsys`, готов помощник на `pytest`, който улавя какво е отпечатано, и `tmp_path` за временен файл:

```python
@pytest.fixture
def csv_file(tmp_path):
    path = tmp_path / "data.csv"
    path.write_text("категория,сума\nхрана,10\nкафе,2.5\nхрана,5\n", encoding="utf-8")
    return path

def test_main_prints_json(csv_file, capsys):
    code = csvsum.main([str(csv_file), "--by", "категория", "--value", "сума", "--format", "json"])
    assert code == 0
    data = json.loads(capsys.readouterr().out)
    assert data["храна"] == {"count": 2, "sum": 15.0}

def test_main_missing_file_returns_1_and_writes_to_stderr(tmp_path, capsys):
    code = csvsum.main([str(tmp_path / "no.csv"), "--by", "a", "--value", "b"])
    captured = capsys.readouterr()
    assert code == 1
    assert "няма такъв файл" in captured.err
    assert captured.out == ""

def test_main_without_required_option_exits_with_2(csv_file):
    with pytest.raises(SystemExit) as info:
        csvsum.main([str(csv_file), "--by", "категория"])
    assert info.value.code == 2
```

Две новости: `@pytest.fixture` е твоя собствена готова подготовка, която тестовете получават по име. А когато `argparse` отхвърли аргументи, той вика `sys.exit(2)`, което вдига `SystemExit`; тестваме го с `pytest.raises`.

Целият файл в моя вариант има 10 теста. Пускаме:

```
$ python3 -m pytest -q
..........                                                               [100%]
10 passed in 0.02s
```

За да проверим, че тестовете наистина пазят, счупваме нарочно нещо: сменяме `start=2` на `start=1`, така че номерата на редовете да са с 1 по-малко. Резултатът:

```
....F.....                                                               [100%]
______________________ test_bad_number_reports_row_number ______________________
E       AssertionError: Regex pattern did not match.
E         Expected regex: 'ред 3'
E         Actual message: "ред 2: 'abc' не е число"

tests/test_csvsum.py::test_bad_number_reports_row_number
1 failed, 9 passed in 0.02s
```

Тестът за номера на реда хвана бъга. Връщаме `start=2` и всичко е зелено отново.

## Стъпка 6: проблемът с пътя

Тук има типична клопка. Файлът с тестовете е в `tests/`, а `csvsum.py` е една папка по-горе. Ако пуснеш `pytest` без `python3 -m` и без настройка, ще видиш:

```
ImportError while importing test module 'tests/test_csvsum.py'.
E   ModuleNotFoundError: No module named 'csvsum'
```

Причината е, че командата `pytest` не добавя текущата папка към пътя за търсене, докато `python3 -m pytest` го прави. Постоянното решение е малък файл `pytest.ini` в корена:

```
[pytest]
pythonpath = .
testpaths = tests
```

С него и `pytest -q` работи, дори от папката `tests`. Опцията `pythonpath` в `pytest.ini` е налична в по-новите версии на `pytest`.

## Пример от практиката

Да кажем, че пазиш разходите си в таблица и в края на месеца я експортираш като CSV. Преди инструментът да е готов, броиш ръчно или правиш формули. Сега един ред в терминала дава обобщението за секунди и можеш да го подадеш в скрипт с `--format json`.

След два месеца в банковия експорт колоната вече се казва `Сума (лв.)`. Инструментът ти казва: „няма колона 'сума'; налични: дата, категория, Сума (лв.)“ и веднага ти показва какво да напишеш в `--value`. А когато добавиш ново правило – например да пропуска празни суми – тестовете ти гарантират, че старото поведение остава. Така пишеш с увереност.

Инструментите за ИИ, които ще пишеш в другите курсове, са същата форма: малки програми с аргументи, ясни грешки и JSON изход, който друга програма чете.

## Чести грешки

- **Логика, вързана с `main`.** Ако цялата работа е в `main`, не можеш да я тестваш без терминал. Раздели я на функции.
- **`print` на грешки в `stdout`.** Ползвай `file=sys.stderr`, за да не се смесват с данните.
- **Трасировка вместо съобщение.** Потребителят не трябва да чете вътрешности. Хващай очакваните грешки и казвай какво да направи.
- **Код за изход винаги 0.** Скриптовете не могат да разберат, че нещо е счупено. Връщай ненулев код при грешка.
- **Кодировка по подразбиране.** `open(path)` без `encoding` може да чете с друга кодировка на някои системи. Пиши `encoding="utf-8"` или `utf-8-sig`.

## Бърза справка

| Нужда | Запис |
