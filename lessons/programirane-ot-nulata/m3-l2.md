## Масивът е ред от съседни кутии

Във Python списъкът `[70, 85, 90]` знае колко е дълъг, расте при нужда и можеш да го подадеш на функция, без да мислиш. **Масивът (array)** в C е много по-прост: това са няколко стойности от един и същ тип, наредени една до друга в паметта, и нищо повече. Няма дължина, няма `append`, няма проверка за граници.

Представи си блок от гаражи по една улица. Всеки гараж е еднакъв по размер и номерата им вървят последователно. Знаеш откъде започва редът и колко е голям един гараж, така че можеш да пресметнеш къде е гараж номер 3. Но ако поискаш гараж номер 50, никой няма да те спре: ще отидеш на 50-ото място от началото, дори там да е чужд двор.

Ето пълна програма с масив:

```c
#include <stdio.h>

void show(int arr[], size_t n)
{
    printf("в функцията: sizeof(arr) = %zu\n", sizeof(arr));
    for (size_t i = 0; i < n; i++)
        printf("%d ", arr[i]);
    printf("\n");
}

int main(void)
{
    int scores[5] = {70, 85, 90, 60, 100};
    size_t n = sizeof(scores) / sizeof(scores[0]);

    printf("sizeof(scores) = %zu, n = %zu\n", sizeof(scores), n);

    int sum = 0;
    for (size_t i = 0; i < n; i++)
        sum += scores[i];
    printf("сума = %d, средно = %.1f\n", sum, (double)sum / n);

    printf("scores[2] = %d, *(scores + 2) = %d\n", scores[2], *(scores + 2));
    show(scores, n);

    int zeros[3] = {0};
    int part[4] = {1, 2};
    printf("%d %d %d | %d %d %d %d\n", zeros[0], zeros[1], zeros[2],
           part[0], part[1], part[2], part[3]);
    return 0;
}
```

Компилаторът даде предупреждение, още преди да пуснем програмата (ще го обясним след малко):

```
arr.c:5:54: warning: 'sizeof' on array function parameter 'arr' will return size of 'int *' [-Wsizeof-array-argument]
```

А изходът е:

```
sizeof(scores) = 20, n = 5
сума = 405, средно = 81.0
scores[2] = 90, *(scores + 2) = 90
в функцията: sizeof(arr) = 8
70 85 90 60 100 
0 0 0 | 1 2 0 0
```

Нека го разчетем.

**Декларацията.** `int scores[5]` казва „пет `int`-а един до друг“. Индексите започват от **0**, както в Python: първият елемент е `scores[0]`, последният е `scores[4]`.

**Броят на елементите.** `sizeof(scores)` е 20 байта (5 пъти по 4), а `sizeof(scores[0])` е 4. Като разделиш, получаваш 5. Това работи само там, където масивът е деклариран, и ще видиш защо.

**Връзката с указателите.** `scores[2]` и `*(scores + 2)` са едно и също нещо. `scores + 2` е адресът на третия елемент (указателят се премества с размера на елемента, тук 4 байта), а `*` го чете. Записът със скоби е удобно съкращение.

**Масив към функция.** Когато подадеш масив на функция, тя получава само **адреса на първия елемент**. Затова `sizeof(arr)` вътре е 8 (размерът на указател на този компютър), а не 20. Оттам и предупреждението. Масивът „забравя“ дължината си и затова винаги подавай дължината като отделен параметър, както направихме с `n`.

## Когато излезеш извън границите

В Python `scores[7]` дава `IndexError` и програмата спира с ясно съобщение. В C никой не проверява. Ето цикъл с пръстовидна грешка, с `<=` вместо `<`:

```c
#include <stdio.h>

int main(void)
{
    int a[3] = {1, 2, 3};
    int after = 99;
    for (int i = 0; i <= 3; i++)
        printf("a[%d] = %d\n", i, a[i]);
    printf("after = %d\n", after);
    return 0;
}
```

Компилирано с `-Wall -Wextra` и пуснато:

```
a[0] = 1
a[1] = 2
a[2] = 3
a[3] = 811540992
after = 99
```

Компилаторът мълчи, а `a[3]` е четене от чужда памет. Стойността `811540992` е боклук и при теб ще е друга. С `-O2` същият код даде `a[3] = 0` и предупреждение `-Waggressive-loop-optimizations`: същата програма, друг резултат, защото поведението е **неопределено**.

Четенето извън границите е грубо, а **записът** извън границите може да презапише съседни данни, като адреси за връщане, и е един от най-старите източници на уязвимости в сигурността. За това ще говорим в следващия урок. Сега правилото е просто: пази дължината и проверявай индекса. Валидните индекси са от `0` до `n - 1`.

## Низът е масив от байтове с нулев край

Във Python `str` е истински обект с дължина и поддръжка на Unicode. В C **няма тип низ**. Низът е масив от `char`, чийто край се отбелязва с байт със стойност 0, записван като `'\0'` (нулев терминатор). Всички функции от `<string.h>` вървят по байтовете, докато не срещнат нулата.

Това е важно: масивът за низ трябва да е с **един байт повече**, отколкото са знаците.

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
    char name[] = "Ана";
    char word[] = "abc";
    char manual[4] = {'a', 'b', 'c', '\0'};

    printf("sizeof(word) = %zu, strlen(word) = %zu\n", sizeof(word), strlen(word));
    printf("manual: %s, %zu\n", manual, strlen(manual));
    printf("name = %s, sizeof = %zu, strlen = %zu\n", name, sizeof(name), strlen(name));

    const char *greet = "Здравей, свят!";
    printf("%s -> strlen = %zu байта\n", greet, strlen(greet));

    for (size_t i = 0; i < strlen(name); i++)
        printf("%02x ", (unsigned char)name[i]);
    printf("\n");
    return 0;
}
```

```
sizeof(word) = 4, strlen(word) = 3
manual: abc, 3
name = Ана, sizeof = 7, strlen = 6
Здравей, свят! -> strlen = 25 байта
d0 90 d0 bd d0 b0 
```

Какво виждаме:

- `"abc"` заема 4 байта: `a`, `b`, `c` и нулата. `strlen` брои до нулата и връща 3. `sizeof` връща размера на целия масив.
- **Кирилицата в UTF-8 заема по 2 байта на буква.** „Ана“ са три букви, но `strlen` връща 6, а шестнадесетичните стойности `d0 90 d0 bd d0 b0` са именно шестте байта. Така `"Здравей, свят!"` са 14 знака, но 25 байта (интервалът, запетаята и удивителната са по един байт). Във Python `len("Здравей, свят!")` дава 14, а `len(s.encode("utf-8"))` дава 25. C брои като втория.

За C няма „букви“, а само байтове. `strlen` не знае нищо за кодировки. Това е важен факт, ако някога обработваш български текст в C: резане на низа на произволен байт може да разреже буква наполовина.

Нагледно доказателство. Да обърнем низ „на място“:

```c
void reverse(char *s)
{
    size_t n = strlen(s);
    for (size_t i = 0; i < n / 2; i++) {
        char tmp = s[i];
        s[i] = s[n - 1 - i];
        s[n - 1 - i] = tmp;
    }
}
```

С латински текст всичко е както очакваш:

```
stressed  ->  desserts
```

С `"програма"` функцията обръща **байтовете**, а не буквите. Резултатът е невалиден UTF-8 и терминалът показва повредени знаци:

```
�маЀѳоЀѿ�
```

(Преглед с `od -c` потвърждава: низът започва с байтове `260 320 274` (в осмичен запис), т.е. с половин буква.) За да обръщаш български текст правилно, ти трябва библиотека, която разбира UTF-8. Това е грешка на подхода, не на `reverse`.

### Сравнение и копиране

Низовете не се сравняват с `==`: това сравнява адреси, а не съдържание (gcc предупреждава с `-Warray-compare`). Ползвай `strcmp(a, b) == 0`. Във Python `==` сравнява съдържанието, затова тази грешка е типична за идващите оттам.

Копирането е по-опасното. Ето два начина с твърде малък буфер:

```c
char buf[8];
const char *src = "Здравей, свят!";
snprintf(buf, sizeof(buf), "%s", src);

char dst[8];
strcpy(dst, "Hello, world!");
```

```
cpy.c:8:33: warning: '%s' directive output truncated writing 25 bytes into a region of size 8 [-Wformat-truncation=]
cpy.c:12:5: warning: '__builtin_memcpy' writing 14 bytes into a region of size 8 overflows the destination [-Wstringop-overflow=]
*** stack smashing detected ***: terminated
Aborted
```

Видяхме две неща. `snprintf` **знае** размера на буфера и отрязва текста, затова е безопасен, но компилаторът пак ни предупреждава, че текстът се реже. `strcpy` **не знае** размера и записва 14 байта в 8, т.е. препълва буфера. Тук защитата на системата засече повредата и спря програмата със съобщение (при пускане с пренасочен изход редовете на `printf` преди срива може да липсват, защото още не са изпратени от буфера). Но тази защита не е гарантирана във всяка среда, а препълването е дефект при всички положения. Правилото: никога не копирай в буфер, без да знаеш размера му. Предпочитай `snprintf` или `strncpy` с ръчно поставена нула, или проверка на `strlen` преди това.

Низов литерал като `"abc"` може да е в памет само за четене: `char *s = "abc"; s[0] = 'X';` даде `Segmentation fault` без дума от компилатора. Ползвай `const char *s` за четене и `char s[] = "abc";` за променяем низ.

## Структури: свързани данни под едно име

Досега всяка стойност беше сама. Ако описваш музикално парче, имаш заглавие, темпо и дължина, и не искаш три разхвърляни променливи. В C ползваш **структура (struct)**: контейнер, който групира полета от различни типове.

```c
#include <stdio.h>
#include <string.h>

struct Track {
    char title[32];
    int bpm;
    double length_min;
};

void print_track(struct Track t)
{
    printf("%s | %d BPM | %.1f мин\n", t.title, t.bpm, t.length_min);
}

void speed_up(struct Track *t, int delta)
{
    t->bpm += delta;
}

int main(void)
{
    struct Track t = {"Нощен ритъм", 124, 5.5};
    print_track(t);
    speed_up(&t, 4);
    printf("след speed_up: %d\n", t.bpm);

    struct Track set[2] = {
        {"Утро", 100, 3.0},
        {"Вечер", 128, 6.5},
    };
    for (int i = 0; i < 2; i++)
        print_track(set[i]);

    printf("sizeof(Track) = %zu\n", sizeof(struct Track));
    return 0;
}
```

```
Нощен ритъм | 124 BPM | 5.5 мин
след speed_up: 128
Утро | 100 BPM | 3.0 мин
Вечер | 128 BPM | 6.5 мин
sizeof(Track) = 48
```

Какво да забележиш:

- **Точка за достъп до поле:** `t.bpm`. Със структура-указател ползваш стрелка: `t->bpm` е съкращение за `(*t).bpm`.
- **Структурите се предават по стойност**, като `int`. `print_track` получава пълно копие (48 байта), което е лошо за големи структури. `speed_up` получава адрес и променя оригинала. Това е същият урок от swap. За четене на голяма структура често се дава `const struct Track *`.
Структурите могат да се кръстят с `typedef`, за да не пишеш `struct` навсякъде, и се копират с `=` поле по поле, като числата, не като списъците във Python.

### Подравняване и „дупки“

Полетата не винаги са плътно едно до друго. Процесорът чете най-бързо, когато числата са на адреси, кратни на размера им, затова компилаторът слага празни байтове (padding). Две структури с едни и същи полета в различен ред:

```c
struct Pad  { char a; int b; char c; };
struct Pad2 { int b; char a; char c; };
```

```
Pad = 12, Pad2 = 8
```

Полетата са същите (1 + 4 + 1 = 6 байта), но първата заема 12, втората 8. Размерът зависи от компилатора и платформата. Не предполагай, че `sizeof` на структура е сумата на полетата; питай `sizeof`.

## Пример от практиката

Да кажем, че правиш малка програма за списък със задачи. Всяка задача е структура с кратко заглавие и приоритет, а всички са в масив с 10 елемента. Тестваш с три задачи и всичко минава. После приятел въвежда единадесета. Твоята функция `add` не проверява броя, записва в `tasks[10]` и тихо поврежда съседни променливи. Поправката е проста и се прилага винаги: функцията получава `capacity`, проверява `count < capacity` преди запис и връща грешка, ако няма място. В следващия урок ще направиш масив, който расте динамично. А как точно такива препълвания се превръщат в проблеми със сигурността, ще разгледаш в курса за reverse engineering.

## Чести грешки

- **Индекс от `1` до `n`** – валидните са от `0` до `n - 1`. Типичната грешка е `<=` вместо `<`.
- **`sizeof` върху параметър на функция** – връща размера на указател. Подавай дължината отделно.
- **Низ без място за нулата** – `char w[3] = "abc"` е твърде малък. Нужни са 4 байта. Най-лесно е да оставиш компилатора да брои: `char w[] = "abc";`.
- **`==` за низове** – сравнява адреси. Ползвай `strcmp`.
- **`strcpy` и `strcat` към буфер с неизвестен размер** – препълване. Ползвай `snprintf` или проверявай дължината.
- **Промяна на низов литерал** – срив. Декларирай `const char *` или копирай в масив.

**Как да проверя дали се справих:**
- Програмата се компилира с `-Wall -Wextra` без предупреждения.
- `count_char` дава верен брой във всичките три случая.
- Не променяш низов литерал и никъде не пишеш извън буферите.

## Бърза справка

| Искаш | Пишеш |
|---|---|
| Масив от 5 `int` | `int a[5];` |
| С начални стойности | `int a[5] = {1, 2, 3};` (останалите са 0) |
| Брой елементи | `sizeof(a) / sizeof(a[0])` (само където `a` е масив) |
| Елемент | `a[i]` е същото като `*(a + i)` |
| Низ с автоматичен размер | `char s[] = "текст";` |
| Дължина на низ в байтове | `strlen(s)` от `<string.h>` |
| Сравни низове | `strcmp(a, b) == 0` |
| Безопасно копиране | `snprintf(buf, sizeof(buf), "%s", src);` |
| Псевдоним на тип | `typedef struct { int x, y; } Point;` |

## Обобщение

Масивът е поредица от еднакви елементи в съседни клетки и не знае дължината си: тя е твоя грижа, а излизането извън границите е неопределено поведение. Низът в C е масив от `char`, завършващ с нулев байт, и `strlen` брои байтове, затова българският текст в UTF-8 е почти два пъти по-дълъг. Низовете се сравняват със `strcmp` и се копират само в буфери с известен размер. Структурата групира полета в един тип, предава се по стойност, освен ако не ѝ дадеш адрес, и може да съдържа неизползвани байтове. Следващият урок ще покаже как да поискаш памет с произволен размер, и как се случват най-тежките грешки с нея.
