> **Цел на урока:** да събираш повторяем код във функции с ясни входове и изход и да разделиш играта „Познай числото“ на три функции.

## Какво ще научиш
- Как се пише функция с `def`, как се вика и каква е разликата между `print` и `return`
- Как работят параметрите, стойностите по подразбиране и именуваните аргументи
- Как функция връща няколко стойности и какво връща, когато не пише `return`
- Какво е видимост (scope) и защо променливите вътре във функцията са „частни“
- Как да раздробиш по-голяма програма на малки функции, всяка с една ясна задача

## Защо ни трябват функции
В предишния урок написа играта на един блок, дълъг около двадесет реда. Докато е малка, се чете лесно. Но представи си, че искаш същата проверка на входа на още пет места, или искаш да изпробваш само частта „сравни с числото“, без да играеш цяла игра. Копирането на кода е капан: ако намериш грешка, трябва да я поправиш на всяко място.

**Функцията (function)** решава това. Тя е парче код с име, което можеш да извикаш, когато ти трябва. Аналогията е с рецепта в кухненска книга: пишеш я веднъж („как се прави бяла сос“), а после в десет ястия просто пишеш „добави бял сос“. Рецептата има **съставки** (входове), **процедура** и **резултат**.

Всъщност вече си ползвал функции: `print()`, `input()`, `len()`, `int()`, `range()`. Сега ще пишеш свои.

## Първата функция: def, параметри и return
```python
def greet(name):
    print(f"Здравей, {name}!")

def add(a, b):
    return a + b

greet("Мария")
result = add(2, 3)
print(result)
print(add("ка", "фе"))
x = greet("Иван")
print(x)
```

```
Здравей, Мария!
5
кафе
Здравей, Иван!
None
```

Разбор:
- `def` е ключовата дума, която „дефинира“ функция. Следват име, скоби с **параметри** и двоеточие. Тялото е с отстъп – като при `if` и `for`.
- Параметрите (`name`, `a`, `b`) са имена за входовете. Когато викаш `greet("Мария")`, стойността „Мария“ се нарича **аргумент** и влиза в параметъра `name`.
- Дефиницията само „записва рецептата“. Нищо не се изпълнява, докато не извикаш функцията с `име(...)`.
- `return` връща стойност към мястото на извикването и **веднага завършва** функцията. Получената стойност можеш да запазиш в променлива, както направихме с `result`.

### print и return не са едно и също
Това е най-честото объркване. `print` показва нещо на екрана за човека, а `return` предава стойност на програмата. Функцията `greet` само печата и не връща нищо, затова `x = greet("Иван")` оставя в `x` специалната стойност `None` – видя го в последния ред на изхода. Функцията `add` връща резултат, с който можеш да продължиш да смяташ: `add(add(1, 2), 3)`.

Правило, което ще ти спести часове: **ако резултатът е нужен на друга част от програмата, връщай го; печатай само на най-горното ниво.** Така функцията може да се ползва и в игра, и в тест, и в скрипт без екран.

Забележи и `add("ка", "фе")`: функцията работи и с низове, защото `+` ги слепва. Python не проверява типовете на параметрите предварително. Това е гъвкаво, но значи, че ти носиш отговорност да подаваш смислени стойности.

## Стойности по подразбиране и именувани аргументи
Параметрите могат да имат стойност по подразбиране, която важи, когато не подадеш друга:

```python
def price_with_vat(price, vat=20):
    return round(price * (1 + vat / 100), 2)

print(price_with_vat(10))
print(price_with_vat(10, 9))
print(price_with_vat(vat=0, price=10))
```

```
12.0
10.9
10.0
```

Първото извикване използва ДДС 20 по подразбиране. Второто подава 9 на втората позиция. Третото показва **именувани аргументи (keyword arguments)**: пишеш `име=стойност` и редът вече няма значение. Така извикването се чете като изречение и не се налага да помниш какъв е редът на параметрите.

Две правила:
- Параметрите със стойност по подразбиране се слагат **след** тези без.
- За стойност по подразбиране ползвай числа, низове, `True`/`False` или `None`. Променливи неща като списъци са коварни и ще ги обсъдим, когато учим списъци.

Числото 20 е просто пример. Стойностите на данъци са различни и се променят, така че в реална програма ги провери за конкретния случай.

## Връщане на няколко стойности
Функцията може да върне няколко неща наведнъж, като ги изброиш със запетая. Python ги опакова в **кортеж (tuple)** – подредена група, а при извикването можеш да ги разопаковаш в отделни променливи:

```python
def min_max(numbers):
    return min(numbers), max(numbers)

low, high = min_max([4, 9, 1, 7])
print(low, high)
print(min_max([4, 9, 1, 7]))
```

```
1 9
(1, 9)
```

Квадратните скоби `[4, 9, 1, 7]` са списък. Още не сме го учили подробно, достатъчно е да знаеш, че това е „подредена колекция от стойности“, а `min` и `max` са вградени функции. Подробности – в следващия урок.

### Ранен return и документиране
Функция може да има няколко `return` и всеки завършва извикването:

```python
def grade(points):
    """Връща оценка според точките."""
    if points >= 90:
        return "отличен"
    if points >= 50:
        return "добър"
    return "слаб"

print(grade(95), grade(60), grade(10))
help(grade)
```

```
отличен добър слаб
Help on function grade in module __main__:

grade(points)
    Връща оценка според точките.
```

Няма нужда от `elif`, защото `return` така или иначе излиза от функцията. Този стил се нарича **ранно връщане (early return)** и прави кода плосък и лесен за четене.

Текстът в тройни кавички точно под реда с `def` е **docstring** – кратко описание на функцията. Той не е просто коментар: `help()` го показва, а редакторите го появяват като подсказка. Пиши го за всяка функция, която не е очевидна.

## Видимост: кой какво вижда
Променливите, създадени във функцията, са **локални**: съществуват само докато функцията работи и никой отвън не ги вижда. Аналогията е със стая, която има свои собствени чекмеджета. Във функцията можеш да четеш и „глобалните“ променливи отвън, но да ги променяш е различна работа.

```python
level = 1

def local_demo():
    secret = 42
    print("вътре:", secret, level)

local_demo()
try:
    print(secret)
except NameError as e:
    print("NameError:", e)

def bad():
    level = level + 1
    return level

try:
    bad()
except UnboundLocalError as e:
    print("UnboundLocalError:", e)

def good(level):
    return level + 1

level = good(level)
print(level)
```

```
вътре: 42 1
NameError: name 'secret' is not defined
UnboundLocalError: cannot access local variable 'level' where it is not associated with a value
2
```

(Конструкцията `try`/`except` хваща грешка, за да я покажем, без да спре програмата. Ще я учим подробно в курса по-нататък; засега я чети като „опитай това, а при такава грешка направи онова“.)

Какво се случи:
- Във функцията `secret` е видима, а извън нея – `NameError`.
- Функцията може да **прочете** `level`, защото той е във външния обхват.
- Но в `bad()` присвояването `level = ...` прави `level` локално име за цялата функция. Затова четенето му преди присвояването е грешка – `UnboundLocalError`.
- Правилният начин е да подадеш стойността като параметър и да вземеш резултата с `return`, както във `good`.

Има и ключова дума `global`, която позволява писане във външна променлива, но е знак за лошо проектиране. Функции, които работят само с входовете си и връщат резултат, се тестват и четат несравнимо по-лесно. Те често се наричат „чисти“ (pure) функции.

## Стъпка по стъпка: разделяме играта на три функции
Да вземем играта от предишния урок. Тя прави три различни неща: чете и проверява вход, сравнява догадката с числото и върти рундовете. Всяко от тях е кандидат за функция.

1. Избери кои задачи са ясно отделни. Тук са три: четене на допустим отговор, сравнение и самата игра.
2. За всяка функция реши **входовете** и **изхода**. Четенето не приема нищо, освен номера на опита за подканата, и връща цяло число. Сравнението приема догадка и тайно число и връща `"low"`, `"high"` или `"ok"`. Играта приема броя опити и връща `True` или `False`.
3. Премести кода на всяка задача в собствена функция с docstring.
4. Остави най-отдолу един ред, който пуска играта.
5. Пусни я и провери, че се държи **по същия начин** като преди. Това е целта на преработката (refactoring): външното поведение не се променя, а вътрешната структура става по-добра.

Ето резултата, `game.py`:

```python
import random


def read_guess(tries):
    """Пита, докато получи цяло число, и го връща."""
    while True:
        text = input(f"Опит {tries + 1}: ")
        if text.isdigit():
            return int(text)
        print("Моля, въведи цяло число.")


def check_guess(guess, secret):
    """Връща 'low', 'high' или 'ok'."""
    if guess < secret:
        return "low"
    if guess > secret:
        return "high"
    return "ok"


def play(max_tries=7):
    """Играе един рунд. Връща True при победа."""
    secret = random.randint(1, 100)
    print(f"Мисля си число от 1 до 100. Имаш {max_tries} опита.")
    for tries in range(max_tries):
        result = check_guess(read_guess(tries), secret)
        if result == "ok":
            print(f"Позна за {tries + 1} опита!")
            return True
        print("По-голямо." if result == "low" else "По-малко.")
    print(f"Загуби. Числото беше {secret}.")
    return False


play()
```

Проверих я със същите семена и входове като в предишния урок. Със семе 5 (числото е 80) и вход 50, „абв“, 75, 85, 80 изходът е:

```
Мисля си число от 1 до 100. Имаш 7 опита.
Опит 1: По-голямо.
Опит 2: Моля, въведи цяло число.
Опит 2: По-голямо.
Опит 3: По-малко.
Опит 4: Позна за 4 опита!
```

Със семе 11 (числото е 58) и седем числа от 1 до 7 играта завършва с „Загуби. Числото беше 58.“ – точно както преди. Поведението е същото, но кодът се чете по нов начин.

Какво спечели:
- `play()` се чете почти като описание на играта, без подробности за проверката на вход.
- `check_guess` няма нито `print`, нито `input`, затова я тестваш наведнъж. Извиках я с `check_guess(10, 50)`, `check_guess(70, 50)` и `check_guess(50, 50)` и получих `low`, `high` и `ok`.
- Ако решиш да променяш правилата, например да приемаш и отрицателни числа, променяш `read_guess` на едно място.
- `play(max_tries=7)` показва стойност по подразбиране: `play(5)` дава по-трудна игра.

Една конвенция, която ще срещаш: в готовите програми най-отдолу се пише `if __name__ == "__main__":` и под него извикването `play()`. Така файлът може да бъде импортиран от друг файл (например за тестове), без играта да започне сама. В следващите модули ще го ползваме, а сега просто знай, че съществува.

## Пример от практиката
Да кажем, че пишеш програма за домашния бюджет и на три места смяташ една и съща сума с отстъпка. Без функция имаш три копия на формулата. С функция:

```python
def apply_discount(price, percent=10):
    """Връща цената след отстъпка в проценти."""
    return round(price * (1 - percent / 100), 2)

print(apply_discount(50))
print(apply_discount(50, 25))
```

Когато си намисли промяна („заоблявай към цели левове“), променяш едно място. Функциите са и начинът, по който се свързват части на програми: когато по-нататък даваш на ИИ агент „инструменти“ (tools) за ползване, всеки инструмент е точно функция с ясно име, документиран вход и върната стойност – така моделът разбира как да я извика.

## Чести грешки
- **Забравено извикване** – `greet` без скоби само назовава функцията и не я изпълнява. Пиши `greet("Иван")`.
- **`print` вместо `return`** – функцията показва резултата, но не можеш да го ползваш по-нататък; получаваш `None`. Връщай стойности.
- **Липсващ `return` по някой път** – ако някой клон на `if` не връща нищо, функцията дава `None` и после се чудиш откъде идва. Мини през всички клонове.
- **Промяна на глобална променлива отвътре** – води до `UnboundLocalError` или до код, който е трудно да се следи. Подавай параметри и връщай резултат.
- **Прекалено дълга функция** – ако не можеш да опишеш какво прави с едно изречение, раздели я.
- **Лоши имена** – `do_stuff()` не казва нищо. Ползвай глаголи: `read_guess`, `check_guess`, `calculate_total`.
- **Подаване на аргументи в грешен ред** – за функции с много параметри ползвай именувани аргументи.

## Упражнение
Преработи собствената си версия на играта „Познай числото“ (от упражнението на предишния урок или от примера по-горе) така, че да има поне три функции:
1. `read_guess` – чете и валидира вход;
2. `check_guess` – сравнява и връща резултат, без да печата;
3. `play` – върти един рунд и връща `True`/`False`;
4. добави четвърта, `choose_difficulty`, която връща броя опити според избора на играча, и главен цикъл „Пак ли?“ с броене на победите.

Критерии за самопроверка:
- всяка функция има docstring от едно изречение;
- в `check_guess` няма `print` и `input`;
- пускането на играта дава същия резултат като преди преработката;
- можеш да извикаш `check_guess(10, 50)` в интерактивния режим на Python и да получиш `low`, без да играеш;
- никъде не ползваш `global`.

Бонус: напиши функция `average(numbers)`, която връща средно аритметично. Помисли какво трябва да направи при празен списък и реши дали да върне `None`, или да покаже съобщение.

## Бърза справка

| Задача | Запис |
|---|---|
| Дефиниция | `def name(a, b):` |
| Извикване | `name(1, 2)` |
| Връщане на стойност | `return value` |
| Връщане на няколко | `return a, b` → `x, y = f()` |
| По подразбиране | `def f(a, b=10):` |
| Именуван аргумент | `f(b=5, a=1)` |
| Описание | `"""Какво прави."""` |
| Помощ | `help(name)` |
| Без `return` | връща `None` |
| Локални променливи | живеят само във функцията |

## Обобщение
Функцията събира повторяем код под едно име, приема входове чрез параметри и връща резултат с `return`. `print` показва на човека, `return` предава на програмата, а функция без `return` връща `None`. Стойностите по подразбиране и именуваните аргументи правят извикванията гъвкави и четими. Променливите във функцията са локални, затова най-ясният дизайн е „влиза през параметри, излиза през `return`“. С тези идеи раздели играта на малки функции и запази поведението ѝ непроменено.

## Бележки за видеото
- Покажи „рецептата“: нарисувай функцията като кутия със стрелка на входа и на изхода.
- Сравни на екрана `greet` и `add`, и изведи `None` от функцията без `return`.
- Анимирай видимостта: стая във функцията с чекмеджета, към която отвън не се вижда.
- Преработи играта на живо: маркирай три части в стария код и ги премести във функции, като пускаш играта след всяка стъпка.
- Извикай `check_guess` директно в интерактивен режим, за да се види колко лесно се тества.
