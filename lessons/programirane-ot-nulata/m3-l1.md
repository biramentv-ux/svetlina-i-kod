> **Цел на урока:** да разбереш как C пази данните в паметта, колко място заема всеки тип и какво е указател, за да можеш да го ползваш и да четеш чужд код с него.

## Какво ще научиш
- Какви са основните типове на C, колко байта заемат и къде свършват
- Какво се случва, когато число излезе извън обхвата си
- Какво е адрес в паметта и как работят операторите `&` и `*`
- Защо функция не може да смени чужда променлива, освен ако ѝ дадеш адреса
- Кои са най-честите грешки с указатели и как компилаторът и системата ги издават

## Паметта като улица с номера

В Python пишеш `age = 17` и не се питаш къде е това число. В C този въпрос е основен. Представи си компютърната памет като много дълга улица с къщи. Всяка къща е един **байт** и има свой пореден номер: **адрес (address)**. Когато заявиш променлива, компилаторът ѝ отрежда няколко съседни къщи и помни от кой номер започва.

Различните типове данни заемат различен брой къщи. Цяло число може да иска четири, символ иска една. Затова в C **трябва да кажеш типа** при всяка променлива: `int age = 17;`. Типът отговаря на два въпроса: колко байта да се отделят и как да се тълкуват.

В Python `int` расте колкото трябва. В C той е с фиксиран размер. Ето и сравнението:

```python
print(2**31, 2**100)
```

```
2147483648 1267650600228229401496703205376
```

Python смята без проблем с числа от 31 или 101 бита. Нека видим какво дава C.

## Типовете и техните размери

Ето програма, която пита компилатора колко място заема всеки тип. Операторът `sizeof` връща размера в байтове:

```c
#include <stdio.h>
#include <limits.h>
#include <stdint.h>

int main(void)
{
    printf("char      : %zu\n", sizeof(char));
    printf("short     : %zu\n", sizeof(short));
    printf("int       : %zu\n", sizeof(int));
    printf("long      : %zu\n", sizeof(long));
    printf("long long : %zu\n", sizeof(long long));
    printf("float     : %zu\n", sizeof(float));
    printf("double    : %zu\n", sizeof(double));
    printf("int *     : %zu\n", sizeof(int *));
    printf("char *    : %zu\n", sizeof(char *));
    printf("int32_t   : %zu\n", sizeof(int32_t));
    printf("INT_MAX   : %d\n", INT_MAX);
    printf("INT_MIN   : %d\n", INT_MIN);
    printf("UINT_MAX  : %u\n", UINT_MAX);
    return 0;
}
```

Реалният изход на 64-битов Linux:

```
char      : 1
short     : 2
int       : 4
long      : 8
long long : 8
float     : 4
double    : 8
int *     : 8
char *    : 8
int32_t   : 4
INT_MAX   : 2147483647
INT_MIN   : -2147483648
UINT_MAX  : 4294967295
```

**Важно:** стандартът на C не фиксира точните размери, освен че `char` е един байт. На 64-битов Windows например `long` е 4 байта, а не 8. Затова, когато ти трябва точен размер, ползвай типовете от `<stdint.h>`: `int8_t`, `int16_t`, `int32_t`, `int64_t` и техните `unsigned` варианти като `uint8_t`. Името казва колко бита са.

Ето по-подредено кои типове ще ползваш най-често:

| Тип | Типичен размер | За какво | Формат в `printf` |
|---|---|---|---|
| `char` | 1 байт | един символ или малко число | `%c` или `%d` |
| `int` | 4 байта | обикновено цяло число | `%d` |
| `unsigned int` | 4 байта | цяло число без отрицателни | `%u` |
| `long long` | 8 байта | големи цели числа | `%lld` |
| `float` | 4 байта | дробно число, около 7 цифри точност | `%f` |
| `double` | 8 байта | дробно число, около 15–16 цифри точност | `%f` (в `printf`) |
| `size_t` | 8 байта на 64-битов | размери и бройки | `%zu` |
| указател | 8 байта на 64-битов | адрес в паметта | `%p` |

Забележи, че указателят `int *` и `char *` имат еднакъв размер, въпреки че сочат към различни неща: адресът е просто номер на къща, независимо какво има в нея.

## Когато числото не се побира

Фиксираният размер има последица: числата имат граници. `int` от 4 байта (32 бита) побира стойности от -2 147 483 648 до 2 147 483 647. Какво става извън тях? Да опитаме:

```c
#include <stdio.h>
#include <limits.h>

int main(void)
{
    unsigned int u = 0;
    u = u - 1;
    printf("0u - 1 = %u\n", u);

    unsigned char b = 250;
    b = b + 10;
    printf("250 + 10 в unsigned char = %d\n", b);

    printf("7 / 2 = %d\n", 7 / 2);
    printf("7 %% 2 = %d\n", 7 % 2);
    printf("7 / 2.0 = %.2f\n", 7 / 2.0);
    printf("-7 / 2 = %d\n", -7 / 2);

    double x = 0.1 + 0.2;
    printf("0.1 + 0.2 = %.17f\n", x);

    char c = 'A';
    printf("c = %c, код = %d, c + 1 = %c\n", c, c, c + 1);

    int big = INT_MAX;
    big = big + 1;
    printf("INT_MAX + 1 = %d\n", big);
    return 0;
}
```

```
0u - 1 = 4294967295
250 + 10 в unsigned char = 4
7 / 2 = 3
7 % 2 = 1
7 / 2.0 = 3.50
-7 / 2 = -3
0.1 + 0.2 = 0.30000000000000004
c = A, код = 65, c + 1 = B
INT_MAX + 1 = -2147483648
```

Нека разгледаме по реда им:

- **Числа без знак (unsigned) се „навиват“.** Като километража на колата: след най-голямото число идва нулата. `0 - 1` дава най-голямото число на типа, а `250 + 10` в един байт дава `4`, защото 260 минус 256 е 4. За `unsigned` това поведение е гарантирано от езика.
- **Деление на цели числа отрязва дробната част.** `7 / 2` е `3`, а не `3.5`. В Python `//` прави същото, но `/` дава дробно. В C операторът е един и типовете решават: за дробен резултат поне единият операнд трябва да е дробен (`7 / 2.0`). Забележи и `-7 / 2`: резултатът е `-3`, а Python с `//` дава `-4`. C отрязва към нула.
- **Дробните числа са приблизителни.** `0.1 + 0.2` не е точно `0.3` и в C, и в Python. Това не е бъг, а как се записват дробните числа в двоична система.
- **`char` е малко число.** `'A'` е просто числото 65, а `c + 1` е 66, т.е. `'B'`. Таблицата ASCII ще срещнеш пак в следващия урок.
- **Препълването на число със знак е опасно.** `INT_MAX + 1` на моята машина даде `-2147483648`, и то и при `-O0`, и при `-O2`. Но за числа със знак стандартът на C казва, че това е **неопределено поведение (undefined behavior)**: програмата може да направи каквото и да е, а друг компилатор или други флагове могат да дадат друг резултат. Не разчитай на това, което видя.

Защо е важно извън упражненията? Грешка при размерите на числа е класическа причина за уязвимости: ако програма пресметне размер на буфер с препълнено число, тя може да отдели твърде малко памет. Затова при пресмятания с размери проверявай границите, преди да смяташ.

## Указателят е адрес

Сега стигаме до най-важното понятие в C. **Указател (pointer)** е променлива, в която се съхранява адрес, а не обикновена стойност. Да се върнем на улицата: `age` е къщата, в която живее числото 17. Указателят е лист хартия, на който пише номерът на тази къща.

Два оператора вършат цялата работа:

- **`&`** („адресът на“) – взима адреса на променлива.
- **`*`** („това, към което сочи“) – отива на адреса и работи с каквото има там. Нарича се **дереференциране (dereferencing)**.

Ето ги в действие:

```c
#include <stdio.h>

int main(void)
{
    int age = 17;
    int *p = &age;

    printf("age       = %d\n", age);
    printf("&age      = %p\n", (void *)&age);
    printf("p         = %p\n", (void *)p);
    printf("*p        = %d\n", *p);

    *p = 18;
    printf("след *p=18: age = %d\n", age);

    printf("sizeof(age) = %zu, sizeof(p) = %zu\n", sizeof(age), sizeof(p));
    return 0;
}
```

```
age       = 17
&age      = 0x7ffe688c9c9c
p         = 0x7ffe688c9c9c
*p        = 17
след *p=18: age = 18
sizeof(age) = 4, sizeof(p) = 8
```

Разгледай изхода внимателно. `&age` и `p` са едно и също число: адресът. `*p` е 17, защото отиваме на адреса и четем. А записът `*p = 18` променя истинската променлива `age`, въпреки че никъде не сме написали `age = 18`.

Адресът (`0x7ffe...`) е записан в шестнадесетичен вид и **се променя при всяко пускане**: при второто ми пускане беше `0x7fff1270aa1c`. Така че не го запомняй и не разчитай на конкретни стойности.

Забележи записа `int *p`. Звездичката тук е част от **декларацията**: „`p` е указател към `int`“. Същата звездичка в `*p = 18` е **операция**: „иди там и запиши“. Знакът е един, значението зависи от мястото. Това обърква всички в началото.

Сравни с Python. Там всички променливи вече са своего рода указатели към обекти: `b = a` кара двете имена да сочат към един и същ списък. Но Python крие адресите и ги следи сам. В C адресът е обикновено число, с което работиш ръчно.

## Защо функциите се нуждаят от указатели

В C аргументите на функциите се предават **по стойност**: функцията получава *копие*. Във Python същото важи за числата (функцията не може да промени `n` от външния свят), но списъкът се променя, защото се предава връзката към него. Ето същото с числа в Python:

```python
def g(n): n = n + 1
n = 1; g(n); print(n)   # 1
```

В C няма „списък, който се променя сам“. Ако искаш функция да промени твоя променлива, ѝ даваш нейния адрес. Класическият пример е размяната на две числа:

```c
#include <stdio.h>

void swap_value(int a, int b)
{
    int tmp = a;
    a = b;
    b = tmp;
}

void swap_ptr(int *a, int *b)
{
    int tmp = *a;
    *a = *b;
    *b = tmp;
}

int main(void)
{
    int x = 3, y = 8;

    swap_value(x, y);
    printf("след swap_value: x=%d y=%d\n", x, y);

    swap_ptr(&x, &y);
    printf("след swap_ptr:   x=%d y=%d\n", x, y);
    return 0;
}
```

```
след swap_value: x=3 y=8
след swap_ptr:   x=8 y=3
```

`swap_value` разменя собствените си копия и нищо не се променя навън. `swap_ptr` получава адресите на `x` и `y` и през тях променя оригиналите. Затова при извикването пишем `&x`, `&y`: „дай ти адреса, за да можеш да пишеш там“. Същият механизъм стои зад `scanf("%d", &n)`, който ще срещнеш по-късно.

## Опасните указатели

Мощта на указателите има цена. Три неща трябва да знаеш още сега, като грешки, които се поправят.

**Нулев указател.** `NULL` е специалният адрес „никъде“. Ако указателят няма към какво да сочи, дай му `NULL`, за да можеш да проверяваш. Но четене през него е грешка:

```c
int *p = NULL;
printf("p = %p\n", (void *)p);
printf("*p = %d\n", *p);
```

```
Segmentation fault
exit=139
```

Операционната система спира програмата. Точната дума на съобщението зависи от системата, а кодът 139 е типичен за Linux (128 + сигнал 11). Компилаторът не предупреди, защото програмата е синтактично правилна: само изпълнението я издава.

**Висящ указател (dangling pointer).** Локалните променливи на функция живеят само докато функцията работи. Ако върнеш адреса на такава променлива, сочиш към къща, която вече е разрушена:

```c
int *make(void)
{
    int local = 42;
    return &local;
}
```

```
wild.c:6:12: warning: function returns address of local variable [-Wreturn-local-addr]
    6 |     return &local;
```

Предупреждението идва от `-Wall`: още една причина да го ползваш. При пускане на моята машина програмата също се срина със `Segmentation fault`. Но друг компилатор или друга версия може да „покаже“ 42 и да изглежда, че работи. Това е най-коварното в тези грешки: понякога минават незабелязано.

**Неинициализиран указател.** Ако не зададеш начален адрес, указателят съдържа каквото е останало в паметта. Четенето през него е лотария. Винаги го свързвай с реална променлива или с `NULL`.

В следващите уроци ще видиш още грешки от този род. Научи се да ги разпознаваш като дефекти, не като странности на езика.

## Аритметика с указатели

Още един факт, който обяснява масивите от следващия урок. Ако `p` сочи към `int`, то `p + 1` не прибавя 1 към адреса, а прибавя **размера на една стойност** (тук 4 байта), т.е. сочи към следващото число:

```c
int a[4] = {10, 20, 30, 40};
int *p = a;
printf("%p %p\n", (void *)p, (void *)(p + 1));
printf("*(p+1) = %d\n", *(p + 1));
```

```
0x7ffc756dffe0 0x7ffc756dffe4
*(p+1) = 20
```

Двата адреса се различават с 4 (`...fe0` и `...fe4`). Типът на указателя казва колко да се премести. Затова указателят към `char` и към `int` не са взаимозаменяеми, въпреки че са еднакво дълги.

За reverse engineering това е ежедневие: когато разглеждаш декомпилиран код, повечето от него е именно такава аритметика с адреси.

## Стъпка по стъпка

1. Създай файл `types.c` и копирай програмата с `sizeof`. Компилирай с `gcc -Wall -Wextra -o types types.c`.
2. Сравни изхода със своята система. Ако имаш Windows, провери размера на `long`.
3. Добави променлива `unsigned char level = 255;`, увеличи я с 1 и отпечатай. Обясни резултата.
4. Напиши `ptr.c`, който взима адреса на `int` и го променя през указател. Пусни го два пъти и сравни адресите.
5. Напиши `swap.c` с двете функции. Първо виж, че `swap_value` не работи, после, че `swap_ptr` работи.
6. Опитай се да подадеш `printf("%f\n", n)`, където `n` е `int`, и прочети предупреждението.
7. Нарочно дереференцирай `NULL` в отделен файл и виж как се държи системата ти.

## Пример от практиката

Да кажем, че пишеш програма за таймер на концерт и пазиш времето в милисекунди в обикновен `int`. Тестваш я няколко минути и всичко е наред. След около 24 дни непрекъсната работа числото достига 2 147 483 647 и препълва: таймерът изведнъж започва да показва отрицателно време. На проверка тези 24 дни не се забелязват, но на място, където програмата работи седмици, дефектът излиза.

Поправката е да смяташ времето в `uint64_t` или `long long` и да си зададеш правило: всяка стойност, която расте с времето, получава достатъчно голям тип. Така разликата между Python (където числото никога не свършва) и C става конкретна: в C ти избираш размера, затова ти носиш и отговорността.

## Чести грешки

- **Деление на цели числа, когато очакваш дробно** – `7 / 2` е `3`. Направи единия операнд дробен.
- **Грешен формат в `printf`** – `%d` за `double` дава боклук, а предупреждението от `-Wall` те спасява: при мен `printf("%f\n", n)` с `int` получи `0.000000` и предупреждение `-Wformat=`.
- **Разчитане, че `int` е винаги 4 байта или `long` винаги 8** – за точен размер ползвай `<stdint.h>`.
- **Препълване на число със знак** – неопределено поведение. Проверявай границите преди да смяташ.
- **Мълчаливо стесняване** – присвояване на голямо число на по-малък тип. При мен `long big = 3000000000; int small = big;` даде `-1294967296` без предупреждение при `-Wall -Wextra`. Включването на `-Wconversion` ги показва.
- **Дереференциране на `NULL` или неинициализиран указател** – срив или тихо повредени данни.
- **Връщане на адрес на локална променлива** – висящ указател; гледай за предупреждението `-Wreturn-local-addr`.
- **Смесване на двата смисъла на `*`** – в декларацията е тип, в израза е операция.

## Упражнение

**Задача.** Напиши програма `swap.c` с функция `void swap(int *a, int *b)`. В `main` създай две променливи, размени ги, отпечатай ги преди и след. После добави втора функция `void order(int *a, int *b)`, която сама разменя числата така, че след извикването `*a` да е по-малкото. Накрая пробвай всички три числови типа: `int`, `unsigned char` и `double` (за `double` ще ти трябват указатели към `double`).

Допълнителна задача: отпечатай `sizeof` на `size_t`, `long long` и `uint8_t` и обясни резултата.

**Как да проверя дали се справих:**
- Програмата се компилира с `-Wall -Wextra` без нито едно предупреждение.
- Размяната променя оригиналните променливи в `main`, а не само копия.
- `order(&x, &y)` дава подредено при всеки от случаите: `x < y`, `x > y`, `x == y`.
- Можеш да обясниш защо при извикването пишеш `&x`, а в тялото на функцията `*a`.
- Никъде не дереференцираш указател, който не сочи към реална променлива.
- Можеш да обясниш с една дума разликата между `age` и `&age`.

## Бърза справка

| Искаш | Пишеш |
|---|---|
| Размер на тип или променлива | `sizeof(int)`, `sizeof(x)` |
| Тип с точен размер | `int32_t`, `uint8_t` от `<stdint.h>` |
| Граници на `int` | `INT_MAX`, `INT_MIN` от `<limits.h>` |
| Декларирай указател | `int *p;` |
| Адрес на променлива | `&x` |
| Стойност през указател | `*p` |
| Празен указател | `NULL` |
| Печат на адрес | `printf("%p\n", (void *)p);` |
| Следващ елемент | `p + 1` (прибавя `sizeof(*p)` байта) |
| Функция променя външна променлива | параметър `int *a`, извикване `f(&x)` |

## Обобщение

В C всеки тип има фиксиран размер, а числата имат граници, които не бива да се прекрачват, особено при тип със знак. Паметта е поредица от номерирани байтове, а указателят е променлива, която пази такъв номер: `&` взима адрес, `*` отива на адрес. Тъй като функциите получават копия, адресът е начинът функция да промени чужда променлива. Нулевите, неинициализираните и висящите указатели са дефекти, които компилаторът само понякога хваща. В следващия урок ще видиш, че масивите и низовете са точно поредици от байтове, до които стигаш с указатели.

## Бележки за видеото
- Покажи изхода на `sizes.c` и обясни защо `long` на Windows може да е различен.
- Нарисувай паметта като улица с номера и отбележи на нея `age`, `p` и стойността им.
- Пусни `ptr.c` два пъти и подчертай, че адресът се променя.
- Покажи `swap_value` и `swap_ptr` един до друг и проследи копията на `a` и `b`.
- Покажи `Segmentation fault` при `NULL` и предупреждението `-Wreturn-local-addr`.
- Покажи `INT_MAX + 1`, като подчертаеш, че резултатът не е гарантиран от езика.
