## Защо модули
Докато програмата е на двадесет реда, един файл е достатъчен. Когато нарасне, започваш да търсиш функции в стотици редове, имената се бият, а всяка промяна може да счупи нещо на друго място. Модулът е файл със собствен обхват: това, което не изнесеш, остава скрито, а това, което ти трябва, внасяш изрично. Така всеки файл има ясна задача, а зависимостите се виждат в началото му.

Ще изградим малко приложение за задачи от три файла: `tasks.js` (чисти функции), `store.js` (клас със състояние) и `app.js` (показване в страницата).

## Износ и внос
Започваме с чистия модул:

```js
// tasks.js
export function addTask(tasks, title) {
  const clean = title.trim();
  if (clean === "") return tasks;
  return [...tasks, { id: tasks.length + 1, title: clean, done: false }];
}
export const toggle = (tasks, id) =>
  tasks.map((t) => (t.id === id ? { ...t, done: !t.done } : t));
export const remaining = (tasks) => tasks.filter((t) => !t.done).length;
export default function summary(tasks) {
  return `${remaining(tasks)} от ${tasks.length} остават`;
}
```

Думата `export` пред декларацията я прави достъпна отвън. Модулът може да има много именувани износи и най-много един подразбиран (`export default`). Вносът ги различава:

```js
import summary, { addTask, toggle, remaining } from "./tasks.js";
import * as T from "./tasks.js";
```

Подразбираният се внася без къдрави скоби и под име по твой избор. Именуваните са в скоби и с точното си име (можеш да го смениш с `as`, например `import { toggle as flip }`). Формата `* as T` събира всичко в един обект. В пътя на файла задължително се пише разширението и началото `./` за относителен път.

Какво вижда `T`? Подразбираният износ е записан под името `default`:

```js
console.log(Object.keys(T));
```

```
[ 'addTask', 'default', 'remaining', 'toggle' ]
```

Ако поискаш име, което не е изнесено, получаваш грешка още преди програмата да тръгне:

```
SyntaxError: The requested module './tasks.js' does not provide an export named 'nope'
```

Ето защо много екипи предпочитат именувани износи: името не може да бъде объркано, а редакторът го подсказва. Подразбираният износ е удобен, когато файлът има една главна функция или клас.

Модулът има и други свойства. Той работи в строг режим (strict mode) автоматично, има собствен обхват, не създава глобални променливи и се изпълнява само веднъж, дори да бъде внесен от много места.

### Модули в браузъра и в Node.js
В страницата модулът се зарежда с `type="module"`. Такъв скрипт е отложен (като `defer`), затова не е нужно да го слагаш в края на `body`:

```html
<script type="module" src="./app.js"></script>
```

Ако отвориш страницата директно като файл, Chromium блокира зареждането. Съобщението (с пътя съкратено) е:

```
Access to script at 'file:///…/app.js' from origin 'null' has been blocked by CORS policy: Cross origin requests are only supported for protocol schemes: chrome, chrome-untrusted, data, http, https.
```

Решението е да обслужваш папката през локален сървър. В курса за Node.js (`node-api-bazi`) ще напишеш такъв за минути, а между другото много редактори и инструменти имат вграден сървър за разработка. Същата страница, обслужена от `127.0.0.1`, работи.

Node.js разпознава модул по две неща: файл с разширение `.mjs`, или файл `.js` в папка, където `package.json` съдържа `{ "type": "module" }`. Именно така са пуснати примерите в този урок с командата `node main.js`.

## Класове
Класът е шаблон за обекти, които имат общи данни и поведение. Държим състоянието на задачите в клас:

```js
// store.js
import { addTask, toggle } from "./tasks.js";

export class TaskStore {
  #tasks = [];
  #listeners = new Set();
  static from(titles) {
    const s = new TaskStore();
    for (const t of titles) s.add(t);
    return s;
  }
  get tasks() { return this.#tasks; }
  get count() { return this.#tasks.length; }
  subscribe(fn) { this.#listeners.add(fn); return () => this.#listeners.delete(fn); }
  #emit() { for (const fn of this.#listeners) fn(this.#tasks); }
  add(title) { this.#tasks = addTask(this.#tasks, title); this.#emit(); }
  toggle(id) { this.#tasks = toggle(this.#tasks, id); this.#emit(); }
}
```

Какво виждаш:

- Класът се използва с `new TaskStore()`. Без `new` получаваш `TypeError: Class constructor Circle cannot be invoked without 'new'` (тук `Circle` е името на клас от проба).
- Полета с `#` пред името са частни: достъпни са само от кода вътре в класа. Опит да ги прочетеш отвън не е „undefined“, а синтактична грешка: `SyntaxError: Private field '#tasks' must be declared in an enclosing class`.
- `get tasks()` е getter: чете се като свойство (`store.tasks`), но е функция.
- `static from(...)` се вика върху самия клас (`TaskStore.from([...])`), не върху обект.
- `subscribe` връща функция за отписване. Така страницата казва „извести ме при промяна“ и по-късно може да спре.

Използване:

```js
const store = TaskStore.from(["Идея", "Скрипт"]);
const stop = store.subscribe((tasks) => console.log("промяна:", tasks.length, "задачи"));
store.add("Запис");
store.toggle(2);
stop();
store.add("Монтаж");
console.log(store.count, store instanceof TaskStore, typeof TaskStore);
```

```
промяна: 3 задачи
промяна: 3 задачи
4 true function
```

След `stop()` добавянето на „Монтаж“ вече не вика слушателя, но състоянието расте до четири. Забележи, че `typeof TaskStore` е `function`: класът е по-удобен запис върху функция.

### Частно, но не неизменяемо
`#tasks` не може да се прочете отвън, но getter-ът връща самия масив, и някой може да го промени:

```js
const s = new TaskStore();
console.log(s.tasks === s.tasks, s["#tasks"]);
s.tasks.push({ id: 9 });
console.log(s.count);
```

```
true undefined
1
```

Частното поле защитава променливата, не съдържанието. Ако искаш вътрешното състояние да е недосегаемо, върни копие (`[...this.#tasks]`) или се довери на правилото „не променяме масива отвън“. Именно затова модулът `tasks.js` е написан с чисти функции.

### Наследяване
Класът може да разшири друг с `extends`. Методите на наследника заменят тези на родителя, а `super` вика родителя:

```js
class Shape {
  constructor(name) { this.name = name; }
  describe() { return `${this.name}: ${this.area().toFixed(2)}`; }
  area() { return 0; }
}
class Circle extends Shape {
  constructor(r) { super("кръг"); this.r = r; }
  area() { return Math.PI * this.r ** 2; }
}
class Rect extends Shape {
  constructor(w, h) { super("правоъгълник"); this.w = w; this.h = h; }
  area() { return this.w * this.h; }
}
for (const s of [new Circle(1), new Rect(2, 3), new Shape("празна")]) console.log(s.describe(), s instanceof Shape);
```

```
кръг: 3.14 true
правоъгълник: 6.00 true
празна: 0.00 true
```

Наследявай само когато връзката е наистина „е вид“. Често е по-просто да направиш обекти от по-малки части и функции.

## Чисти функции и разделяне на отговорностите
Чистата функция при едни и същи аргументи връща един и същ резултат и не променя нищо извън себе си: нито входните данни, нито глобални променливи, нито страницата. Такива са `addTask`, `toggle` и `remaining`:

```js
const a = [];
const b = addTask(a, "  Монтирай клип ");
const c = toggle(b, 1);
console.log(a, b, c, b === c);
console.log(summary(b), "|", summary(c), "|", remaining(c));
```

```
[] [ { id: 1, title: 'Монтирай клип', done: false } ] [ { id: 1, title: 'Монтирай клип', done: true } ] false
1 от 1 остават | 0 от 1 остават | 0
```

`a` остава празен, `b` е нов масив, а `c` е друг нов масив със сменено `done`. Тези функции се проверяват с едно извикване, без страница и без мрежа. Нечистата част е сведена до `store.js` (състояние) и `app.js` (страница).

Правилото „една отговорност на файл“ ти дава три слоя: логика (`tasks.js`), състояние (`store.js`) и показване (`app.js`):

```js
// app.js
import { TaskStore } from "./store.js";
import summary from "./tasks.js";

const store = new TaskStore();
const list = document.querySelector("#list");
const input = document.querySelector("#t");

function render(tasks) {
  list.replaceChildren(...tasks.map((t) => {
    const li = document.createElement("li");
    li.textContent = t.title + (t.done ? " (готово)" : "");
    li.dataset.id = t.id;
    return li;
  }));
  document.title = summary(tasks);
}
store.subscribe(render);
document.querySelector("#add").addEventListener("click", () => { store.add(input.value); input.value = ""; });
list.addEventListener("click", (e) => { const li = e.target.closest("li"); if (li) store.toggle(Number(li.dataset.id)); });
```

Обслужено от локален сървър, добавянето на „Идея“ и „Монтаж“ и щракване върху първия ред дава `<li data-id="1">Идея (готово)</li><li data-id="2">Монтаж</li>`, а заглавието на раздела е `1 от 2 остават`. В конзолата `this` на най-горно ниво в модула е `undefined`, а `window.store` – също `undefined`: променливите на модула не изтичат в глобалния обхват.

3. Изнеси ги с `export` и ги внеси там, където трябват.
4. Ако има състояние с няколко действия, събери го в клас.
5. Единствено в `app.js` пипай страницата.

## Чести грешки
- **Липсва разширение или `./` във вноса** – `import x from "tasks"` не се намира. Пиши `"./tasks.js"`.
- **Отваряне на модулна страница с двоен клик** – блокира се от CORS. Ползвай локален сървър.
- **Смесване на именуван и подразбиран износ** – `import { summary }` вместо `import summary`. Грешката идва от `SyntaxError ... does not provide an export named`.
- **Циклични вноси** – два модула, внасящи се взаимно, могат да четат стойност, която още не е създадена. Измести общото в трети файл.
- **Промяна на входните данни** – `tasks.push(...)` вътре в функция чупи чистотата. Връщай нов масив.
- **Клас за всичко** – не всяко нещо иска `class`; функции и обикновени обекти често стигат.
- **Очакване частното поле да замрази съдържанието** – getter-ът връща същия масив.

## Упражнение
Раздели програмата си от предишните уроци (например списък със задачи или клипове) на два модула: `logic.js` с поне две чисти функции (без `document`) и `app.js`, който ги внася и пипа страницата. Добави и проста проверка с `console.log` на логиката в Node.

Критерии за проверка:
- `logic.js` не споменава `document`, не променя входните данни и може да се пусне в Node
- има поне един именуван износ и ясен подразбиран износ или само именувани
- `app.js` се зарежда с `type="module"` през локален сървър без грешки в конзолата
- никоя променлива не е глобална
- при празен вход функцията връща входните данни непроменени

## Бърза справка
| Задача | Код |
| --- | --- |
| Именуван износ | `export const a = 1;` |
| Подразбиран износ | `export default function f() {}` |
| Внос | `import f, { a } from "./x.js";` |
| Целия модул | `import * as X from "./x.js";` |
| Модул в страница | `<script type="module" src="app.js">` |
| Node модул | `.mjs` или `"type": "module"` |
| Клас | `class A { #x = 1; get x() { return this.#x; } }` |
| Статичен метод | `static from() {}` |
| Наследяване | `class B extends A { constructor() { super(); } }` |

## Обобщение
Модулът е файл със собствен обхват: изнасяш с `export`, внасяш с `import`, а страницата го зарежда с `type="module"` от локален сървър. Класът описва обекти със състояние и методи, а частните полета с `#` пазят вътрешните променливи. Чистите функции не променят нищо и лесно се проверяват, затова логиката се държи отделно от състоянието и от показването.
