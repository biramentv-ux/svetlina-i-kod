> **Цел на урока:** да взимаш данни от сървър с `fetch`, да различаваш успех, HTTP грешка и мрежова грешка и да показваш чужди данни безопасно.

## Какво ще научиш
- Как се прави заявка с `fetch` и какво връща тя
- Защо `response.ok` е задължителна проверка и защо 404 не е изключение
- Как да покажеш на потребителя три състояния: зареждане, успех, грешка
- Как се четат и пращат данни във формат JSON
- Как да вмъкнеш чужд текст в страницата, без да пуснеш чужд код

## Заявка и отговор

Когато отвориш страница, браузърът праща **заявка** (request) до сървър и получава **отговор** (response). Всеки отговор има три важни части: **статус код** (200 – успех, 404 – няма такъв адрес, 500 – грешка на сървъра), **заглавия** (headers, например типът на съдържанието) и **тяло** (body) с данните. Функцията `fetch(url)` прави същото от твоя код, без да презарежда страницата. Връща Promise (виж предишния урок), който се изпълнява, когато пристигнат статусът и заглавията. Тялото се чете отделно, с втори Promise: най-често `response.json()`, който разчита тялото като JSON.

JSON е текстов формат за данни: обекти `{...}`, масиви `[...]`, низове, числа, `true`, `false` и `null`. Изглежда като JavaScript обект, но имената на полетата са в двойни кавички, а коментари и функции няма. `JSON.stringify(стойност)` превръща стойност в текст, а `JSON.parse(текст)` прави обратното.

Няма да ползваме чужд публичен адрес. Ще си направим собствен учебен сървър на твоя компютър, който симулира успех, грешка и бавен отговор.

## Собствен сървър за упражнения

Запиши този файл като `server.mjs` в празна папка (нужен е само Node.js 22, без инсталиране на пакети):

```js
import { createServer } from "node:http";
import { readFile } from "node:fs/promises";

const tasks = [
  { id: 1, text: "Да подредя клавиатурата", done: true },
  { id: 2, text: "Да напиша урока за fetch", done: false },
  { id: 3, text: "<img src=x onerror=\"document.title='хакнат'\"> текст с таг", done: false },
];

function sendJson(res, status, data) {
  res.writeHead(status, { "Content-Type": "application/json; charset=utf-8" });
  res.end(JSON.stringify(data));
}

const server = createServer(async (req, res) => {
  const { pathname } = new URL(req.url, "http://127.0.0.1");

  if (pathname === "/" || pathname === "/app.js") {
    const file = pathname === "/" ? "index.html" : "app.js";
    const type = file.endsWith(".js") ? "text/javascript" : "text/html";
    res.writeHead(200, { "Content-Type": type + "; charset=utf-8" });
    return res.end(await readFile(new URL(file, import.meta.url)));
  }
  if (pathname === "/api/tasks" && req.method === "GET") return sendJson(res, 200, tasks);
  if (pathname === "/api/tasks" && req.method === "POST") {
    let body = "";
    for await (const chunk of req) body += chunk;
    const created = { id: tasks.length + 1, ...JSON.parse(body), done: false };
    tasks.push(created);
    return sendJson(res, 201, created);
  }
  if (pathname === "/api/error") return sendJson(res, 500, { error: "Нещо се счупи на сървъра" });
  if (pathname === "/api/slow") {
    await new Promise((resolve) => setTimeout(resolve, 3000));
    return sendJson(res, 200, []);
  }
  sendJson(res, 404, { error: "Няма такъв адрес" });
});

server.listen(Number(process.argv[2] ?? 3457), "127.0.0.1", () =>
  console.log("слушам на 127.0.0.1:" + server.address().port));
```

Третата задача нарочно съдържа HTML таг; ще видим защо след малко. Пусни сървъра с `node server.mjs` в отделен терминал и го затвори с Ctrl+C, когато свършиш.

## Първата заявка (в Node)

`fetch` е вграден и в Node 22, затова най-бързият опит е без страница:

```js
const base = "http://127.0.0.1:3457";
const response = await fetch(base + "/api/tasks");
console.log(response.ok, response.status, response.headers.get("content-type"));
const tasks = await response.json();
console.log(tasks.length, "задачи; първата:", tasks[0]);
try {
  await response.json();
} catch (err) {
  console.log("второ четене:", err.name + ": " + err.message);
}

const missing = await fetch(base + "/api/missing");
console.log("404 не е изключение:", missing.ok, missing.status, await missing.json());
```

```
true 200 application/json; charset=utf-8
3 задачи; първата: { id: 1, text: 'Да подредя клавиатурата', done: true }
второ четене: TypeError: Body is unusable: Body has already been read
404 не е изключение: false 404 { error: 'Няма такъв адрес' }
```

Три извода:
- Тялото може да се прочете само веднъж. Ако ти трябва два пъти, запази резултата в променлива.
- **404 и 500 не отхвърлят Promise.** Заявката е минала, сървърът е отговорил, просто отговорът не е добър. Затова проверяваш `response.ok` (истина за статуси от 200 до 299) или `response.status`.
- Отхвърляне има при **мрежова грешка**: няма връзка, няма такъв сървър, прекъсната заявка. Тогава `fetch` хвърля `TypeError`.

| Случай | Какво прави `fetch` | Как го разпознаваш |
|---|---|---|
| Успех (200–299) | изпълнява Promise | `response.ok === true` |
| HTTP грешка (404, 500) | изпълнява Promise | `response.ok === false` |
| Няма сървър, няма мрежа | отхвърля с `TypeError` | `catch` |
| Таймаут през `AbortSignal` | отхвърля с `TimeoutError` | `catch`, `err.name` |
| Отговорът не е JSON | `response.json()` отхвърля със `SyntaxError` | `catch` |

## Три състояния в страницата

Добрата страница никога не е „празна и мълчалива“. Тя показва едно от три състояния: **зареждане**, **успех** или **грешка**. Ето `index.html` и `app.js` (в същата папка като сървъра):

```html
<!doctype html>
<html lang="bg">
<meta charset="utf-8">
<title>Задачи от сървъра</title>
<h1>Задачи</h1>
<p id="status" role="status"></p>
<ul id="list"></ul>
<script type="module" src="/app.js"></script>
```

```js
const statusEl = document.querySelector("#status");
const listEl = document.querySelector("#list");

async function getJson(url, options = {}) {
  const response = await fetch(url, options);
  if (!response.ok) {
    throw new Error(`Сървърът върна ${response.status} ${response.statusText}`);
  }
  return response.json();
}

function render(tasks) {
  listEl.replaceChildren();
  for (const task of tasks) {
    const li = document.createElement("li");
    li.textContent = (task.done ? "[x] " : "[ ] ") + task.text;
    listEl.append(li);
  }
}

async function loadTasks(url) {
  statusEl.textContent = "Зареждане…";
  try {
    const tasks = await getJson(url);
    render(tasks);
    statusEl.textContent = `Заредени: ${tasks.length}`;
  } catch (err) {
    listEl.replaceChildren();
    statusEl.textContent = "Грешка: " + err.message;
  }
}

const url = new URLSearchParams(location.search).get("url") ?? "/api/tasks";
await loadTasks(url);
console.log("статус:", statusEl.textContent, "| елементи:", listEl.children.length);
```

Помощната `getJson` събира в едно трите стъпки (заявка, проверка, четене) и превръща HTTP грешката в обикновено изключение, така че извикващият код има само един път за грешки. Заредихме страницата в Chromium с Playwright; ето какво отпечата конзолата за три адреса (отпред е адресът, който заредихме):

```
/                    статус: Заредени: 3 | елементи: 3
/?url=/api/error     статус: Грешка: Сървърът върна 500 Internal Server Error | елементи: 0
/?url=/api/missing   статус: Грешка: Сървърът върна 404 Not Found | елементи: 0
```

При грешките браузърът добавя и собствено съобщение „Failed to load resource“. Текстът след кода („Internal Server Error“) идва от `response.statusText`; при някои протоколи той може да е празен, затова не разчитай на него, а на числото.

## Чужд текст и innerHTML

Данните от сървър са **чужди**: някой друг ги е написал или е могъл да ги промени. Третата ни задача съдържа таг `<img>` с атрибут `onerror`, който би изпълнил код. Нека видим какво става, ако я вмъкнем с `innerHTML`. Това е нарочно лош учебен вариант, пуснат само върху нашата страница:

```js
const unsafe = document.createElement("ul");
document.body.append(unsafe);
unsafe.innerHTML = tasks.map((task) => `<li>${task.text}</li>`).join("");
```

Резултат в Chromium: в страницата се появи реален елемент `img`, а заглавието на документа стана „хакнат“. Браузърът е разчел текста като HTML и е изпълнил кода от атрибута. В истинско приложение там би имало вредно действие. Тази слабост се нарича XSS.

Поправката е във `render` по-горе: `li.textContent = ...`. Свойството `textContent` слага текст като текст и таговете се виждат буквално. В теста със същите данни страницата показа `[ ] <img src=x onerror="document.title='хакнат'"> текст с таг`, елементи `img` нямаше, а заглавието остана непроменено. Правилото: **чужди данни влизат през `textContent`**, а `innerHTML` е само за HTML, който си написал ти.

## Изпращане на данни и таймаут

За да пратиш данни, подаваш втори аргумент: метод, заглавие за типа и тяло като JSON текст. Бавните сървъри се прекъсват с `AbortSignal.timeout`:

```js
const created = await fetch(base + "/api/tasks", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "Нова задача" }),
});
console.log(created.status, await created.json());

try {
  await fetch(base + "/api/slow", { signal: AbortSignal.timeout(500) });
} catch (err) {
  console.log("таймаут:", err.name, "-", err.message);
}

try {
  await fetch("http://127.0.0.1:3999/");
} catch (err) {
  console.log("няма сървър:", err.name, "-", err.message, "-", err.cause.code);
}
```

```
201 { id: 4, text: 'Нова задача', done: false }
таймаут: TimeoutError - The operation was aborted due to timeout
няма сървър: TypeError - fetch failed - ECONNREFUSED
```

Статус 201 значи „създадено“. Съобщенията за грешки са на английски и се различават между Node и браузърите (в Chromium мрежовата грешка е `TypeError: Failed to fetch`), затова в интерфейса показвай собствен български текст, а техническото съобщение записвай в конзолата.

## Защо не работи от файл и какво е CORS

Ако отвориш `index.html` направо от диска (адрес `file://…`) и поискаш `fetch("tasks.json")`, Chromium отказва: `Fetch API cannot load file:///…/tasks.json. URL scheme "file" is not supported.` и `fetch` отхвърля с `TypeError: Failed to fetch`. Решението е да сервираш страницата през сървър, както направихме.

Втората спънка е **CORS**. Страница от един произход (схема, адрес и порт) не може да чете отговорите на друг, освен ако сървърът не позволи това със заглавие `Access-Control-Allow-Origin`. Когато от страница на порт 3457 поискахме данни от втори екземпляр на сървъра на порт 3458, Chromium блокира заявката: `Access to fetch at 'http://127.0.0.1:3458/api/tasks' from origin 'http://127.0.0.1:3457' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.` Проблемът не се решава от страната на страницата, а от сървъра. Подробно ще го разгледаш в курса `node-api-bazi`.

## Стъпка по стъпка
1. Създай папка с `server.mjs`, `index.html` и `app.js` от урока и пусни сървъра.
2. Отвори адреса на сървъра в браузъра и в раздела за мрежата на инструментите за разработчици виж заявката към `/api/tasks`.
3. Добави `?url=/api/error` към адреса и провери, че се показва грешката.
4. Замени `textContent` с `innerHTML` само за да видиш разликата, и върни поправката.
5. Добави бутон „Презареди“, който извиква `loadTasks` отново.
6. Спри сървъра и натисни бутона: трябва да видиш съобщение за мрежова грешка, а не празна страница.

## Пример от практиката

Да кажем, че правиш страница с програмата на местна проява и данните идват от файл на сървъра. Първо показваш „Зареждане…“. Ако сървърът върне 404, потребителят чете „Програмата не е намерена“, а ако връзката падне, „Няма връзка, опитай пак“, и двата пъти с бутон за повторение. Заглавие със знак `<` се вижда като текст, защото минава през `textContent`.

## Чести грешки
- **Липсва проверка на `response.ok`** – при 404 `response.json()` може да хвърли странна грешка за невалиден JSON или да даде обект с грешка, който кодът ти приема за данни.
- **Двойно четене на тялото** – `response.json()` втори път хвърля `Body is unusable`.
- **`innerHTML` с чужди данни** – отваря вратата за XSS. Ползвай `textContent` или `createElement`.
- **Отваряне през `file://`** – `fetch` не работи; пусни локален сървър.
- **Липсва `Content-Type` при POST** – сървърът не разбира тялото.

## Упражнение

Разшири примера: добави форма с едно поле, която праща нова задача с POST към `/api/tasks` и след отговор 201 я добавя в списъка. Покажи „Изпращане…“ по време на заявката и български текст при грешка. Добави таймаут от две секунди към зареждането.

Критерии: (1) има и трите състояния; (2) проверява се `response.ok`; (3) таговете в текста на задача се виждат като текст; (4) при спрян сървър се появява съобщение, а не празна страница; (5) в конзолата няма необработени грешки.

## Бърза справка
- `const response = await fetch(url, options)`; `response.ok`, `response.status`, `await response.json()` (само веднъж)
- 404 и 500 не отхвърлят Promise; мрежова грешка отхвърля с `TypeError`
- POST: `method`, `headers: {"Content-Type": "application/json"}`, `body: JSON.stringify(...)`
- Таймаут: `signal: AbortSignal.timeout(мс)`
- Чужд текст: `textContent`, не `innerHTML`
- `file://` не позволява `fetch`; CORS се решава от сървъра

## Обобщение
`fetch` праща заявка и връща Promise, който се изпълнява и при HTTP грешки, затова проверяваш `response.ok`. Грешките в мрежата отхвърлят Promise и се хващат с `catch`. Добрата страница показва зареждане, успех или грешка, а чуждите данни слага само с `textContent`. С това можеш да заредиш данни от своя сървър. В курса `node-api-bazi` ще направиш такъв сървър по-сериозно, а следващият урок ще научи страницата да помни данни и без сървър.

## Бележки за видеото
Видеото показва: страница със „Зареждане…“ и данни от адрес; `fetch` с `await` и `response.ok`; показване на текста с `textContent`; обработка на грешка с `try/catch`, когато адресът не може да се зареди и страницата показва „Грешка: TypeError“. За простота в кадъра данните идват от адрес от тип `data:`, а не от сървър; в урока ползваш `server.mjs`.
