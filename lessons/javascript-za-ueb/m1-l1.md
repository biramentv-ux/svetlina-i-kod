> **Цел на урока:** да свързваш действията на потребителя с кода: да обработваш събития, да четеш данни от форма, да спираш стандартното поведение и да ползваш делегиране на събития.

## Какво ще научиш
- как работи `addEventListener` и какво съдържа обектът на събитието
- как да обработваш форма със `submit` и `preventDefault`
- как да четеш полетата с `FormData` и да ги валидираш
- как се разпространява събитието и защо делегирането пести код
- как да махаш слушатели и да ги пускаш само веднъж

## Събития и слушатели
Събитие е сигнал, че нещо се е случило: щракване, натискане на клавиш, промяна в поле, изпращане на форма. Браузърът създава обект на събитието и го подава на функция, която си регистрирал с `addEventListener(тип, функция)`. Тази функция се нарича слушател или обработчик.

Най-честите типове:

| Събитие | Кога настъпва |
| --- | --- |
| `click` | щракване (и натискане на Enter или интервал върху бутон) |
| `input` | при всяка промяна на стойността на поле |
| `change` | след приключване на промяна (при текст – при напускане на полето) |
| `submit` | изпращане на формата |
| `keydown`, `keyup` | натискане и пускане на клавиш |
| `focus`, `blur` | получаване и загуба на фокус |
| `DOMContentLoaded` | документът е разчетен |

Не се закачай за `click` на `div` вместо бутон. Истинският `<button>` се фокусира с клавиатурата и се задейства с Enter и интервал, което прави страницата достъпна. Събитието има полезни полета: `event.type`, `event.target` (елементът, върху който е станало), `event.currentTarget` (елементът, към който е закачен слушателят) и за клавиатурата `event.key` и `event.code`.

Слушателят е обикновена функция. Една и съща функция, закачена два пъти със същите параметри, се регистрира само веднъж, а различните анонимни функции се натрупват. Проверка с бутон показва това:

```js
function hello(e) { console.log("hello", e.type, e.isTrusted); }
b.addEventListener("click", hello);
b.addEventListener("click", hello);
b.addEventListener("click", () => console.log("втори слушател"));
b.click();
b.removeEventListener("click", hello);
b.click();
b.addEventListener("click", () => console.log("веднъж"), { once: true });
b.click(); b.click();
```

```
hello click false
втори слушател
втори слушател
втори слушател
веднъж
втори слушател
```

Първото извикване печата `hello` само веднъж, макар да е добавен два пъти. След `removeEventListener` остава само вторият слушател. Опцията `{ once: true }` изпълнява слушателя еднократно. `removeEventListener` изисква същата функция, затова анонимна функция не може да се махне: запиши я в променлива. Полето `isTrusted` е `false`, защото събитието е предизвикано от кода с `b.click()`; при истинско щракване е `true`.

## Форми: submit и preventDefault
Когато формата бъде изпратена, браузърът по подразбиране презарежда страницата или отива на адреса от `action`. За приложение в една страница искаме да се справим сами. Затова слушаме `submit` и викаме `event.preventDefault()`, което спира стандартното действие:

```html
<form id="f" novalidate>
  <label for="t">Задача</label>
  <input id="t" name="task" required minlength="3">
  <select name="prio"><option value="low">ниска</option><option value="high">висока</option></select>
  <button type="submit">Добави</button>
  <p id="err" role="alert"></p>
</form>
<ul id="list"></ul>
```

```js
const form = document.querySelector("#f");
const list = document.querySelector("#list");
const err = document.querySelector("#err");

form.addEventListener("submit", (event) => {
  event.preventDefault();
  const data = new FormData(form);
  const task = String(data.get("task")).trim();
  console.log("submit:", event.type, event.defaultPrevented, JSON.stringify(Object.fromEntries(data)));
  if (task.length < 3) { err.textContent = "Напиши поне 3 знака."; return; }
  err.textContent = "";
  const li = document.createElement("li");
  li.dataset.prio = data.get("prio");
  const span = document.createElement("span"); span.textContent = task;
  const btn = document.createElement("button");
  btn.type = "button"; btn.textContent = "Изтрий"; btn.dataset.action = "delete";
  li.append(span, " ", btn);
  list.append(li);
  form.reset();
  form.elements.task.focus();
});
```

Слушаме `submit` върху формата, а не `click` върху бутона. Така кодът се изпълнява и когато потребителят натисне Enter в полето. `new FormData(form)` събира всички полета с атрибут `name`; `data.get("task")` връща стойността, а `Object.fromEntries(data)` я превръща в обикновен обект. Стойностите са винаги низове (или файлове), затова текстът се чисти с `trim()`, а числата се превръщат с `Number()`.

Да проиграем сесия: въвеждаш `ab` и натискаш „Добави“, после пишеш `Ку` и натискаш Escape, добавяш „Купи боя“ с висок приоритет и „Заснеми клип“ с Enter. Конзолата (в Chromium, управляван с Playwright) показа:

```
input: "ab"
submit: submit true {"task":"ab","prio":"low"}
грешка: Напиши поне 3 знака.
input: ""
input: "К"
input: "Ку"
keydown: Escape Escape
input: "Купи боя"
submit: submit true {"task":"Купи боя","prio":"high"}
input: "Заснеми клип"
submit: submit true {"task":"Заснеми клип","prio":"low"}
```

Събитието `input` се задейства при всеки знак. Escape изчиства полето през кода и затова не предизвиква нов `input`. Редът „грешка“ е текстът в абзаца `#err`, а не от конзолата.

### Валидация
Браузърът знае правилата от атрибутите `required`, `type="email"`, `min`, `max`, `minlength`. Полето има `validity`, а формата – `checkValidity()`:

```html
<form id="f" novalidate>
  <input name="email" type="email" required>
  <input name="n" type="number" min="1" max="5">
</form>
```

```js
const f = document.querySelector("#f");
const email = f.elements.email, n = f.elements.n;
console.log(f.checkValidity(), email.validity.valueMissing);
email.value = "не-е-имейл";
console.log(email.validity.typeMismatch, f.checkValidity());
email.value = "ana@example.com";
n.value = "9";
console.log(n.validity.rangeOverflow, f.checkValidity());
n.value = "3";
console.log(f.checkValidity(), typeof n.value, n.valueAsNumber);
```

```
false true
true false
true false
true string 3
```

Първият ред казва, че празната форма е невалидна, защото липсва задължителна стойност. Вторият показва грешен тип (`typeMismatch`), третият – надхвърлен максимум (`rangeOverflow`), а в четвъртия формата е валидна, `value` е низ, а `valueAsNumber` е числото 3. Без `novalidate` браузърът сам показва съобщения и не вика `submit` при невалидна форма. С `novalidate`, както по-горе, показваш свои съобщения на български. Валидацията в браузъра е само удобство за потребителя: в курса за Node.js (`node-api-bazi`) ще видиш защо сървърът проверява данните отново.

## Разпространение и делегиране
Щракването върху елемент минава през родителите му. Първо се изпълняват слушателите на самия елемент, после на родителите нагоре (фаза „балон“, bubbling). Затова един слушател на родителя вижда събитията на всички деца. Това е делегиране на събития:

```js
list.addEventListener("click", (event) => {
  console.log("click: target=" + event.target.tagName, "currentTarget=" + event.currentTarget.tagName);
  const btn = event.target.closest("button[data-action='delete']");
  if (!btn) return;
  btn.closest("li").remove();
});
```

```
click: target=BUTTON currentTarget=UL
останаха: [ 'Заснеми клип' ]
```

Слушателят е само един и работи и за елементи, добавени по-късно: при отделни слушатели те щяха да останат без такъв. Защитата `if (!btn) return` игнорира щраквания върху останалите части на списъка. `closest` е важен, когато вътре в бутона има други елементи (икона, текст): `target` ще е тя, а не бутонът. Разпространението може да се спре с `event.stopPropagation()`, но правете го рядко, защото чупи слушатели на други места.

## Стъпка по стъпка
1. Намери формата и нужните полета и ги запиши в константи.
2. Закачи слушател за `submit` и веднага извикай `event.preventDefault()`.
3. Прочети данните с `new FormData(form)` и изчисти текста с `trim()`.
4. Провери правилата и при грешка покажи съобщение в елемент, не с `alert`.
5. Ако данните са валидни, създай елемент със `textContent` и го закачи в списъка.
6. Изчисти формата с `form.reset()` и върни фокуса на първото поле.
7. За бутоните вътре в списъка ползвай един слушател на родителя и `closest`.

## Пример от практиката
Да кажем, че правиш табло със задачи за монтаж. Всеки запис има приоритет, който се пази в `data-prio`. С един CSS селектор `li[data-prio="high"]` оцветяваш важните, а делегираният слушател маха изпълнените. Формата остава работеща и при Enter, не презарежда страницата, а фокусът се връща към полето, така че следващата задача може да се напише веднага.

## Чести грешки
- **Липсва `preventDefault`** – страницата се презарежда и данните се губят.
- **Слушател за `click` на бутона вместо `submit` на формата** – Enter в полето не работи.
- **Слушател върху всеки елемент от списък** – повече код, а новите елементи остават без слушател. Делегирай.
- **`event.target` вместо `closest`** – при вложени елементи `target` е най-вътрешният елемент (например текстът в бутона), а не самият бутон.
- **Анонимна функция в `removeEventListener`** – не съвпада с регистрираната и не се маха. Запиши функцията в променлива.
- **Очакване на число от `input.value`** – винаги е низ: `"3"`. Ползвай `Number()` или `valueAsNumber`.
- **`innerHTML` с текст от потребител** – отваря път за XSS. Ползвай `textContent`.
- **`alert` за грешки** – блокира страницата. Изписвай съобщението в страницата.

## Упражнение
Направи форма „Нов клип“ с полета за заглавие (минимум 3 знака) и продължителност в секунди (число от 1 до 600). При валидно изпращане добавяй ред в списък във вида `Заглавие (м:сс)`, с бутон „Изтрий“, обработван чрез делегиране.

Критерии за проверка:
- страницата не се презарежда при изпращане
- Enter в полето добавя клип
- при невалидни данни се показва съобщение на български и нищо не се добавя
- след успех полетата се изчистват, а фокусът е в първото поле
- има един слушател за „Изтрий“, а не по един на ред
- заглавие с `<b>` се показва буквално

## Бърза справка
| Задача | Код |
| --- | --- |
| Закачане | `el.addEventListener("click", fn)` |
| Махане | `el.removeEventListener("click", fn)` |
| Веднъж | `addEventListener("click", fn, { once: true })` |
| Спиране на стандартното | `event.preventDefault()` |
| Данни от форма | `Object.fromEntries(new FormData(form))` |
| Валидна ли е формата | `form.checkValidity()` |
| Кой е щракнат | `event.target.closest("button")` |
| Клавиш | `event.key` (например `"Escape"`) |
| Изчистване | `form.reset()` |

## Обобщение
Събитията свързват действията на потребителя с кода чрез `addEventListener`. Формите се обработват със `submit` и `preventDefault`, а данните се четат с `FormData`; стойностите са низове и трябва да се чистят и проверяват. Събитията се разпространяват нагоре, затова един слушател на родителя със `closest` обслужва всички деца, включително новите. Показвай чужд текст само със `textContent`.

## Бележки за видеото
Видеото показва форма с поле и бутон на живо отдясно и кода отляво:
- форма с поле и празен списък
- слушател на `submit` с `preventDefault`; в полето се пише `Clip` и Enter добавя ред без презареждане
- един слушател на списъка с `closest` за делегиране; добавя се още един ред
