> **Цел на урока:** да разбереш как JavaScript чака, без да замръзва страницата, и да пишеш асинхронен код с Promise и async/await, който хваща грешките си.

## Какво ще научиш
- Защо JavaScript върши една работа в даден момент и как опашката на събитията му позволява да „чака“
- Какво е Promise и в какви състояния може да бъде
- Как async/await прави асинхронния код да се чете като обикновен
- Как се обработват грешки с try/catch и с метода catch
- Кога да пускаш операциите една след друга и кога едновременно

## Един поток, една опашка

JavaScript изпълнява кода си в един поток: във всеки момент върви само един ред. Затова ако една функция работи дълго, всичко останало чака зад нея: бутоните не реагират, анимациите спират, страницата „замръзва“. Мрежови заявки, таймери и четене на файлове обаче са бавни по природа. Не искаме да ги чакаме на място, а да кажем: „започни, а когато свършиш, извикай този код“. Това е асинхронният код.

Как става това без втори поток? Средата (браузърът или Node.js) държи две опашки, а езикът ги обслужва в цикъл (event loop):

1. Изпълнява се текущият синхронен код до край.
2. Изпълняват се всички чакащи **микрозадачи** (например функциите от `then` на вече готови Promise).
3. Взема се една **задача** от опашката на задачите (таймер, събитие, завършил запис) и цикълът се връща към стъпка 1.

Ето го в действие (пуснато с Node 22):

```js
console.log("1 синхронно: начало");
setTimeout(() => console.log("2 таймер (опашка на задачите)"), 0);
Promise.resolve().then(() => console.log("3 микрозадача (then)"));
console.log("4 синхронно: край");
```

```
1 синхронно: начало
4 синхронно: край
3 микрозадача (then)
2 таймер (опашка на задачите)
```

Таймерът е с нула милисекунди, но все пак излиза последен. Обратният извод е важен: `setTimeout(..., 0)` не значи „веднага“, а „след като свърши текущият код и микрозадачите“. В браузъра това се вижда нагледно. Ако пуснеш цикъл, който заема процесора за половин секунда, таймерът от 10 милисекунди ще се изпълни едва след него. В Chromium получихме:

```
цикълът свърши
таймерът със 10 ms се изпълни след ~500 ms
```

Извод: **никога не блокирай потока с дълги синхронни цикли**. Дългата работа се дава на асинхронни операции (или на Web Worker, ако е чисто изчисление).

## Promise: обещание за бъдеща стойност

Promise е обект, който представя резултат, който още не е наличен. Той е в точно едно от три състояния:

| Състояние | Значение | Какво следва |
|---|---|---|
| pending | още се чака | може да стане fulfilled или rejected |
| fulfilled | успех, има стойност | изпълняват се функциите от `then` |
| rejected | неуспех, има причина (обикновено `Error`) | изпълняват се `catch` и `finally` |

След като Promise излезе от pending, състоянието му не се променя повече. Най-често ще ползваш готови Promise (като този от `fetch`), но е полезно да можеш да направиш свой. Типичният пример е „пауза“:

```js
const pause = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
```

Верижното писане с `then` изглежда така:

```js
const pause = (ms, value) => new Promise((resolve) => setTimeout(() => resolve(value), ms));

pause(100, 2)
  .then((n) => n * 10)
  .then((n) => {
    console.log("вътре във веригата:", n);
    return pause(50, n + 1);
  })
  .then((n) => console.log("след втората пауза:", n));
console.log("веригата е сглобена, но още не е свършила");
```

```
веригата е сглобена, но още не е свършила
вътре във веригата: 20
след втората пауза: 21
```

Всяко `then` връща нов Promise. Ако върнеш обикновена стойност, тя става резултат на следващата стъпка; ако върнеш Promise, веригата го изчаква. Това е полезно, но дълбоките вериги се четат трудно. Затова съществува по-удобен запис.

## async и await

Функция, пред която стои `async`, винаги връща Promise. Вътре в нея `await` спира **само тази функция** до готовността на Promise и връща стойността му. Останалата програма продължава да работи.

```js
const pause = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function greet(name) {
  await pause(200);
  return `Здравей, ${name}!`;
}

console.log("преди");
console.log(await greet("Мила"));
const promise = greet("Борис");
console.log(promise);
console.log(await promise);
```

```
преди
Здравей, Мила!
Promise { <pending> }
Здравей, Борис!
```

Забележи третия ред: без `await` получаваш самия Promise, а не стойността. `await` може да се ползва вътре в `async` функции и на най-горното ниво на ES модул (в Node файлове с разширение `.mjs` и в `<script type="module">`). В обикновен скрипт без модул най-горното `await` дава синтактична грешка.

## Грешки: try/catch и catch

Отхвърленият Promise при `await` се превръща в обикновено изключение, затова го хващаш с `try/catch`. С вериги от `then` се ползва `.catch(...)`. `finally` върви и в двата случая, независимо от изхода:

```js
const pause = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function getTask(id) {
  await pause(100);
  if (id > 3) throw new Error(`Задача ${id} не съществува`);
  return { id, text: `Задача №${id}` };
}

try {
  console.log("ok:", await getTask(2));
  await getTask(7);
  console.log("тук не се стига");
} catch (err) {
  console.log("грешка:", err.message);
} finally {
  console.log("finally се изпълнява винаги");
}

getTask(9)
  .then((task) => console.log(task))
  .catch((err) => console.log("catch:", err.message))
  .finally(() => console.log("край на веригата"));
```

```
ok: { id: 2, text: 'Задача №2' }
грешка: Задача 7 не съществува
finally се изпълнява винаги
catch: Задача 9 не съществува
край на веригата
```

Ако никой не хване отхвърлянето, Node 22 прекратява процеса с код 1 и показва `Error: никой не ме хваща`. Браузърът не спира страницата, но показва в конзолата червена грешка за необработено отхвърляне, а страницата остава в полусчупено състояние. Правило: на всяко място, където започваш асинхронна работа, трябва да има кой да хване грешката.

## Едновременно или последователно

Три независими заявки, пуснати една след друга с `await`, чакат сумата от времената им. Ако не зависят една от друга, пусни ги заедно с `Promise.all`:

```js
const pause = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const round100 = (ms) => Math.round(ms / 100) * 100;
async function fetchPart(name, ms) {
  await pause(ms);
  return name;
}

let start = performance.now();
const a = await fetchPart("профил", 300);
const b = await fetchPart("задачи", 300);
const c = await fetchPart("настройки", 300);
console.log("последователно:", [a, b, c].join(", "), "~" + round100(performance.now() - start), "ms");

start = performance.now();
const parts = await Promise.all([
  fetchPart("профил", 300),
  fetchPart("задачи", 300),
  fetchPart("настройки", 300),
]);
console.log("паралелно:", parts.join(", "), "~" + round100(performance.now() - start), "ms");
```

```
последователно: профил, задачи, настройки ~900 ms
паралелно: профил, задачи, настройки ~300 ms
```

Времената са закръглени и зависят от машината, но съотношението е устойчиво. Другите комбинатори решават различни въпроси:

| Метод | Резултат | Кога го ползвам |
|---|---|---|
| `Promise.all` | масив със стойностите; отхвърля се при първата грешка | всички части са нужни |
| `Promise.allSettled` | масив от `{status, value/reason}` за всяка част | искам изхода на всички, дори при грешки |
| `Promise.race` | първият приключил (успех или грешка) | таймаут, най-бързият източник |
| `Promise.any` | първият успешен; грешка само ако всички паднат | резервни източници |

```js
const broken = () => Promise.reject(new Error("мрежата падна"));

const results = await Promise.allSettled([fetchPart("добре", 100), broken()]);
for (const r of results) {
  console.log(r.status, "->", r.status === "fulfilled" ? r.value : r.reason.message);
}
try {
  await Promise.all([fetchPart("бавно", 500), broken()]);
} catch (err) {
  console.log("Promise.all:", err.message);
}
console.log("race:", await Promise.race([fetchPart("бавно", 400), fetchPart("бързо", 100)]));
console.log("any:", await Promise.any([broken(), fetchPart("втори успя", 50)]));
```

```
fulfilled -> добре
rejected -> мрежата падна
Promise.all: мрежата падна
race: бързо
any: втори успя
```

Тук `fetchPart` е същата помощна функция като в предишния пример.

## Пример от практиката

Да кажем, че страницата ти за мениджър на задачи трябва да покаже профила на потребителя, неговите задачи и настройките му. Трите данни са независими. Ако ги чакаш с три `await` подред, потребителят вижда празна страница, докато не минат трите отговора един след друг. С `Promise.all` времето за зареждане става колкото най-бавната от трите заявки. Ако настройките са по желание, ползваш `Promise.allSettled`: страницата се показва със стандартни настройки, когато те липсват, вместо да откаже да се зареди.

## Чести грешки
- **Забравено `await`** – получаваш Promise вместо стойност: `taskCount() + 1` даде `[object Promise]1`, а правилното `(await taskCount()) + 1` даде `4`.
- **`await` във `forEach`** – `forEach` не чака функциите си. В теста „след forEach“ се изписа преди „forEach край“. За последователно изпълнение ползвай `for...of`, а за паралелно `Promise.all` с `map`.
- **Празен `catch`** – `catch {}` без нищо вътре скрива истинските проблеми. Поне запиши грешката в конзолата или я покажи на потребителя.
- **Последователни `await` за независими работи** – губиш време. Ако втората заявка не ползва резултата от първата, пускай ги заедно.
- **Ползване на `await` извън async или модул** – получаваш синтактична грешка. Сложи `type="module"` или обгради кода в `async` функция.
- **Дълъг синхронен цикъл** – замразява страницата, както в примера с половината секунда.

## Упражнение

Напиши модул `timer.mjs` със следното:
1. `pause(ms)` – връща Promise, който се изпълнява след `ms` милисекунди.
2. `slowSquare(n)` – `async` функция, която чака 200 милисекунди и връща `n * n`; ако `n` не е число, хвърля `Error` със съобщение на български.
3. Скрипт, който смята квадратите на `[1, 2, 3, 4]` първо последователно, после с `Promise.all`, и печата времето на двата варианта.
4. Трети вариант с `Promise.allSettled` върху списък, в който има и нечислова стойност.

Критерии за самопроверка: (1) паралелният вариант е около четири пъти по-бърз; (2) грешката не срива програмата, а се показва като съобщение; (3) няма `await` във `forEach`; (4) няма празен `catch`.

## Бърза справка
- `async function f() {}` винаги връща Promise; `await` е позволено само в `async` функция или в модул
- `new Promise((resolve, reject) => ...)`; състояния: pending, fulfilled, rejected
- `.then(...)`, `.catch(...)`, `.finally(...)` за вериги; `try/catch/finally` за `await`
- `Promise.all`, `Promise.allSettled`, `Promise.race`, `Promise.any`
- Ред: синхронен код, микрозадачи (`then`), задачи (таймери и събития)
- `setTimeout(f, 0)` не е „веднага“

## Обобщение
JavaScript работи в един поток и ползва опашки, за да чака мрежата и таймерите, без да замръзва. Promise е обект за бъдещ резултат, а `async/await` ти позволява да го четеш като обикновена стойност. Грешките се хващат с `try/catch`, а независимите работи се пускат заедно с `Promise.all`. Следващият урок прилага всичко това върху `fetch`. Същият модел ще срещнеш и в Node.js, ако минеш курса `node-api-bazi`.
