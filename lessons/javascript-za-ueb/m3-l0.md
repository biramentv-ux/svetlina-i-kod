> **Цел на проекта:** да сглобиш със свои сили завършено приложение за задачи, което запазва данните в браузъра, зарежда примерни данни от собствен локален сървър и показва ясно състоянията зареждане, успех и грешка.

## Какво ще научиш
- Как се превръща списък от изисквания в работещо приложение на малки стъпки
- Как да разделиш кода на модули, така че логиката да се тества без страницата
- Как да съчетаеш DOM, събития, `fetch`, `localStorage` и обработка на грешки в едно цяло
- Как да докажеш, че приложението работи: тестове, ръчен сценарий и кратък отчет

## Условие

Правиш едностранично приложение „Моите задачи“. Потребителят може да добавя задачи, да ги отбелязва като готови, да ги трие и да ги филтрира (всички, активни, готови). Списъкът **остава след презареждане** на страницата. Освен това има бутон „Зареди примерни задачи“, който взима няколко готови задачи от файл `samples.json` през `fetch`. Ако заявката се провали, приложението не се чупи, а показва съобщение.

Целият код е твой: HTML, JavaScript и по желание CSS. Не ползваш библиотеки и рамки. Данните идват само от твой локален сървър, не от чужд адрес. Така проектът може да се пусне на всеки компютър с Node.js 22, без интернет.

Този проект събира всичко от курса: променливи и функции, масиви и обекти, DOM, събития и форми, модули, `async/await`, `fetch`, `localStorage` и дебъгване. Ако продължиш със `node-api-bazi`, същото приложение може да получи истински сървър с база данни.

## Изисквания

**Задължителни (минимум за оценка):**
- Форма за нова задача; празен или състоящ се само от интервали текст не се добавя.
- Списък със задачи; всяка има отметка „готова“ и бутон „Изтрий“.
- Броячът показва колко задачи остават (например „Оставащи: 2 от 4“).
- Филтри „Всички“, „Активни“, „Готови“.
- Данните се записват в `localStorage` след всяка промяна и се четат при стартиране; повреден запис не срива приложението.
- Бутон „Зареди примерни задачи“ с `fetch` към `samples.json`: показва „Зареждане…“, при успех добавя задачите (без дубликати), при грешка показва български текст.
- Проверка на `response.ok` и на формата на получените данни.
- Текстът на задачите се вмъква само с `textContent`.
- Кодът е разделен най-малко на три модула: логика (чисти функции), хранилище и работа с мрежата.

**По избор (бонус):**
- Редактиране на текста на задача с двойно щракване.
- Таймаут на заявката и бутон „Опитай пак“ при грешка.
- Бутон „Изтрий готовите“.
- Достъпност: етикети, фокус след добавяне, подходящи контрасти.
- Адаптивен вид за телефон.

**Забрани:**
- Без библиотеки и рамки (React, jQuery и други).
- Без `innerHTML` с данни от потребителя или от файла.
- Без чужди публични адреси и без ключове, пароли и лични данни в кода.
- Без останали `debugger` и излишни `console.log`.

## Скелет

Следващите части са проверени с Node 22 и Chromium. Те не са готовото решение: липсват `app.js`, `logic.js` и интерфейсът. Това е твоята работа.

**Сървър за файловете** (`node server.mjs`, по подразбиране порт 3000; друг порт с променливата `PORT`):

```js
import { createServer } from "node:http";
import { readFile } from "node:fs/promises";
import { extname, join, normalize } from "node:path";

const root = import.meta.dirname;
const types = { ".html": "text/html", ".js": "text/javascript", ".css": "text/css", ".json": "application/json" };

createServer(async (req, res) => {
  const pathname = new URL(req.url, "http://127.0.0.1").pathname;
  const name = pathname === "/" ? "/index.html" : pathname;
  const filePath = normalize(join(root, name));
  if (!filePath.startsWith(root)) {
    res.writeHead(403).end("Забранено");
    return;
  }
  try {
    const body = await readFile(filePath);
    res.writeHead(200, { "Content-Type": (types[extname(filePath)] ?? "application/octet-stream") + "; charset=utf-8" });
    res.end(body);
  } catch {
    res.writeHead(404, { "Content-Type": "text/plain; charset=utf-8" }).end("Няма такъв файл");
  }
}).listen(Number(process.env.PORT ?? 3000), "127.0.0.1", () =>
  console.log("http://127.0.0.1:" + (process.env.PORT ?? 3000)));
```

Проверката `startsWith(root)` е допълнителна защита: заявка като `/../../etc/passwd` не излиза извън папката на проекта (при нас получи 404). Сървърът слуша само на `127.0.0.1`, така че не е достъпен от мрежата.

**Хранилище** (`storage.js`):

```js
const KEY = "tasks-v1";

export function load() {
  try {
    const data = JSON.parse(localStorage.getItem(KEY) ?? "[]");
    return Array.isArray(data) ? data : [];
  } catch {
    return [];
  }
}

export function save(tasks) {
  try {
    localStorage.setItem(KEY, JSON.stringify(tasks));
    return true;
  } catch {
    return false;
  }
}
```

**Мрежа** (`api.js`) със защита срещу неочакван отговор:

```js
export async function fetchSamples(url = "/samples.json") {
  const response = await fetch(url, { signal: AbortSignal.timeout(5000) });
  if (!response.ok) throw new Error(`Сървърът върна ${response.status}`);
  const data = await response.json();
  if (!Array.isArray(data)) throw new Error("Очаквах списък със задачи");
  return data
    .filter((t) => typeof t.id === "number" && typeof t.text === "string")
    .map((t) => ({ id: t.id, text: t.text, done: Boolean(t.done) }));
}
```

**Примерни данни** (`samples.json`) са масив от обекти с полета `id`, `text` и `done`. Добави поне три свои задачи на български.

**Тест на чистите функции** (`logic.test.mjs`) с вградения изпълнител на Node. Когато си напишеш `logic.js` с `addTask`, `toggleTask`, `removeTask` и `filterTasks`, проверката върви с `node --test`. Примерен тест:

```js
import test from "node:test";
import assert from "node:assert/strict";
import { toggleTask } from "./logic.js";

test("превключването не променя оригиналния масив", () => {
  const original = [{ id: 1, text: "а", done: false }];
  const result = toggleTask(original, 1);
  assert.equal(result[0].done, true);
  assert.equal(original[0].done, false);
});
```

## Етапи на работа

1. **Скелет.** Пусни сървъра и покажи празна страница с форма. Провери в конзолата, че няма грешки.
2. **Логика.** Напиши `logic.js` като чисти функции: получават масив и връщат нов. Към тях напиши тестове, преди да ги свържеш със страницата.
3. **Интерфейс.** Една функция `draw()` изчиства списъка и го създава наново от текущото състояние. Слушателите променят състоянието и викат `draw()`. Използвай делегиране на събития за бутоните „Изтрий“ и отметките.
4. **Памет.** След всяка промяна викай `save`. Провери: добави задачи, презареди, повреди ръчно записа в инструментите за разработчици и презареди пак.
5. **Мрежа.** Добави бутона за примерни задачи със състоянията. За проверка на грешките преименувай временно `samples.json`, спри сървъра и върни отговор, който не е списък.
6. **Шлифоване и отчет.** Прегледай кода за останали `console.log`, `debugger` и повторения. Напиши `README.md` и `report.md`.

## Контролен сценарий

Ето как трябва да се държи завършеното приложение. Преминахме го в Chromium с референтна реализация (редовете са съкратен наш запис на видяното: брояч, брой редове в списъка и съобщение):

```
добавям                    | Оставащи: 1 от 1 | 1 реда |
текст с таг                | Оставащи: 2 от 2 | 2 реда |
примерни задачи            | Оставащи: 4 от 5 | 5 реда | Заредени: 3
пак (без дубликати)        | Оставащи: 4 от 5 | 5 реда | Заредени: 3
филтър: готови             | Оставащи: 3 от 5 | 2 реда | Заредени: 3
след презареждане          | Оставащи: 2 от 4 | 4 реда |
сървър 500                 | Оставащи: 2 от 4 | 4 реда | Грешка: Сървърът върна 500
отговор, който не е списък | Оставащи: 2 от 4 | 4 реда | Грешка: Очаквах списък със задачи
```

Обърни внимание на три неща. Задачата с текст `<b>удебелен</b> текст` се показва буквално и в списъка няма елемент `b`. Второто натискане на бутона не добавя повторения. Грешката не променя вече съществуващия списък.

## Чести грешки
- **Състояние на две места** – масив в паметта и отделен списък в страницата, които се разминават. Дръж един масив и рисувай страницата от него.
- **Промяна на масива на място** – `push` и `splice` по общия масив затрудняват тестването. Връщай нови масиви.
- **Забравено `save`** – данните се губят точно при един от пътищата (изтриване, отметка).
- **Липсваща проверка на формата на отговора** – `fetch` връща JSON, който не е списък, и кодът се чупи при `for...of`.
- **Тестове, които зависят от страницата** – чистите функции не бива да докосват `document`.
- **Една огромна функция** – разбий я на малки с ясни имена.

## Бърза справка
- Пускане: `node server.mjs`, после `http://127.0.0.1:3000`; тестове: `node --test`
