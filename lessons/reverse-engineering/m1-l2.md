> **Цел на урока:** да разпознаваш в асемблера на x86-64 условията, циклите, switch конструкциите, масивите и структурите на C – и без оптимизации (`-O0`), и с оптимизации (`-O2`).

## Какво ще научиш
- Как изглежда `if`/`else`, `&&` и тернарен израз в асемблер и защо условието в кода често е обърнато
- Как да различиш `for`, `while` и `do-while` по подредбата на сравнението и прехода назад
- Трите начина, по които компилаторът превежда `switch`: верига от сравнения, таблица с преходи и таблица със стойности
- Как отместванията и мащабът в адресирането издават масиви, структури и масиви от структури
- Какво се променя при `-O2`: условни премествания (`cmov`), вграждане, завъртане на цикли, указател вместо индекс, „студени“ части от функции

## Защо започваме от собствен код
Анализаторите не четат асемблер ред по ред – те търсят **шаблони** (patterns), които компилаторът оставя. Най-бързият начин да ги научиш е обратният: пишеш малка функция на C, компилираш я и гледаш какво е станало, с верния отговор пред себе си. Всичко по-долу е реален изход от GCC 13.3 и GNU objdump 2.42 под Ubuntu 24.04 на x86-64. С друг компилатор (Clang, MSVC) или друга версия подробностите ще са различни, но шаблоните са едни и същи.

Работим с учебен `ex.c` с малки функции и с програмата на курса `vm.c`, чиято функция `run` е интерпретатор със `switch`.

## Подготовка: компилиране и показване на една функция
Компилирай всеки пример два пъти и показвай само функцията, която те интересува:

```
gcc -O0 -o ex_O0 ex.c
gcc -O2 -o ex_O2 ex.c
objdump -d -M intel --no-show-raw-insn --disassemble=clamp ex_O0
```

Опцията `--disassemble=име` показва само един символ, `-M intel` превключва към синтаксиса на Intel, а `--no-show-raw-insn` скрива байтовете на инструкциите. Алтернативи: radare2 (`pdf @ sym.clamp`), Ghidra, Cutter или Compiler Explorer, който показва C и асемблера един до друг (не качвай в него чужд или поверителен код).

Под Ubuntu ще прескачаш две неща. `endbr64` в началото на функциите е маркер за допустима цел на индиректен преход (Intel CET), добавян по подразбиране. `fs:0x28` в началото и `__stack_chk_fail` в края са защитата на стека (stack canary) във функции с локални масиви.

## Условия: cmp, test и обърнатото условие
Ето `clamp`, която ограничава стойност между две граници:

```c
int clamp(int v, int lo, int hi) {
    if (v < lo) return lo;
    if (v > hi) return hi;
    return v;
}
```

При `-O0`:

```
1171:  mov  DWORD PTR [rbp-0x4],edi     ; v
1174:  mov  DWORD PTR [rbp-0x8],esi     ; lo
1177:  mov  DWORD PTR [rbp-0xc],edx     ; hi
117a:  mov  eax,DWORD PTR [rbp-0x4]
117d:  cmp  eax,DWORD PTR [rbp-0x8]
1180:  jge  1187                       ; ако v >= lo, прескочи
1182:  mov  eax,DWORD PTR [rbp-0x8]     ; return lo
1185:  jmp  1197
1187:  mov  eax,DWORD PTR [rbp-0x4]
118a:  cmp  eax,DWORD PTR [rbp-0xc]
118d:  jle  1194                       ; ако v <= hi, прескочи
118f:  mov  eax,DWORD PTR [rbp-0xc]     ; return hi
1192:  jmp  1197
1194:  mov  eax,DWORD PTR [rbp-0x4]     ; return v
1197:  pop  rbp
```

Първо, `-O0` прави всичко буквално: аргументите от `edi`, `esi`, `edx` се записват в стека и се четат обратно, така че всяка променлива има собствено място `[rbp-...]`.

Второ, условието е **обърнато**. В C пише `if (v < lo)`, а в асемблера има `jge` – „ако v >= lo, прескочи тялото“. Компилаторът генерира код, който пада (fall-through) в тялото на `if` и прескача го при обратното условие. Затова, когато четеш, превеждай прехода наобратно: `jge X` пред блок означава „блокът се изпълнява, когато е по-малко“.

Трето, видът на прехода издава типа: `jl`/`jg`/`jle`/`jge` са за числа със знак, а `jb`/`ja`/`jbe`/`jae` – без знак (`unsigned`, указатели, `size_t`).

Ето същата функция при `-O2`:

```
11b4:  cmp    edi,edx         ; v ? hi
11b6:  mov    eax,esi         ; резултат = lo
11b8:  cmovle edx,edi         ; ако v <= hi, edx = v
11bb:  cmp    edi,esi         ; v ? lo
11bd:  cmovge eax,edx         ; ако v >= lo, резултат = edx
11c0:  ret
```

Няма нито един преход. Компилаторът изчислява и двата варианта и избира с **условно преместване** (`cmovCC`). (if-conversion). Видиш ли `cmov`, мисли „тернарен оператор“ или „min/max“. Подредбата на проверките може да се различава от изходния код.

### Логическо „и“ и превръщане в 0/1
Функцията `int both(int a, int b) { return a > 0 && b > 0; }` при `-O0` е две последователни проверки, които скачат към една и съща „лъжа“ (`jle 12e4` два пъти) – типичният отпечатък на късото изчисляване (short-circuit) на `&&`. При `-O2` прескачанията изчезват:

```
12d4:  test  edi,edi
12d6:  setg  dl          ; dl = (a > 0)
12d9:  xor   eax,eax
12db:  test  esi,esi
12dd:  setg  al          ; al = (b > 0)
12e0:  and   eax,edx
```

`setCC` записва 0 или 1 в байтов регистър според флаговете. Видиш ли `setCC` следван от `and`/`or`, това е булев израз, превърнат в число. Това е възможно само защото `b > 0` няма странични ефекти; при извикване на функция преходите остават.

`test reg,reg` е идиом за сравнение с нула, а `xor eax,eax` – за `eax = 0`.

## Цикли: къде е проверката и накъде сочи преходът
```c
int sum_arr(const int *a, int n) {
    int s = 0;
    for (int i = 0; i < n; i++) s += a[i];
    return s;
}
```

При `-O0`:

```
11a8:  mov  DWORD PTR [rbp-0x8],0x0    ; s = 0
11af:  mov  DWORD PTR [rbp-0x4],0x0    ; i = 0
11b6:  jmp  11d5                      ; към проверката
11b8:  mov  eax,DWORD PTR [rbp-0x4]   ; ---- тяло ----
11bb:  cdqe
11bd:  lea  rdx,[rax*4+0x0]           ; i * 4
11c5:  mov  rax,QWORD PTR [rbp-0x18]  ; a
11c9:  add  rax,rdx
11cc:  mov  eax,DWORD PTR [rax]       ; a[i]
11ce:  add  DWORD PTR [rbp-0x8],eax   ; s += a[i]
11d1:  add  DWORD PTR [rbp-0x4],0x1   ; i++
11d5:  mov  eax,DWORD PTR [rbp-0x4]   ; ---- проверка ----
11d8:  cmp  eax,DWORD PTR [rbp-0x1c]
11db:  jl   11b8                      ; i < n -> отново
```

(При теб адресите може да са различни.) Шаблонът на `for`/`while` без оптимизации: инициализация, `jmp` надолу към проверката, тяло, стъпка, проверка и условен преход **назад**. Всеки условен преход към по-малък адрес е кандидат за цикъл. `rax*4` издава елемент от 4 байта, а `cdqe` (разширяване със знак) – индекс от тип `int`.

Сега `-O2`:

```
11d4:  test   esi,esi
11d6:  jle    11f8                 ; n <= 0 -> return 0
11d8:  movsxd rsi,esi
11db:  xor    eax,eax              ; s = 0
11dd:  lea    rdx,[rdi+rsi*4]      ; end = a + n
11e8:  add    eax,DWORD PTR [rdi]  ; s += *p
11ea:  add    rdi,0x4              ; p++
11ee:  cmp    rdi,rdx
11f1:  jne    11e8                 ; p != end
11f3:  ret
```

Първо, **завъртане на цикъла** (loop rotation): проверката е отдолу, а отгоре има еднократна защита `n <= 0` – `for` изглежда като `if (n > 0) do {...} while (...)`. Второ, индексът е изчезнал: `a[i]` е заменено с указател, който расте с 4 до крайния адрес. (Пропуснатите тук `nop` са само подравняване.)

В по-нови версии на GCC и при по-сложни цикли ще видиш и **векторизация** – SSE/AVX инструкции като `paddd`, `movdqu`, които обработват по четири или осем елемента наведнъж, с „опашка“ за остатъка. Подробно – в урока за оптимизациите.

### while, който изчезва
```c
int count_down(unsigned n) { int c = 0; while (n) { n >>= 1; c++; } return c; }
```

При `-O2` цикълът изобщо го няма:

```
1204:  test edi,edi
1206:  je   1210          ; n == 0 -> 0
1208:  bsr  edi,edi       ; индекс на най-старшия единичен бит
120b:  lea  eax,[rdi+0x1]
120e:  ret
```

GCC е разпознал, че цикълът брои битовата дължина на числото, и го е заменил с инструкцията `bsr`. Поуката е важна: **при оптимизиран код липсата на цикъл не значи, че в изходния код няма цикъл**. Ако не разпознаваш идиома, провери с дебъгер какво връща функцията за няколко входа.

## switch: три превода
### Таблица с преходи
Функцията `run` във `vm.c` е сърцето на интерпретатора: чете байт код операция и чрез `switch` избира действие. При `-O0` (`objdump ... --disassemble=run vm_O0`):

```
12ac:  movzx eax,BYTE PTR [rbp-0x11a]    ; op
12b3:  cmp   eax,0x5
12b6:  ja    13fa                        ; op > 5 -> default
12bc:  mov   eax,eax
12be:  lea   rdx,[rax*4+0x0]
12c6:  lea   rax,[rip+0xd67]             ; 2034: база на таблицата
12cd:  mov   eax,DWORD PTR [rdx+rax*1]   ; 32-битово отместване
12d0:  cdqe
12d2:  lea   rdx,[rip+0xd5b]             ; 2034
12d9:  add   rax,rdx                     ; база + отместване
12dc:  notrack jmp rax
```

Шаблонът: **проверка на горната граница** (`cmp` + `ja` към `default`), елемент от таблица и **индиректен преход** `jmp reg`. Проверката е без знак (`ja`), за да хване с едно сравнение и отрицателните стойности.

Таблицата е в `.rodata`. В изпълним файл, независим от позицията (PIE), тя не съдържа адреси, а 32-битови отмествания спрямо собственото си начало. Виж ги в учебния `ex_O0`, където `op_name` има таблица на адрес `0x2024`:

```
objdump -s -j .rodata ex_O0
 2020 00000000 4ff2ffff 19f2ffff 22f2ffff  ....O......."...
 2030 2bf2ffff 34f2ffff 3df2ffff 46f2ffff  +...4...=...F...
```

Първият елемент `4f f2 ff ff` е little-endian число `0xfffff24f`, тоест −0xdb1. `0x2024 − 0xdb1 = 0x1273` – точно адресът на клона `default`. Вторият (`0xfffff219` = −0xde7) дава `0x123d` – клонът за `case 1`. Така по таблицата възстановяваш кой номер на случай към кой код води. Декомпилаторите правят това автоматично, но ако пропуснат таблицата, функцията изглежда „отрязана“ след `jmp rax`.

При `-O2` в `vm_O2` функцията `run` дори не съществува – вградена (inlined) е в `main`. Таблицата обаче остава и е по-къса:

```
1289:  movzx edx,BYTE PTR [r12+rbx*2+0x5]   ; op
128f:  movzx ecx,BYTE PTR [r12+rbx*2+0x6]   ; arg
1295:  lea   eax,[rdx-0x1]                  ; op - 1
1298:  cmp   al,0x4
129a:  ja    1361                           ; default
12a3:  movsxd rax,DWORD PTR [r13+rax*4+0x0]
12a8:  add   rax,r13
12ab:  notrack jmp rax
```

`lea eax,[rdx-0x1]` изважда най-малкия случай (`OP_PUSH = 1`), за да започне таблицата от нула. Значи, за да получиш номера на случая, добавяш обратно 1. Забележи и `rbx*2+0x5`: стъпка 2 байта (двойка opcode–операнд) и начало 5 байта след буфера (след магията `PV01` и байта за брой) – това директно издава формата на `.prog` файла.

### Таблица със стойности
Ако всеки случай само връща константа, GCC прави още една крачка – масив от резултати, наречен `CSWTCH`:

```
1194:  sub  edi,0x1
1197:  mov  eax,0xffffffff         ; default = -1
119c:  cmp  edi,0x4
119f:  ja   11ab
11a1:  lea  rax,[rip+0xe88]       ; 2030 <CSWTCH.2>
11a8:  mov  eax,DWORD PTR [rax+rdi*4]
```

Няма индиректен преход – само четене от масив. Името `CSWTCH` се вижда само ако файлът не е strip-нат.

### Верига от сравнения
При редки стойности (`10`, `200`, `3000`, `40000`) GCC прави **двоично търсене** от `cmp`/`je`/`jg`. При `-O2` се появява и трик: `cmp edi,0xc8; sete al; add eax,eax` връща 2 за `case 200` и 0 иначе, без преход. Дърво от сравнения с „кръгли“ константи означава рядък `switch` или верига `if`/`else if`.

## Масиви и структури: отместване и мащаб
Адресирането в x86-64 има вида `[база + индекс*мащаб + отместване]` и почти всеки достъп до данни в C се превежда в тази форма:

```c
struct point { int x; int y; char tag; long id; };
long get_id(struct point *p, int i) { return p[i].id; }
int  get_y(struct point *p)         { return p->y; }
```

```
get_id (-O2):
12a4:  movsxd rsi,esi
12a7:  lea    rax,[rsi+rsi*2]             ; i*3
12ab:  mov    rax,QWORD PTR [rdi+rax*8+0x10]  ; p + i*24 + 16
get_y (-O2):
12c4:  mov    eax,DWORD PTR [rdi+0x4]
```

`+0x10` е отместването на полето, `rax*8` при `rax = i*3` дава стъпка 24 (размерът на структурата), а `QWORD PTR` – поле от 8 байта. В `get_y` има само база и отместване 4 с размер `DWORD`.

Реалната подредба, отпечатана от малка програма с `offsetof`:

```
sizeof=24 x=0 y=4 tag=8 id=16
```

Между `tag` (1 байт на отместване 8) и `id` (на 16) има 7 байта **подравняване** (padding), защото `long` трябва да е на адрес, кратен на 8. Затова размерът е 24, а не 17. Отмествания 0, 4, 8 и 16 от една база без достъп до 9–15 означават дупка от подравняване, а не скрито поле.

При `-O0` същата `get_id` смята `i*24` като `(i+i+i)<<3` с `add` и `shl` – компилаторът избягва `imul` за малки константи.

## Справочна таблица: от асемблер към C
| Виждаш | Вероятно означава |
|---|---|
| `cmp a,b` + `jge` пред блок | `if (a < b) { блок }` – условието е обърнато |
| `jl/jg/jle/jge` | сравнение на числа със знак |
| `jb/ja/jbe/jae` | сравнение без знак, указатели, `size_t` |
| `test r,r` + `je/jne` | сравнение с нула, проверка на указател за NULL |
| `cmovCC` | тернарен оператор, min/max, `if` с просто присвояване |
| `setCC` + `and`/`or` | булев израз, превърнат в 0/1 |
| `jmp` надолу, после условен преход назад | `for`/`while` при `-O0` |
| защитна проверка + условен преход назад | `for`/`while` при `-O2` (завъртян цикъл) или `do-while` |
| указател, който расте с константа, и `cmp` с краен адрес | обхождане на масив, индексът е премахнат |
| `cmp x,N` + `ja` + `jmp reg` | `switch` с таблица с преходи, N+1 случая |
| `sub x,K` преди таблицата | най-малкият `case` е K |
| четене от `CSWTCH.*` | `switch`, който само връща константи |
| дърво от `cmp`/`je`/`jg` | рядък `switch` или `if`/`else if` |
| `[база+индекс*S]` | масив с елементи по S байта |
| `[база+K]` с различни K и размери | полета на структура |
| `lea r,[i+i*2]` + `*8` | индекс в масив от структури по 24 байта |
| `fs:0x28` + `__stack_chk_fail` | защита на стека, в функцията има локален масив |
| `__printf_chk`, `fwrite` вместо `fprintf` | `_FORTIFY_SOURCE` и замяна на printf с по-проста функция |
| символ `име.cold` | рядко изпълнявана част от функцията, изнесена настрана |

## Стъпка по стъпка
1. Във временна папка сложи `vm.c` и свой `ex.c` с функциите от урока и кратък `main`, който ги вика.
2. Компилирай с `-O0` и `-O2` и провери, че двата отпечатват едно и също.
3. Покажи всяка функция в двете версии една до друга (`diff -y` или два прозореца).
4. В `-O0` версията отбележи коя променлива е всеки `[rbp-...]`.
5. В `-O2` версията намери кои конструкции са изчезнали (преходи, индекси, цикли) и с какво са заменени.
6. За `op_name` разчети таблицата с преходи в `.rodata` ръчно и свържи всеки елемент с низа, който клонът връща.
7. В `vm_O2` намери къде е вградена `run` в `main`, таблицата за `switch` и мястото, от което се чете двойката opcode–операнд.
8. Сравни ръчната си разшифровка с декомпилирания `switch` в Ghidra или radare2.

## Пример от практиката
Да кажем, че колега е загубил изходния код на стара версия на собствения ви интерпретатор и имаш само strip-нат, оптимизиран файл. В `main` виждаш `movzx edx,BYTE PTR [r12+rbx*2+0x5]`, после `lea eax,[rdx-0x1]`, `cmp al,0x4` и `jmp rax`. Оттук знаеш: входът се чете на двойки байтове от байт 5 нататък, първият байт е код на операция от 1 до 5, а `switch` има пет клона. Разчиташ таблицата, виждаш `add`, `imul`, `sub` и `__printf_chk` в клоновете – и си възстановил набора инструкции, без да пускаш програмата.

## Чести грешки
- **Четеш условието буквално** – `jge` пред блока означава, че блокът се изпълнява при „по-малко“. Винаги обръщай прехода, когато описваш условието на `if`.
- **Бъркаш знаковите и беззнаковите преходи** – `ja` и `jg` издават различен тип. Записвай го, ще ти трябва при типовете.
- **Търсиш функция, която е вградена** – при `-O2` малки функции изчезват. Ако символ липсва, търси кода му в извикващата функция.
- **Смяташ, че липсващ цикъл значи липсваща логика** – `bsr`, `popcnt`, векторни инструкции и `CSWTCH` масиви заместват цели цикли и `switch` конструкции.

## Речник
- **Шаблон** (pattern) – повтаряща се поредица инструкции, която съответства на конкретна конструкция на C.
- **Условно преместване** (conditional move, cmov) – инструкция, която копира стойност само при изпълнено условие, без преход.
- **Завъртане на цикъл** (loop rotation) – преместване на проверката в края на цикъла и добавяне на еднократна защитна проверка отпред.
- **Таблица с преходи** (jump table) – масив от адреси или отмествания, по който `switch` скача с индиректен `jmp`.
- **Таблица със стойности** (switch conversion, CSWTCH) – масив с готовите резултати на `switch`, от който се чете вместо да се скача.
- **Вграждане** (inlining) – замяна на извикването на функция с нейното тяло.
- **Подравняване** (padding, alignment) – празни байтове в структура, които поставят полетата на кратни адреси.
- **Защита на стека** (stack canary) – контролна стойност между локалните данни и адреса за връщане, проверявана преди `ret`.
- **Студена част** (cold section) – рядко изпълнявана част от функция, изнесена в отделен символ като `main.cold`.

## Бърза справка
```
gcc -O0 -o p0 p.c ; gcc -O2 -o p2 p.c          # две версии
objdump -d -M intel --no-show-raw-insn --disassemble=f p0
objdump -s -j .rodata p0                        # таблици и низове
nm p2 | grep -E ' [tT] |CSWTCH'                 # кои функции са оцелели
gcc -O2 -S -masm=intel -fverbose-asm p.c        # асемблер с коментари
```

## Упражнение
Напиши функция на C с поне: един `if`/`else` със сравнение без знак, един `while`, един `for` по масив от структури и един `switch` с поне шест последователни случая, от които поне два правят нещо различно от връщане на константа. Компилирай с `-O0` и `-O2`.

Критерии, по които сам проверяваш дали си се справил:
- Във всяка от двете версии си посочил адреса на всяко сравнение и си написал условието от изходния код, което отговаря на него.
- Намерил си таблицата на `switch` в `.rodata`, разчел си поне три елемента ръчно и си ги свързал с правилните случаи.
- Посочил си размера на структурата и отместванията на полетата само от асемблера и си ги проверил с `offsetof`.
- Описал си поне три разлики между `-O0` и `-O2` с адресите им.

## Обобщение
Конструкциите на C се превеждат в малко шаблони: обърнат условен преход за `if`, преход назад за цикли, граница плюс индиректен скок за `switch`, база плюс индекс по мащаб плюс отместване за масиви и структури. Без оптимизации шаблоните са буквални и всяка променлива живее в стека. С `-O2` преходите стават `cmov`, циклите се завъртат, индексите стават указатели, малките функции се вграждат, а цели цикли се свиват до една инструкция или таблица. Учиш ги, като компилираш собствен код и сравняваш.
